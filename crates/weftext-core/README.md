# Local Core

The v0.3/v0.4 extensions preserve existing `weftext.local-mvp.v1` libraries and complete private journals without resetting real data. `prepare_operation` freezes the request, random PlanId, complete preimages/afterimages, actual file/directory objects and preview; `execute_operation(operationId, planId)` executes only that plan. Changed input with the same ID conflicts; committed operations return the original receipt, while unknown installation outcomes require inspection and explicit preservation rather than re-execution. Preparation does not install user files.

Managed same-volume rename, move, application trash and restore retain stable NodeId and physical identity. Namespace operations use a deduplicated root-to-leaf handle closure, request source DELETE access initially, and retain no-share-delete guards through the decision. Handle-relative rename is no-replace. Node rename first renames the canonical leaf, then its directory; intermediate failure retains the complete plan and barriers both paths. Trash moves the original tree into `.weftext-trash/<operationId>` without deleting bytes; occupied restore targets conflict. Trashed sources are read-only through Core.

`read_snapshot` holds all selected source/config/resource share-zero handles together and returns opaque current baseIds. Writes recheck actual object, stamp, exact bytes and parent object; same-byte replacement cannot revive an old basis. `UpdateFiles` gives source and annotations one original journal and one commit decision; partial installation barriers every participant. External tools can still observe partial installation, so this logical atomicity is not atomic filesystem replacement.

`admitted_snapshot` uses committed births from this one private Core authority, subtracting actually owned trash trees. Every selected source and schema handle coexists during capture. Missing, duplicated, excluded or damaged admitted members set `complete=false`; raw discovery `rawComplete/rawPending` is separate, and raw metadata does not create membership. `prepare_admitted_operation` freezes complete membership and source/schema bases as dependencies and revalidates them before effects. A Query result does not confer write authority.

Schema/settings use real config roles, exact bytes and the same journal. Styles are the real `library-style.typ` Resource owned by `Styles/Styles.typ`; settings select its stable ResourceRef. First application creates node, module, resource manifest and selector in one decision. Native source and style controls share that file. Resource import is create-only and commits manifest plus exact resource bytes together. Random ResourceId admission requires the private committed object birth; external manifest UUIDs do not establish identity.

Copy freezes members, the actual current schema (or explicit bundled-schema absence), after blobs and fresh Node/Resource/Annotation/definition mappings. It invokes Knowledge's pure planner for official AST slots and schema-qualified typed/current/pinned references while retaining ordinary bytes. Unproven closure rejects by default; explicit `allowLosses` preserves originals and specific losses. Registered template instantiation uses the same owned-subtree copy planner, including self references and resource ownership, and freezes exact source/config/resource dependencies in the original plan. New decisions record exact after-stamps and random retained revisions; actual legacy records lacking this evidence remain observed, and an annotation transaction can explicitly admit its current source basis.

Backup captures the entire selected library tree, including ignored bytes and trash, plus its related original journal, drafts, draft history and relocation-consumption markers. Other libraries and ordinary documents sharing the private data directory are excluded. It creates the destination only if absent and writes versioned `backup.json` with exact hashes and restore boundaries. The active singleton lock and backup's own new operation are outside the input cut. Snapshot limits are 5000 files and 64 MiB total bytes; unreadable or excessive snapshots fail. New physical paths/devices require explicit rebinding; automatic cross-device restore/migration is not implemented. Preserve originals and never reset private state or activate a foreign library from its backup marker.

`admitted_compile_snapshot(root, lifecycle)` freezes the admitted source/schema set together with bounded native inputs and the exact selected style module, owner and manifest. Its root-relative byte map is the compiler's entire filesystem input; unknown dependencies fail without reading later disk/package state. This immutable local cut supports rendered Query products without claiming causal or continuously current filesystem coverage.

Full historical SourceSchemaBasis/causal LogicalCut, cross-device sync/hosted permissions, automatic cross-device backup restoration, semantic transfer of every unknown Typst construct, real power-loss and every filesystem/filter qualification remain unimplemented. These bounded local features have actual NTFS tests; they do not establish completion of all v0.4 or future synchronization contracts.

This crate implements open, exact UTF-8 source save, create-only Save As, private retained drafts, pending journals, bounded inventory and explicit new library/note creation on Windows local NTFS. It uses the official Typst AST to inspect declarations. Ordinary `.typ` files receive no metadata injection; random session/base tokens are distinct from file identities, Node IDs and persistent revisions.

Existing-file saves use `NtCreateFile` to retain no-share-delete guards over the actual directory ancestor chain, with LIST_DIRECTORY/READ_ATTRIBUTES access. Adjacent directories and the leaf are opened by names relative to parent handles. A read/write share-zero leaf handle reads the actual object and exact preimage, flushes the full before/after journal, writes/truncates/flushes/readbacks through that same handle, then flushes the original operation decision. The absolute DOS path only locates the initial volume root; subsequent writes do not resolve mutable path strings. Volume GUID/NTFS, object types, reparse/offline/recall flags and a single leaf hard-link are checked. Inventory enumerates real protected directory handles and does not inherit `.gitignore`.

Journals and drafts live in the caller-selected application private directory, which the caller should place outside user material and sync roots. Only one live Core may use that private directory: its Windows share-zero lock and ancestor guards for private journal/draft directories last until Core is dropped. Plans, births and commit decisions are written/flushed to unique temps before atomic no-replace publication of final record names; unpublished partial temps are not recovery operations. Separate private data directories accessing the same tree do not share a reader barrier and are unsupported. A saved operationId with identical input replays the original result; changed input is rejected. Creation `_with_id` APIs also support exact retries without allocating a second identity after a lost response.

Pending journals prevent affected files from becoming fresh read/write bases. Transaction recovery reports every actual member's before/after/current bytes, object binding and coherence. Explicit `resumeOriginalPlan` finishes only known mixed before/after Update members under their original object/parent bindings; `adoptAfterImages` commits only verified complete original after objects. Third/unknown states cannot release the barrier. Namespace intermediate states remain visible and are never blindly replayed. Drafts follow committed subtree relocations across restart, retaining competing proposals and their original bases; explicit resolution archives both the old proposals and the reviewed merge.

Library creation requires an absent directory and rejects every existing directory. The create-only syscall returns the original new directory handle; configurations/markers are created without replacement and remain protected through decision. Configuration declares `weftext.local-mvp.v1` and unimplemented schema/sync support. Activation additionally requires the real committed initialization fact in this application's private journal; markers and externally declared UUIDs do not activate a library. New notes use `A/A.typ`; their default title is native `document(title: [...])` presented by `title()`, separate from section headings. Existing notes and supplied template source are not migrated. Declaration IDs are admitted only with a matching private committed birth/object binding. External copies, unknown IDs, duplicates and damaged pairing receive distinct diagnoses. A damaged known node does not silently become an ordinary file that bypasses identity constraints.

The MVP `.weftext-rules` subset is exact relative-path JSON below. Ignored boundaries are hidden; explicitly unmanaged boundaries remain browsable as ordinary files while node discovery/creation does not re-enter them. Ordinary containers lacking a same-name main file remain browsable and allow discovery of nonexcluded descendant pairs.

```json
{"version":1,"ignored":["Hidden"],"unmanaged":["Ordinary"]}
```

Globs, `.gitignore` semantics and other rule formats are unsupported. Incomplete interpretation reports warnings/incompleteness and blocks structural creation. Sources are limited to 2 MiB each; inventory to 5000 entries and 16 MiB total source. Limits/errors set `complete=false`. Inventory is a bounded external observation, not an atomic whole-library snapshot, complete typed Query or sync fact.

Full historical SourceSchemaBasis, hosted permissions, cross-device sync, automatic foreign-library admission, permanent deletion and publication remain unimplemented. Copying the library alone cannot recover this application's identity admissions or pending responsibilities. In-place installs are not crash atomic; process failure can leave partial bytes. Power loss, all volume/filter combinations and Windows file symlinks are unqualified. Network, non-NTFS, reparse, cloud placeholder and hard-link targets are rejected without falling back to read-hash-replace.

Isolated verification: `cargo test -p weftext-core` and `cargo clippy -p weftext-core --all-targets -- -D warnings`. Tests cover exact BOM/newline/invalid-source preservation, shortening/sequential saves, external equal-byte replacement and new content, stale bases/retries, third-state recovery/partial decisions, busy writers/persistent writable mappings, ancestor/leaf replacement protection, hard-link rejection, junction rejection without symlink privilege, pairs/ordinary browsing/ignore boundaries/duplicate identities and create-only collisions. When file symlink fixture creation receives Windows privilege error 1314, it explicitly remains unexercised and is not platform qualification evidence.

System-call contracts: [NtCreateFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile), [NtQueryDirectoryFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntquerydirectoryfile), and [FILE_DIRECTORY_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_directory_information).
