# Local Core

All clients share Core for ordinary/managed-file opening, saving, Drafts, inventory, explicit operations, original-receipt recovery, history, resources and synchronization admission. Author writes have one `Intent → Plan → OperationJournal → Receipt` path. The storage contract is `weftext.qualified-fs.v2`, independently of the native export-package version. Physical identity and preserved metadata have platform tags. Old untagged physical records are rejected with original bytes retained for explicit import/conversion, without resetting devices or inventing historical continuity.

Windows local writing retains actual NTFS handles/share modes: a parent closure and the same leaf handle qualify objects/exact preimages, write/truncate, flush, reread and decide. Handle-relative no-replace moves retain original objects; equal-byte replacement cannot revive an old basis. Destination absence inside a moving source is checked through that retained source directory, without reopening its protected pathname. Windows `BoundFile` retains the original NT entry authority and existing guard closure, including canonical-witness handoff at a final parent. The cross-platform abstraction does not keep an extra DELETE parent handle that blocks that handoff.

The [Linux controlled-service profile](../../docs/LINUX.md) uses explicit `BackendContext::controlled_service` and `Core::with_backend`. An administrator-created fresh empty root, distinct OS service/client/worker identities, private permissions and actual-root descriptor lock establish the boundary. A same-UID directory, API assertion or advisory lock cannot replace OS isolation. The service verifies real/effective/saved UID/GID, empty supplementary groups, no capabilities and an exclusive service group. Clients have never held direct root-inode write authority; retained data enters only by explicit create-only import. Linux `BoundFile` retains root/parent descriptors and exact entry names. `openat2`, opaque handles/FSID, strict enumeration, no-replace and separate file/directory fsync are real Linux implementations, without synthesized Windows fields or inode/ctime fallback. Other unqualified platforms remain explicitly unavailable.

Every initial guard receives the owning Core's explicit backend. No ambient registration admits another Core's root. Private reads, cached facts, empty catalogs and negative existence facts share the enrollment fence; failed reads never become guessed absence. Missing or damaged original committed birth/revision/Plan facts remain errors and cannot reclassify a managed Node as an ordinary file.

Device state belongs to the original physical private profile. Device record v2 explicitly selects Windows DPAPI/SID or Linux controlled-service HMAC-SHA256. Linux keeps keys in administrator configuration outside profiles, libraries and backups. Profile copying, changed machine/enrollment or authentication tampering cannot continue the original device qualification. Known foreign-platform records keep their ID with non-current status; unknown formats fail with originals preserved. Preferences, Drafts and authorization retain their respective original scopes.

Library creation requires an absent target. Files are create-only, and actual directory/file birth objects remain held through decision. Windows obtains the new directory handle directly; only the administrator-enrolled continuously isolated Linux namespace permits the equivalent `mkdirat → constrained open`, with entry synchronization. Source/Schema/Query scopes exclude conflicting writes. Moves retain objects; copy freezes exact inputs and assigns fresh identities. Trash/restore retain originals without permanent deletion or expanded confirmation scope.

Ordinary `.typ` files receive no management metadata. `A/A.typ` admission requires declaration identity and actual committed birth/object binding. Names, UUIDs, markers and matching bytes grant no historical/write qualification. Observed/partial inventory and complete admitted cuts remain distinct; budgets/enumeration failures do not become complete empty results. Native source, Schema, resources, authored order, tags and export consumers share real typed metadata and physical witnesses.

Drafts and active journals are private and outside the author tree; on Linux both remain inside the same admitted service root. Complete temporary records are flushed before publication. Private replacement declares replacement; public record names are create-only. Linux synchronizes both moved directories, independently of file flush. Different data directories cannot bypass one root's writer coordination. Lost authority, disk exhaustion, third states and unknown effects retain original operationId, Drafts and journals without allocating replacement requests.

Replication retains stable author references while admitting actual destination-platform objects anew. Historical Windows physical evidence does not become Linux continuity. Complete owner backup freezes the library and its related original private recovery material, excluding device keys, machine state and other-library bodies. Native content export and complete recovery backup remain distinct; an export package cannot reconstruct lost execution responsibility.

[CORE](../../docs/design/CORE.md) owns the contract; [MVP](../../docs/MVP.md) records actual scope and historical candidate qualifications. Source implementation and artifact acceptance are separate. Mechanism probes, WSL command-line checks and earlier Windows results establish no new-candidate, Linux desktop, Mobile, macOS or actual power-loss acceptance. Unisolated non-Windows product workers remain explicitly unavailable.

Use the existing product entries: `python scripts/check.py --models`, Rust formatting, `cargo clippy -p weftext-core --all-targets -- -D warnings` and `cargo test -p weftext-core`. The Linux guide describes explicit deployment tests and required identities/environment; run them as the service UID, since root does not establish service-authority acceptance. Results belong to the original source/artifact candidate record.
