# 公开文档策略

## 语言布局

面向读者的公开 Markdown 使用配对文件。中文源文件命名为 `name.zh-CN.md`；同步英文译文保留稳定的 `name.md` 路径。两份文件具有对应的标题层级和语言切换链接。一次变更须同时更新两种语言。

根目录 `LICENSE` 中的 GNU AGPL 文本保持原样并作为唯一权威文本；`LICENSE.zh-CN.md` 只是非权威阅读说明。测试夹具、生成证据、锁文件、机器可读样例和上游许可证原文不翻译。

## 公开内容

公开文档描述当前契约、当前实现边界和剩余发布门槛，不保留开发阶段编号、已完成任务叙事、旧决策时间线、内部排期、任务交接、研究比较、验收台账或竞品名称。Git 记录文档历史；私有控制工作区保存规划和研究材料。

兼容与迁移文字只说明读取或转换现有数据所需的有效边界。已经退出的语法不能作为另一种受支持产品语言介绍。

公开文档使用中性、可验证的语言。不得使用宣传口号、竞品式比较、优越性判断、没有证据的成熟度声明，或把目标能力写成产品成就。安全性、完整性和性能表述必须是可测试的约束、当前证据或明确标注的未满足门槛，不能作为自我评价。

## 读者层与契约层

`docs/guides` 使用普通语言解释用户概念、常见任务和能力状态。它必须明确区分当前基础、已确定但仍在实现的设计以及发布前限制。指南不能把计划中的能力写成已经交付。

`docs/specifications` 和 `docs/architecture` 保存实现契约与架构权威。它们可以使用严格的约束语言，但仍须遵循[术语表](TERMINOLOGY.zh-CN.md)，避免机翻、无定义缩写和不必要的长段落。指南与新规范冲突时，以新规范为准，并在同一变更中同步指南。

## 同步门禁

编辑公开文档后运行文档检查：

```text
python scripts/check_docs.py
```

检查会验证文件配对、frontmatter、语言链接、标题层级一致性、相对链接、本地化交叉链接、中文禁用译法、禁用的历史标签和排除的产品比较名称。源代码门禁运行同一命令。自动检查不能替代逐段语义校订；改变契约含义时仍须人工对照两种语言。
