# 本地写作与知识工具

当前 **0.6.0 Windows／NTFS 既定 v0.6 范围已完成并通过最终优化程序验收，尚未正式发布**。本地功能、[受控 Server / WebUI](SERVER.zh-CN.md)、多用户权限与同所有者同步使用同一 Core；同一最终优化程序已通过完整 HTTP 矩阵、受影响浏览器和真实 NAS HTTPS 验收。功能划分见 [路线图](ROADMAP.zh-CN.md)。作者内容始终保存在原生 `.typ` 中，界面、搜索和视图不另存一套正文。

本候选接入**本地笔记时间线**和**正文内嵌 Query 五档交互**，复用 Core 保存与恢复、共享源码/Draft/Undo 和既有 Query 执行器。具体本地范围和待验平台条件见 [路线图](ROADMAP.zh-CN.md)；实现存在不等于所有交付条件均已验收。

此前 **0.6.2 本地交付候选，初始 Windows 本地／自托管范围已完成**；上面的 0.6.0 结论仍只对应原已验基线。0.6.1 已完成其本轮自动检查、受影响浏览器和真实 Word 结构／语言槽位往返，但继承以下证据限制：Windows 11 微软拼音正文、普通格和合并格人工输入只在前一候选核对，最终候选没有真实系统输入法复验；此前一次跨档撤销插入多余源码的异常尚未同形复现。可复现的组合输入收尾及历史隔离缺陷已修复并有自动回归，不能据此宣称原异常根因或整版输入法验收完成。Obsidian／参照插件只用于独立体验对照，不是运行依赖，也不与 Weftext 共享或同步资料库。

## 0.6.3 发布候选：整版验收中

当前工作树的稳定化候选为 `0.6.3-rc.4`。前三阶段及 rc.1／rc.2 的原产物和已验结论保留原边界。本轮按 CodeMirror 的实际修改增量维护 Unicode 字符数，并复用当前文档的源码字符串；超长源码行与原生预览文字仅关闭字偶距计算，保留完整文本、自动折行、来源映射及同一 Undo。托管恢复稿同步保留紧凑差异、实际基线及原未决保存请求，避免每次输入重复写入整篇正文。新增真实浏览器键盘输入的延迟测量入口，分别记录反馈上界、Chrome Layout 和有界范围；它不测操作系统 IME，也不代表整套性能目标通过。新候选须以同一产物完成受影响检查；真实系统 IME、原 K 撤销异常及完整参照／性能／平台门仍按下文保留。

rc.4 在连接时逐个报告独立面板的失败，继续初始化其它获权面板；例如库配置目录暂时不可用，不应阻断资料导入入口。点击“全部文档”可重试连接，正文草稿保留，成功后清除旧失败提示；身份变化或撤权仍中断旧连接。新增故障注入不等于解释了原批次中的重启超时，浏览器文字输入也不代表真实系统输入法通过。

多级标签现使用 Core 接纳的 v2 完整森林。支持指定父级创建、改名、换父／移至根、统一可消歧选择器和树浏览；笔记保直接 TagRef／literal，不把父链写入正文。导航新标签条件默认含自身及子级，精确／含子级模式可见并保存；现有明确精确条件不改含义。`tagInSubtree` 使用同 cut 的完整获权标签树和静态依赖，零行、否定和保存定义的 current／pinned 调用仍校验结构；树完整与笔记范围完整分开。移动权独立于创建／改名，通用写入、提交和原操作恢复按实际差异检查。v1 原历史／分支保准确 blob 及全根读取语义，当前后继只接受 v2；实际旧资料盘点／转换不由合成测试替代。硬删除、合并、多父和标签手工排序仍后置。

保留第一阶段接通的当前页面内的快捷打开（Ctrl+P）、命令搜索（Ctrl+Shift+P）、最近访问、返回／前进（Alt+左／右），以及本地节点内容、面包屑、个人排序、选择／多选、独立摘要预览和相同对象菜单的右键／更多／Shift+F10 入口。整个节点的改名／移动／复制／回收沿用已有文件影响预览；多选不会隐式批量改写。作者同级顺序现由原 Settings 中的稳定父／直接子级引用维护；只有显式作者模式的上移／下移或前后拖放才准备写入，预览后确认原计划，取消／未知结果沿原操作处理。个人排序、摘要／缩略图和密度按稳定父身份保存在本机。图片／PDF 首页缩略图逐个按需读取准确源与资源版本，区分无图、生成中、失败、不支持和不可用，不打开编辑会话、不等待全库完成，也不抢草稿焦点。第二阶段的属性／Query 范围如下。

导航轨迹最多 128 项、最近访问最多 32 项，均为当前页面内的个人状态。已打开笔记保留自己的草稿、源码选区和撤销；返回时重新核对实际目标及当前目录，失败保原稿。自托管最多保留 16 个正文编辑会话；第 17 个新目标明确拒绝，原会话及恢复稿保留，可保存后刷新释放内存。退出／撤权清除保留编辑器、轨迹和菜单；恢复偏好不产生读取或写入权限。页面关闭／重启继续沿用原草稿恢复合同，不承诺跨进程保留浏览轨迹或逐步 Undo。

“插入与块操作”、命令搜索和正文对象菜单复用同一动作。普通段落、标题、列表和已导入图片路径进入同一草稿；普通根块可在段落／标题／列表项间转换，并在有空段分隔的相邻普通根块间移动。保范围外原字节；带标签、生成／嵌套构造、未知绑定或规则、跨规则／注释及无法证明的来源保源拒绝。标题移动只移动所选标题块，不隐含移动整棵章节子树。一次原生命令产生一次可撤销编辑；菜单与未应用提案取消不修改正文。

本地“插入内嵌 Query”使用已显式安装的 schema，新定义提案只进入正文草稿，每次保存前可新增一个定义。Core 沿原所有者、原 key 预约和原保存编号恢复；撤销后保存其它文字不消耗该定义预约，重启后也不按同名重建 key。保存成功后才有正式定义资格。错误或丢回执保留名称和筛选输入，重试沿原预约；确认期间输入变化时不采用旧提案。自托管入口定位已有高级查询的新定义提案，继续沿原预约／权限及草稿保存链。第二阶段同时提供复用已保存定义的调用入口；显示实际归属，明确选择 current／pinned 和准确版本。修改调用及参数只改当前节点，打开归属笔记后才可在其自身资格下编辑定义。复杂高级计划保留原源并提供源码入口，不被简化控件覆盖。

新建资料库默认不创建根笔记；也可明确选择空白根笔记或附初始查询的普通根笔记。预设提供全部笔记／任务／事件，最多三项；查询路径在同一预览中列明普通根文件、集中 schema、真实作用域与筛选，不创建示例业务记录。根文件为 `<库目录>/<库目录名>.typ`，使用普通 NodeId、正文和原生 Query key，同一固定创建计划完成出生及定义接纳。关闭预览不创建文件；丢回执沿原 operationId 查询／重试。后续编辑、清空、重开及升级不会重放预设或重置正文。默认不选择根笔记时的原创建行为保持不变。

同一节点的多个内嵌 Query 各自保留运行／错误／结果与个人视图。可见控件编辑类型、typed 筛选、投影字段、排序、分组汇总和条数；复杂 CEL 保留原条件，重复记录的 same-item 条件不拆散。作者修改进入原 Draft／Undo，保存前不写文件。更多菜单可在仅空白分隔的相邻可写 Query 间上下移动，或明确移除此处定义／调用；注释、正文、规则及未知来源屏障保源拒绝。移除定义会明确影响其它调用，不级联删除结果笔记；取消不改稿。

每个出现项可独立切换表格／列表／看板／日历并选择显示列、分组列或日期列。此类个人偏好不修改 Query 或结果字段：本地按准确 NodeRef／Query key 保存，自托管仅保留当前页，退出清除。投影或字段配置变化会提示并回到完整表格供重新选择；未填写、none、无效、未投影及无日期结果各自保留。汇总、派生、历史或不具备明确直接字段来源的行只读，旧结果不恢复写资格。

属性面板及本地高级查询中的直接字段使用同一 typed 编辑器；应用仍修改真实笔记的草稿，单独保存。无效的未完成输入在刷新或返回原笔记时保留；字段身份／形状变化保留原输入并要求重新核对，不绑定同名新字段，迟到旧表单不改新笔记。组合输入期间延后面板替换及应用。关系选择沿原获权对象选择器，不猜文本。自托管查询目录只披露独立字段读取授权覆盖的最小表单 schema；结果就地编辑另需实际字段写权，正文／查询读取权不授予字段写权，撤权清除保留内容。

独立高级查询面板在后台读取完成时保留正在编辑的筛选值、汇总选择、完整计划及参数原文、光标和组合输入；登记标签与周期笔记控件的输入和展开状态也保留。未应用的筛选或计划不会自动成为作者查询。schema 变化后，原字段不可用会明确标记并保留输入，须重新选择准确字段；不会用同名新字段代替，保留旧输入也不恢复写入资格。

普通根笔记与库控制文件位于同一目录时，同步只收集该笔记的作者文件，不把 `.weftext-workspace.json`、提交记录及格式标记当笔记资源。副本中的位置由原纳管关系重绑定，内容回传保留接收端原根笔记位置，不移动整个资料库或新增“工作台”身份。其它结构修改继续经过原位置与授权检查。

第三阶段新增“关系”诊断：链接问题按目标／来源／逐处分组，每处可定位；孤立页区分真正孤立、无入链、预期孤立、仍有无效出链和扫描不完整，支持列表与目录分组。节点存在但片段失效仍保节点连接。忽略准确来源→地址及预期孤立规则先预览、可取消和撤销；规则仅为个人呈现，本地按库保存，托管仅存当前页面并在退出／撤权时清除。搜索、筛选和刷新保输入；失败标过期，失效依据不供写入。停止等待只取消观察，不宣称服务端只读计算已停止。

潜在链接保精确 Unicode 字面及全部重叠匹配，新增本次成功编译中唯一标签和可按准确源位置关联的非生成主文件标题文字。候选分别展示对象、片段及来源，可选标题／名称或稳定片段范围，并按此篇或个人授权范围忽略词／排除目标。无稳定标签不猜寻址或新建标签；重复／变化／撤权的片段不能转换为旧目标。明确选择后才将原生稳定链接加入同一 Draft／Undo，不自动保存。本地正文提示默认关闭；托管使用默认关闭的可访问候选列表。正文问题提示只标记本地现有链接，不改变原导航。

诊断只消费本次获权原生正文与 typed 属性引用，生成／导入等链接未获完整缺席证明时保持部分覆盖；无入链和孤立只在声明范围解释，不宣称全库绝对无关系。标签／片段词典每次至多编译 8 篇；本地最多 20,000 处链接及 2,000,000 个文字 scalar，托管最多 4,096 个候选／链接、500,000 scalar 和 8 MiB 回执，预算外标部分，不静默给完整空结果。恢复、同步和权限继续由原 Core 合同处理。

二维关系图谱与键盘可用列表消费同次获权知识投影，默认当前笔记局部，可切换本次获权全库、方向／深度、关系类型、目录及精确／含子级标签条件。保留同端点多出处、方向、对称及派生反向的原作者来源；搜索只定位，选中显示来源，再明确打开。平移／缩放／适应和拖动只改布局，关系编辑须回到准确正文／字段入口重新获权；目录和标题不混作业务关系边。本地图谱最多 5,000 节点／20,000 边，托管最多 512 节点／4,096 边并保原回执预算；SVG 至多绘制 200 节点／1,000 边，下方列表保本次已取得范围，部分覆盖与绘制截断分开提示，不泄漏隐藏总数。

独立只读标题结构使用同次原生编译的角色、层级与编号，提供文档根、整篇／子树、折叠、搜索及跳转，最多 5,000 标题。准确主源标题可选择其来源；生成标题只沿该次可见渲染节点定位，缺依据则明确不可用，不按同名文字猜地址。新增图谱／标题控件及既有任务的整版实际验收仍在进行。

托管片段导航在恢复准确的已保留目标编辑器时使用其原草稿序号，独立新会话和本次编译仍须重新获权核对，不按序号零或旧位置猜测。隐藏且未开启提示的知识面板不扫描其它笔记；开启后的只读扫描异步观察预览，不阻塞正文安装或属性／导航动作。

最终候选真实系统 IME 及原 0.6.1 K 候选跨档撤销异常仍待人工复验；原形态／根因未由自动回归建立，不能从自动浏览器或组合事件推断。固定版本 Structural Tables、Number Suite、DocWen Assistant 已有部分旧宿主实测，覆盖边界和原失败保留；其余参照插件仍为源码／设计核查，整版同任务对照及完整辅助技术尚未完成，不能宣称体验追平。0.6.2 的已验识别／Office 范围及限制继续保留。

## 启动与文件

0.7 宿主批正在集成，以下是本批统一入口合同；整版原生窗口、保稿关闭和安装验收尚未完成。Windows 界面使用 `weftext.exe`，正式控制台使用 `weftext-cli.exe`。本机界面与命令行共享同一物理 profile 的唯一 Core，不需要云服务或账户。普通启动或再次点应用打开库窗口，`--capture` 只打开独立碎片窗口。本机浏览器服务须显式运行 CLI `serve`；受控多用户使用它的 `--server-config`，见 [Server 指南](SERVER.zh-CN.md) 与 [CLI 指南](CLI.zh-CN.md)。

下例中的程序名须替换为本次 `scripts/mvp.py build/check` 打印的固定角色完整路径，或交付目录内的对应程序。两个 PE 与同批 `artifact-catalog.json` 必须放在一起；不能从 Cargo 的裸 `target/debug` 或 `target/release` 程序推断有效候选，也不能混用两次构建的程序。

```text
weftext.exe
weftext.exe --capture
weftext.exe --data-dir "D:\Weftext-Local-State"
weftext-cli.exe serve --data-dir "D:\Weftext-Local-State" --port 0
weftext-cli.exe serve --data-dir "D:\Weftext-Local-State" --open "D:\Project\chapter.typ" --root "D:\Project" --port 0
```

界面输入本机文件和目录的完整路径。新资料库使用尚不存在的目录；普通目录可以浏览，不自动纳管。新笔记是 `A/A.typ` 配对，使用原生 metadata 存放 ID、类型和字段。库内外普通文件可直接打开、编辑和保存，不主动添加 metadata。无标题笔记有效，导航可回退显示文件名。

显式目录登记只赋予稳定导航身份，不创建笔记正文。目录快捷目标和标签按实际身份解析；同名不自动合并，缺失或无效目标不换成另一个同名对象。

## 功能

| 范围 | 候选实现 |
| --- | --- |
| 写作 | V01 完整源码、V02 带样式源码、V03 局部语法、V04 文字和结构控件、V05 只读，共享草稿与撤销。标题／副标题、同段标题、列表、表格、公式、代码、行内格式；原生库样式与笔记覆盖；连续预览和真正的分页 PDF。 |
| 结构化信息 | 中央 schema、原生字段、重复记录、精确数值与未知成员保留；人员、组织、文献、任务等类型；快速记录；实际 CEL Query、保存定义、列表／表格／看板／日历／汇总等视图；周期笔记。 |
| 知识组织 | 真实链接、属性引用与重叠潜在链接；链接形式转换；源码与媒体批注；模板预览创建；资源导入、复制、改名、移动、回收恢复和相关资料备份。 |

只有官方 Typst AST 与当前编译结果能证明的来源才可回写。正文表格支持逻辑格选择、连续输入、行列增删／重排、范围剪贴板、显式合并／拆分／表头及整表转置，并共享源码、草稿和撤销；不兼容拓扑、未知样式或生成格明确拒绝，保留原源。复杂跨构造选区、嵌套多行列表调整及生成内容提供准确源码入口。流式无法表达的 frame 明示需要分页。样式使用标准 module、set/show；改变库样式不改笔记正文。同源交付离线中文、代码和数学字体，实际清单与许可证在 `resources/fonts`；加载失败明确提示，不依赖公共字体 CDN。

侧栏按文件名／标题过滤，正文和属性搜索进入 Query。Query 消费 Core 捕获的已纳管笔记快照；原始目录中的未纳管项单独列明。部分、过期、无效与完整空结果不同。复杂算子、current／pinned 定义和原生编译产品要求实际冻结输入，不偷偷读取未限定的最新文件。周期笔记先查已有对象再明确创建；有限历法／时区表超出范围显示不可用，事件展开有预算，不把不完整展开当作没有发生项。

潜在链接提示可以关闭；同词多目标、嵌套、交叉候选均保留。最多两条下划线通道，更多候选仍能从完整列表选择。显示提示不改源，转换须核对准确目标与当前源码依据。独立 JSON 保存批注讨论及目标；失效不删除讨论，相似文字不自动重锚。接受建议经同一 Core 操作提交源文件与批注状态。

图片、PDF、WAV 与受支持 MP4 使用真实尺寸／时基；复杂 PDF 结构、旋转／裁切及不支持的视频时间线明确拒绝区域批注写入。资料识别的坐标预览与原页批注分别处理，OCR 文字不会自动成为原页批注目标。任意媒体格式、完整 IANA 数据库和所有具名农历包并非本候选已交付功能。

**语言与地区。** 建库时可选择文档语言／地区，原生样式与库内容进入同一创建计划，默认 `"zh"`／`"CN"`；单篇及局部可原生覆盖。导入／校对的个人偏好、共享默认与有范围词表是处理建议，须在本次处理明确采用，不暗改排版语言；缺词典、未知地区及未覆盖片段分别说明。共享词表沿库设置的授权、历史与同步，个人偏好独立。识别语言、处理地区与输出语言独立。当前界面主要固定中文，完整界面语言切换仍属后续平台范围。各自范围见 [REQUIREMENTS](REQUIREMENTS.zh-CN.md) §5.12–5.13、[ROADMAP](ROADMAP.zh-CN.md) LC01–10／IM01–10。

**资料导入与识别。** “资料导入与识别”提供保留原件、提取文本和生成笔记三种目的。支持 PDF 文本层与扫描／混合页、PNG／JPEG，以及公文 DOCX 的有界段落／编号读取。简体、繁体、英文及两种中文加英文组合使用固定离线模型，文字体系不暗转；缺模型仍可保资料，不会联网补装。原页通过受限渲染预览；可明确页／多区域、旋转、OCR 比例、段落顺序、标题和基础完整直线网格，复杂合并／跨页表格、手写及公式保原件并报损失。

首批方案为 `official-document-cn-mainland-hans@1` 和 `invoice-cn-mainland-digital-ordinary-single-page@1`。公文提供标题、层级编号、机关／文号／日期／主送候选，须明确选中结构再保留、去除或重建；DOCX 原生编号与正文数字分开，不能凭段首数字删正文。数电普通发票字段为号码、日期、购销方名称与税号、不含税金额、税额、合计及币种。号码保前导零，金额用精确小数；缺值、冲突、多票及算术不符不猜补。原图片全页 OCR 的标题／日期曾失败；明确区域及比例的 PNG／JPEG 路线可取得十项准确候选，但低可信标题／日期仍使结果为部分，不能当全自动高可信识别。公文图片的机关空格也可能需明确人工修正。所有原失败样例继续保留。

确认前核对原页、每页／区域状态、来源及损失；部分结果和格式损失须分别接受。只有显式确认的字段进入笔记：可映射当前库已安装、适用的可选 text／decimal／date FieldId 与 TypeId，未映射项为可编辑正文，不创建隐形 schema。原件、只读历史证据、作者源和字段通过同一 Core 计划创建；原 jobId／operationId 查询不重跑／重复创建。原件、模型、规则、目标或授权变化使旧待确认计划失效。进程中断的逐页检查点可恢复查看，缺最终完整性复核时不能直接导入，须显式新作业重跑。原始提取文本与来源／损失 JSON 共用独立下载授权，与导入授权分开，准确摘要相互绑定；作者核对后的修改保存在笔记中。

安装入口为 `scripts/recognition/install.py`，固定清单为 `resources/recognition/runtime-lock.json`（均在交付包的 `source.zip` 中）。运行前按 [独立安装说明](../scripts/recognition/README.zh-CN.md) 配置 `WEFTEXT_RECOGNITION_RUNTIME` 为绝对路径。产品包不包含 Python／PDFium／Tesseract 或模型的整套再分发包。输入上限 16 MiB、100 页、300 DPI／40 MP、每页 60 秒、整作业 15 分钟、共两个执行名额及新保留资料 256 MiB。初始执行端为 Windows 本地／自托管；其他平台安装与模型再分发按 IM10 留待 v0.7。权限及 API 见 [SERVER](SERVER.zh-CN.md)。

**链接与引用。** 统一入口区分普通链接、带显示文字链接、稳定片段和正式文献引用；更新文字、选择同 Work 的既有键及改名均是明确草稿提案，不按同名合并身份。复制形式分别保留准确身份／片段；Web 深链只使用明确配置的部署来源，缺路由时不可用。hosted 仅按获权目标实际编译的唯一标签及准确主稿范围定位，并核对真实个人草稿；失败保留原编辑器，只有明确选择才仅打开笔记。生成／外部标签无准确范围时明确不可定位。文献引用与普通语义链接分别分类；动态或未知原生规则保源，实际输出逐项说明可更新域、固定文字或未转换。详细范围见 [SERVER](SERVER.zh-CN.md)、[ROADMAP](ROADMAP.zh-CN.md) CR01–16；应用 URI 可解析不替代外部应用唤起的平台验收。

## 办公输出与资料交换

“Mermaid 图表”在编辑客户端离线生成 PNG，保留准确图源和版本依据，再明确插入本篇草稿；原生编译与 DOCX 使用同一张已确认图片。源变化后旧图片提案失效，生成失败保留输入。DOC 是可选外部软件转换路线，明确探测执行端依赖并保原件、中间 DOCX、损失与原操作结果；可用性按执行端单独判定。WPS 原生格式当前禁用，不通过改后缀代替转换。Obsidian 与参照插件不参与这些产品执行路径。

**脚注、尾注及题注。** 候选实现原生脚注、固定随附模块的文末尾注、重复引用、图表题注及公式编号／描述性题注；内容编辑、个人辅助序号和文档编号分别处理，应用文档提案进入同一草稿／撤销。安装尾注模块只增加本篇获权资源，不代为保存正文。DOCX 使用真实脚／尾注部件、已证明目标的重复引用与有界题注／编号；导入 SEQ 题注须显式确认所指对象，不能凭相邻位置猜配对。未知字段开关、定制计数／分节布局及无法证明的动态来源保留原件并报损失。脚／尾注属于作者内容，与审阅批注 JSON 分离。具体完成门见 [ROADMAP](ROADMAP.zh-CN.md) NC01–10。

**公式与对象内批注。** LaTeX 输入先转换并预览原生 Typst 数学提案；不能安全转换的命令保留输入并拒绝，不另存第二份公式正文。DOCX 实现有界 OMML 双向转换，以及普通文字、单元格／列表和可证明数学结构的精确、多条／重叠讨论映射。相同显示文字不能代替准确对象来源；未知 OMML、宏、任意复杂容器和无法证明的子范围保原件／讨论并报告限制。实际双向修改、回复和解决状态以真实宿主验收为准，不能把 XML 计数当作通过。

导入无法定位的讨论保存在原件资料／JSON；导出无法映射的批注及受影响回复可能不进入 DOCX，并列具体损失，不自动挂到整篇或附近文字。批注正文按普通文字交换，富格式／内嵌公式不保证保留。普通批注重叠与修订冲突分别处理；不合格或重叠的待审修订仅在准确目标可用时降为普通批注，否则报告未定位。具体范围与宿主限制见 [ROADMAP](ROADMAP.zh-CN.md) AW01–10。

当前脚／尾注正文的跨部件批注不保证随 DOCX 输出；确认重建题注后，旧批注目标也可能需要重新确认。这些讨论仍保留在原件资料／JSON，并列出实际损失。

打开已纳管笔记，在“链接与批注 → 校对”中配置词典、白名单和检查范围，再开始校对。检查读取当前成功编译的可见正文；代码、公式、链接和 metadata 不参与，生成内容无准确来源时只读提示。可疑字符检查针对替代字符、正文 BOM 和异常控制字符；符号检查覆盖常用中英文括号及中文引号，识别交叉嵌套，不是全语言语法检查。错别字／敏感词按用户词典准确匹配，空词典明确提示未配置。个人规则可 JSON 导入／导出；共享词表通过“处理默认与词表”明确存入库设置，并沿用原权限、历史和同步。采用后的处理预览绑定准确版本；词表变化或原对象替换使旧待确认结果失效，不自动重写历史结果。单次最多 2000 条结果，单段词典匹配 20000 次，达到预算明确标 partial。

选中结果后可批量加入批注或保存忽略记录，每批最多 200 条。正文须先保存；没有准确位置的结果不能写批注，跨格式词可提示但不会伪造可执行替换。相同规则／版本和同一已验证位置复用既有批注，保留回复及处理状态；建议须另行审阅接受。忽略项保存在已解决批注中，白名单排除准确词条。所有记录仍使用 `weftext.annotations.json`。改稿后的旧范围保持失效，可人工选择当前完整字符范围或准确普通文字／空正文插入点重新确认；当前不提供无编辑映射证据的自动迁移。

导入格式选择 Word（DOCX）后，预览正文草稿、批注／修订数量及损失，确认后创建新副本并保留上传原件。首轮支持普通段落、段落层级或可证明样式继承中的标题、粗斜体、链接、列表内容、简单表格和可读取图片。编号／层级、合并单元格、页眉页脚、分页和复杂版式不保证等价，列为损失。Word 批注保留正文、作者／时间、回复和解决状态；不确定范围挂到原件资料，不能按同文猜位置。基础文字修订以**修订前正文**为基线：插入保持待插入建议，删除的文字仍在正文并保持待删除建议；替换可表现为相邻删除和插入，不自动接受。嵌套、结构、格式或移动等复杂修订保原件并报告未支持。

语言或字符格式边界上的待审插入，只有在同段相邻原始 run 的映射与原生上下文均确定时才自动定位。完全未声明语言且样式继承可确认的普通文字，按实际无语言包装的上下文认证，不推断语言或地区；整篇只有一个无包装、无字符格式的待插入建议时，另须由原生编辑映射证明唯一空正文末尾位置。已声明但无效、未解析或脚本槽缺失的语言不视为未声明。不同上下文、结构或歧义点保留原件，并标记需要重新确认；不在生成的包装语法中猜测插入位置。

DOCX 输出可选择正文版、带批注审阅版、批注及待审文字修订，并决定是否包含已解决批注。带审阅输出要求已保存正文，冻结源与批注；生成时不再次校对、不改变应用内建议状态。准确目标映射为 Word 批注／回复，具备当前可执行资格的待审建议可映射为文字修订；重叠或不可定位项明示降级或损失。为支持解决状态，审阅副本使用 Word 2013 或更新兼容模式；旧模板升级另列损失。不是任意 Word 审阅结构的无损往返。 真实应用验收分别记录：Word 的批注编辑／回复／解决及修订接受／拒绝，LibreOffice 的保存重开，WPS 的修订接受／拒绝。WPS 12.1.0.29161 的 `Replies.Add` 对自建和 Weftext 文档均新增独立批注，未写入新的回复关系；同范围批注在其 COM 读取中被呈现为回复。XML 与真实 Word 重开确认原有回复仍保留。此问题定位到当前 WPS 自动化新增回复路径，不作为 Weftext 导出结构缺陷；手工 WPS 回复交互仍未验证。

正文内嵌 Query 在连续视图按实际位置显示；V01/V02 可见源码，V03 主动展开，V04 用构建器或显式源码提案，V05 只读。修改共用草稿与撤销，换档不自动保存。通过“输出与导入”选择 DOCX 或 PDF，可在正文原位置纳入当前准确草稿已显示的冻结 Query 结果；DOCX 模板须绑定正文槽。结果保留原行、顺序与 partial/stale/空范围状态，不重新查询、不自动保存。输出确认前可检查原 cut、完整性和诊断；没有当前结果的出现项明确报告缺失，不借其他草稿结果。原生分页预览仍不显示 Query，需使用独立的 PDF 输出入口。复杂、生成或来源不唯一的出现项，以及自定义绑定无法证明安全的 PDF 插入，明确受限。

打开笔记后，在“输出与导入”中选择准确 Typst 源码、DOCX、PDF、XLSX、原生资料包或文献格式。先生成并检查实际输入、工件信息和损失，再明确确认和下载；下载核对同一份字节的长度和 SHA-256。输出不会替用户保存当前草稿。生成的本机工件保留一小时，过期需要明确重新生成；关闭程序后重新生成，不承诺跨进程恢复输出任务。最多保留 32 个输出和 32 次查询结果，总缓存 256 MiB，单次文件和冻结依赖 64 MiB。

DOCX 从一次冻结的 Typst HTML 编译转换成可编辑段落、字符、标题、列表、表格、图片和受支持公式；无法映射的元素明确报告损失。上传 DOCX 模板后，用已有内容控件的标签绑定标题、正文、属性或已选择的 Query。默认使用模板样式并保留强调，也可选择保留能映射的来源样式。字号、字体依赖及复杂编号、引用或公式仍以具体损失和实际目标应用验证为准；不保证任意 Typst 程序与 Word 完全等价。

同段标题默认占据一个完整 Heading 段落，普通目录可包含随后正文。编号同段标题之前若已有正文，Word 的原生编号仍位于段首；保留正文字符格式和文字，并报告 `run-in-leading-body-loss`，不宣称原位置等价。

XLSX 可输出当前笔记的字段，或从 Query 结果按钮输出那一次结果。后续文件变化不会悄悄重新查询。命名区域／表格模板有明确容量，不自动扩展或改写公式引用；普通字符串不会执行成公式。超出 Excel 精度的数字以及复杂时间、数组和记录使用准确文本，附表保存完整 typed Cell、schema 和原行列顺序。空值、缺值、错误、部分和过期结果有明确区分。

原生包输出**已保存的整个资料库**及纳管依赖，需要先保存打开的库内草稿。它不包含本机历史、journal 或未纳管原始文件，不能替代恢复备份。新增闭合 Tags 角色保完整 v2 标签森林；当前 v1 须先显式升级，不在导出中隐式改原件。导入在目标库的新文件夹创建新笔记及全树标签身份，保祖先，并在同一计划按完整源 TagRef 映射正文 typed 引用、Query 的 tagRef 字面及 typed 参数默认值；literal 不改，不按同名合并。Query 只有包内准确 Schema 基线与语义一致目标可证明时才重绑；缺原历史以 `schemaMappingRequired` 拒绝，不猜 latest。schema 不兼容拒绝，库设置不自动替换，复杂资源模块上下文变化列为损失；上传原件保留，已有笔记不被覆盖。托管标签／Schema 副作用另需独立授权。

当前原生内容包为 v2，损失说明使用同源类型化消息并保完整机器代码、位置和诊断。v1 包明确拒绝且保原 ZIP，不自动升级；此版本与 v2 标签森林及完整恢复备份版本分开。

BibTeX、CSL JSON 和 RIS 导入先展示完整字段映射、未知数据和冲突；无冲突后创建独立论文笔记并保存真实原件。相同 DOI、标题或建议引用键不作为覆盖／合并依据；当前界面不提供已有 Work 的自动刷新或合并。输出使用论文的 typed publication 或文档明确绑定的 Work；引用声明生成同次冻结输入的原生 `.bib`，碰到作者已有同名文件则拒绝替换。未知成员和无法往返的数据保留原件并说明，不以格式转换声称全部字段都可无损互通。

## 保存与恢复

已纳管笔记顶部的“时间线”列出 Core 实际保留的保存记录，显示保存时间、未知时间或准确源码缺失。可以只读查看并与当前已保存内容或明确选择的草稿快照比较。恢复前确认保护草稿，旧版成为一次新的保存，后来的记录保留；原脏稿及期间的新输入仍在编辑器和恢复记录中。历史预览目前为准确源码与文本差异，不重建旧字体、模块或配置的富预览。

Windows 默认 Core 私有数据在 `%LOCALAPPDATA%\Weftext-MVP\core`，包括草稿、操作前后稿和实际身份记录，不是可随意删除的缓存。同一产品保全范围下的 `host-state` 独立保存此 OS 用户的私有宿主元数据，显式 Core 与它不能相同或互为祖先／子孙。旧顶层 Core 不自动采用，原件需保留并显式导入或一次性转换。同一数据目录只允许一个进程使用；不要用不同数据目录同时操作同一资料树。相同文件 ID 本身不能重建接纳证据。

保存核对实际文件对象和原文，拒绝用旧稿覆盖外部新稿。另存为只创建不存在的目标，并核对重新打开结果；期间输入仍留在草稿与 Undo。改名、移动、回收后按原对象衔接打开会话与草稿；多个保留稿需要比较，不静默择一。

恢复记录逐个显示参与文件的操作前、计划和当前内容；二进制可下载比较。完整原状态可取消原计划，确切完整后状态可接纳原计划；可证明的部分内容更新可继续原操作剩余文件。第三种内容或身份不符时不覆盖。目录改名的中间位置保留供检查，不自动重放。原稿和已确认合并稿保留在私有恢复历史中。

完整单库备份包含普通文件、ignored 字节、相关控制事实与一致捕获的相关 journal／Draft，不夹带其他库或库外文件私有资料。保留恢复证据不代表新设备已获得本机 NTFS 身份资格，也不等同同步。

## 边界与检查

识别专项的清晰印刷 TEST 样例按固定字符误差 ≤5% 门槛分别核验，最终 worker 的英文／简体／繁体／简英／繁英结果为 0%／4%／0%／0%／0%；简体样例仍为 partial，达到误差门槛不改变其低可信状态。这组结果只覆盖所列样例，不能代替任意真实票据准确率。完整选区覆盖、零重复、原件摘要、字段逐值比较及负例各有独立门槛。

公文重建支持已证明的第 1–6 级，未知或超出范围明确拒绝，不压成另一层级。DOCX 原生编号的“保留”当前仅支持已证明的单层十进制计数；中文计数及嵌套定义明确拒绝，可保原件，或选择去除／重建。已重建标题编号可进入 Word 原生编号并保存重开；经普通 DOCX 导入再输出时，编号方案可能降级且逐项报告 `word-heading-numbering` 或 `word-list-numbering`，列表可降为项目符号，必须接受实际损失，不能称编号结构完整往返。

当前 v0.7 源码选择 `weftext.qualified-fs.v2`，旧物理记录须显式导入／转换并保留原件。Windows／NTFS 资格属于实际对应的候选产物。独立的 [Linux 受控服务后端](LINUX.zh-CN.md) 要求管理员 enrollment 与 OS 分离服务权限；实现不把旧 Windows 结果提升为 Linux 或 v2 验收。普通本地写入支持 Windows／NTFS；网络共享、网盘、其他文件系统、跨设备接纳和同步不在此档位承诺内。多用户由受控 Server 串行提交到同一后端，不允许多个独立 writer 共享作者树。符号链接、junction、硬链接和无法证明的路径不进入写入流程。

作者源上限 2 MiB，普通扫描最多 5,000 项，预算不足明确显示不完整。可视显示树最多 100,000 个节点、嵌套深度 256 层；编译子进程限时 20 秒、Windows 内存 1 GiB、结果 24 MiB；冻结 Query 编译输入上限 64 MiB。这些预算分别生效；可视投影受限时使用源码入口，草稿与文件的保存仍按原源码预算检查。普通编译拒绝根外依赖，冻结编译不读捕获范围外本机文件。不自动下载网络包，也没有包安装界面。

超过源码上限的完整输入仍可在当前窗口保留和撤销，但不会写入恢复草稿或文件；界面明确说明未持久保存。保存前的恢复草稿检查可以先拒绝该输入，文件原文保持不变；缩短或撤销超限输入后再保存。

Server 已按独立权限接通五档编辑、窄字段与高级／内嵌 Query、Provider／目录／回收站范围、库配置与样式、批注与校对、媒体与资源集合、创建／模板／复制／移动／回收恢复、知识链接和既有文献生成。DOCX、PDF、XLSX、原生包及 BibTeX／CSL JSON／RIS 输出、既有 DOCX 与原生／文献导入，以及单库所有者恢复资料备份也已分批完成真实 HTTP 与后台浏览器检查；每项仍限于各自原输入、授权、损失和恢复合同，不扩大本地格式转换能力。原生包是已保存内容交换，不能替代包含相关个人草稿与原操作记录的恢复备份。详细配置与边界见 [SERVER](SERVER.zh-CN.md)。

0.6.0 既定 Windows／NTFS 范围的结构、语义及各权限消费者验收已完成；0.6.1 按上文候选范围记录本轮通过与限制。其他客户端和 Agent 自动化按路线图推进；当前结果不代表 Linux／macOS Weftext、NAS 浏览器、其他平台、实际断电或完整辅助技术验收。真实输入法仅有上文明确的人工切片证据；故障注入与后台浏览器检查不冒作未跑环境通过。

候选验收运行前端和 Rust 测试、基础／功能／输出 HTTP 场景、格式和 Clippy、字体及文档／有界模型检查。实际浏览器和 Office 应用验证另记；纯 XML 检查不代替目标应用打开、编号更新或可编辑性验收。具体候选结果见交付记录，不把此前候选的通过数冒作本版结果。

需要通过 rustup 安装 Rust、Node.js/npm、Python 3.11+ 及 Windows C++ 构建工具。仓库的 `rust-toolchain.toml` 为本地和 CI 选择相同的 Rust 1.99.1 与组件，不改变本机默认工具链。此前候选证据使用 Rust 1.98；Node.js 24 和官方 Typst 0.15.1 继续使用。

## 同所有者本地副本同步入口

工具栏“同步”可在没有打开笔记时使用。先在原资料库启用同步，复制界面里的完整配对身份；“刷新已保存版本”把原已提交操作的不可变内容发布到本机同步存储，不会保存当前编辑器草稿。导出时选择对象和交换目录；目标须为不存在的新目录或已经按相同身份配对的目录，不能使用作者树、私有状态或已有未配对文件夹。

另一个独立程序使用自己的 `--data-dir` 和不同的资料库路径。粘贴配对身份并接收交换目录，选择对象后“预览创建独立副本”；目标资料库路径须尚不存在。完整核对路径、文件和字节变化后确认。现有副本使用“预览应用所选对象”。接收仅保存历史，不修改工作文件；所选对象仍须带上原事务及依赖闭包，最终实际写入范围以原预览为准。部分副本显示已安装对象和确切版本，不把接收完毕称为全部安装。

独立副本可以在没有交换目录连接时正常保存，原提交进入本机待发布记录。之后双方分别导出、接收。界面列出全部并发版本和共同基础，显示已安装版本，版本编号不表示先后时间。可读取当前冲突分支及共同基础的准确 UTF-8 文件；二进制或超过 2 MiB 的文件只显示摘要与长度。当前提供明确采用一个完整分支的合并预览，包含该分支的正文、批注、资源和位置；并不自动逐字段合并。双方原稿仍在同步历史里。一个对象冲突时，可以只选择无关对象继续应用。

确认前保留原请求、编号和预览。丢响应后“检查原操作结果”；刷新同一地址后仍使用保留的原记录。地址变化或浏览器记录丢失时，输入之前保管的原同步操作编号找回准确原提案，不重建请求。若确认阶段尚未开始任何安装，可以明确取消原提案；一旦存在原安装标记，取消被拒绝，须进入恢复检查。取消不会回滚或改写外部修改。应用后已打开笔记的草稿和撤销记录保留；磁盘稿变化时须明确比较后继续。

已收到但未安装的准确版本与真实因果前代可只读查看，查看不安装文件。外部语义采纳固定原已安装 cut 和实际外部观察，核对定义、文献、原生 Query／Provider 及真实 after World；不跟随较新但未安装的收到分支，也不因重新打开文件就接纳任意外部改稿。准确缺席的已登记 Resource 可显式采纳，原请求、负依赖、历史和 blob 保留；普通源不需要原生产品时不强制整篇编译。

同一原 ApplySync／MergeSync 的 Compound 可组合 Node／普通 Directory 的移动、改名和内容更新，支持交换／循环重排、祖先抽取及嵌套最终位置；最终 parent 图须闭合无环。移动树内外的新 Node／Directory 父级、自有资源嵌套目录和缺失根 Rules／Schema／settings 与其他改动共同提交。原 FI、准确内容修订、资源、批注、伴随文件、个人草稿和历史保留；同字节替换、迟到外来对象、依赖变化或无法证明的中间状态不能沿旧 Plan 续交。

Clone 支持已回收根及继承子树；现有副本支持多根回收、回收加 live 移动／内容及恢复加移动。同一回收操作的多个根按准确 NodeId 选择，独立恢复草稿和原请求不按列表顺序猜测。已从所选资源 registry 与文件集中准确退出的登记资源，接收端沿原 Compound 把同一原文件保全到固定位置，保 FI、字节与 attributes；不另造 Node、不清空原件，旧 Ref 不继续授予 current Resource 角色。其他未知或未证明角色的文件不会随之删除。

原生导入的包装目录从同一次原 CreateTree 预览取得准确文件修订和 Directory 身份，资源角色不冒作目录资格。成功导入、同步克隆、原操作重启重试及受影响的原生／文献输出、冲突和 DOCX 导入已有真实回归；仍不扩大为任意格式无损往返。

主动 RevalidateSync 提供只读 cut／review、保留所选版本或显式修复及原请求 prepare／commit／重启恢复。保留准确源与原 fileRevision，改变文件的显式修复使用新 fileRevision；迟到分支、安装集或实际依赖变化拒绝原提案。原编号绑定新回收布局；继承 Trash 不改写子节点 portable 退休标记。原生最终 title／body／headings 通过真实 Engine 与 Data 执行器消费，实际 include、Style、Settings、资源正负依赖求有界闭包；不可用产品不能冒完整空结果。current／pinned 定义与缺失批注目标的 unavailable／原记录保全沿同一证据链，不要求普通 Save 或 Apply 先产生冲突。

最终优化程序（SHA-256 前缀 `704e86eb`）通过前端 247 项、App 173 项、Core 496 项及其余 workspace 测试、格式、严格 Clippy、字体与文档／有界模型检查；完整 HTTP 矩阵共 30 套、313 项通过。相同程序在 Chrome 155.0.8059.41 通过 60 组受影响浏览器场景，并通过真实 NAS 严格 CA／IP SAN 的 HTTPS 六组验收。资源退役、Style、多对象回收／恢复、准确历史／资源读取、个人 Draft／Undo、原请求未知结果及重启恢复均保留原断言。构建检查与 HTTP 分阶段使用同一最终程序完成，本地包装复用已验字节；尚未正式发布。

准确 canonical 出生源的定义 key 接纳已修复原复验性能热点。本次最终优化程序对原参数化定义反例实测 review 0.157 秒、原 prepare 0.390 秒、同 ID 重试记录为 0.000 秒、定义运行 0.109 秒。这是并发验收过程的单次观察，不是隔离 benchmark，也不承诺跨规模、跨平台或所有输入的时延。NAS 客户端通过同样不代表 Linux Weftext 或 NAS 浏览器支持。
