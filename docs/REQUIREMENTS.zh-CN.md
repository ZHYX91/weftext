# 需求与技术方案的边界

状态：当前需求已补 Folder Nodes、普通文件模式及 Agent 使用范围；旧固定技术基线的独立接受保留，当前修订见 [REVIEW](design/REVIEW.zh-CN.md) §8。需求实现、有限原型和产品验收分开记录。

## 1. 设计依据

按一个新项目选择技术，优先实现已确认的用户需求。沉没成本、已有代码、文档篇幅、协议名称和历史评审通过均不产生技术继承义务。用户已选择 Typst 与原生优先，这属于当前明确约束；原生语法能表达的内容优先使用官方能力，不增加另一套作者语言。

一项设计条款须分清：用户要完成什么；结果必须满足什么可靠性、隐私或体验条件；当前建议怎样实现。前两者形成可观察的验收，后者可以重新选择。需求不能靠删去失败场景来简化；技术也不能靠重命名保留全部旧复杂度。

## 3. 历史与兼容

历史输入、原评审和实验结果保持可追溯；它们是设计证据，不是新系统运行时依赖。旧候选中的 CP、Notice、Proof、Policy、回执及 decoder 版本不得仅因已写入文档而强制进入新实现。此前的“保持原协议形状”“保持原错误顺序”等条款进入技术重审，不自动视为新项目约束。

只有存在明确的真实数据、已部署接口或用户确认的兼容对象，才据此定义兼容需求。目前仓库原型和未实施设计本身不能证明这些对象存在。发现真实数据时保留原件，另行确定显式导入、转换或兼容范围；不得删除用户数据，也不得为未部署候选虚构迁移层。

原 21 项及后续发现先还原为完整失败场景和用户损害。问题仍适用则新方案必须解决，可以使用新的办法；旧机制被取消而使场景不再适用时，记录依据。既不机械继承旧修法，也不把所有旧 CLOSED 复制为新方案通过。

## 4. 实施依据

第 5 节的需求与第 6 节的失败场景已由当前协调技术方案承接，独立全局设计接受见 [REVIEW](design/REVIEW.zh-CN.md) §7。按 [INTEGRATION](design/INTEGRATION.zh-CN.md) 的纵向切片进入重构；保持需求、方案和实际证据相连，不因整理文档而再次启动完整设计终审。改变需求或关键技术合同须针对影响复核。

标题、副标题、同级混排、Word 输出、丰富类型、五档视图及中文默认支持仍在范围内。历史机制不是兼容义务；实现、产品验收与发布分别记录。

### 4.1 范围校准与交付原则（2026-10-30）

恢复因 AsciiDoc 表达限制而缩减的已选使用能力；不恢复仅为旧载体服务的封装、协议或通用事实系统。以下是当前范围取舍，不是实现或验收完成声明。

- **核心能力。** 普通写作、五档连续体验、丰富原生属性、查询、文件组织、稳定链接和明确范围的 Office 交换继续保留。常用任务不要求填写来源、置信度、逐值身份或内部协议信息。
- **按需使用的丰富能力。** 任职与状态历史、多来源、争议记录、量值和较复杂关系保留已选用途；通过可选字段、分组和模板进入，不能强迫普通笔记承担完整 HR、CRM 或史料考证流程。可选使用不等于取消已承诺的编辑、查询或导出。
- **明确后置。** 完整 HR／CRM、未选定的关系自动推断／自动写回、通用事实裁决平台、完整项目管理及尚未选定的连接器不因原生值可以表达就进入首发。既有反向视图及有来源的派生关系仍保留，不因后置自动写回而删除。来源和争议的记录能力不等于自动判断真假。新增范围须说明用户任务及收益，不能以历史字段数量作为完成目标。
- **可视编辑与格式交换有边界。** 完整合法 Typst 源保留；常见构造必须可用，无法安全回写的复杂构造局部说明限制并提供明确源码入口。五档共用作者源、草稿和撤销，不要求任意程序生成内容均可逆编辑。Office 按支持的语义和真实宿主验收，不承诺任意文档跨格式完全无损往返；原件、未知信息和准确损失必须保留。
- **按平台交付。** Windows 日常使用与安装可形成独立已验交付，其他平台按实际能力依次交付。全部平台方向和未验项保留；单平台完成不授予整版跨平台通过，也不以尚未完成的移动端阻止已验 Windows 范围单独交付。发布仍是独立动作。
- **性能以负载和实测界定。** 分别测普通写作、大源码、复杂排版及查询；记录硬件、模式、冷／热状态、时延分位数与实际进程内存范围。已有数值保留为研究目标，不能合成所有负载同时满足的承诺，也不能因失败重命名用例或放宽原检查。可降频预览、按需加载和明确限制支持范围；已接纳输入的保稿与超限安全拒绝不能降级。

保存可靠性、冲突保双方、撤权边界和原请求恢复是核心结果，不能通过“精简”取消。实施按现有 SOURCE／EDITOR／FEATURES／CORE owner 和 ROADMAP 的原用例落地，不另建一套需求或验收台账。

## 5. 需求清单与范围

#### 5.1.1 多级标签

2026-10-20 确认纳入 v0.6.3、在第三阶段与二维图谱之间补齐 NAV03／NAV04。每个标签在共享标签树中最多有一个父标签，允许多个根。层级表示可调整的归组，决定浏览位置及显式的后代筛选；不表示类型、属性或权限继承。父标签仍可直接赋给笔记，不增加“纯分组标签”类型。同一个标签不能同时放在多个父级下；笔记可以赋多个标签，但这不替代将来真实多父需求的单独评估。

笔记只记录作者直接赋予的标签。例如仅赋“技术 → 编程 → Rust”中的 Rust，精确筛选“编程”不命中，“编程及其子级”命中；将 Rust 移出后，新运行的后代筛选随之变化，笔记源不补写祖先。改名、换父保留原标签身份、引用和快捷目标。普通文字标签不因同名、斜杠或层级显示而变成已登记标签。

新增的标签树浏览默认“此标签及子级”，结果页始终可辨并切换“仅此标签／此标签及子级”。已有精确条件保持精确；保存当前筛选必须保存准确模式，不能只记标签后重开成另一范围。首版不加入隐式的每标签模式记忆。保留同名合法性，创建时提示已有候选；在赋值、选父级及树项中用分段路径和足够区分的身份短码消歧。名称中的 `/` 是普通字符，父级单独选择，不自动解析路径或按大小写／Unicode 形式合并。

首版包含指定父级创建、改名、换父及移至根、树浏览与统一 Query 后代筛选，提供键盘等价入口和原有取消／恢复行为。标签树读取不扩大笔记、字段或 Query 权限；完整标签树不代表笔记范围完整。创建、移动和查询同时承担当期权限、同步、冲突及恢复责任。硬删除、合并、多父、本体继承和手工排序后置；可逆隐藏也只有真实整理需求成立后另定，不预留状态或默认改变查询／赋值含义。技术分工见 CORE §2.3、FEATURES §§5.6、7.4；完成门集中在 ROADMAP TAG01–10。该合同已接入 0.6.3-rc.1 工作树的共用 Core／Query／UI／授权及同步／Native 消费者，整版验收仍在进行；alpha.3 扁平标签只描述原候选，不宣称这些完成门已全部通过。

### 5.2 所有笔记类型的结构化能力

2026-10-12 用户澄清：此前简化人员等类型，原因是 AsciiDoc 原生属性承载复杂数据不便；如果 Typst 能优雅实现，就不需要因此删减功能，其他笔记类型同理。这是 U 级原则修正，具体字段、交互和技术细化属于 D。人员、组织、任务、项目、论文及其他内置或自定义类型都适用，不能只为人员解除限制。

此前为迁就旧载体而缩减字段的方案已经被替代。当前 [SOURCE](design/SOURCE.zh-CN.md) §§3–6 与完整 schema 承接丰富类型能力；常用界面简洁不等于取消有用结构。

1. **保留需求，重新选择表示。** 对历史已经选择的业务能力逐项核对，尤其检查此前仅因载体不便而删去的字段或结构；这些能力回到设计输入。多值、嵌套记录、关系、任职/状态历史、重要事件或来源信息有实际用途时可以保留，不能一律压成平铺字段或正文备注。只是讨论过的候选和已明确后置的功能仍分别记录，不自动纳入全部首发。
2. **原生表达与应用含义分开。** 优先用 Typst 原生值、数组、字典和适用的标准构造表达数据，类型和校验由集中 schema 定义。不要仅为沿用旧封装而要求作者在 Typst 中嵌入 JSON；也不能把能写出嵌套值当作查询、编辑、关系、同步或权限已经实现的证明。
3. **界面简洁不等于数据缩水。** 常用字段易录入，可选信息按组展开、增加条目；不使用的复杂能力不要求填写。源码仍应可理解，避免为了一个普通值必填大量内部信息。每种类型的必要字段由其真实使用目的决定，不把所有历史字段设为必填。
4. **逐项论证必要机制。** 稳定笔记引用、关系方向、派生反向视图及历史记录按相应需求设计；不要求双向手工维护，也不因取消旧关系引擎而取消有用关系。逐值 UUID、置信度、通用事实账本或旧协议既不自动恢复，也不先验禁止；若确有需要，应说明它解决的场景和更轻方案为何不足。
5. **以完整使用链验收“优雅”。** 对代表性类型检查作者源、属性表单、编辑/撤销、Query/视图和导入导出是否一致；涉及引用、共享或历史时还须检查相应身份、权限及保存/同步行为。不能只证明语法可编译。实际取舍或暂不支持的能力须明确记录，不能沿用旧语言的限制冒充产品选择。

技术重写应给出各类能力的保留/重设计/后置依据与当前 owner，覆盖历史已选能力，避免把整个旧 schema 当作新实现。至少验证：同值多联系方式仍各保标签/备注及顺序；人员任职与组织关联可保留时间和目标含义；论文作者等有序结构在表单、Query 与导出间一致；任务详情仍是正文、结构化字段服务于视图；普通使用无需填写可选复杂信息。这些是设计检查要求，未运行产品测试。

| 置信度、争议声明、观测精度和逐值身份 | 来源、历史与测量的已选用途保留为可选业务信息；不作为所有属性的必填包装 | 普通联系值可直接录入；有依据的争议或观测记录保原来源，不把精确小数置信度冒作客观可信度。跨版本逐值身份须有独立定位任务及更轻方案比较 |
| 高级历法／重复规则／领域预设 | 已选语义保留；具体数据包、专业预设及界面便利性按实际支持交付 | 精度、时区与重复例外不丢；未装数据包、覆盖不足或未知导入值明确提示，不靠默认值伪造完整支持 |

本表细化既有 RQ08–10、15–17；SOURCE §5.1 继续承担七类能力的详细覆盖。通用机制被取消不等于删除领域信息，已保存的复杂记录不能因默认界面简化而丢失。未实现或未验的消费者继续具名列在原路线图及候选记录。

### 5.3 库级默认样式与原生覆盖

2026-10-12 用户确认：笔记库可以设置正文、标题、列表、表格等元素的默认字体、间距、边框和其他样式；单篇笔记及局部元素仍可通过原生 Typst 语法覆盖。普通使用不要求每篇手工添加样式代码。此项为 U，样式文件组织、编译入口、设置面板与依赖交付为 D。

默认样式、单篇规则和局部规则遵循 Typst 的实际作用域及组合语义，不发明独立样式语言或虚假的统一优先级。设置面板与源码编辑消费同一份样式权威；无法理解的自定义规则保留并提供源码入口，不能被控件覆盖或清空。库样式变化使受影响预览重新求值，不改各笔记的作者字节、身份或批注原始范围。

### 5.4 从源码到阅读的五档视图

2026-10-12 用户再次确认五档体验，中间三档为“渲染成标题等但显示语法”“按需显示语法”“完全隐藏语法，只能通过界面修改”。五档为 U 级需求，具体控件和映射方法为 D，不能缩成源码、写作、阅读三个产品档位。

| 档位 | 必须呈现的体验 |
| --- | --- |
| V01 纯源码 | 完整 Typst 源可见、可编辑，允许语法高亮；不隐藏作者标记。 |
| V02 渲染且显示语法 | 标题、强调等具有可辨认的渲染样式，同时作者语法保持可见、可编辑；不只是着色的纯文本。 |
| V03 按需显示语法 | 平常呈现渲染内容，在编辑焦点或明确操作需要时显示相应来源语法，其余内容保持渲染；键盘和触屏可主动进入/退出，不依赖悬停。 |
| V04 隐藏语法的界面编辑 | 文档区完全隐藏 Typst 语法，通过输入、菜单、工具栏和结构控件编辑。缺可靠控件或来源映射的构造保留并明确只读，可主动切换其它档位处理；不偷偷展开源码或损坏复杂源。 |
| V05 阅读 | 只读呈现正文，无正文编辑控件和语法露出；导航、选择、复制和获权独立批注仍可用。 |

五档共享一份作者源、当前草稿和撤销历史，不产生五份文档。视图切换不保存、不改源码、不成为内容撤销项；保留可恢复的光标、选择和阅读位置，区分当前草稿预览与已提交版本。分页/连续布局另行选择，不能把 PDF 预览算作一档来凑五档。语法显示与隐藏不改变权限。

验收至少覆盖：同一标题/强调/链接在五档中的差异；V02 全部作者标记仍可见；V03 键盘/触屏显示与收起语法不丢输入；V04 无源码漏出且保全未知构造；V05 不直接修改正文；带未保存稿、选区、撤销及 IME 时逐档切换保稿；源暂时无效或投影迟到时不以旧结果覆盖新稿。这些场景尚未运行产品测试。

#### 5.4.1 正文内嵌 Query

2026-10-14 用户明确补充；属于 RQ02、RQ15–16 的体验补全，不是另一套查询产品。

| 档位 | 查询定义与结果的用户体验 |
| --- | --- |
| V01 | 直接编辑完整查询源码；结果可另开预览。 |
| V02 | 查询完整源码始终可见、可编辑，同时显示结果；结果不能替代或遮掉源码。 |

| V04 | 默认显示结果，通过查询构建器修改；明确选择“编辑源码”才进入独立编辑界面或源码可见档。聚焦结果或控件不自动露出语法。 |
| V05 | 展示结果，不提供修改查询定义的入口。 |

五档操作同一查询定义，沿用同一笔记草稿和撤销历史；切换显示方式不改源、不自动保存。构建器不能表达的查询仍保留，不能简化或替换原定义。各档一致显示权限限制、错误、不完整和过期状态，不能将错误或未获权结果显示为正常空集合。具体交互规则由 [EDITOR](design/EDITOR.zh-CN.md) 与 [FEATURES](design/FEATURES.zh-CN.md) 负责，交付与验收见 [ROADMAP](ROADMAP.zh-CN.md)。

### 5.5 无需逐篇启用的中文支持

2026-10-13 用户确认补齐：正文、标题、列表、表格、行内代码、代码块和公式中的中文文字应开箱可用，不要求每篇声明中文、导入中文包或粘贴字体配置。此项是 RQ01–03、RQ20–21 和 §5.3 的 U 级澄清；默认字体选择、交付和语言设置的实现为 D，不增加另一套作者语法。

中文字符能显示与语言相关排版/朗读分别保证。代码块语言标记用于语法高亮，不是开启中文的开关；公式中的文字使用原生字符串或 text 内容，如 `$ "总价" = "单价" times "数量" $`。引号用于区分文字和数学表达式，不是中文声明，应用不偷偷改写合法数学源。

库级默认提供中文所需字体及语言/地区设置，允许单篇和局部原生覆盖。正文、代码和公式的字体职责分别落实；不因默认拉丁字体缺字而显示方框，不以改变全篇数学字体来修中文文字。简繁中文及中英混排属于基本范围；支持范围外的生僻字、作者禁用回退或指定缺失字体保留原文并明确问题，不承诺任意字体覆盖所有 Unicode。

Desktop、WebUI、Server/CLI 编译和离线内网不依赖宿主恰好安装中文字体或公共字体 CDN。预览、PDF、DOCX 与独立 Typst 工程按各自真实能力验证字体和语言交付；可编辑输出不能用整段图片替代中文文本。具体机制和 CJK01–08 验收由当前 [EDITOR](design/EDITOR.zh-CN.md) §8.6 负责；它们是设计要求，尚未运行产品验收。

### 5.6 本地笔记时间线

2026-10-14 用户明确补充 RQ22、RQ24：用户可以按时间浏览该笔记实际保留的已保存版本，打开旧版并与当前已保存内容比较；有未保存草稿时应清楚区分比较对象，查看和比较本身不改稿。

恢复旧版形成一次新的保存，后来的版本仍保留；当前未保存草稿必须先得到明确保护，不能被恢复动作静默替换。笔记改名、移动后仍能访问同一笔记的历史；无法确认仍为同一笔记时明确提示，不把同名文件或复制出来的新笔记混为同一时间线。

界面说明实际保留范围和不可用的版本，不承诺永久保存每次键入，也不把文件修改时间当作完整历史。文件版本时间线与任务、事件等 Query 业务时间轴分别呈现。该项复用现有 Core 历史与恢复能力，用户不需要维护第二套版本资料。

此项与 §5.4.1 在当前 v0.5 阶段补齐本地范围；多用户历史权限及同步后版本展示随 v0.6 验证。用户结果不因当前实现范围而缩减；实际交付边界和验收见 [ROADMAP](ROADMAP.zh-CN.md)，设计规则见 [CORE](design/CORE.zh-CN.md)。

### 5.7 本地校对与 Word 审阅交换

2026-10-14 用户确认补充 RQ02、RQ18–20、RQ24：在 v0.5 完成本地“Word 导入 → 校对与审阅 → Word 导出”，v0.6 再验证多人、同步与权限。当前 alpha.3 不包含此完整闭环；以下是实施和验收要求。

- 校对独立于导出：错误字符／符号修正、错别字、成对符号（含交叉嵌套）、敏感词可分别启用；使用本地规则、用户词表和忽略项，不依赖另一产品或外部 AI。命中不等于确定错误，只有明确替换才成为可执行修改建议。
- 用户选择正文范围或整篇，先看结果，再一键把全部、分类或勾选结果加入现有批注 JSON。重复运行不重复堆批注、不覆盖人工回复或已处理状态；文本变化后旧结果重新核验。校对可见文字，准确映射原源，不能把 Typst 语法、代码、公式或 URL 当普通正文机械检查。
- 人工批注、导入批注和校对批注使用同一体系，保留来源、原作者／时间、回复、解决状态和历史。来源归属不授予应用账号或权限；无法定位仍保讨论，不按相同文字猜位置。应用建议继续经 Core 同时提交正文与状态。
- DOCX 正文导入保原件、结构、资源和未知信息，并预览损失；批注及回复映射到新文档，不能把模板上传称为正文导入。首轮基础修订支持可准确映射的文字插入、删除和替换，保留待审语义，不能默默接受或拒绝。
- 导出有正文版和带批注审阅版；后者将所选批注转换为真正的 Word 批注。Word 修订输出是独立选择，不能把修改建议正文冒作修订。导出消费固定正文、批注和规则结果，不悄悄重新校对或修改作者文档。
- 复杂格式／移动／结构修订、无法定位范围或目标格式不支持的信息保留原件并明确影响与选项；不以保原件冒充完整往返。真实 Word 验证导入、修改、回复、接受／拒绝和再导出；WPS、LibreOffice 分别记录实际支持，不能互相替代通过。

实施顺序和完成门见 [ROADMAP](ROADMAP.zh-CN.md)，校对／修订、导入及导出分别由 [FEATURES](design/FEATURES.zh-CN.md) §9.7、§10.2、§11.3 承接。AI 语义校对仍是后续评估项，不作为本地规则校对的前置条件。

### 5.7.1 单元格、列表、公式批注与双向审阅

2026-10-14 明确 RQ18–20 的对象内粒度及交换条件。单元格／列表普通文字的精确批注和基础文字修订是既有范围的澄清，不因本节延期；新增公式反向转换、公式及结构元素批注映射在 v0.6.1 与 §5.8 一起实施。专项双向矩阵在该版本闭环，v0.7 补目标平台；现有 v0.6 消费者的权限、同步与数据保全完成门不变。

- **局部与多条。** 单元格内可选一个完整字符或连续几个字符加批注，同一格的不同范围可分别批注，同一／包含／交叉范围也可保存多条独立讨论。每条保身份、作者、回复及状态，不因位置或文字相同而合并为一条或误判为回复。列表项正文同样适用；批注整格／整项与批注其中几个字必须分清。人工批注不受校对默认跳过公式等区域的规则限制。
- **公式及结构。** 已有准确源范围可记录公式源码讨论；新增交互须支持公式整体，并对明确列出的常用符号／子式提供可证明的细粒度选择。整表／整格／列表整体、自动编号、合并或嵌套结构均按真实元素或准确文字范围定位，不以截图矩形或同名文字猜目标。细粒度不能映射时保讨论和原范围，解释并由用户明确选择是否改为整体批注，不静默扩大。首轮不增加一条批注指向多个不连续片段的复合目标；可分别建批注。
- **Word 双向。** 分别验 DOCX → 笔记 → DOCX 和笔记 → DOCX → 笔记，逐条核对选中文字／元素、独立讨论与回复关系、作者／时间和解决状态。普通单元格／列表文字不因所在容器而退成整格／整项。支持的 Word 原生公式按 §5.8 转为原生 Typst，导入时建立原公式与新源范围关系，导出时建立源到 Word 公式的关系；不能用“公式可导出”代替“公式及批注可双向映射”。编号、布局与批注范围分别报告。
- **明确退化。** 预览逐条区分准确保留、经用户选择改变范围、仅保普通批注／文字、未定位且留在原件／JSON、未进入目标 DOCX及不支持。后两类必须说明导出文件没有什么，不能笼统写“批注已保留”。批注自身富格式、媒体区域／时间段、生成内容及未知结构不能表示时保原信息并说明损失；不自动挂到附近文字或伪装整篇批注。
- **修订语义。** Word 文字修订以修订前正文为基线，插入点／待删文字对应 pending suggestion；替换不凭相邻或同作者猜成组。接受同时改正文与建议状态，拒绝不改正文。再导出只有仍待审且当前可执行的非冲突文字建议成为真正 Word 修订；已接受内容属于正文，已拒绝项不重新变待审。重叠修订可明确降为普通批注，但普通批注重叠本身不应被拒绝。格式／移动／结构修订及不确定目标保原件和限制，不承诺全量修订往返。

定位与转换职责见 [EDITOR](design/EDITOR.zh-CN.md) §2.4、[FEATURES](design/FEATURES.zh-CN.md) §9.9；专项矩阵见 [ROADMAP](ROADMAP.zh-CN.md)。这是范围与完成门补充，当前实现限制仍见 [MVP](MVP.zh-CN.md)。

### 5.8 公式、Mermaid 与旧办公格式交换

2026-10-14 补充 RQ01–03、RQ19–20 的用户范围，实施安排在 **v0.6 完成后的 v0.6.1**，v0.7 补齐目标平台验收。此项属于写作和办公交换的后续增强，不扩大当前 v0.6 收尾任务，也不把已有 v0.6 要求移到后续版本；尚未实现的能力不因列入计划而成为产品可用声明。

- **LaTeX 公式输入与转换。** 提供显式输入／粘贴、转换预览和确认插入；先覆盖常用分数、上下标、根式、积分、矩阵及分段函数。插入后以原生 Typst 公式作为当前可编辑内容，原始 LaTeX 可作为导入记录保留，不形成两份独立可编辑的公式。未知命令、缺失宏、歧义或转换失败保留输入并说明，取消不改草稿；确认插入进入同一 Draft／Undo。首轮离线使用不要求完整 TeX 安装。
- **公式双向及批注。** 复用 Typst → MathML → DOCX 原生公式输出，并增加有界的 Word OMML → 原生 Typst 导入；首轮分别列出字符／运算符、分数、上下标、根式、矩阵及分段等实际支持结构。验证 Word 中编辑、保存、重开及再导入；公式整体批注必须纳入往返，内部符号／子式按 §5.7.1 的可证明范围验证。LaTeX 输入、Word 公式导入、导出及批注定位分别列能力，预览成功不等于可编辑往返。复杂结构无法映射时保准确原件并报告损失，不以截图／普通文字冒充可编辑公式，也不静默丢公式或其批注。
- **Mermaid。** 支持图源码编辑与预览，保留一份可编辑 Mermaid 源码，渲染图片属于派生结果。导出 DOCX 时嵌入与当前确认源一致的图片；首轮优先 PNG，SVG 及兼容回退按实测能力决定。重新导入 DOCX 时保留普通图片，**不要求还原 Mermaid 源码**。语法错误、中文字体、尺寸及源码改变后旧图失效须有明确行为。
- **旧办公格式。** 提供可选的本机外部软件适配，支持 `.doc` 和金山文字 `.wps` 的导入与导出，以 DOCX 衔接现有转换链。导入保准确原件和中间转换文件；输出保准确生成物。转换前后分别报告正文、图片、公式、批注、回复、解决状态和修订的支持与损失，不自动接受或拒绝待审修订。使用 WPS 打开 DOCX 不等于支持 `.wps` 文件交换。普通 DOCX 功能不要求安装 Office；旧格式能力按实际软件／版本探测，缺项说明不可用。

### 5.10 原生引用、交叉引用与双向链接

2026-10-14 确认补充 RQ01–02、RQ06–07、RQ10、RQ12、RQ19–20。保留 Typst 原生引用与稳定对象关联；当前 v0.6 继续完成既有引用消费者的权限、同步、撤权及正确性要求，既有缺陷按原完成门处理。新增引用编辑、分类展示与导出增强安排在 v0.6.1，v0.7 补目标平台体验；以下不构成当前已实现声明。

- **引用编辑。** 选择文献后可插入、修改普通引用、叙述式、仅作者、仅年份、完整条目及页码／章节补充；可明确选择仅加入文献表而不在正文显示。编号、作者—年份、上标等由选定引用样式决定，界面区分“引用形式”和“样式”。变更形式、页码或样式不换文献对象；插入正文与必要绑定进入同一草稿及撤销操作，不要求用户手写内部 ID。
- **交叉引用。** 可选择本篇可引用的章节、图、表、公式并插入原生引用，区分自动编号引用、页码引用和自定义文字链接。增删及重新编号后结果跟随正确目标；无编号、不适用分页、缺失／重复标签或来源不确定时解释限制，不伪造编号或位置。
- **关系展示。** 同一关系入口按普通笔记链接、文献引用、文内交叉引用、属性关系分类；潜在提及保持独立。文献反向引用按来源笔记分组，可展开该篇各准确引用位置。“已绑定但未引用”、仅加入文献表、实际可见引用分别显示；三次引用同一论文不变成三篇论文。文内章节引用不冒充跨笔记边，无法证实的关系不按同名猜测。
- **原生源与可用性。** 保留合法 `cite`、`ref`、`link`、bibliography、set/show 及复杂动态源；应用识别或控件不足时说明限制，不改写成另一种作者语言。重名、缺目标、缺依赖、无权限与部分索引分别可见；不能把暂不可识别当作没有引用，不能泄露不可读目标信息。
- **输出。** 独立 Typst 工程包含本次实际所需文献数据及样式等依赖，明确应用专用链接的外部可用性；精确源码导出不暗改原文。DOCX 逐项说明自动更新域、超链接、固定文字及未转换项的实际结果，不能以看起来相同冒充可更新引用。保留本次引用形式、定位补充及文献顺序，无法表示的部分给出准确损失；Word 中编辑、保存、重开及适用域更新须实测，其他宿主单列。

技术落点为 [SOURCE](design/SOURCE.zh-CN.md) §1.2、[EDITOR](design/EDITOR.zh-CN.md) §2.5 和 [FEATURES](design/FEATURES.zh-CN.md) §10.1.1；实施及 CR01–16 验收统一在 [ROADMAP](ROADMAP.zh-CN.md)，沿用现有候选记录。

#### 5.10.1 引用操作的六项细化

- **复制与输出。** 区分应用稳定 URI、已实现部署的 Web 深链和完整原生 Typst 链接；按真实能力提供选项，Web 深链经登录及权限校验后定位同一对象／片段。导出明确实际链接可用性、应用依赖、可更新 Word 域、固定文字及未转换项，不修改精确源下载的字节。

### 5.11 脚注、尾注、题注与编号的文档交换

2026-10-14 确认补充 RQ01–02、RQ06–07、RQ19–20，与 §5.8、§5.10 在 **v0.6.1** 完成有界实现及双向验收，v0.7 补目标平台。当前 v0.6 的既有正确性、权限、同步和数据保全要求不延期。本节是待实现范围，不把当前可见文字转换视为完整结构转换。

- **作者内容。** 脚注、尾注正文及图／表／公式题注保存在原生 Typst 源中，属于文档内容；审阅讨论仍属于独立批注 JSON。二者不自动互转，不能把脚注转成审阅批注来代替文档交换。
- **脚注与尾注。** 用户可插入、编辑、删除注释，在正文标记与注释内容间跳转；同一注释可被多次引用。脚注与文末尾注可同篇共存，分别自动连续编号，增删后引用仍指正确注释。同文的两个独立注释不合并，一条注释的重复引用不复制正文。首轮覆盖普通段落、强调、列表、链接及已支持的公式内容；章末／分节尾注、特殊重启编号及复杂内容保源／原件并逐项说明实际支持。
- **题注与公式编号。** 支持图、表及公式的描述性题注，明确所属对象、类别、题注文字和编号；图与表独立计数。公式本体编号与描述性题注分别设置，每个引用目标明确采用哪条编号序列，默认不重复显示两套公式编号。手输“图 1”等普通文字不自动变为题注。对象移动、增删及更新编号后题注和交叉引用仍对应原对象。
- **Word 双向。** 分别验 DOCX → 笔记 → DOCX 与笔记 → DOCX → 笔记。已支持的脚注／尾注输出为真正 Word 注释结构，题注与编号采用可更新的 Word 结构／域及准确引用目标；保内容、类型、顺序和对应关系。不能只把上标数字、题注文字或缓存域结果保留下来就算结构往返。无法证明对象配对时预览供用户明确选择，不能按相邻位置、样式或相同文字自动认定。
- **损失与交付。** 逐项报告结构保留、仅文字／链接、无法定位及未转换内容，保准确原件；特别注明脚注／尾注正文未进入新文档的情况。分页和浮动位置分别说明，不承诺 Word 与 Typst 页码相同。普通 DOCX 不以安装 Office 为运行前置，真实宿主用于验收；DOC／WPS 外部适配逐段报告转换链损失，不因中间 DOCX 支持而自动宣称旧格式支持。

原生表达及映射由 [FEATURES](design/FEATURES.zh-CN.md) §10.1.2 负责，编辑由 [EDITOR](design/EDITOR.zh-CN.md) §2.6 负责；实施及 NC01–10 验收见 [ROADMAP](ROADMAP.zh-CN.md)。

### 5.12 语言、地区与针对性导入／校对

2026-10-14 补充 RQ01–03、RQ18–21 的适用范围。现有库样式语言／地区不是统一的界面、导入或 OCR 设置。v0.6.1 补文档设置体验及现有 DOCX 导入、本地校对的语言／地区适用机制；v0.6.2 按 §5.13 接 PDF／图片识别与首批专用方案；v0.7 补界面语言切换和目标平台验收。当前 v0.6 完成门不扩张，既有缺陷仍按原门修复；以下新增能力尚待实现。

- **分清三种设置。** 界面语言属于个人客户端偏好；文档排版语言／地区以原生 Typst 样式和作者源为权威，允许库默认与单篇／局部覆盖；本次导入／校对另有处理语言、已明确的文字体系、地区及优化方案。界面切换不改文档、词典或已确认导入计划。地区不自动代表时区、历法、币种或业务／法律适用范围。
- **默认与覆盖可见。** 处理设置优先采用本次明确选择，再采用原文可证明的语言标记，最后将可解析的文档／库默认作为标明来源的回退建议；自动检测只提供建议及不确定状态。地区未知时保留未知，不从汉字、界面、IP 或操作系统位置猜原文地区。混合语言允许分段及多语言选择，不把整篇强制改成库语言。
- **优化方案有适用条件。** 各方案声明语言、文字体系、地区、文档类型、输入格式及版本；通用结构恢复不强制绑定地区。公文、特定地区发票等方案由用户选择或确认推荐，不由界面语言自动启用。规则不匹配、原文缺标记或所需模型／词典缺失时展示实际可用范围，不能悄悄改用另一地区规则。

- **原件与跨格式。** 保原件及可用的原文语言标记；新文档语言单独预览，不通过本次识别选项改写整个库。Word 与 Typst 的有效语言映射逐项验证，不能表达的文字体系／语言范围报告损失。识别语言不等于翻译目标，不自动翻译、简繁转换或规范化含糊日期和数字。预览固定实际设置、方案／词典版本及输入依据，设置变化使旧待提交结果失效。
- **版式／图片入口。** PDF／图片 OCR、首批语言及公文／发票方案按 §5.13 的有界范围在 v0.6.2 实施，不因这套设置而宣称已有能力。识别语言与输出文档语言分别选择，保页／区域来源、原始识别结果及不确定项；缺模型、离线、部分失败和实际执行端明确可见。现有 PDF／图片资源阅读、区域批注继续可用；复杂识别和更多方案按支持表后置。

- **三种明确目的。** 可选择保留原件作为资料、提取文本、转为可编辑笔记；后两者仍保原件。结构恢复、专用字段提取和独立校对分别选择。流程为保原件 → 提取／识别 → 可选优化 → 预览确认 → 生成笔记 → 可选校对，不能暗中纠错或用整页图片冒充可编辑文字。
- **PDF 与图片。** 首轮覆盖 PDF 文本层、扫描 PDF、混合页面及 PNG／JPEG 图片，至少交付简体中文、繁体中文、英文及中英混合识别的明确模型组合。按页面／区域选择文本层或 OCR，避免双写；保页码、坐标与阅读顺序。单栏和可确认的简单双栏、段落及基础规则表格有界恢复；复杂布局或表格不能可靠重建时保图片／文字并说明损失，允许用户核对阅读顺序。
- **识别可核对。** 识别语言与输出文档语言独立，检测仅建议。保原始识别结果、处理结果、来源和实际不确定状态；低可信、未识别、空白页、未处理页与失败不同。用户可对照原页调整文字或顺序，修改进入新笔记作者源，不能改写原件或伪造原文。缺依赖或某页失败允许保原件／明确部分导入，不能宣称全部成功。
- **公文首批方案。** 先交付明确适用于中国大陆简体中文公文的方案，支持 DOCX 结构输入及已提取／识别的 PDF、图片文字；识别标题、层级编号、发文机关、文号、日期、主送等候选。用户选择保留、去除或按明确方案重建编号，避免重复编号；字段和结构候选保来源，不能把普通段首数字当作已证明的列表或改写公文内容。
- **发票首批方案。** 先交付中国大陆中文电子发票的有限票种／版式，首个实现切片必须列名并冻结票种、输入格式、字段与样例，至少完成一种明确票种的 PDF／PNG／JPEG 闭环。提取号码、开票日期、购销方、金额／税额／合计等适用字段，保精确原文及来源；缺失、重复、歧义、解析失败分别呈现。金额用准确十进制，日期不猜，算术不符只提示核对；不据识别结果承诺真伪、有效性或税务合规。不能以通用 OCR 代替专用字段验收。
- **持久化与权限。** 原件、资源、生成的原生 Typst、已确认字段及映射进入既有 Core 操作，取消不改用户原文件，未知结果查原操作。可保存的原始识别／处理记录是只读来源证据，可编辑正文仍只有作者源。私有词表、识别结果、缓存、搜索和下载继承权限／撤权；首轮本地或自托管离线执行，浏览器明确实际执行端，模型／工具独立交付并记录版本和许可证。
- **首轮边界。** 不承诺复杂跨页／合并表格重建、手写识别、公式 OCR、所有地区票据、所有字体／版式、OFD／XPS 或一比一版式复刻。此类输入保原件、说明实际可用结果；后续按独立支持表扩展。现有普通文档导入与资源阅读不等待新增识别模型。

交互见 [EDITOR](design/EDITOR.zh-CN.md) §8.8，处理与来源保全见 [FEATURES](design/FEATURES.zh-CN.md) §10.4，实施顺序及 IM01–10、LC09 见 [ROADMAP](ROADMAP.zh-CN.md)。首轮具体后端、模型和实际存储合同在实现前定版，不能把文档计划记成产品通过。

#### 5.15.1 可选的根节点初始内容

用户确认：**不新增工作台类型或工作台系统。** 初始化资料库时，可选择空白根节点或把普通根节点的初始内容预设为“工作台”，由说明文字及多个普通内嵌 Query 组成；也可不采用此预设。建库前预览将添加的内容和查询范围，允许选择需要的查询，不自动生成示例业务记录或改变现有库。

生成后，根节点与其它普通节点使用相同编辑、保存、历史、同步和权限规则。用户可自行改标题与正文，增删、调整条件或重排 Query，清空预设，或用其它普通节点组织相同内容。预设只在用户选择时生成初始作者内容；重开或升级不重新填回已删除的查询、不覆盖用户调整，也不要求保留“工作台”名称或特殊标志。移除查询只移除该处定义／调用，不删除结果中的笔记或另一处复用的定义。

每个 Query 仍有自己的定义、参数、获权范围和结果状态；没有数据时呈现合格空结果，缺类型／字段、权限不足、过期或不完整分别说明。根节点中的查询定义是节点作者内容，按该节点权限共享；当前用户的可见结果与个人显示偏好不能写回根节点成为他人的内容。普通多 Query 节点已由 §5.4.1 支持，NAV05 对个人列表偏好的限制不禁止这种组合。

该可选初始化体验已随 v0.6.3 第二阶段接入原建库与普通内嵌 Query，UX01／UX07 的整版任务仍按最终候选验收，不把原阶段通过扩大到所有组合。FEATURES §7.2／§10 和 EDITOR §2.3 负责实现衔接。

### 5.16 品牌连续性

保留既定古文字“文”意象的主图形及墨蓝黑／暖纸色应用图标；它不是特定甲骨文字形的严格复刻。技术重构不得用字母 W 或通用占位图替换品牌。恢复时从留存原件核对图形并显式导入品牌资产；不把历史私有记录复制进产品仓库。各实际交付入口使用同一源派生的资源，涵盖程序／托盘、安装包及使用品牌图形的 WebUI；检查小尺寸、透明／深浅背景和资源引用。主图形改版是单独产品决定，小尺寸适配不能改变识别特征。
