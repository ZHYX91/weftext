# 实现路线图

2026-10-13：按 **首版 MVP 加后续 7 个里程碑**安排当前需求。版本号是工作划分，可按实测结果拆成若干小版本；不是工期承诺，也不表示列出的功能已经实现。唯一范围依据仍为 [REQUIREMENTS](REQUIREMENTS.zh-CN.md)，竞品调研储备不自动加入。

当前本地 **0.5.0-alpha.4** 候选涵盖下列 v0.2–v0.5 的有界 Windows 功能。实际可用范围、检查结果与尚未验收项目见 [预览版说明](MVP.zh-CN.md)；版本号不代表 IME、完整富编辑、任意 Office 转换或跨平台条件已经全部验收。

| 里程碑 | 用户可完成的工作 | 主要需求与完成条件 |
| --- | --- | --- |
| v0.1 本地写作 MVP | 在 Windows 本地创建/打开库与 `A/A.typ` 笔记，浏览未管理项目；打开库外普通 `.typ`；源码编辑、原生预览、基础五档、搜索、基础链接、保存与恢复。 | RQ01–03、12、22、24–26 的有限切片。交付可运行产物；实测不丢稿、拒绝覆盖外部新稿、另存为、空文档与安全文字编辑。完整富编辑、同步和 Office 不在首版。 |
| v0.2 写作体验完整化 | 五档连续编辑，常用列表/表格/公式控件，标题/副标题、深层标题与同段标题；库样式及原生覆盖，布局与中文体验。 | RQ01–06、25–26；§5.3–5.5。同一草稿、选区和撤销连续；无法安全回写的原生构造保留。实测 IME、键盘、无障碍与复杂源，不能用源码入口冒充完整富编辑。 |
| v0.3 结构化信息与 Query | 人员、组织、论文、任务等丰富类型，属性面板与快速记录，搜索/筛选/Query，列表、表格、看板、日历、汇总和图表。 | RQ08–11、15–17、NAV01–05。同一字段在编辑、查询和视图中语义一致；多值、精确数值、缺失、错误与不完整结果可区分。任务详情仍是正文。 |
| v0.4 链接与知识组织 | 链接形式转换、出链/入链/反链、重叠潜在链接；正文及媒体批注；模板、完整复制、移动、回收恢复和备份。 | RQ12–14、18–19、22。身份与引用正确、批注失效不丢讨论、不猜测重锚；多文件操作与未知结果具备实际恢复证据。 |
| v0.5 办公输出与资料交换 | 可继续编辑的 Word、真实工作簿、文献引用协同、带依赖的导出/导入、清晰损失报告与本地下载。 | RQ07、10、19–20。真实 Word/表格应用验证；同段标题编号和正文字符格式正确；保原件。服务端撤权下载在 v0.6 验证。 |
| v0.6 多用户与同步 | Server/WebUI、内网、多用户非实时编辑、离线副本和部分同步；权限与下载交付闭环。 | RQ21–24 及所有消费者。冲突保双方稿，无关笔记可继续；撤权后搜索、预览、批注、缓存和下载不泄漏。实时协作仍后置。 |
| v0.7 多端及整体验收 | 补齐承诺的桌面环境、Mobile、CLI；跨端文件访问、触屏、RTL、性能、安装更新和离线字体交付。 | RQ03、21、25–26 与跨平台条件。按 [WORKFLOW](WORKFLOW.zh-CN.md) 的影响矩阵选择真实目标环境，补齐各平台产品场景与未验证项；不以 Windows、浏览器视口或执行环境资格替代其他平台的通过。 |
| v0.8 Agent 与自动化 | 获准读取、提出修改和人工应用，再提供指定范围的规则与明确连接器。 | RQ27。写入、出站、凭据、费用和外部效果分开授权；停止/失败/未知结果可见，未知外部效果不盲重试。首代外部效果逐请求确认。 |

保存可靠性、权限边界、可访问性和性能从首版持续验证，不留到最后集中补。每个里程碑复用已有通过的证据，针对真实变化及其消费者检查；不要求每版重做全部设计终审。开发顺序可因依赖调整，完整产品验收须覆盖全部 27 组需求、导航补充、样式、五档与中文支持，不能只按版本数量判断完成。

## v0.5 本地补齐：时间线与正文 Query

2026-10-14 接入本地候选 `0.5.0-alpha.2`：正文内嵌 Query 五档是 **v0.2／v0.3 的补全**；本地笔记时间线属于 **v0.4／Core**。复用原版本存储、操作恢复和 Query 执行。此前 `0.5.0-alpha.1` 不包含两项完整交互。版本号或既有历史存储本身不能代替验收。

需求见 [REQUIREMENTS](REQUIREMENTS.zh-CN.md) §5.4.1、§5.6；行为规则分别由 [CORE](design/CORE.zh-CN.md) §3.1、[EDITOR](design/EDITOR.zh-CN.md) 与 [FEATURES](design/FEATURES.zh-CN.md) 负责。实施顺序为：补齐现有提交记录的保存时间及按笔记历史枚举，接通只读查看/比较和保护草稿的恢复；再接通内嵌 Query 的同源五档、构建器及结果状态。最后验证受影响的 Core、编辑器和 Query 路径并打包下一候选；复用未变的办公输出证据。

以下条件对应本轮实现与验收，逐项结果沿用 [WORKFLOW](WORKFLOW.zh-CN.md) 的候选记录。Core/HTTP 和隔离无头浏览器检查分别说明能证明的范围；键盘和触控事件模拟不替代真实 OS IME、实体触屏及完整辅助技术验收。

| 场景 | 必须观察到的结果 |
| --- | --- |
| LHT01 保存版本与时间 | 连续保存三个不同版本后按实际保存时间浏览；旧记录缺时间显示未知，同时间/时钟回拨不伪造提交次序。Draft、未提交/未决操作不冒充已保存版本。 |
| LHT02 只读查看与比较 | 可打开准确旧版，并与当前已保存版本比较；有草稿时明确选择已保存内容或草稿快照。浏览、比较、关闭窗口均不改源，不丢 Draft/Undo。 |
| LHT03 恢复保护 | 保存 v1、v2、v3 后，在有未保存草稿时恢复内容不同的 v1：先明确保护草稿，再产生新保存 v4；v2、v3 和受保护草稿仍可找回，取消恢复不改当前稿。 |
| LHT04 身份连续 | 经应用改名、移动并重启后仍显示原笔记历史；复制的新笔记与同名文件不混入。外部改名或替换无法证明同一身份时提示待处理，不猜测续接。 |
| LHT05 保留与缺失 | 显示实际保留范围，未保留/缺失/不可读记录明确不可用，不用 latest 顶替。原配置或依赖缺失不阻止查看仍可读的准确源码；不承诺永久保留全部版本或键入。 |
| LHT06 冲突与重试 | 恢复准备后发生外部修改则拒绝覆盖，保双方稿；丢响应查询同一原操作，不重复产生新保存。未决恢复和草稿持久化失败不能被静默略过。 |
| IQV01 第一、二档 | 同一内嵌查询：V01 可直接改源码并另开结果；V02 完整查询源码始终可见且同时显示结果，结果不遮掉或替换源码。 |
| IQV02 第三档 | 默认展示结果，键盘/触屏可主动展开该查询源码；编辑后收起保留输入，不因普通结果聚焦自动改源。 |
| IQV03 第四档 | 默认结果，通过构建器修改；结果或控件聚焦不露语法。只有显式“编辑源码”才进入独立编辑界面或源码可见档；取消独立编辑不改 Draft，确认只产生同一草稿的可撤销编辑。 |
| IQV04 第五档 | 展示结果和状态，没有修改查询定义的按钮、菜单或快捷键入口，也不能借结果交互直接写正文；获权导航、选择和复制仍可用。 |
| IQV05 档位与草稿连续 | 带未保存查询在五档来回切换，源码字节、Draft 和 Undo 连续，切换不产生内容撤销项或自动保存。构建器与源码修改可在同一 Undo 历史撤销/重做。 |
| IQV06 同一执行与状态 | 各档复用同一定义/草稿依据及查询机制，明确权限、错误、partial、stale、完整空结果；修改后迟到的旧结果不能冒充新结果或授予写资格。换档不另建执行机制。 |
| IQV07 多查询与复杂源 | 同篇多个 Query 只修改选中定义；构建器不能表达、来源不唯一或源码暂时无效时保留原文并解释限制，不简化查询、猜测来源或覆写另一查询。 |

本轮限于本地笔记与现有本地权限边界。**v0.6** 补验多用户历史列表/读取/比较/恢复的分别授权、撤权后的缓存与展示，以及同步后实际收到/缺失/并发版本的展示；不能仅靠时间戳把同步历史排成虚假的单一因果链。文件版本时间线始终与 Query 的任务/事件业务时间轴分开。

## v0.5 补充：校对、批注与 Word 审阅交换

2026-10-14 确认实施 [REQUIREMENTS](REQUIREMENTS.zh-CN.md) §5.7。归属第 4 阶段跨对象能力，补充现有 v0.4 批注基础，在 v0.5 完成本地闭环后再进入 v0.6；此前 alpha.3 的有界收尾不代表这些新增能力已完成，不改写旧验收结果。

| 顺序 | v0.5 实施切片 | 完成门 |
| --- | --- | --- |
| 1 | 批注来源、校对规则与状态；基础修订的准确范围及插入位置 | 复用批注 JSON 与 Core 事务；旧批注、回复和未知信息保全；失效不猜位置。 |
| 2 | 四类本地校对、结果面板、批量加入批注 | 正常／疑似／排除范围可区分；跨格式文字可定位；重复运行不重复添加，迟到结果不冒当前。 |
| 3 | 正文版与带批注 Word 导出 | 批注正文、范围、作者及回复按实际支持映射；未定位和不支持项明确报告；导出不重新校对。 |
| 4 | Word 正文、资源、批注与回复导入 | 保准确原件和损失；新对象身份与原 Word 标识分开；不覆盖已有笔记。 |
| 5 | 基础文字插入／删除／替换修订的导入、处理与导出 | 未处理仍待审；接受／拒绝结果正确；重叠、结构或格式修订不能静默拉平。 |
| 6 | 同一候选的完整往返验收 | 带批注／修订 DOCX → Weftext 校对、回复、处理建议 → DOCX → 真实 Word 复核；WPS／LibreOffice 各自列实际结果。 |

必测反例：粗斜体拆开的同一词、中文与非 BMP 字符、重复同文、跨段和表格边界、交叉符号、空词典、重叠命中、已忽略项、校对后改稿、插入点前后编辑、批注所指文字被修订删除、重复点击／丢响应、源与批注提交冲突、未知 DOCX 部件与复杂修订。预览、确认和下载必须为同一准确内容；不能把 XML 检查冒作 Office 交互验收。

v0.6 对此完整链补验分别授权、批量操作冲突、离线同步、撤权后的结果／历史／工件缓存及下载。v0.7 补齐承诺的其他平台；本地规则校对不等待 v0.8 Agent。完整复杂 Word 修订往返及 AI 语义校对未自动纳入本轮。实际进度与结果沿用现有候选记录，不另建验收事实库。

## 后续验证与范围

v0.7 的工程验证优先复用产品入口：每个目标平台的一轮候选构建一次，纯引擎／HTTP／后台浏览器先覆盖可证明的部分，安装、系统文件集成、真实 IME 和 AT 进入已验证能力的隔离系统环境。Windows Sandbox 的可见查看器与独立 VM 的后台能力分别记录；Linux／macOS 桌面使用对应真实 OS，Android／iOS 使用各自模拟器及必要真机。执行环境的已声明、可用和实证状态分清，启动失败不回落宿主前台；必要前台短窗口提前告知并排期。按问题复现、修复回归、发布验收分别报告最小结果，复用未变范围的有效证据。这是后续验证安排，当前 0.5.0-alpha.2 没有新增跨端或隔离执行通过。

白板、学习系统、提醒送达、实时协作、共享布局等仍属储备。进入未来版本须另行明确范围，避免“全部需求”无限增长。正式发布沿用 [WORKFLOW](WORKFLOW.zh-CN.md)，不因创建本路线图自动发布。
