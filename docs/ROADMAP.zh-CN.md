## v0.5 本地补齐：时间线与正文 Query

2026-10-14 接入本地候选 `0.5.0-alpha.2`：正文内嵌 Query 五档是 **v0.2／v0.3 的补全**；本地笔记时间线属于 **v0.4／Core**。复用原版本存储、操作恢复和 Query 执行。此前 `0.5.0-alpha.1` 不包含两项完整交互。版本号或既有历史存储本身不能代替验收。

需求见 [REQUIREMENTS](REQUIREMENTS.zh-CN.md) §5.4.1、§5.6；行为规则分别由 [CORE](design/CORE.zh-CN.md) §3.1、[EDITOR](design/EDITOR.zh-CN.md) 与 [FEATURES](design/FEATURES.zh-CN.md) 负责。实施顺序为：补齐现有提交记录的保存时间及按笔记历史枚举，接通只读查看/比较和保护草稿的恢复；再接通内嵌 Query 的同源五档、构建器及结果状态。最后验证受影响的 Core、编辑器和 Query 路径并打包下一候选；复用未变的办公输出证据。

以下条件对应本轮实现与验收，逐项结果沿用 [WORKFLOW](WORKFLOW.zh-CN.md) 的候选记录。Core/HTTP 和隔离无头浏览器检查分别说明能证明的范围；键盘和触控事件模拟不替代真实 OS IME、实体触屏及完整辅助技术验收。

| 场景 | 必须观察到的结果 |
| --- | --- |
| LHT01 保存版本与时间 | 连续保存三个不同版本后按实际保存时间浏览；旧记录缺时间显示未知，同时间/时钟回拨不伪造提交次序。Draft、未提交/未决操作不冒充已保存版本。 |
| LHT02 只读查看与比较 | 可打开准确旧版，并与当前已保存版本比较；有草稿时明确选择已保存内容或草稿快照。浏览、比较、关闭窗口均不改源，不丢 Draft/Undo。 |
| LHT03 恢复保护 | 保存 v1、v2、v3 后，在有未保存草稿时恢复内容不同的 v1：先明确保护草稿，再产生新保存 v4；v2、v3 和受保护草稿仍可找回，取消恢复不改当前稿。 |
| LHT04 身份连续 | 经应用改名、移动并重启后仍显示原笔记历史；复制的新笔记与同名文件不混入。外部改名或替换无法证明同一身份时提示待处理，不猜测续接。 |
| LHT05 保留与缺失 | 显示实际保留范围，未保留/缺失/不可读记录明确不可用，不用 latest 顶替。原配置或依赖缺失不阻止查看仍可读的准确源码；不承诺永久保留全部版本或键入。 |
| LHT06 冲突与重试 | 恢复准备后发生外部修改则拒绝覆盖，保双方稿；丢响应查询同一原操作，不重复产生新保存。未决恢复和草稿持久化失败不能被静默略过。 |
| IQV01 第一、二档 | 同一内嵌查询：V01 可直接改源码并另开结果；V02 完整查询源码始终可见且同时显示结果，结果不遮掉或替换源码。 |
| IQV02 第三档 | 默认展示结果，键盘/触屏可主动展开该查询源码；编辑后收起保留输入，不因普通结果聚焦自动改源。 |
| IQV03 第四档 | 默认结果，通过构建器修改；结果或控件聚焦不露语法。只有显式“编辑源码”才进入独立编辑界面或源码可见档；取消独立编辑不改 Draft，确认只产生同一草稿的可撤销编辑。 |
| IQV04 第五档 | 展示结果和状态，没有修改查询定义的按钮、菜单或快捷键入口，也不能借结果交互直接写正文；获权导航、选择和复制仍可用。 |
| IQV05 档位与草稿连续 | 带未保存查询在五档来回切换，源码字节、Draft 和 Undo 连续，切换不产生内容撤销项或自动保存。构建器与源码修改可在同一 Undo 历史撤销/重做。 |
| IQV06 同一执行与状态 | 各档复用同一定义/草稿依据及查询机制，明确权限、错误、partial、stale、完整空结果；修改后迟到的旧结果不能冒充新结果或授予写资格。换档不另建执行机制。 |
| IQV07 多查询与复杂源 | 同篇多个 Query 只修改选中定义；构建器不能表达、来源不唯一或源码暂时无效时保留原文并解释限制，不简化查询、猜测来源或覆写另一查询。 |

本轮限于本地笔记与现有本地权限边界。**v0.6** 补验多用户历史列表/读取/比较/恢复的分别授权、撤权后的缓存与展示，以及同步后实际收到/缺失/并发版本的展示；不能仅靠时间戳把同步历史排成虚假的单一因果链。文件版本时间线始终与 Query 的任务/事件业务时间轴分开。
