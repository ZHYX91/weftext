# First bounded Server / WebUI slice

`0.6.0-alpha.1` adds a single-writer hosted native-document editing entry for Windows/NTFS. It reuses Core file guards, save journals and recovery evidence, with actor-owned drafts and original operation records. This is the first v0.6 slice; the complete scope remains in the [roadmap](ROADMAP.md).

## Configuration and startup

Create a library and notes in local mode first, or select existing ordinary `.typ` files. Managed notes require their original `--data-dir` identity/history evidence. Stop the local process before starting Server. One writer owns the author tree; a second instance with a different private directory must not bypass ownership.

Create configuration outside the document root. This example exposes two existing notes. The helper is create-only, never overwrites configuration, and does not start or expose a service. It prints one-time random credentials and stores only their SHA-256 digests. Keep administrator and personal tokens separately, outside source repositories and synchronization roots.

```text
python scripts/server_config.py --root "D:\Notes" --out "D:\Weftext-Service\server.json" --document shared=Shared/Shared.typ --document other=Other/Other.typ --user alice --user bob
weftext.exe --server-config "D:\Weftext-Service\server.json" --data-dir "D:\Weftext-State" --no-browser
```

The default bind is `127.0.0.1:47821`. Open the service URL and enter a personal token; the administrator token cannot log into the editor. A trusted operator chooses `root`, resource IDs/relative paths/display titles/`editable`, explicit dependency `inputs`, and deployment ID. Clients supply resource IDs or opened sessions, never filesystem paths, dependency roots or asserted actor identities. Each actor/resource has separate `read`, `write`, `history`, and `download` grants. Missing grants deny access; a disabled user loses all access. The latter three require `read`. Resources are authorized separately; dependencies do not inherit main-source permission.

TLS, password accounts, SSO, service installation and high availability are not built in. For LAN deployment, run behind a trusted HTTPS reverse proxy with an exact `origin`, such as `https://notes.example.test`, preserve that Host, and send tokens only over encrypted connections. `bind` selects the actual listener. The app neither changes firewalls nor deploys a proxy. Non-loopback HTTP requires explicit `allowInsecureHttp: true` for controlled test networks; WebUI secure-context features still require HTTPS or loopback. Host and any Origin must match exactly; forwarded headers never grant authority. Local HTTP/browser tests do not establish cross-machine TLS deployment acceptance.

## Writing, conflicts and disconnection

The WebUI provides source, styled source, on-demand syntax, visual writing and reading views, Typst preview within explicit authorized dependencies, title/source-text search within authorized configuration, exact historical source viewing, and saved-source download. Search explicitly covers configured readable sources, reporting incomplete results on budget exhaustion or read failure. This search entry is separate from the field-authorized CEL Query below. Ordinary files without admitted note history report it unavailable.

Two users editing one document keep separate drafts. The first save commits; the other old-Base save is rejected, preserving the original proposal and current source. Reopen, inspect both, edit the merged proposal, confirm its new basis, then Save. Basis confirmation itself does not change the author file; Core retains the original conflicting draft. An unrelated document continues saving.

Input is immediately retained in the current tab's session storage, and asynchronously in the actor's server draft while connected and idle. Disconnection permits further typing without local commit authority or automatic save retry. Reloading while offline does not guarantee the app can load. After reconnecting, reopening compares a draft still present in that tab's storage. Closing the browser, private mode or clearing storage may lose input not yet sent to the service; storage write failure is reported. Different users, devices and browser tabs do not share this tab's recovery store.

Each save first retains its exact operation ID and submitted source. A lost response queries that same operation, including after server restart. Unknown/recovery-pending states do not become success or a new blind retry. A not-registered/not-committed result is durably settled before permitting a new explicit proposal, fencing any delayed original request. Receipt application preserves input typed after dispatch. Actor drafts and operation records reside under `actors/` in the existing private state directory, outside the document tree. A server backup must consistently capture the entire private state and document tree; the existing local library backup entry does not promise all actors' private drafts.

## Revocation and delivery

The administrator reads `GET /api/hosted/admin/policy` with its Bearer token, then posts the complete `{expectedGeneration, users}` policy. The update conditionally commits and persists against the current generation; stale updates conflict. Restart loads saved policy rather than restoring revoked bootstrap grants. This endpoint cannot change document paths. After first startup, initial configuration users no longer overwrite persisted policy. Change the administrator token by stopping the service and editing private configuration.

Authorization epochs are server-generated per actor. Reads, search, history, saves and every download chunk reauthorize. Preview freezes individually authorized explicit inputs before compilation and checks the actor epoch again before delivery. Frozen World never fills missing inputs from disk; compiler diagnostics containing absolute server paths are not returned. Revocation and save/chunk-admission decisions are ordered at the same short service boundary. Already admitted bytes cannot be recalled; further chunks stop. Old sessions/tickets cannot revive after regranting permission. Other actors whose authorization did not change retain valid save sessions.

Downloads freeze exact bytes, length and digest. Each request returns at most 64 KiB; later saves never replace the artifact. Tickets bind actor and authorization epoch, expire after 15 minutes or restart, and cannot be transferred to another user. The WebUI verifies the complete digest before delivering a file. Responses disable browser caching. An online idle UI checks authorization every five seconds, clearing old display, preview and tab recovery cache on detected changes or denial. Already received/exported content cannot be recalled, and offline browsers cannot immediately learn about revocation.

## Budgets, acceptance and remaining scope

Configuration permits at most 128 users and 256 files, with 32 open sessions per actor and 128 service-wide. Source is limited to 2 MiB. Preview permits 64 explicit inputs and 32 MiB of frozen files, reuses compiler process time/memory budgets, and allows one active preview. Search reads at most 16 MiB. Download staging is limited to 32 artifacts and 64 MiB. Exhaustion produces an error or incomplete result, never a subset posing as complete.

`scripts/test_hosted_review.py` extends the full `test_hosted_fields.py`, `test_hosted_editor.py` and `test_hosted.py` suites and is included in the existing `scripts/mvp.py check/package` entry. It exercises real-process concurrent conflicts, actor drafts, idempotence/restart, rejection of local-path APIs, hidden-object nondisclosure, history permissions, frozen compilation, exact resumed bytes and persisted revocation. Browser checks additionally cover login, lost responses, offline drafts, explicit merging and cache removal. Actual outcomes belong to the candidate record, not this document.

**Not yet connected to Server:** structure operations and other local output formats. Exact resources, authorized collections and original-file import, preauthorized Word import-slot resources, media annotation targets and explicit inputs are described below alongside library configuration/styles, history, Query and Office. These remain v0.6 work; existing local features remain local. Local APIs cannot bypass hosted authorization. Realtime collaboration, other OS backends, Mobile/CLI whole-product acceptance and automation follow later milestones.

## Saved history and stable Node navigation

History lists, exact source and comparisons reuse Core's original save records. Browsing requires both `read` and `history`; restoration additionally requires `write`. Comparison explicitly distinguishes the current saved version from a fixed snapshot of the current draft. It neither saves source nor replaces the buffer or clears Undo. Only historical source and text differences are provided; current dependencies do not impersonate historical rich preview. Missing versions remain unavailable instead of falling back to latest. Returned locations use authorized resource IDs, without absolute server paths or another actor's private drafts.

Restore proposes the selected version as a new ordinary save and retains later history. The browser first durably retains the complete original request and operation ID; unsaved input requires an explicit draft-retention choice. Core protects both that actor's persisted draft and submitted buffer, preserving their original bases, while other actors' drafts remain independent. After commit, an originally dirty buffer or input typed during the request stays in the shared editor. Only a clean buffer still matching the original basis receives one undoable replacement. The new save basis comes from the currently authorized document.

`/api/hosted/history/list`, `read`, `compare` and `compare-draft` provide read-only consumption; the original `/api/hosted/history` list remains. `history/restore` fixes the actor, resource, actual Node/FileIdentity, selected version, Base, exact source snapshot and draft choice. `history/status` and `history/settle` use the original resource and operation ID without requiring an expired editor session. An unregistered request can be durably settled to fence delayed restore; an already committed or potentially effective operation cannot masquerade as cancelled. Changed intent with the same ID conflicts, including reuse as ordinary Save or another operation category. Restart or lost delivery never creates a replacement restore operation.

Commit facts and result delivery are separate. A committed operation can still report that actor's original commit fact after the configured resource points to another object, but cannot deliver the former object's contents. When readable, the result identifies whether its basis remains current, was superseded by a later save, or has external changes. Another save with identical bytes does not revive the old receipt. The browser checks the current document before applying a result; an old result is comparison material and never binds an old Base to newer source. A known commit whose result cannot be delivered has an explicit exit from applying that tab's receipt, followed by reopening and comparing current source. It neither cancels the Core commit nor automatically rebases input, and unknown or recovery-pending operations cannot use this exit. Acknowledged terminal records can be explicitly removed from tab storage; unresolved requests remain retained.

Stable links use native `weftext-node://` / `NodeRef`. `navigation/ref` reads the current authorized document's stable reference. `navigation/resolve` considers only operator-configured candidates with independent source `read` permission, then the existing open flow protects the current draft and switches documents. Core checks the current declaration, actual file identity, proven placement and boundaries, without guessing by name/path or scanning the whole library for more candidates. Updating deployment configuration after a Core move preserves the original reference; a copy receives an independent identity. Hidden, missing, ambiguous or unqualified targets return the same unavailability. Reading a source grants no target access, and a link grants neither writing nor history rights.

Stable references with `#label` parse identity and the UTF-8 fragment separately, accepting Chinese labels and percent encoding while rejecting empty labels, invalid encoding, control characters and multiple fragments. `navigation/resolve` first checks independent target authority and exact ownership, then compiles the saved target with authorized inputs. Fragment status distinguishes found, missing, ambiguous and unavailable; only a unique actual compiled label with an exact main-source range is locatable. Unevaluated source labels, generated content without a proven range and auxiliary-module labels are never guessed into a main-source location. Hidden and unknown objects retain uniform unavailability.

`navigation/fragment` takes the complete stable reference, sessionId, source, sourceHash and serial, qualifying the current target session and exact personal Draft before reusing the original compilation environment. Delivery rechecks authority, owner, source and original dependencies. Ranges refer only to that main source, without host paths or auxiliary-module source. The browser preserves the source editor and Undo until location succeeds; another target uses a temporary session to verify its actual local/recovered Draft instead of applying saved-version offsets. Missing, ambiguous or unlocatable targets and pending original saves keep the original page and offer an explicit open-whole-note choice. Same-document location does not reopen the editor, and late results cannot replace later input, another target or revoked state. `scripts/test_hosted_navigation_fragments.py` is included in check/package; actual acceptance remains in the candidate record. v0.6.1 Web-deep-link copying separately requires real deployment routes and login-return acceptance.

`scripts/test_hosted_history.py` exercises real HTTP permissions, both actors' drafts, exact comparisons, restore/original-operation restart, external conflicts, configuration rebinding and move/copy navigation through the existing `scripts/mvp.py check/package` entry. Browser Undo, late responses, failed local retention and revocation are separately exercised by `scripts/test_hosted_history_browser.mjs`; actual passing scope remains part of the candidate record.


## Same-owner remotely hosted synchronization

Server can additionally host one explicitly paired manifest/blob history. The operator supplies the original replica's WorkspaceId and genesis digest through `syncIdentity`. `users.<id>.syncOwner: true` explicitly grants full-history transport for that pairing and defaults to false. It is independent of document read/write/history/download rights; document authors, field-only clients and the administrator login credential do not inherit it. Do not give full-sync credentials to users who should see only selected documents. This mode trusts the owner's devices and hosting account; digests establish integrity, not protection against a malicious server or a device with stolen owner credentials.

The provisioning helper accepts `--sync-workspace-id ID --sync-genesis DIGEST --sync-owner USER`; USER must also be explicitly created through `--user`. The document list may be empty, allowing an existing empty root folder to serve an independent relay. Received records never directly install into root. If root is already a paired replica owned by the same Core private state, its identity must match. Authorized hosted author saves enter that replica's original outbox and are published when full-sync history is read; private actor drafts and policy are excluded.

Persistent policy also binds `syncIdentity`: existing full-sync grants cannot silently move to another pairing through startup configuration. Adding sync to a deployment that previously had none preserves its user policy; new bootstrap syncOwner values do not override it. Grant explicitly through the existing administrator policy API. Revoking syncOwner changes that user's authorization epoch; regranting never revives old tickets. Unchanged users retain their tickets.

In the local Sync panel's remote transport section, enter the service root URL and full-sync credential. Upload selected local objects, or inspect the remote inventory, select objects and receive them. Original clone/apply/merge previews still control author-file changes after reception. Received and installed versions remain distinct. Non-loopback URLs require HTTPS; literal loopback IPs support HTTP acceptance. The client validates certificates, refuses redirects and ambient proxies, and never takes credentials from URL userinfo/query parameters. Credentials stay in the current UI and active process memory, not browser storage or the author tree. Closing the panel clears its input; an already started transfer can continue. Stop prevents subsequent requests after the current block.

Transfers are idempotent by complete record digest, with 64 KiB blocks. Downloads freeze an exact record set; inventory pages contain at most 128 records. Every block rechecks actor, epoch and current full-sync rights, and newer commits never replace the frozen download. Upload buffers resume within the same actor/epoch/record; identical repeated blocks do not rewrite content. Only complete records passing digest and Core manifest validation enter private history. Wrong bytes never become author versions. Restart drops partial in-memory records and tickets while retaining complete durable records; a new transfer skips verified complete records. Transfer completion means records were copied, not that every commit is admitted or the working tree is installed.

Server permits at most four download snapshots totalling 256 MiB, and 32 upload buffers/completed receipts with a total retained budget of 256 MiB. Clients close completed receipts. Records retain Core's 64 MiB blob, 4 MiB manifest and graph limits. Tickets expire after 15 minutes, and revocation clears caches for the revoked epoch. The local program allows one remote task at a time for up to 15 minutes, retaining up to 64 task statuses for one hour within that process. Browser storage keeps only the task ID; a lost response queries the original task first. After process restart/expiry, explicitly start a new transfer and reuse complete records. Installation remains a separate durable original operation, so a network restart does not repeat author effects.

`test_remote_sync.py` joins the existing check/package entry and covers three real programs, offline conflicts/unrelated progress, partial replicas, block retry/restart, per-block revocation/regrant, unaffected owners, persistent pairing, non-expansion of old grants, redirects and response budgets. `test_remote_sync_browser.mjs EXE NEW_EVIDENCE_DIRECTORY` uses explicitly configured Playwright for actual UI acceptance. Loopback HTTP/headless browser results do not establish cross-machine HTTPS, long latency, real network failures, malicious-transport defenses or other OS acceptance.


## Hosted authorization for native document views

All five views share the native SourceEditor, WritingController, source buffer and undo history. V02 decorates original syntax/headings; V03 reveals the same editor at an exact current construct; V04 edits only text, empty slots and structures whose unique origin is certified by both the final tree and official AST; V05 has no document-editing entry. Title, subtitle, formatting, list, ordinary table, math, code and link controls propose native patches. These remain drafts until the existing Save transaction commits. View changes never write files. Reopening the same retained source preserves Undo; switching documents or logging out follows the existing draft lifecycle.

`editor/map` and `editor/render` register exact session source/serial. `editor/edit` consumes that already observed source/serial/hash. Older serials, different text at the same serial and revived old addresses after equal-byte Undo are refused. After asynchronous work, the service rechecks the actor, session epoch and exact draft; edit proposals additionally require document write. Reader maps/trees have no write flags and readers cannot call the edit endpoint. The client also checks its current editor, source and serial. Revocation destroys the editor, structure dialogs, preview and tab cache; late results cannot reinstall them.

Compilation uses only independently authorized explicit inputs and rechecks dependency bytes before delivery. Only main-document origins can become edit ranges, with resource IDs replacing filesystem paths. Include origins remain read-only with original paths/raw ranges removed; metadata does not flow to other consumers through presentation. Hosted and local views share DOM element, attribute, image and style allowlists instead of injecting author HTML. Bundled offline fonts load from the same origin; failures are visible and preserve input. Compilation retains its single-active-worker budget. Manual read-only preview may briefly wait for a busy compiler; saves never automatically repeat.

`test_hosted_editor.py` adds exact-draft/ABA, cross-actor and reader denial, hidden/missing dependencies, virtual main origins/read-only includes, and in-flight revocation/newer-draft checks. `test_hosted_browser.mjs` covers the five views, Chinese/non-BMP input and Undo, original save conflict/lost-response/disconnection, input fencing on reopen and late rich edits after revocation. Automated keyboard input is not real operating-system IME acceptance. Independent field, annotation and library-style permissions are described below.


## Narrow fields and authorized-scope Query

Each object can independently configure `fields`, for example `"fields": {"tasks/status": {"read": true, "write": true}}`. Keys are permanent FieldIds in the installed Schema. Field write requires that field's read, without requiring source read. Full-source permissions do not automatically grant these structured endpoints or full sync. `GET fields` lists only explicitly granted resource IDs/FieldIds. `fields/read`, `fields/write`, `fields/operation` and `fields/settle`, all under `/api/hosted/`, reauthorize the resource and field on every request.

The WebUI field/Query area reuses native value forms for qualified enums, text, arrays, records and other shapes. Tab storage retains input, including invalid form text; Query, switching and reload do not replace it with an older valid value. Rereading preserves it and requires comparison with the current field. Before saving, the client retains the original operation ID, basis and value. Lost responses/reloads query that operation even when the current field cannot be read. Not-registered/not-committed requests are durably settled before a new explicit proposal; a resolved recovery outcome is not presented as a successful save. Server recovery drafts are separated by actor and original field operation, preserving that actor's independently edited full-source draft. Revocation removes field displays, Query results and tab recovery caches; late responses cannot recreate them.

The static producer uses the official AST to certify a unique direct-root declaration, standard constructor bindings, static keys and selected fields. It decodes only authorized fields, without executing the body or validating unchanged hidden fields. Arbitrary legal body functions, show rules and query calls remain valid. Deliveries contain selected definitions, cells, write availability and an opaque basis, with no source, ranges, raw expressions, Node control declaration, paths or complete revision. Affected constraints establish authorized dependencies before reading values. Missing field grants or resource/relation target evidence yield read-only availability rather than validation differences driven by hidden values. Resource and relation writers still require separately authorized producers.

The writer reacquires current source/qualification and applies a native exact patch preserving every unselected byte. Hidden-body or unrelated-field changes alone do not stale the basis. Changed authorized preimages, including local saved A→B→A history, reject old bases. Current source requires a Core-admitted saved witness; external observations or unavailable history cannot be replaced by equal-byte guesses. Bases bind actor epoch, expire after 15 minutes and do not survive restart; original operation receipts remain durable. The basis includes selected shapes, affected constraints and their actual validator/provider dependencies. Unrelated registry entries do not stale ordinary fields. Complex fields whose dependency closure cannot be proven are explicitly unavailable; the whole registry is not borrowed.

**Write prerequisite:** explicitly install Schema through the local properties panel or the hosted configuration panel with independent `library.schema.write` authority, retaining the same Core private state. The narrow writer must hold the installed, admitted `.weftext-schema.json` behind a protected handle through its commit decision. Bundled defaults or externally unadmitted Schema still permit field reads, but do not yield a writable basis. Query can use bundled defaults; an existing externally changed, unadmitted configuration is explicitly unavailable. An observed absent configuration file is not treated as a lockable condition. Field permission alone does not authorize Schema installation.

`POST query` accepts explicit `fields`, optional resource-ID set `resources`, the original CEL `plan`, and `parameters`, `products` and `relations`. Without resources, scope is the intersection of configured objects granting the requested access. Unrequested field definitions are removed before CEL type checking, so expressions cannot retrieve them. The existing evaluator provides filtering, selection, sorting, grouping, array expansion, parameters, unionAll, distinct and definition calls. Requested fields form the default selection; rows use deployment resource IDs and remain read-only. Defaults/maxima are 500 rows, 64 requested fields and 64 requested objects; source/configuration capture is limited to 64 files including Schema, definitions and compilation inputs, with at most 64 explicit directories. Scope-marker/control witnesses add entities but share the 32 MiB input budget; the definition-save guard pool also has Core’s separate 64-unique-file limit; underlying step/byte budgets remain active. Insufficient qualification reports partial results without adding hidden-object counts. Ordinary CEL and native dates require no Provider grants; Provider computations follow the independent authorization and exact-version requirements below.

The service retains at most 1024 field bases, 128 per actor, with at most 64 explicit field grants per object. Static shape expansion is bounded to 20000 nodes and dependency traversal to 200000 steps; field bases currently require at most 2000 retained source versions. `test_hosted_fields.py` covers field/source separation, hidden-source and same-actor draft preservation, ABA, external changes, Schema witnesses, original-operation restart and revocation/regrant, plus CEL hidden-field/scope isolation. `test_hosted_fields_browser.mjs EXE NEW_EVIDENCE_DIRECTORY` exercises native forms, Query, lost responses, offline/reloaded input, explicit comparison and late-delivery revocation. Outcomes remain in the candidate record.

## Query Providers and exact versions

User-level `queryProviders` grants separate ID sets for `providers` and `seriesPolicies`, both empty when omitted. Source, field, definition and Office permissions never imply these capabilities. `GET query/catalog` returns only safe authorized descriptors, exact fingerprints and unavailable states, without Provider data tables, the full Schema or server paths. Series policies require independent grants; authorized calendars and zones do not automatically expose every series policy.

Fingerprints cover complete Provider or policy records, including implementation identity, ABI, data and budgets. Only supported trusted built-in implementations are used; this is not dynamic plugin installation or proof of a runtime build digest. The browser preserves the selected IDs and fingerprints. Changed data under the same ID invalidates the old selection and requires explicit reselection instead of silently adopting the latest version.

Dependency discovery reuses the original CEL syntax tree, deriving static requirements from literals, parameter shapes, defaults and each called definition's original Schema baseline. Dynamic values execute only within the explicitly selected authorized subset. Named parameter Shapes are limited to definitions referenced by the requested authorized fields, or shapes and dependencies exactly matching the product's public built-ins. Parameter validation cannot probe other private enums or definitions. Definition preparation/editing and source saves still use the original Core operations, with no new Provider request ledger or full granted registry passed to static validation. Current/pinned definitions retain their original baselines. Missing exact versions, insufficient coverage or incompatible baselines report unavailable or partial results without falling back to the latest version. Queries without result rows also check actual row-independent Provider calls, preventing an unevaluable condition from appearing as a complete zero result.

Frozen Queries retain their original result and actual dependencies. Office continues preparing and delivering exact bytes from the original `queryId`; later configuration changes do not rerun existing output. The Excel structure worksheet retains authorized field shapes and exact results without internal Provider data tables, executable registries or parameter-only validation definitions. Delivery still rechecks actor epoch and Provider/series permissions. Revocation followed by regrant never revives old results or downloads. `test_hosted_providers.py` is included in product check/package; `test_hosted_providers_browser.mjs EXE NEW_EVIDENCE_DIRECTORY` checks browser selections, late results and draft preservation. The library root also needs a DirRef through directory admission; a workspace marker alone is not stable directory identity. Directory authority grants no descendant source, fields, semantic products, definitions or Office access. Catalog entries expose only authorized IDs, labels, references, kinds, lifecycles and availability, without physical paths, hidden children or counts.

Queries retain `plan.scope.directory/descendants/lifecycle`. A directory selector may be an authorized configured ID or its stable reference; saved definitions normalize it to the native stable reference. Actual leaf scopes in current/pinned calls, unions and related queries are checked separately. Their lifecycle must match the configuration. Filtering uses the current real tree; a live root does not substitute for a Trash object's historical position. Unknown, hidden or unqualified scopes cannot produce a false complete zero, even with `resources: []`. Core qualifies only selected paths against actual objects, birth admission, original move/trash facts, current declarations, rules and Pending boundaries, without scanning hidden subtrees. Copied markers or another object occupying an old address do not inherit identity. Original witnesses and authority are checked again after execution.

Scoped definition saves use the original Core save and protected dependencies, with no separate ledger. New libraries create the default rules file in their original initialization transaction. Older libraries that never installed it can still run read-only queries, but their owner must explicitly install it before saving these definitions. Query preparation does not create that file implicitly, and observing absence is not continuous protection. Browser top-level scope controls change the temporary plan only on explicit application, preserving nested branches and author source. The operator updates explicit slots after trashing. Trash queries without a directory also use only authorized configured objects, not automatic whole-trash browsing. Restoration invalidates the old qualification. Results remain read-only. Office consumes the original frozen result and rechecks scope authority and actor epoch on delivery; regrant does not revive old artifacts.

Trash slots can declare exact registered images, auxiliary Typst files and other resources as explicit inputs. Each asset has independent read authority and the same qualified owner/lifecycle as its Trash note; labeling it live cannot bypass qualification. A missing registered leaf with an admitted manifest and original resource birth produces unavailable semantic products and partial coverage for the affected row. Static field projections remain usable. Missing owner/manifest identity, replacement objects, revocation and budget failures still fail qualification. Restoring the note invalidates its original Trash qualification; neither Query nor media reading restores it.

## Advanced Query, definitions and embedded consumption

Each resource's `query` separately grants `definitions`, `definitionHistory`, `products` and `relations`, defaulting to no access. Product keys are `title`, `body`, `headings`, `types` and `self`; relations is an array of permanent RelationIds. Source read implies none of these permissions. A matching CEL name or readable raw source does not authorize an ungranted semantic product. Field values, relation assertions, target types and actual compilation inputs have their required authority established before evaluation; hidden body execution is not used to derive narrow field values.

`GET query/catalog` lists granted configured resources, fields/products/relations and admitted current definitions. An externally changed or temporarily unavailable definition owner explicitly makes the catalog partial with that unavailable resource, without blocking other granted resources. `POST query/definitions` accepts resource and optional selection using the existing `{"mode":"current","key":"…"}` or `{"mode":"pinned","key":"…","revision":"…"}`. Pinned reads additionally require definitionHistory; missing revisions never fall back to latest. Calls use the existing QueryPlan `advanced.call`, with a configured resource ID as the HTTP owner. Stable owner references in native definitions resolve only within explicitly configured, authorized resources. Each callee uses its own exact Schema baseline instead of reinterpreting old aliases through the caller's current schema. Definition readers receive neither the whole source nor the complete Schema.

Query captures admitted files and configuration within the explicit authorized closure. Each request owns its read witnesses, releasing them on failure, cancellation or completion instead of retaining them in Core’s write-basis store. Visible input copies, original read witnesses, directory/node qualification witnesses, context and repeated compilation inputs share a cumulative 32 MiB capture budget. Retained inputs, witnesses and incrementally produced semantic products remain subject to a 32 MiB execution budget; exceeding it fails explicitly. The consumer then rechecks current authority, configured bindings and exact inputs after evaluation and native compilation. Body, title and heading products come from one native Html result, without treating source strings as rendered body. Relations consume authorized fields and trusted identity/type projections; parameters, terminal columns and CEL locals do not acquire extra field/product rights by matching their names. Frozen results retain their original queryId, row order, column order and values for Office. Export and every download chunk additionally require Office rights across all consumed resources and current Query authority.

The body `query/embedded/discover`, `run` and `edit` endpoints reuse the official AST, original executor and current editor session. Exact source/serial/hash prevent late proposals and equal-byte ABA from reacquiring a writer. Builder or source replacement yields draft patches in the same five-view source and Undo history; only the original Save commits. Readers have no editing controls, and source access alone does not authorize a definition's data dependencies. Obsolete results, resource/actor changes and revocation invalidate late delivery.

New saved definitions use `POST query/definition/prepare`, binding resource, sessionId, baseId, source/serial/sourceHash, operationId, label and the native QueryPlan. Client keys, paths and Schema bindings are not accepted. Source read/write and definition read are required; actual fields, products, relations and current/pinned callees are authorized separately. Core allocates the key and durably records the initial admitted Schema baseline, complete original proposal and identity in one step. Preparation returns an exact UTF16 draft patch without running results or saving source. The UI retains the original ID/request before inserting the patch into the same source and Undo history. Configured call-owner selections are converted to native stable Node references before persistence.

Repeating the same original request checks the same key/baseline/patch; changed intent with that ID conflicts. Once its old session has ended, a recovered proposal is for comparison only and cannot automatically replace the current draft. `query/definition/operation` and `settle` accept resource/operationId; `reservations` accepts the current sessionId. Reopening can recover pending reservations for the same actor and actual owner. Explicit settlement durably fences late allocation; installed or recovery-pending saves cannot be disguised as cancelled. Undo, removing a definition or saving source without its carrier does not cancel the reservation. Replacing the current draft with an old proposal requires explicit comparison of both texts and remains undoable.

Ordinary `save` may carry an explicit `definitionReservations` set of original IDs, fixed alongside the full source in the original save fingerprint. Only qualified keys present in that exact afterimage and reserved by the same actor for the same owner are admitted. Invented keys in raw source and reservations belonging to another owner/actor do not establish identity; legal author source that preserves Node identity but has no admissible definition can still be saved normally. If incomplete full-source syntax prevents confirming Node identity, the original Core writer refuses installation and retains the complete personal draft; repair can reuse the same reservation. First admission rechecks current Schema compatibility against the original baseline, actual callees and current permissions. Non-owner dependencies retain their exact snapshot protection handles through the save decision; the original Core save protects the owner. One save accepts at most 32 reservations, with at most 128 pending per actor and owner. Snapshots across proposals are deduplicated only after their complete versions agree, within a combined limit of 64 files and 64 MiB. The UI removes admitted/cancelled save IDs only after checking their original status; unapplied entries in the recovery directory are not automatically included in a save. Lost save responses still query the original save ID rather than replaying effects under a new operation. Once admitted, identity is proved by the original committed history, so later Undo/save/Redo needs no new key allocation.

All hosted recovery caches are partitioned by deployment, actor and server authorization epoch. Original operations in the same epoch remain recoverable; protected source, previews and Query input from an older epoch are not restored. ## Authorized resource collections and original-file import

Operators can configure `resourceCollections.<id> = {owner, expectedOwner, lifecycle, title}`, binding one file ID, exact NodeRef and live/trash lifecycle. An arbitrary new note at that path, copied markers or same-byte replacement cannot borrow this preauthorization. Operators can preselect the collection's `/*` in the imported file's inputs and separately grant collection read/download so native preview and Office use actual imported resources. `GET media` lists only collections with at least one granted capability. Their `status` and overall coverage report unavailable entries accurately. A truly never-initialized collection provides only a read-only negative witness, not a persistent write basis.

`media/import/prepare|commit|operation|settle` accepts only collection ID, filename, this upload's bytes and original operationId/planId. The browser retains the complete original request before preparation. Changed owner, deployment binding or authorization epoch prevents old-plan commit; regrant does not revive it. Import-only actors receive references from their own original operation, without gaining collection or other-file reads.

`files.<id>.inputs` and `styleInputs` can explicitly select one member or `collectionId/*`. Execution freezes actual membership and original collection version, checking each resource's read authority; Office additionally requires original-resource download.
