# 开发、验收与发布

## 当前阶段

最终需求与技术方案已接受；下一步按 [INTEGRATION](design/INTEGRATION.zh-CN.md) §4 重构。先交付一个可运行的本地闭环，再逐步扩展。旧原型依赖问题留在归档，不使新的纯设计检查依赖旧 UI 或 npm 审计。

## 日常检查

纯文档改动运行 `python scripts/check.py`。涉及 schema、类型/时间算法或模型时运行 `python scripts/check.py --models`。实现切片增加自己的格式、静态分析和必要测试；跨平台、文件故障、权限、编辑和 Office 输出按真实影响选场景。失败记录实际原因；不通过删断言或改期望掩盖问题。

每个可交付切片保留一份简短验收记录：提交或产物标识、环境、范围、实际命令/手动场景、结果、已知限制与必要证据位置。正常日志只保摘要；用户真实输入与输出分开放置，原件不被测试覆盖。文档链接检查和有限模型不计作产品验收。

## 发布

有可运行产品后，再实现版本号、打包和上传入口。先构建一个候选，验收该候选；正式发布复用同一产物，不在发布步骤重新构建另一份。发布前明确目标版本、平台、未通过项和用户授权；发布后核对下载内容及最小运行场景。

仓库保存可独立执行的产品构建/检查/打包入口。个人工作区只负责路径与本地环境，不建立另一套发布平台。发布产物校验与关键交接使用哈希，不对每轮讨论重复计算全库哈希。只有正式交付需要标签和发布记录；当前不创建空发布。
