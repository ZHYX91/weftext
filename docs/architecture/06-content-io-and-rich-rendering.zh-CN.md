# 内容输入输出和富渲染

受管源文本、导入、导出和富渲染是彼此独立的边界。受管源文本包括规范 `X/X.adoc`、节点资源和可移植伴随文件。导入产出经验证的提议；导出读取已授权内容而不变更它；渲染产出安全的派生视图，不成为源文本权威。参见[元数据](14-canonical-document-metadata-and-review.zh-CN.md)、[接入](15-content-intake-foundation.zh-CN.md)和[PDF/OCR](16-pdf-import-and-ocr.zh-CN.md)。

## 导出和兼容性

导出计划冻结经授权的源集合、修订、目标 Profile、资源、选项、不受支持构造和输出限制。导出不是备份，也不会变更工作区。Markdown 是兼容性输出，不是第二种受管生成；不支持的文缕构造需要显式降级或警告，导入已导出的 Markdown 是一次新的已审阅转换。

## 数学和图表

原生 `latexmath:[...]`、`[latexmath]`、`stem:[...]`、`[stem]` 和 AsciiMath 保持精确源代码。渲染器是可离线使用的派生视图，不能执行文档类、包、包含、BibTeX、shell escape 或外部命令。TeX 接入有范围限制，绝不执行 TeX，并报告不受支持的命令/宏。

已接受的 `[mermaid]` 字面块扩展保持精确源代码。其渲染器固定版本、与文件系统/网络访问隔离、受大小/时间限制、插入前清理，并提供源代码、错误和无障碍回退。数学和图表可共享呈现基础设施，但仍是不同的 Core 块类型和渲染器适配器。

## 出版结构和格式适配器

原生 AsciiDoc 注释、锚点、表格、插图、方程、清单和属性在能表达语义时优先使用。编号、标签、格式化引用和视图行是派生的。目标特定布局属于导出 Profile，绝不悄然写回源代码。

适配器使用共同的接入边界。当结构化解析器比版式转换保留更多语义时，优先采用结构化解析器。每个适配器都需要恶意/损坏样本、确定性验证、取消/清理、包/许可证据、无障碍诊断以及诚实的损失报告。
