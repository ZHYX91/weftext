# 内容接入基础

每个导入器都使用同一个由文缕拥有的管线：

```text
源工件 -> 探测 -> 计划 -> 有边界的格式工作进程 -> Weftext Import IR
-> 验证 -> 预览 -> Core 事务 -> 回执
```

导入为规范文档/资源创建可审阅的提案，绝不直接写入工作区。导出和渲染是独立的非权威边界。

## 共享契约

`SourceArtifact`、`FormatProbe`、`ImportPlan`、`ImportDocument`、`ImportProposal` 和 `ImportReceipt` 是版本化、格式中立的契约。Import IR 是内部转换契约，不是工作区格式或规范化文档数据库。适配器将其解析器输出映射为文缕拥有的类型；格式特有结构留在适配器后面。

## 安全和提交

探测使用范围受限的证据，而非信任文件名。加密、格式错误、过大、递归嵌套、解压炸弹、路径穿越、链接/reparse 和活动内容输入会安全拒绝，或使用单独审查的沙箱。工作进程受取消、时间、内存、条目/页面、输出、临时文件、文件系统和网络限制，且不会获得可写工作区句柄。

验证通过规范 Profile 重新解析提议的 AsciiDoc，验证 UTF-8/资源/限制/保留路径，并生成完整预览。提交是一次可恢复的 Core 事务。批准绑定显示出的提案，绝不允许用不同字节悄然重新转换。

## 本地和增强处理

基线路线是确定且可离线使用的。可选增强仅处理所选的不确定证据，并返回类型化 IR 补丁。它披露提供方、外发、范围、可用时的成本、保留、脱敏和不确定性。Core 验证补丁、重新生成提案并遵循相同的预览/事务路线。

## 适配器质量

当结构化解析器保留更多语义时优先采用。每个适配器都需要恶意/损坏样本、在适用时的确定性验证、跨平台执行、取消/清理、路径/资源安全、CJK/RTL 证据、无障碍诊断和明确的损失报告。
