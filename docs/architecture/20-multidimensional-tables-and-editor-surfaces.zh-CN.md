# 多维表格和编辑器界面

多维表格是一个拥有类型化、同质记录存储的受管节点。它不同于 Query：一条记录具有表格本地 UUID，不是受管节点，不能获得节点文档/目录，并且只能通过显式类型化关系字段参与。

## 持久边界

表格节点保留规范 `X/X.adoc` 源文本，以及用于 schema、视图、记录、墓碑的封闭 Profile 伴随文件/存储。大型记录分片存储在表格所属的封闭存储中，而不是巨型 JSON 数组或数据库文件中。表格 Core 负责验证、清单、派生索引、记录身份、事务、备份、回收站和恢复。CSV 和导出文件是互操作输出，绝不是记录权威。

Schema 字段和视图定义有版本、类型和范围。共享视图只能存储已接受的表格视图配置；个人呈现状态保持本地。公式、关系、汇总、排序、筛选、分组和显示字段经由 Core 派生，不能泄漏未授权的节点引用、值、计数或诊断。

## 编辑器和操作界面

编辑器使用**数据**作为 Query 和多维表格功能的总括上下文界面。它公开源特定操作，绝不把网格缓冲、渲染单元格或浏览器状态变为存储权威。记录创建/编辑/删除/恢复、批量粘贴/填充、导入、关系改动和视图改动均使用类型化、修订绑定的 Core 计划，并具有预览、草稿门、授权、可恢复提交和回执。

## 原生表格升级

从原生 AsciiDoc 表格提升必须显式、经过预览且具事务性。它冻结源表格/范围/修订、schema 推断证据、生成的记录 ID、目标文件、源文本处置、批注后果和回滚步骤。不支持或歧义源仍保持源文本和诊断证据；提升绝不悄然替换它。得到的多维表格仍是一个节点，不会把其记录提升为节点。
