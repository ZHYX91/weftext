# 文档历史、比较和备份仓库

Chrono、时间线视图、版本历史、事务日志、草稿和回收站彼此不同。工作区只包含当前可移植权威。版本历史和备份保留在工作区外，因此保存不会创建同步的隐藏历史或导致工作区无限增长。

## 历史层级

**近期历史**是一个有边界的设备本地、内容寻址的已验证规范文档提交存储。它记录精确的提交前/结果源对象和封闭条目证据，明确标为仅本设备，并可禁用/清除。工作区提交成功而历史捕获失败时，提交仍然成功并报告可见缺口；它绝不重试文档写入。

**备份仓库**是一个用户配置的本地、网络、Server 托管或显式受支持远程目标，包含不可变的完整工作区快照 manifest 和去重对象。没有已配置的目标，就没有正式备份。回收站和近期历史都不是备份。

## 仓库和执行边界

一个仓库具有一个显式工作区谱系和一个单一写执行器，除非受支持后端串行化条件写入/租约。凭据保留在 OS/Server 运营存储，绝不在工作区或仓库 manifest 中。仓库使用封闭版本化 manifest、不可变且不覆盖的对象、完整物理清单、已验证发布、受保护恢复点、可恢复保留策略和基于可达性的垃圾回收；派生目录数据库可重建。

完整快照包括受管文档/资源/批注、表格和模板权威、可见非受管和被忽略的物理字节、完整回收站、根控制文件、空目录和恢复相关权威。托管备份在一个一致性点协调不相交的 Server 控制平面。

## 比较、合并和恢复

版本历史是设备、备份、Server 和受保护点条目的、按权限过滤的派生并集，每项都显示来源。节点 UUID 在重命名/移动时保持历史连续。Core 比较独立于 Git，并且理解精确源代码/AsciiDoc。它比较经授权的不可变修订/摘要，区分结构/资源/批注差异，绝不规范化源代码或猜测三方共同基准。

比较是只读的。应用更改或恢复文档内容使用修订绑定的 Core 合并/恢复计划，该计划绑定目标修订、输入摘要、选定处置、提议源代码、诊断、授权和草稿门，然后以新事件一次提交。完整节点/子树/工作区恢复使用备份试运行、不覆盖和恢复计划。历史内容在显式经授权的历史操作之前，从常规搜索、Query、链接、图谱、Chrono、任务和智能体上下文中排除。
