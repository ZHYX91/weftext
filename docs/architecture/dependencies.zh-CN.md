# 当前依赖政策

文缕固定其解析后的 Rust 和 JavaScript 依赖图。已发布依赖必须满足工作区 Rust 基线和受支持平台要求，出现在通知和 SBOM 中，并通过许可证、安全、体积、离线和更新/回滚审查。没有任何依赖会成为 Core 持久性或事务权威。

## Core 与源文本边界

存储/事务支持库仅提供序列化、哈希、UUID、暂存和文件系统对象证据。Core 拥有格式标记、规则、名称、身份、修订、狭窄精确源补丁、日志、恢复和清单。原始文件系统身份绝不序列化。

系统元数据使用狭窄、会安全拒绝的 `weftext` 元数据封装读取器/写入器；YAML 解析器只能支持范围受限的读取分析，绝不能处理通用顶层 YAML 或整体 frontmatter 重序列化。`weftext-asciidoc` crate 和固定版本解析 crate 提供精确源文本建模、安全派生渲染、诊断、出现项和语法编辑；它们没有工作区遍历、Server、UI、导入或无限制处理器权威。安全模式比较渲染器不是规范权威。

## 界面和服务边界

Markdown 库仍是导入/导出或仓库工具依赖。导入/OCR、办公和电子书组件位于工作进程之后。Query 时区验证离线且确定；它绝不读取主机时区、环境、文件系统 zoneinfo、网络或环境时钟。引用呈现仅公开允许列表中的样式/语言环境，不接受调用方提供的路径、URL、插件、处理器、工作区句柄或网络客户端。

桌面 UI 依赖提供打包 UI 渲染和由系统中介的文件夹选择，而不是原始文件系统访问。编辑器依赖仅是精确缓冲区界面；语义范围和编辑来自 Core。Server HTTP/运行时/数据库/加密依赖支持服务操作；其数据库仅对账户、会话、ACL、审计和协调拥有权威，绝不对可移植工作区或 Query 拥有权威。精确解析版本位于 lockfile；发布通知和 SBOM 从已打包工件生成。
