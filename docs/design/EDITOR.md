# A new-project design for Typst editing, reading, titles and Word

Status: **design-refinement-not-implemented**. Independent acceptance of the fixed earlier baseline remains historical; current refinements and evidence limits are recorded in [REVIEW](REVIEW.md) §8.

[SOURCE](SOURCE.md) owns source/type/origin interpretation, [CORE](CORE.md) identity/basis/authorization/unified transactions, and [FEATURES](FEATURES.md) links/Query/templates/conversion. Current outcome requirements come from [REQUIREMENTS](../REQUIREMENTS.md). These new owners coordinate with this proposal; prior-round mechanisms are not normative dependencies.

## 1. Choices and product commitments

Official Typst syntax is the sole body source. Ordinary writing, continuous reading, source editing, paged preview and field editing share one document session. DOM or a separate rich-document JSON never replaces `.typ`. Preserve complex legal source. A locally irreversible construct gets a clear source entry and official layout preview; it is never flattened or discarded. Ordinary documents must support writing and flowing reading.

The revised candidate uses the official Rust parser/compiler, the official HTML target's finally consumed tree, and bounded style/role adaptation plus origin qualification. The official Paged target supplies pagination and printing. Reading and printing use explicit different native targets; deriving flow from the same Paged result is not a user requirement. Official HTML remains experimental. This work validates a controlled integration, without claiming stock HTML or a product reader is ready; see §8 and REVIEW for acceptance scope.

Core remains the sole owner of structure, identity, authorization, commit and recovery. This document consumes authorized SourceSnapshot, ReadBasis, unified Plan/Journal/Receipt and Job abstractions without redefining their persistent formats. A Core change requires coordination of actual consumption here, beyond renaming an interface.

## 2. One session and one current editing basis

Authorized `readEntity(ref,current,purpose)` / `readScope(scope,purpose,completeness)` return identity, exact original bytes and ReadBasis. The latter includes actual revision, observer incarnation, object generation, schema/auth and the operation's actual dependencies. Equal bytes do not imply equal qualification. A session holds Base and ReadBasis, mutable Draft bytes, monotonic draftSerial, selection, input generation and one DraftUndo. Local edit basis is `(session, owner, ReadBasis, draftSerial, exact Draft bytes, Environment)`; a digest is a convenient check, not a substitute for exact bytes or fresh authorization.

Successful local source, rich and field-panel operations change the same Draft, advance serial and enter the same undo stack. A batch paste, format command, table operation, field change, IME composition or run-in toggle is one visible undo unit. Mode changes, layout, reads and compilation are not undo units. Undo/Redo obtain a new serial and map, without reviving old write addresses. Another document in a split pane has its own session; returning restores the original draft and position.

Source changes remain proposals. Save passes the complete proposed source to Core `prepare(operationId,intent,draftBase,budget)`, inspects the actual plan and calls `commit(operationId,planHandle)`. Unknown results retain the draft and use `operationStatus(operationId)`, never a guessed retry with a new ID. Repreparing changed content after a terminal conflict creates a new operation linked to the original Draft. External changes and sync use observeExternal/admitExternal/merge; the editor exposes conflicts and retains both drafts. A changed current revision never silently replaces a local Draft.

Commit success decides only that operation. After a fresh authorized read of after, Base may advance; continuing user input prevents after from replacing Draft. Only exact Draft/after equality makes it clean. Undo of committed content is a new transaction, allowed only when current revision and bytes still equal one's own after, authorization is fresh and the inverse excludes another author's change, control changes and multiple-entity effects. Otherwise preserve the draft and show the conflict. Core recovery protects crash drafts; these are neither saved bodies nor cross-device permissions.

A synchronous paint checks exact projection/source/map once and consumes that snapshot; event handlers and asynchronous proposals still recheck actual qualification when executed. Large-source UTF-8/UTF-16 positions are derived once per source operation. Literal grouping narrows candidates by native origin, then restores actual consumption order to prove unique coverage; duplicate, reordered or invalid ranges remain read-only. CodeMirror retains a derived string only for its current immutable document object and rebuilds it when that object changes, without another author source or revival of an old serial.

Source character count is derived from the current immutable CodeMirror document, inspecting actual edits and adjacent UTF-16 units to handle split/joined surrogate pairs without expanding the entire source into a character array. A source surface containing lines above 32 Ki UTF-16 units, and native preview nodes containing long text, disable optional kerning; other documents and nodes keep their presentation. Complete text, wrapping, selection/copy, source mappings and the same Undo remain. This presentation policy changes neither author source nor export targets and does not replace the actual performance gates in §10.

One hosted personal-recovery codec handles source, actual Base and the original pending-save proposal/request. Large text has an immutable snapshot within the original deployment/actor/generation/resource scope. Every edit synchronously commits exact UTF-16 differences and complete recovery metadata, without a deferred-persistence window. Prepare all snapshots before atomically replacing current metadata; if another holder in this tab updated the record, reject the retained writer and preserve the newer recovery; quota/write failure retains the preceding complete record and prevents unreliable save/switch operations. All reads decode through one entry. Missing snapshots, cross-resource references or invalid ranges retain the record and refuse another body. Logout/revocation clear memory and the text/metadata caches. These references serve browser recovery only, without Core-origin or write authority.

Hosted personal input is a separate deployment/actor-scoped projection, using the shared bounded UTF-16 text codec and recovery UI. It retains only evidenced author insertions, numeric Base positions/digests, exact original save IDs and typed producer owners; protected Base/source, Schema, preview and credentials are excluded. Successful Save confirms the exact submitted atom checkpoint outside CM Undo, without adding an undo item, discarding later input or reinterpreting an old history snapshot under a new Base. Atom identities survive splitting and real Undo/Redo; equal bytes after ABA are not equal provenance. Pending saves retain both old and submitted numeric projections until that original operation is freshly verified. Committed native input already included in the submitted state remains copy-only; a newer producer revision stays active. Restoring an exact Base preserves this distinction. Unmapped protected restoration or uncertain native changes reject automatic replay while keeping proved new text copyable.

Before enabling a new hosted body author producer, obtain its stable reference from the same authorized session and revalidate the original document, actor and epoch. The old editor remains editable while waiting; changed input invalidates stale navigation. Each personal-input record keeps its complete first-captured owner; a same-node alias changes only runtime routing. Save separately freezes the actual resource route of its original operation, without rebinding it to a new alias or current target. Before converting personal-input format v3 to v4, preserve the complete original metadata, UTF-16 text and commit. Only an actual request or receipt with the same original operation ID can establish an old save route. Missing evidence retains an explicit unknown route and original ID, without guessed queries, settle or resubmission; personal text remains viewable/copyable. Preserve terminal status rather than making a completed operation unresolved again. Archive, verification or CAS failure retains the preceding complete record.

Native author controls opt in with their actual body, FieldId/ValuePath, annotation/media, library role or registry target and a disposable binding generation. Search, filters, diagnostic text and temporary Query run parameters do not register. Initial/programmatically restored values are protected; only observed payload and exact edit evidence grant ownership. Clipboard/file/network continuations capture the original lease before awaiting and revalidate it before changing a control or retaining text. Retargets, structural edits, actor/epoch changes and unfinished IME controls retire the old lease; late composition terminal events cannot become another target's first input. Hosted notes use this same store, while Core CaptureDraft requires its own explicit owner sink and cannot fall back to a body. Session storage remains tab-local and is not a Core durability or native-close receipt.

Recovery can explicitly create an independent editable personal copy from a canonical current text record. The new record uses the same v4 recovery domain, its own ID, the complete original owner and a fixed copy-only slot; it has no Base, candidate or pending operation and leaves the original record and operation unchanged. Only that exact acknowledged copy cut can mint an opaque initial-text proof for its dedicated owner sink. This narrow proof seeds the complete personal text, including an empty copy, without turning protected programmatic values into author input or marking an untouched durable copy unapplied. The inline editor remains mounted during recovery-list refresh; its sink retains proved personal text rather than raw control values. Both UI and direct host consumers reject author Restore for a canonical copy-only record.

Finish explicitly accepts the current personal-copy cut: freeze its producer, wait for its Browser ACK, recheck the record sequence, audience, epoch, credential and mount identity, then acknowledge only that producer. Ordinary transport ACK never applies the original note or settles its operation. Failed retain, quota, pending native/clipboard input and stale authorization retain RAM input and the existing close barrier. An explicitly reopened RAM copy retries storage before receiving a seed. Account retirement clears its editor and preserves unresolved producer proof; the whole-surface close guard still includes retired producers from another current account. Active copies cannot be removed through either row deletion or an older producer's discard action.

### 2.1 Shared implementation boundaries for five views

Expose REQUIREMENTS §5.4's V01 Source, V02 rendered with syntax, V03 syntax on demand, V04 syntax-hidden UI editing and V05 Read. They share session, Draft, serial, selection and DraftUndo; view choice is personal UI state. Successful V01–V04 edits update the same buffer. V05 disables body-edit command routing while independent annotations retain their own authorization. Continuous/paged layout and target selection are separate and do not replace a view.

V01 uses the exact source buffer with official-parser highlighting. V02 still draws the complete source buffer in source order, retaining every author-syntax character and exact selection positions while styling recognized headings, emphasis, lists and similar constructs. Markers are separate, always-visible decorations. Compiled semantic styling binds current serial/origins; invalid source remains editable with parser styling and explicit unavailable-preview status. Never deserialize HTML or reconstruct Typst markers to build V02. Generated results may have an explicit auxiliary preview but cannot replace, duplicate as body content or remove their author expression.

When input invalidates syntax results, immediately retire their current semantic eligibility. Unedited regions may temporarily retain only the previous drawing appearance and heading spacing, explicitly labelled “Styles updating · Previous appearance retained”, so unrelated headings do not repeatedly resize and move the input line. This appearance grants no syntax classification, navigation, annotation range or writer, and hides no author characters. Installing current official-parser results still requires exact source, edit-generation and display-eligibility-generation checks. During IME composition, queue new styling proposals and revalidate after composition ends without delaying or taking over input. Retiring a session, source or authorization, or explicitly clearing styling, immediately clears retained appearance and queued proposals; returning to identical source bytes does not revive an old generation.

Rendered portions of V03/V04/V05 consume §8's same current final projection. V03 reveals a linked source editor at an active construct with §3's unique-origin proof and directly edits the same Draft's exact range; revealing syntax changes no source. Keyboard commands and touch controls enter/leave explicitly. Generated, multi-origin or included occurrences without a local writer stay read-only with real-source navigation; matching strings cannot select origins. Failed/pending projections retain Draft and expose explicit V01/V02 entry, never showing stale output as currently writable.

V04 uses the same writer qualification and §4 named operations, without syntax markers or automatic switching to V03 on focus. Specialized controls handle supported constructs; otherwise retain occurrences read-only and let users explicitly switch to a syntax-visible view. Hidden syntax does not imply arbitrary inverse editing. V05 selections support reading/copying/annotations; typing or pasting cannot activate body editing.

Switching first completes or retains IME under §5, then transfers selection through current source/projection associations. Without a unique display position, retain the original source selection and restore the closest proven container/reading position rather than change the source point to fake a mapping. Entering V05 in a session defaults to an explicitly labelled preview of the current Draft. Committed content requires explicit selection and cannot replace an unsaved Draft. Returning to editing resumes the same DraftUndo. Personal view preferences do not modify author source. V02/V03 syntax decorations are excluded from body Query, logical copying, visible annotation excerpts and export; explicit source copying still returns authorized original bytes.

### 2.2 Ordinary files and the input prototype

RQ26 sessions use Core §2.1 FileBasis instead of the EntityRef/Base entry, reusing Draft/Undo, five views, selection, official compilation and local editing algorithms. Lack of NodeId does not prevent body editing. Show dependency root, save location and ordinary-file identity. Do not add application declarations or another library's style, fabricate a stable Node address or node-owned annotations for this ordinary file, or automatically grant library Query. Existing complete Node links in its body may resolve under independent authorization for the target library. Save As does not silently change the original target; switch Base only after success and reopening the destination, preserving subsequent input.

The first real input prototype must prove final native occurrence → exact source range → local edit → recompilation, not fixture-supplied maps. Let official AST drive immediate source-buffer editing and structural commands; the final consumed tree supplies actual display/reading, and rich editing joins them only where the association is proved. Compilation must not block IME and older serial results cannot replace newer drafts. AST-driven input creates no second author model and does not remove V03/V04 origin requirements.

Initial cases include empty documents, Chinese input, emphasis, links, ordinary tables, five-view switching, selection, undo/redo, late projections and save/recovery; negative cases include wrappers, repeated includes, show rewrites and invalid intermediate drafts. Report only measured prototype scope; unimplemented paths or synthetic composition events do not count as real OS IME/product acceptance.

### 2.3 Body Query across the five views

A query definition or invocation in the body remains part of the same native `.typ` source. The five views change presentation and editing entry points around one definition, one session Draft and one DraftUndo. Results are derived presentation: they cannot replace source, impersonate a definition or grant source-write authority. [FEATURES §5.5](FEATURES.md#55-query-embedded-in-the-body) owns Query definitions, execution and result states; this section specifies body interaction.

| View | Query source, results and definition editing |
| --- | --- |
| V01 Source | Edit the exact query source directly; results may open in a separately identified preview. |
| V02 Rendered with syntax | Keep the complete query source visible at all times while showing its corresponding results. Results do not replace the expression or hide syntax, comments or author bytes. |
| V03 Syntax on demand | Show results by default. An explicit keyboard command or touch control expands the query's corresponding source editor, which edits the same Draft's exact range. Expanding or collapsing changes no source. |
| V04 Syntax-hidden UI editing | Show results by default and edit the definition through a query builder. Explicit Edit source opens a separate source-editing surface or switches to a source-visible view, sharing the same Draft/Undo. Focusing results or the builder does not reveal syntax automatically. |
| V05 Read | Results are read-only, with no query-definition editing entry point or writes such as field changes, task checking or row dragging. Reading, selection, copying and authorized navigation remain available. |

Input in a separate Edit source window is an unapplied edit proposal: Cancel changes no shared Draft. Confirm revalidates the opening serial and exact target before writing only the same Draft/Undo; concurrent changes produce a conflict that retains both inputs without overwriting either. This creates no second persistent query definition or Draft authority. Switching to V01/V02 instead edits the same Draft directly under existing rules, without modal cancellation semantics.

The source editor and builder locate their target through the current official AST, exact byte range and proven definition/invocation association, never result text, row order or DOM position. Definition edits in V01–V04 enter the shared source buffer; each named builder change is one Draft operation and one Undo. Change only the proven target, preserving outside bytes and native conditions the builder cannot safely express. If a native query cannot round-trip through the builder, retain its source and a read-only explanation with an explicit source entry. In V04 that entry is separate from the body surface with hidden syntax; V05 provides no editing entry point. Included, generated or repeated query occurrences without a unique local writer cannot select an arbitrary occurrence for writeback. Editable views may offer explicit authorized navigation to the actual source owner.

Switching views changes no query source, saves no note and creates no second definition, result-cache authority or undo stack. Refresh follows existing Query execution, invalidation and permission rules. After a definition's Draft serial, exact source basis or invocation parameters change, earlier results must say Corresponds to an earlier definition/Source basis expired; data-result partial, stale, error and unavailable states remain distinct. Late results cannot overwrite newer definitions, selections or control input, and old results cannot revive a source writer. Existing authorized row operations and definition edits requalify different targets. Row operations in V01–V04 retain FEATURES' current-qualification limits; embedded results in V05 remain entirely read-only.

This belongs to v0.2 five-view editing and v0.3 Query and is connected in the current local v0.5 candidate. Official AST ranges identify complete declarations; final compiled metadata tags associate actual body occurrences, while full source remains the editing authority. V03 reveals the exact range in the shared editor. V04 builder/source proposals contribute one undoable edit to the same Draft. V05 has no definition-edit or result-write entry. Included, generated or repeated occurrences lacking a unique local source have explicit read-only limits instead of guessed writers; unexecutable occurrences report unavailable. Actual interaction acceptance uses [ROADMAP IQV01–07](../ROADMAP.md); real OS IME, complete assistive technology and other platforms require separate validation.

### 2.4 Annotation selection within cells, lists and equations

Implements REQUIREMENTS §5.7.1 and FEATURES §9.9. Annotation targeting and executable text-edit eligibility are separate: an exact valid source range can hold discussion without granting equation, table-structure or generated-output writes. Reuse the same Draft, selection provenance and Core saved revision. V05 body read-only mode does not revoke independently authorized annotations.

One whole character, consecutive characters within a cell and list-item body text retain exact ranges; crossing bold/italic runs does not widen to a whole cell/item. Exact UTF-16/UTF-8/grapheme conversion preserves Chinese, non-BMP and combining sequences. Do not include unselected numbering, container boundaries or neighboring cells. Cross-cell/item selection requires proved continuous same-source ranges and complete conversion coverage; disjoint ranges are not concatenated. Explicitly save and revalidate before commit; failure/stale projections retain annotation input.

Identical, contained and crossing comment ranges retain independent identities. Overlapping markers expose every authorized discussion rather than only the top layer or inferred reply grouping. Reply, resolve and reattach act on each selected annotation; layout changes do not change targets. Explicit whole-cell/item/equation selection remains distinguishable from selected characters.

Whole-equation selection uses supported native constructs and current provenance. Fine symbol/subexpression selection needs a unique real math-structure/source association. Repeated x symbols cannot be located by text search, and numerator/denominator bounds cannot be guessed from screen rectangles. Unproved fine selection is unavailable with retained input and explicit whole-element/source-range choices; export cannot hide scope widening. Five-view changes retain the original range and explain missing display mappings rather than selecting nearby characters.

After Word import, selection uses the converter's new source basis. Export preview separates selected objects, actual mapped ranges and degradation. Rendered hit testing, JSON creation or a displayed equation alone does not establish annotation round-trip acceptance; AW01–10 in ROADMAP cover both directions.

### 2.9 Workspace and task ribbon

Document tabs and command tabs are separate. A compact document bar shows actual open notes and save state. File, Home, Insert, Knowledge, Review and View organize existing actions below it, with only the selected category's labelled groups visible; the ribbon can collapse to enlarge the writing canvas. Home contains text and Undo/Redo, Insert contains structures, equations and note/numbering controls, Knowledge contains properties, links and queries, Review contains annotations/proofreading, and View contains the five modes, preview and sidebars. Language and infrequent configuration live under File/settings rather than another permanent tool row. File paths remain available as descriptions without changing actual open targets.

The center holds editing, reading and preview for open documents. The left sidebar provides independent Files, Nodes, Outline, Timeline and Search views. Files follows actual directories; Nodes follows node relationships and contents, with separate child-node, album and ordinary-file sections rather than a panel above the file tree. Outline follows the current document, distinguishes native headings from proved figure/table/equation/code captions, and offers heading structure and numbering entries. Timeline lists actual note versions, retaining the existing history operation for comparison and restore. Search reuses authorized queries; moving its container grants no additional reads. Node browsing explicitly follows the current document or pins a browsing location; opening a body never silently changes a pinned scope.

The independent local Outline consumes the same native compile/render artifact already accepted by the current body session, binding the complete session/source/serial/inputId/path/root basis and exact native keys/ranges. Mounting, hiding or revealing it performs no whole-library knowledge scan. Pending body input immediately disables old jumps; an accepted new projection restores them automatically. Outline can update independently while body preview is closed, and the local right inspector no longer duplicates it. The hosted outline retains its separate implementation; this does not claim migration to the same layout.

Each Knowledge panel retains at most one actual read and the latest queued demand. Document, native-input or library-environment changes immediately retire old demands. The actual read keeps its slot until it really settles; only the last demand still admitted by the current context may then run. Each caller independently receives completion, its original error or retirement. Retiring a strict readback cannot count as success or clear its original operation. Repeated Draft acknowledgements for equal source input do not add scans; an explicit refresh after completion reads again. Stopping a wait, hiding a view or retiring its result does not cancel work already accepted by Core.

Each invocation owns its temporary read snapshots through the final physical/source checks and accepted Core consumers, then releases them on success, failure or retirement. Qualification batches the complete original records and absence evidence within that invocation while preserving final enumeration and physical checks. These facts cannot become authorization cached across invocations, and releasing temporary tokens cannot destroy independent witnesses or prepared-plan evidence.

The right sidebar hosts properties, annotations, period navigation and extension views on demand. Calendar presents the current library's existing day/week/month/quarter/year navigation; People and similar extensions retain separate container positions, without implying complete business implementations. Each view identifies its actual library, document or object scope. Both sidebars support vertical groups with tabs inside each group. Dragging a view title to a group edge splits/reorders it, dropping in the center merges it into the tab group, and views may move between sides. Separators resize group heights. Equivalent layout menus and keyboard actions offer collapse, hide, maximize, restore and reset, storing validated personal layout per library. Dragging a view title changes layout only; content-object dragging retains its own structural operation rather than sharing an ambiguous write gesture.

One owner per library holds period navigation; Query only opens that sidebar instead of retaining another period form. Series and allowed period kinds come from the current authorized schema. Date selection and Today ask Core's installed calendar for the exact period, without frontend ISO-week calculations or path-based identities. Exact-key and date lookup are mutually exclusive. Results show actual bounds, coverage and existing notes; browsing, resolving and selecting never implicitly create. Explicit creation retains original-operation identity, uniqueness, partial-scope and close guards. This navigation does not establish a monthly state grid, heatmaps, ICS or a complete multi-calendar interface.

A healthy child-node name opens its exact admitted main note, while a separate action browses its contents; menus bind the same source.
