# Typst 编辑、阅读、标题与 Word 的新项目方案

状态：**design-refinement-not-implemented**；固定旧基线的独立接受保持为历史事实，当前修订及证据限制见 [REVIEW](REVIEW.zh-CN.md) §8。

[SOURCE](SOURCE.zh-CN.md) 拥有作者源与类型/来源解释，[CORE](CORE.zh-CN.md) 拥有身份、依据、授权与统一事务，[FEATURES](FEATURES.zh-CN.md) 拥有链接、Query、模板及转换。当前结果要求来自 [REQUIREMENTS](../REQUIREMENTS.zh-CN.md)，这些 owner 的新候选与本文一起协调，前轮技术不成为新的规范依赖。

## 1. 选择与产品承诺

选择官方 Typst 语法作为唯一正文源。普通写作、连续阅读、源码编辑、分页预览和属性编辑共享一个文档会话。编辑器不以 DOM 或自行定义的富文档 JSON 替代 `.typ`。合法复杂源保全；局部不可逆构造在该处提供明确源码入口和官方版式预览，不拉平、不删除，也不把普通文档全部退为源码与 PDF。

新的候选路线为：官方 Rust parser/compiler → 官方 HTML target 的最终消费树 → 有界样式/角色适配及来源资格；官方 Paged target 承担分页与打印。阅读和打印是明确的不同原生 target，不把“必须从同一 Paged 结果重建流式树”当用户需求。官方 HTML 尚属实验功能，当前工作是验证受控集成的可行性，不宣称 stock HTML 或产品阅读器已经就绪；验收范围见§8及 REVIEW。

Core 继续唯一拥有结构、身份、读写授权、提交与恢复。本文只消费 Core 的获权源快照、ReadBasis、统一 Plan/Journal/Receipt 与 Job 抽象，不重新定义它们的持久格式。Core 对象变化必须协调本文的实际消费，不能只修接口名字。

## 2. 一个会话、一个当前编辑依据

获权 `readEntity(ref,current,purpose)` / `readScope(scope,purpose,completeness)` 返回对象身份、完整原源 bytes 和 ReadBasis。ReadBasis 包含真实版本、观察者 incarnation、文件 generation、schema/auth 与该操作实际依赖；相同 bytes 不意味着同一读写依据。编辑会话持有：Base 快照及 ReadBasis、可变 Draft bytes、单调 draftSerial、当前 selection、input generation 和一份 DraftUndo。编辑器局部 basis 为 `(session, owner, ReadBasis, draftSerial, exact Draft bytes, Environment)`；digest 只便于检查，不替代 exact bytes 或新鲜权限。

源码、富编辑、属性面板的成功本地操作都改变同一 Draft、递增 serial、加入同一撤销栈。一个批量粘贴、一次格式命令、一次表格操作、一次属性变更、一个 IME 组合、一次同行切换各为一个可见撤销单元；模式切换、布局、读取与编译不是撤销单元。Undo/Redo 得到新的 serial 和新地图；不复活旧写地址。并排另一篇笔记有另一份会话，返回恢复原稿和位置。

源修改产物始终是提案。保存向 Core `prepare(operationId,intent,draftBase,budget)` 交完整拟议源，消费实际计划检查后 `commit(operationId,planHandle)`；结果未知时保留稿件并查 `operationStatus(operationId)`。不换操作 ID 猜重试；终态冲突后新拟议内容重新准备是关联原 Draft 的新操作。外部修改/同步使用 Core 的 observeExternal/admitExternal/merge；编辑器显示当前冲突并保双方稿。当前版本变化不默默覆盖本地 Draft。

提交成功只更新该操作的决议。重新获权读取 after 之后更新 Base；用户已继续键入时 Draft 不被 after 替换，只有 Draft 与 after 精确相等才 clean。已提交撤销是新事务：仅在当前版本及 bytes 仍精确等于自己的 after、仍获权且反转不包含他人/控制/多实体效果时反转自己的源变化。否则给出冲突和保留稿，不误撤他人。崩溃恢复稿由 Core 的恢复能力保护，明确不是已保存正文或跨设备权限。

同一同步绘制先核一次准确投影／源码／地图，再消费本次快照；事件处理及异步提案仍在执行时重新核对实际资格。大源码的 UTF-8／UTF-16 对应按本次源一次建立字节位置，文字归组先按原生来源缩小候选，再恢复真实消费顺序核唯一覆盖；重复、乱序或无效范围仍只读。CodeMirror 只为当前不可变文档对象保留派生字符串，文档对象改变即重建；不另存作者源或复活旧序号。

源码字符数是当前 CodeMirror 不可变文档的派生状态，只检查实际修改及两端 UTF-16 相邻单元，正确处理拆开／合并的代理对，不把整篇源码展开为字符数组。含超过 32 Ki UTF-16 单元行的源码区及含超长文字的原生预览节点关闭可选字偶距计算，其他文档与节点保持原排版；完整文本、自动折行、选择复制、来源映射和同一 Undo 不变。此呈现策略不修改作者源或导出目标，也不替代第 10 节的实际性能门。

托管端的个人恢复缓存由同一编码入口处理源码、实际 Base 和未决保存的原始提案／请求。大文本在原 deployment／actor／generation／resource 范围内只写一次不可变快照，每次输入同步提交相对快照的精确 UTF-16 差异和完整恢复元数据，不增加延迟持久化窗口。先准备全部快照，再原子替换当前元数据；元数据已由同标签页的另一持有者更新时拒绝旧持有者写入，保留更新后的恢复记录；配额或写入失败保留上一完整记录并阻止不可靠的保存／切换。读取入口统一解码，快照缺失、跨资源或无效范围时保留原记录并拒绝采用另一份正文。退出及撤权清除内存和对应文本／元数据缓存；这些引用只供浏览器恢复，不是 Core 来源定位或写入资格。

托管纯输入另处于本 deployment／actor 恢复域，复用同一有预算的 UTF-16 文本编码和恢复界面。它只保有证据的本人插入文字、数字 Base 位置／摘要、准确原保存编号和实际 producer owner；排除保护 Base／完整源码、Schema、预览和凭据。Save 成功在 CM Undo 之外确认准确 submitted 原子检查点，不新增撤销项、不丢等待期间的新字，也不把旧历史快照换基线解释。原子身份随拆分与真实 Undo/Redo 保留；ABA 同字节不等于同来源。未决保存保留旧基线及准确提交基线两个数字投影，直到按同一原号重新核实结果。已包含在准确提交中的原生纯输入只供复制，新 producer revision 继续活动；重新恢复准确 Base 后仍保持这个区分。保护文字恢复到无映射位置或原生变更来源不明时，拒绝自动重放，仍保已证新字可复制。

托管正文启用新的作者输入 producer 前，先从同一获权会话备齐稳定引用并重验原文档、账号和代次；等待期间原编辑器仍可输入，输入变化使过时切换失效。每个个人输入 record 的完整 owner 固定为首次采集来源，同节点别名只改变运行路由。保存另外冻结原 operation 的实际资源路由，不能随别名或当前目标重绑。个人输入格式 v3 转 v4 前先完整保留原 metadata、UTF-16 文字和 commit；只有同原编号的实际请求或回执能证明旧保存路由，缺证保留明确的未知路由及原编号，禁止猜测查询、settle 或重新提交，仍可查看／复制本人文字。保留原终结状态；未知路由不能把已结束操作重新变成未决。迁移的归档、校验或 CAS 失败保留原完整记录。

原生作者控件显式注册其实际正文、FieldId／ValuePath、批注／媒体、库角色或注册目标及可退休的绑定代次。搜索、筛选、诊断文字和临时 Query 运行参数不注册。初值、程序恢复值都是保护基线，只有观测到的输入 payload 与准确编辑证据才授予本人来源。剪贴板／文件／网络续接在 await 前捕获原 lease，写控件或留字前再核验；改目标、结构编辑、账号／代次变化和未落定 IME 控件使旧 lease 退休，迟到组合终止事件不能冒新目标的首次输入。托管注释共用这一恢复域；Core CaptureDraft 必须使用其明确 owner sink，不能回退借正文。sessionStorage 只属本标签页，不是 Core 持久性或原生关闭回执。

恢复界面可从当前规范化 text record 显式建立独立可编辑的本人副本。新 record 留在同一 v4 恢复域，具有自己的编号、完整原 owner 和固定 copy-only slot；不含 Base、candidate 或 pending operation，原记录与原操作不变。只有该副本准确且已获 Browser ACK 的 cut 能生成不透明初值证明，交给其专用 owner sink。这个窄证明种入完整本人文字，包括空副本，不把受保护程序赋值变成本人输入，也不把未编辑的可靠副本标成未应用。内联编辑器在恢复列表刷新时保留原 DOM，sink 只保有证的本人文字，不采 raw 控件值。界面与宿主直接调用都按当前规范化记录拒绝把 copy-only 副本恢复为作者正文。

“完成副本编辑”明确接纳当前本人副本 cut：冻结其 producer，等待该 cut 的 Browser ACK，重验记录序号、audience、代次、凭据和挂载身份后，只确认该 producer。普通运输 ACK 不应用原注释，也不核定原操作。保留失败、配额、未落定原生／剪贴板输入和失效授权继续保留 RAM 输入及原关闭障碍；显式重开 RAM 副本会先重试存储，再取得初值证明。账号退休清除其编辑 DOM，仍保留未决 producer 证明；整面关闭门继续包含另一当前账号下的旧退休 producer。活动副本不能经单行删除或旧 producer 的放弃入口移除。

### 2.1 五档视图的共享实现边界

按 REQUIREMENTS §5.4 提供 V01 纯源码、V02 渲染且显示语法、V03 按需显示语法、V04 隐藏语法的界面编辑、V05 阅读。它们共享会话、Draft、serial、selection 和 DraftUndo，视图仅是个人界面状态。V01–V04 的成功操作写同一 buffer；V05 禁用正文编辑命令路由，独立批注按自身权限执行。连续/分页是独立布局与 target 选择，不替代其中一档。

V01 使用准确 source buffer 与官方 parser 的高亮。V02 仍按完整 source buffer/顺序绘制，保每个作者语法字符及准确选择位置，为已识别标题、强调、列表等应用可辨认样式，语法标记独立装饰且始终可见。编译语义样式须绑定当前 serial/来源；无效源仍可按 parser 显示并明确预览未就绪。不从 HTML 反序列化或重造 Typst 标记来拼 V02；生成结果可作明确辅助预览，不能替代、重复计入或删除作者表达式。

输入使语法结果过期时，立即撤销旧结果的当前语义资格；未编辑区域可暂存仅用于绘制的上一版外观和标题间距，并明确显示“样式更新中 · 暂存上次外观”，避免无关标题反复缩放造成输入行跳动。暂存外观不提供语法分类、导航、批注范围或 writer，不隐藏任何作者字符；当前官方 parser 结果仍须通过准确 source、编辑代次和显示资格代次核对后替换。输入法组合期间仅暂存新样式提案，组合结束后重验再安装，不延迟或接管输入。会话／来源／权限退休或明确清除时立即清空暂存外观和待装提案；源码回到相同字节不复活旧代次。

V03/V04/V05 的渲染部分消费§8同一当前最终投影。V03 在§3已证明唯一来源的活动构造处显示关联源码编辑区，直接编辑同一 Draft 的准确范围；显示语法本身不改源。键盘命令和触屏按钮可显式进入/退出。生成、多源或 include 出现项没有本篇 writer 时保只读并提供真实来源导航，不用相同字符串猜源。投影失败/待定时保 Draft，给明确 V01/V02 入口，不把旧画面当当前可写。

V04 使用相同写资格和§4具名操作，文档区不显示源码标记，也不因聚焦自动退为 V03。特殊构造由明确专用控件处理；缺控件则保留只读出现项，让用户主动切换可显示语法的视图，不能把隐藏语法解释成任意逆向编辑。V05 选区用于阅读/复制/批注，键入和粘贴不得开启正文写入。

切换先按§5完成或保留 IME，再依当前源/投影关联转移选区；无唯一显示位置时保原源选区、恢复最近可证明容器/阅读位置，不改变源点来假装映射成功。同会话进入 V05 默认显示明确标记的当前 Draft 预览；用户显式选择已提交版本才另看它，不能替换未保存稿。返回编辑继续原 DraftUndo。个人视图偏好不写作者源；V02/V03 语法装饰不进入正文 Query、逻辑复制、批注可见摘录或导出，显式复制源码仍返回获权原字节。

### 2.2 普通文件与输入原型

RQ26 的普通文件会话由 Core §2.1 提供 FileBasis，替代本节的 EntityRef/Base 入口，复用同一 Draft/Undo、五档、选区、官方编译与局部编辑算法。无 NodeId 不阻止正文编辑；依赖根、保存位置和普通文件身份可见。不自动添加应用声明、不套另一库的样式；不为该普通文件伪造自身的稳定 Node 地址或 node-owned 批注，也不自动授予库 Query。正文已有的完整 Node 链接可按目标库的独立授权解析。另存不偷改会话原目标；成功并重新打开目标后才切换 Base，后续输入仍保留。

首个真实输入原型必须证明最终 native 出现项→准确原源范围→局部修改→重新编译，而非预置测试映射。先让官方 AST 驱动源 buffer 的即时编辑与结构命令；最终消费树承担真实显示/阅读，只有证明关联的区域才连接富编辑。编译不阻塞 IME，旧 serial 的结果不能覆盖新稿。选择 AST 驱动输入不产生第二作者模型，也不取消 V03/V04 的来源资格要求。

首批验证包含空文档、中文输入、强调、链接、普通表格、五档切换、选区、撤销/重做、迟到投影与保存恢复；同时放入 wrapper、重复 include、show 重写和无效中间稿作为负例。有限原型按实测范围报告，不将未实现路径或模拟 composition 事件冒充真实 OS IME/产品验收。

### 2.3 正文内嵌 Query 的五档交互

正文中的查询定义或调用表达式仍属于同一份原生 `.typ` 源。五档围绕同一定义、同一会话 Draft 和 DraftUndo 调整显示与编辑入口；结果是派生呈现，不能替代源、冒充定义或授予源写权。Query 的定义、执行及结果状态由 [FEATURES §5.5](FEATURES.zh-CN.md#55-正文内嵌-query) 拥有，本节只规定正文交互。

| 档位 | 查询源码、结果与定义编辑入口 |
| --- | --- |
| V01 纯源码 | 直接编辑准确查询源码；结果可另开明确标识的预览。 |
| V02 渲染且显示语法 | 完整查询源码始终可见，同时展示对应结果；不以结果替换查询表达式，不隐藏其中的语法、注释或作者字节。 |
| V03 按需显示语法 | 默认展示结果；用户通过键盘命令或触屏控件主动展开该查询对应的源码编辑区，直接修改同一 Draft 的准确范围。展开或收起不改源。 |
| V04 隐藏语法的界面编辑 | 默认展示结果，用查询构建器修改定义。用户明确选择“编辑源码”时，打开独立源码编辑界面或切至源码可见档，仍编辑同一 Draft/Undo；聚焦结果或构建器不自动暴露语法。 |
| V05 阅读 | 结果只读，不提供查询定义编辑入口，也不提供改字段、勾选任务或拖移结果行等写操作；保阅读、选择、复制及获权导航。 |

独立“编辑源码”窗口的输入是尚未应用的编辑提案，取消不改共享 Draft；确认须基于打开时的 serial 和准确目标重验后，仅写同一 Draft/Undo，并发修改冲突保双方输入、不覆盖。这不是第二份持久查询定义或草稿权威；切至 V01/V02 则直接按既有同 Draft 规则编辑，没有模态取消语义。

源码编辑区与构建器必须由当前官方 AST、准确字节范围和可证明的定义/调用关联定位，不能按结果文字、行序或 DOM 位置猜源。V01–V04 的定义修改进入共享源 buffer，一次具名构建器修改为一个 Draft 操作和一个 Undo；只做已证明目标内的修改，保外部字节与不能安全表达的原生条件。构建器遇到无法往返的原生查询时保留源及只读说明，提供用户明确选择的源码入口；V04 的该入口独立于隐藏语法的正文区，V05 不提供编辑入口。include、生成或多次显示的查询没有唯一本篇 writer 时不任选一个出现项回写；可编辑档只给已获权真实 owner 的明确源码导航。

切档不改查询源、不保存笔记，也不创建另一份查询定义、结果缓存权威或撤销栈。刷新遵循既有 Query 的执行、失效与权限规则。定义的 Draft serial、准确来源依据或调用参数发生变化后，先前结果必须明示“对应旧定义/来源依据已过期”；数据结果的 partial、stale、错误或不可用状态分别保留。迟到结果不得覆盖新定义、选区或控件输入，旧结果不得恢复源 writer。结果行已有获权操作与定义编辑按不同目标重新验证；V01–V04 的行操作仍受 FEATURES 的当前资格限制，V05 的正文内嵌结果整体只读。

本项归属 v0.2 五档编辑与 v0.3 Query，接入当前 v0.5 本地候选。官方 AST 定位完整声明，最终编译 metadata 标记关联正文实际出现位置；完整源码仍是唯一编辑依据。V03 展開共享编辑器的准确范围，V04 构建器和独立源码提案仅向同一 Draft 提交一次可撤销修改；V05 无定义编辑或结果写回入口。include、生成或重复出现而缺乏唯一当地来源的内容显示只读限制，不猜选 writer；无法执行的出现项明确不可用。实际交互验收统一见 [ROADMAP IQV01–07](../ROADMAP.zh-CN.md)，真实 OS IME、完整辅助技术及其他平台仍须分别验证。

### 2.4 单元格、列表与公式的批注选区

承接 REQUIREMENTS §5.7.1 与 FEATURES §9.9。批注选区与可执行文字修改资格分别判断；源码中的合法准确范围可以承载讨论，不因此获得改写公式、表格结构或生成结果的能力。继续复用同一 Draft、选区来源及 Core 已保存源版本，V05 的正文只读不取消独立批注权限。

单元格内一个完整字符、连续多个字符及列表项正文必须保精确范围；跨粗斜体 run 不自动扩大为整格／整项。通过 UTF-16、UTF-8 与 grapheme 的准确换算保中文、非 BMP 和组合字符。选区未包括自动编号、容器边界或邻格时不能附带进去；跨格／跨项只有在同源连续范围和完整转换覆盖均可证明时成立，不连续范围不拼接。提交前明确保存原稿并重新核验选区，失败或旧投影保批注输入。

同范围、多范围相互包含或交叉的多条批注保独立身份；点击重叠标记时提供全部获权讨论入口，不仅显示最上层，也不按坐标合并为回复。每条回复、解决或重附分别操作；布局变化不修改目标。对“整个单元格／列表项／公式”提供明确元素选择，与“当前几个字符”分开显示。

公式在支持的原生构造及当前来源映射上提供整体选择；符号／子式细选须有实际数学结构到源的唯一对应，重复的 x 不按字面搜索定位，分子分母不按屏幕矩形猜源。无证据的细选明确 unavailable，保草稿并提供用户主动选择整体或源码范围的入口；不能把扩大范围隐藏在导出流程里。跨五档切换保原范围，无法映射到显示位置时说明，而不是另选邻近字符。

Word 导入后的选择只使用转换器产生的新源依据，导出预览分别显示选中对象、实际映射范围及退化项。不得把渲染命中、仅创建 JSON 成功或公式成功显示当作往返批注已验收；正反向 AW01–10 见 ROADMAP。

### 2.5 原生文献引用与交叉引用控件

统一“插入引用”入口先搜索获权笔记／论文，再选择普通链接或正式文献引用；候选显示真实类型及该操作的资格，缺出版数据时给具体原因和普通链接选项，不把普通笔记强行变成 Work。链接文字与文献引用 form／style 分开：前者初始取用户输入或已获权当前标题并保存为文字，后者由原生引用语义控制，不把 supplement 当别名。补全只生成现有原生语法，不增加 `@标题` 自动寻址规则。

承接 REQUIREMENTS §5.10 与 FEATURES §10.1.1。插入文献先获权选择稳定 Work，再选择 form、supplement 和适用样式；候选标题不充当身份。已有绑定可复用，新绑定与正文原生引用合为一个 Draft/Undo 操作；取消不改源，确认重验打开时的 serial、选区、目标与权限。保存仍由同一 Core Plan 处理，不额外保存手工可改 Bib。修改引用形式只改已证明的对应参数，保 key、Work 及其他作者字节；继承 set 规则的值与本次显式覆盖分别显示，不能为改一个引用而改全篇样式。

交叉引用选择器只列当前编译已证明的对象及真实类型，表格编号按其原生 figure/table 组织解释；区分有合法唯一 label 可直接引用、需显式添加 label、不可可靠定位。为可写唯一对象新增 label 与插入 ref/link 是同一可撤销编辑；不按标题文字生成身份，不自动重命名已有冲突标签。页码引用注明对应 Paged 输出，流式阅读无可靠页码时明确不可用。动态／include／生成对象可获权导航，但没有唯一作者槽就不给本篇回写按钮。

V01/V02 保准确原生源；V03 可主动展开所选引用；V04 提供引用形式、定位补充、样式及目标选择控件，复杂表达式不能安全往返时保源并给显式源码入口；V05 仅阅读、复制及获权导航。不能将表达式静默改为 literal，也不把“无法编辑”当“无法排版”。零可见文字的 bibliography-only 引用可从引用面板或源码定位，不用虚构的正文标记改变输出。关系分类及出现次数按 FEATURES 消费同次有效结果，过期导航重验且保用户输入；CR01–16 验证同稿、撤销、身份、范围与输出。

普通链接的获权悬浮提示可显示最新标题，正文显示文字保持作者值；“更新为当前标题”只改所选唯一可写 occurrence 的显示文字，一个 Undo，保目标及片段。复杂 content／生成链接没有唯一可写槽时保源并给源码入口。引用键建议、复用及重命名依 FEATURES §10.1.1；重命名前展示真实作用范围和不能安全改写项，不提供假完整的一键改名。复制菜单按 FEATURES §3.2 区分三种目标形式；片段不可用时先说明，只有用户明确选择才执行“仅打开笔记”，所有导航继续保护当前 Draft。

### 2.6 脚注、尾注、题注与编号编辑

承接 REQUIREMENTS §5.11 与 FEATURES §10.1.2。插入／编辑脚注或文末尾注只改同一 Draft 的原生调用与准确内容槽，编号是派生显示。注释面板显示类型、实际序号、内容及所有获权引用位置；重复引用选既有对象，删除某一标记与删除注释正文分开处理，最后引用被移除时明确展示影响。删除定义所在标记但仍有其它引用时，必须在同一操作中保留／可靠迁移原正文及目标，无法证明则拒绝并保输入，不能留下悬空引用。脚注／尾注类别转换只在支持的原生映射成立时作为显式操作预览，不因阅读布局自动转换类型。

题注控件分别选择图／表／公式对象、类别、编号设置及题注内容；公式“本体编号”和“描述性题注”独立，引用选择器明确显示目标和编号来源。已有合法 figure 包装只改准确 caption／numbering 槽；新增包装、必要 label 与题注共同成为一个可撤销修改，不同时另存题注 JSON。改变显示样式不写死编号，局部修改不改其它对象或全篇 set 规则；不能按渲染文字反推题注与对象关系。

这些操作继续遵守 §2.5 的 V01–V05、serial／权限、取消与同稿撤销规则。流式视图可用注释面板或明确文末区域展示内容，Paged 显示实际脚注位置；两者保同一原生类型和源。脚注标记、注释正文、题注文字及对象本体各有来源范围，生成编号不能当作者可写字符；无唯一 writer 的函数／include／show 结果保源并说明只读。Word 导入配对预览的选择必须随完整创建 Plan 提交，迟到结果和失败保用户输入。NC01–10 同时验证键盘、触屏可达入口及回跳，真实辅助技术按平台另验。

### 2.7 日常入口与普通节点组合体验

REQUIREMENTS §5.15 的 v0.6.3 入口复用本章会话。命令搜索、插入菜单、上下文菜单和快捷键指向相同动作；普通段落、标题、列表、图片及 Query 的转换／移动仅在完整来源与结构边界可证明时开放。菜单可解释当前限制，输入法组合期间不截走斜杠、Enter 或方向键。快捷打开和前进／返回保各笔记 Draft、选区与可恢复位置；后台预览不抢正文焦点。

可选根节点预设由初始化流程创建普通作者内容。生成后用 §2.3 的同一内嵌 Query 控件增删、编辑、重排及复用定义，没有特殊工作台编辑器或隐藏布局副本。每个出现项独立显示结果／运行／过期状态；普通编辑、撤销、保存和模板复制保持一致。空白与预设路径都须可发现，后续重开或升级不会重置用户调整。个人显示偏好与节点正文的共享修改分开，阅读档仍整体只读。

2026-10-19 第一阶段实现：`EditorMap.bodyBlocks` 是官方根语法树对普通段落、标题和列表项产生的准确临时范围，不是持久块身份。转换／相邻移动重算当前 hash、范围、原生绑定、级别规则与空段边界；标签、嵌套／生成内容和规则／注释屏障保源拒绝。菜单与搜索共用动作，地图过期时先核当前源码；返回保留每篇实际编辑器及选区，不用整篇替换伪造 Undo。具体预算和当前切片见 MVP。

2026-10-19 第二阶段实现（`0.6.3-alpha.2`）：内嵌 Query 通过原生控件编辑筛选／排序／投影／分组，独立个人视图不写作者源；共享调用显示 owner／current／pinned／参数，只改调用方。相邻 Query 重排保完整原 carrier 及范围外字节，注释／正文屏障拒绝；移除须确认且不级联删除结果。两者沿当前 source hash／serial／授权 recheck 和同一 Draft／Undo。属性表单保留无效原输入并绑定原 FieldId／形状与打开时会话，组合期延迟替换；异步响应不能改新笔记。简单 call 和 group 可用构建器，复杂高级计划回到准确源码，不覆盖原条件。范围与保留限制见 MVP。

### 2.8 操作入口、焦点与取消的统一规则

2026-10-16 的交互细化属于待实现设计，参照版本及证据等级见 REQUIREMENTS §5.15.2。常用动作同时提供可发现的控件、上下文菜单和可搜索命令；悬停可以补充说明，不能成为唯一入口。鼠标悬停或键盘焦点进入对象时呈现同组操作，粗指针使用明确的更多按钮。菜单打开期间保持原对象和选区，关闭后返回触发控件；对象已消失则回到最近仍有效的容器，不跳到同名对象。只读或暂不可用的动作说明原因和可行下一步，不能点后无反应。

先处理当前最内层：Esc 关闭候选／菜单并回焦点；未应用的模态提案可取消且不改 Draft；已进入共享 Draft 的文字通过 Undo 撤销，Esc 不静默清掉整段输入。运行中的任务使用明确的取消按钮，不把关闭窗口假报成后台工作已取消。组合输入期间不解释导航、命令或快捷键；弹层不越出所属窗口，搜索结果刷新不替换活动输入框或抢走光标。触屏、键盘、缩放及屏幕阅读器所需的文本标签和状态从同一动作定义产生，实际平台验收仍按 v0.7。

Query 出现项的工具条区分“编辑查询”“视图”“刷新”“更多”；更多中区分移除本次调用与打开／编辑共享定义。直接定义修改写当前节点 Draft；共享定义显示实际归属，只有明确打开归属笔记并取得写资格才修改。筛选、排序、分组、字段及视图使用可见控件，条件显示为可逐项移除的项；列表呈现偏好与作者查询参数的作用范围分别标示。刷新按钮只更新该出现项的结果，不保存正文；更改定义后旧结果标过期。运行、完整空结果、筛选无匹配、缺字段、失败、部分结果分别有状态和相应操作，重试保留输入。删除调用不默认删除定义，拖动区块只改该节点中的顺序；根节点预设也使用这些控件。

### 2.9 工作区与任务功能区

文档标签与命令选项卡分开：顶部紧凑文档栏显示真实打开的笔记及保存状态；其下以“文件、开始、插入、资料、审阅、视图”组织既有动作，只显示当前类别的命名分组，可收起功能区以扩大写作画布。开始承载文字及撤销／重做，插入承载结构、公式及注释编号，资料承载属性、链接与查询，审阅承载批注／校对，视图承载五档、预览与侧栏。语言及低频配置位于文件／设置，不再永久占用独立工具横排。文件路径保留可到达的说明，不因布局变化改实际打开目标。

中间区域承载打开文档的编辑、阅读和预览；左侧栏以“文件、节点、大纲、时间线、搜索”提供独立视图。文件视图按实际目录浏览；节点视图按节点关系及其内容浏览，独立呈现子节点、相册与普通文件，不再嵌在文件树上方。大纲跟随当前文档，区分原生标题和图／表／公式／代码等有证题注，并提供标题结构图及编号入口；时间线列出当前笔记的实际版本，比较与恢复仍进入原历史操作流程。搜索复用获权查询，不能因换容器增加可读范围。节点浏览明确“跟随当前文档”或“固定浏览位置”，打开正文不暗中改变固定范围。

本机独立大纲直接消费当前正文会话已接受的同次原生编译／渲染产物，绑定 session、source、serial、inputId、path、root 的完整依据及准确原生 key／range。挂载、隐藏和重新显示大纲不触发全库知识扫描；正文输入等待新投影时立即停用旧跳转，新投影获接纳后自动恢复。关闭正文预览仍可独立更新大纲；右侧检查器不再重复承载本机大纲。托管端原大纲仍沿其独立实现，不据此宣称已经迁移到同一布局。

每个知识面板最多保留一个实际读取和最后一个待执行需求。文档、原生输入或库环境变化立即退休旧需求；旧读取真正结束前仍占用读取槽位，之后只执行仍获当前上下文接纳的最后需求。各调用独立得到完成、原错误或退休结果，严格回读退休不能冒充成功并清掉原操作。相同源输入的重复 Draft 确认不增加扫描；一次读取结束后，明确刷新重新读取。停止等待、隐藏或退休界面结果不等于取消 Core 已接受的工作。

临时只读快照由本次调用持有，覆盖最终物理／来源复核及已接纳的 Core 消费任务，随后在成功、错误或退休收尾中释放。资格记录在同次调用内批量读取完整原始事实及缺失证据，并保留末次枚举和物理检查；不能把这些事实跨调用缓存为授权，释放临时令牌也不能销毁独立 witness 或已准备计划的证据。

右侧栏按需承载属性、批注、周期导航及扩展视图。日历承载当前库既有的日／周／月／季／年周期导航；人员等扩展仍保留独立容器位置，容器不等于完整业务功能已实现。每个视图都标明实际库、文档或对象范围。两侧栏均可纵向分区，一个分区内可有多个选项卡。拖动视图标题到分区边缘可拆分／排序，拖到中间可并入选项卡，也可移到另一侧；分隔条调节分区高度。提供同一组布局菜单及键盘操作，可折叠、隐藏、最大化、恢复和重置，按库保存经过校验的个人布局。拖动视图标题只改布局，拖动内容对象仍遵循对应结构动作，二者不共用含混的写入手势。

周期导航由每库单一 owner 持有，Query 只提供打开该侧栏的入口，不再维护另一份周期表单。系列和允许的周期类型来自当前获权 schema；选日与今日交给 Core 已安装历法计算准确周期，不在前端猜 ISO 周或用路径推断身份。准确 key 与 date 查询互斥，结果显示实际日期范围、完整性及已有笔记；浏览、解析和选择均不隐式新建。显式创建沿用原操作号、唯一性、部分范围与关闭守卫。该导航不冒充月格批量状态、热图、ICS 或完整多历法日历界面。

节点内容的健康子节点名称打开获接纳的准确主笔记，浏览内容另有明确按钮；菜单使用同一准确来源。只有获接纳的规范主文件才可合并隐藏，冲突、重复或未接纳的同名源仍可见。标题搜索以 Enter／Shift+Enter 遍历命中，组合输入不触发；列表与导图定位同一原生 key，标题卡显示原生编号与真实直接子标题数，分支折叠不改正文或被搜索过滤的真实计数。画布的 100% 以实际 CSS 像素为准，标题首开与搜索定位保持可读比例，全图缩小由明确的“适应视口”选择；侧栏隐藏、重显和调整大小不无故重置镜头，真正退役时释放尺寸观察及回调。

属性呈现偏好仅改变本地字段位置、名称排序和可见性，提供置顶、默认、沉底、隐藏、显示隐藏和恢复默认；必填、无效、包含未绑定成员或有未应用输入的字段仍可发现。多值首末及指定位置移动复用原生单字段有序编辑，保留重复值、未知成员和一次 Undo；无效输入不得被重排悄悄丢弃。诊断列表只消费当前获权投影，提供排序、来源目录分组及每页至多 100 项的遍历；个人预期标记仅在本次确认为孤立时形成“预期孤立”，不能掩盖仍有连接或范围不完整。

原生列表值提供独立拖动把手、实际目标位置线及原有首末／指定位置的键盘等效入口，不拖动整个属性字段。拖动只改变同一列表的成员顺序，保重复值及未知成员，沿所在表单原有的变更／应用流程进入草稿，不暗中保存文件。无效原始输入或 IME 组合时阻止重排；Esc、在有效列表外松开、来源值改变、表单冻结／隐藏或 DOM 退休取消手势并释放捕获与监听，不将旧目标套到新列表。通用控件只说明列表顺序变化，具体草稿和保存状态由所在表单显示。

本机值预设从字段按钮打开独立的个人对话框；命名、预设值和个人 IME 不进入 DataPanel 作者控件、raw 采样或共享 Schema。配置以真实库身份、FieldId、成员／项槽和完整 Schema semanticDigest 隔离；同范围关闭重开保未保存名称、typed 值和无效 raw，record 的添加／移除／置空按钮不能丢弃其他成员的无效 raw／IME；坏存储或写入失败保输入。预设写／删只在支持的同源同 key 锁内重读、比较原 token 和核回读，缺锁只读／采用，不宣称浏览器存储天然 CAS 或对外部手改原子。对话框从打开至关闭持续参与关闭等待。保存／删除只核个人配置资格，采用才重验当前作者输入、字段对象／revision、binding、raw、IME、权限及冻结状态。动作明确为替换一个标量或向列表追加一项，只形成该字段的 staged 表单变化；可在同一对话框连续追加，关闭后仍须原“应用到草稿”。真实来源／Schema 退休保个人输入、停用旧动作，普通同来源刷新不虚造新作者。 属性投影绑定 inputId、source、serial、base 及实际 owner 等稳定作者 cut；同一 cut 的异步 Draft ACK token 更新不构成新作者输入，也不授写权，真实输入、Schema 或所需权限变化仍使相应旧读取／动作退休。

源读取与编辑建议共用 `SourceInputBasis`，明确只复制 inputId、sessionId、source、serial、baseId、path、root、workspaceId、nodeId；属性投影、跨字段移动和资源正文插入按这九项认定同一作者输入，Query 的任务字段建议也核实际库／节点。重复 Draft ACK 不改变该身份，同字节新输入或 Undo／Redo 仍由 inputId／serial 阻止旧结果复活。属性 Apply 与 Query 在发出源转换请求前、等待返回后及交付宿主前核当前输入和所需编辑资格；最终作者写入仍由真实宿主与 Core 核权。提醒设备设置保留独立的已保存／dirty 条件，同时核 inputId；原设置操作的未知结果仍可按原编号查询／重试。这个窄接口不含 inputRevision 或保存／关闭证明，完整 `DocumentBasis`、原保存与查询定义保存请求继续持有其真正所需的 ACK；不能把源身份当成保存、关闭保留、授权或原操作完成的证明。

跨字段列表移动使用本篇当前完整源和 Schema 的两个现存字段，不借展示分组或相同文本认项。界面选择源／目标 FieldId、连续起止序号和目标插入位置，最终联合验证后只交付一个源补丁及一个共享 Undo；不暗中应用其他字段或丢弃其提案。当前文档存在任何未应用／无效 raw／类型／Schema 提案、组合输入或只读状态时停用，其他文档的保留稿仍属原 owner。请求、补丁交付及最终回读共同参与关闭等待；补丁已改源但 Draft ACK 失败时按实际当前源刷新，不能重用旧序号再移一次。

本机多文件资源对话框把资源提交与正文安全末端追加分别呈现：选择顺序和原操作身份贯穿预览、确认与恢复，已提交不重新导入。个人 locator 的写／删以同 key 短锁串行支持的同源 producer，锁内核原字符串及回读，网络／hash／应用在锁外等待，随后重验本阶段 owner 路由，正文追加另核完整源依据；缺锁不启动新 prepare 或改记录，仍可查询原操作。正文插入的来源读取／交付依据绑定 source、inputId、serial、base、session、path／root 及实际 owner 的稳定作者 cut；同一 cut 的重复 Draft ACK 更新不构成新输入或写权，真正输入、owner 或所需权限变化仍拒绝旧交付。 追加只消费原操作已确认的稳定引用，并重验当前文档；auto 仅为扩展名匹配且通过检查的 PNG／JPEG 生成 `format: auto`，其他文件为稳定链接。无安全正文末端则保资源及明确继续入口，不猜文件末尾；正文应用／ACK 不确定不自动重放。一次 Undo 撤正文追加而不删已提交资源，磁盘正文仍沿原保存流程。Hosted 的本批入口只导入获准资源集合，不联合正文或跨字段写入。

校对结果按 200 条增量显示，来源／规则排序和加载更多保留已有控件、焦点与滚动，明确总数、已显示与已选数。显式选择当前显示的可定位问题，单次生成批注仍最多 200 项，不静默拆成多笔作者写入。扫描状态与报告入口接入现有任务／结果；过期依据不启用旧来源操作，退休不冒充取消 Core 工作，例行完成不抢写作焦点。

底部是可收起的“问题、任务、结果”工作面板，另保留紧凑状态栏。问题消费实际编译／资源／引用诊断，并在有准确依据时定位来源；任务反映真实导入、导出、识别、同步等原操作的进度、失败和待处理状态；结果只展示已经生成的实际产物及可用的打开／预览入口。详细比较和恢复可进入独立的大视图，不在底栏另建操作事实。例行更新只更新计数与状态，不自动展开或抢走写作焦点。

功能区、侧栏分区和底栏的切换、移动及收起只改变呈现，不重建编辑器、不改变选区、Draft、Undo 或提案 owner；每个视图保留自己的筛选、展开和滚动状态，组合输入期间不执行冲突的布局手势。隐藏面板继续参加关闭与恢复检查。托管检查器用外层呈现槽切换，不覆盖原控制器表达授权／不可用的隐藏状态。窄屏或收起的侧栏退出焦点顺序及可访问性树，恢复时保有明确入口；保可读字号，二维内容在自身区域滚动。源码和组件检查不替代新候选的实际窗口、IME、键盘、读屏及安装验收。

文件树以目录坐标决定层级，以原文件坐标打开笔记。合并展示的 `X/X.typ` 以 `X` 作为树位置；折叠只隐藏严格后代，父节点始终保留，搜索和浏览范围不因此改写身份。每行至多一个独立可聚焦的展开按钮，只有实际投影子项才显示；名称打开对象，更多菜单和浏览范围按钮分别表达动作。此处的布局合同与真实客户端验收分开，键盘、系统 IME、读屏和受影响任务仍按 WORKFLOW 核验。

## 3. 可写区域的实际产生方式

当前完整官方 AST 与精确源字节产生 revision scoped 编辑地图。每个可写区域须证明：当前 root 的唯一构造/内容槽、准确 UTF-8 半开范围、标准绑定未被重绑定、当前 show/set 作用域、显示与源的可逆对应、操作允许改动的完整范围。Span、AST 路径、label、数组位置、相同文字、渲染坐标都不单独授写。官方 AST 给范围与语法，数据流和求值观察给对应与依赖；两者都不能省。

| 来源 | 阅读与查询 | 当前富编辑 |
| --- | --- | --- |
| 本篇唯一 literal 或适配过的标准 construct | 显示官方实际结果 | 证明成立的文字槽或具名结构命令可写 |
| 变量、函数、loop、show 生成内容 | 保实际出现项、真实来源与含义 | 无默认写地址；明确“编辑来源” |
| include/import 的内容 | 另行获权来源后呈现 | 本篇只读；打开该来源建立新会话 |
| 同一源重复输出或多来源拼接 | 每个实际出现项可读 | 无唯一逆映射则只读，不任选一个来源 |
| 不透明或缺可靠阅读顺序的布局 | 有界版式岛及准确状态 | 源码入口；不根据图中文字反写 |

依赖闭包按区域计算；旁边有 macro 不取消独立普通段落。全局自定义 show 真正影响全部正文且无法证明时，可以整篇 rich-readonly，但须解释实际原因、保 Draft 和 Source 路径；基本文档出现这种结果仍是基本能力失败。生成标题保真实 level 及查询出现项，无写地址不等于标题不存在。

空文档、只有控制数据/注释的文档和删除最后一段后，官方 AST 仍须产生正文 sibling 插入边界；空 list item/content slot 产生该槽的零宽插入点。注释、label、metadata 或表达式里的空白不冒正文插入点。Core/共享 Rust adapter 重算当前边界与能力；过期点整次拒绝，不能因 byte offset 一样继续。字节、UTF-16、scalar、grapheme、视觉 stop 显式换算，CRLF、combining 和 ZWJ 不拆。不同宿主使用同一版本化 Unicode 实现并跑对应矩阵，不继承旧文档写下但未证明的版本号。

## 4. 最低编辑矩阵与保源算法

所有富操作以具名 intent 输入共享 Rust 适配器，返回完整新 Draft 与可证明的新选区。只做目标范围内最小 splice，保范围外每个 byte；保注释、空白、EOL、作者函数和参数写法。不用 innerHTML 反序列化，也不 whole-file pretty-print。

| 必须交付的操作 | 默认原生表示与边界 |
| --- | --- |
| 任意普通文本位置输入/删、Enter、合并、删空再输入 | 当前正文槽；文字按 native literal codec 转义，不把 `#`/`=`/`-` 粘贴成代码或结构 |
| 粗/斜/删除线与跨格式文字选区 | 标准 strong/emph/strike；同段 inline tree split/merge，未选 leaves 与 trivia 原样保留 |
| 文档 title、副标题、section heading 与改级 | §6 的角色和唯一源值；实际 level 为正整数，控件常用 1–9，更多深度有数字入口 |
| inline/display 公式创建与修改 | 原生 math 源局部编辑器及官方预览；可视公式是 atom，不把 glyph 逆推源；定界符逃逸不能附加代码 |
| bullet/enum/terms 的创建、拆并项、缩进 | 原生 list 构造；空正文可创建实际空项继续键入，裸 marker 不冒成功 |
| 链接插入、地址转换 | 消费链接 owner 的 encoder/resolver；源写与目标读分别验证，保文字、fragment 与同一目标 |
| 普通网格 cell、增删行列、行重排、矩形 TSV | 仅官方可证明固定 columns、显式 cells、无 span 的完整简单网格；失败整次不改 |
| header/span/block cell 的局部内容 | 保完整拓扑；唯一源槽可单格改，复杂拓扑命令进入 Source/高级入口 |
| Source 编辑任意合法 Typst | exact source，不受控件矩阵限制；不同有效性与保存结果分别说明 |

格式跨界、跨普通段落/列表的删除和 plain paste 使用覆盖完整范围的结构命令，一次撤销。跨 heading、title、table、code、math 或 generated island 的写选区缺具名算法时拒绝该操作并给准确 Source 选区；阅读复制仍可用。Copy Text 按逻辑顺序含明确块分隔；Copy Source Fragment 交获权的准确原始片段，不拼接合成源。Cut 先确认系统剪贴板写成功再改 Draft。默认 paste 只收 text/plain 并编码；无 plain flavor 显示不可用。Source paste 明确处于源码模式。

表格的生成 cells、spread、ragged、span、header/footer、自定义 show 均原样保留，缺控件不变成矩形网格。两个相同 cell 依当前 AST 槽区分，只改用户选中者。行重排只对简单网格证明 comment/trivia 归属：cell 内随 cell，行间 leading trivia 随后行，closing 前尾 trivia 固定；不明归属拒该 reorder。矩形 TSV 显式预览尺寸/扩展，一次完整预算/权限验证，不能部分贴入或拆批绕预算。

每次成功适配须官方完整重解析、证明 intent 的结构和值、范围外 bytes 不变、非目标控制/字段/构造不变、caret 能唯一定位；依赖 active show 的可视操作须重新求值检验，不能 AST 相同就称显示正确。错误岛只允许有完整边界及依赖证明的其它区域富编辑；错误吞后文不能猜安全分区。

### 4.1 v0.6.1 正文表格交互增强

REQUIREMENTS §5.14 是后续待实现范围，不改变上表当前有界能力。先在固定列数、显式单元格的简单网格接连续交互，再扩展有完整来源证明的合并格和表头。正文表格的编辑地图属于当前 source revision；逻辑行列、跨格覆盖和唯一作者槽共同定位，DOM 顺序、屏幕坐标、相同文字或旧 cell 索引不单独授写，不增加持久化表格副本。

- **导航和选择。** 区分格内 caret／文字选区与单格／矩形范围选择；Tab／Shift+Tab 导航逻辑单元格，方向键及 Shift 扩选在单元格选择状态生效，格内方向键仍用于文字编辑。Enter／Esc 的编辑与退出行为按 §4.2 实现并实测，不截获 IME preedit。合并格按逻辑覆盖计算选择，重复文字不混槽；重排、撤销或异步重编译后恢复可证明的目标及可见位置，失效目标不猜测恢复。
- **表内控件和范围操作。** 行列入口提供插入、删除、移动／拖动及可键盘操作的等效命令。范围复制／剪切／TSV 粘贴按逻辑顺序处理，粘贴前展示尺寸和明确扩展选择；跨格覆盖不完整或无法证明兼容的目标整次拒绝。剪切遵守剪贴板先成功规则，结构操作一次验证、一次 Undo，不能通过分批绕过预算或权限。
- **合并、拆分、表头、转置。** 只操作可证明的显式原生构造；预览单元格内容的保留顺序、合并后内容位置、拆分后的内容归属，以及行列格式、表头与跨格拓扑变化。作者文字、公式、链接、批注来源和 trivia 不静默丢失；无法维持准确批注映射时保留讨论并明确未定位。转置不能只交换显示坐标或无条件套换行列参数；动态表达式、生成内容和不明 trivia 归属拒绝该命令并保原稿。
- **同稿与消费者。** 所有命令复用共享 Rust adapter、Draft／Undo、当前权限和原保存操作，遵守 §3–5 的完整重解析、范围外字节保全和迟到结果规则。同步冲突、撤权和 Source 修改使旧选择／预览失效，保可恢复的用户输入；不把渲染快照当作当前编辑依据。

ROADMAP TB01–06 验交互与源保全，并与 AW01–04 的单元格审阅及已有 DOCX 表格支持范围联验。v0.6.1 的键盘／中文／焦点与滚动验收不能仅由命令单测代替；v0.7 再补触屏、RTL 和真实辅助技术的目标平台结果。原有正确性缺陷继续按当前 v0.6 完成门修复。

2026-10-16 的 UX04 补充：提供明确的表格粘贴／复制入口，有界解析剪贴板 HTML 的逻辑单元格、rowspan／colspan 和可支持文字结构；不执行脚本或自动读取外部资源。预览目标、拓扑、扩展及损失，再提交一次同 Draft 变更。HTML、TSV、CSV 输出声明合并结构与格式的真实保留能力；平面格式的展开／空格策略明确，不冒无损。无法安全转换时保剪贴板输入和原表，提示其它可选格式，不静默截断、丢格或改变普通文本粘贴默认语义。源码注释、公式和生成单元格仍按原来源资格处理。

### 4.2 表格操作的默认行为

承接 TB01–06、UX04，以下是 Weftext 的操作约定，不直接复制插件的独立单元格草稿机制。格内文字始终进入 §2 的共享 Draft；“结束编辑”和“保存笔记”是不同动作。

| 场景 | 默认交互与反馈 |
| --- | --- |
| 进入与退出 | 可写单元格单击进入编辑；点击位置与准确原生文字可证明时放置 caret，否则置于格内文字末尾并说明。整格文字替换由明确的全选动作表达，不把普通单击当全选。网格焦点下 Enter／F2 进入当前格。Esc 从文字编辑回到网格选择并保留已输入 Draft；Undo 才撤销文字。只读格仍可选择、复制和查看限制。 |
| 连续输入 | Tab／Shift+Tab 按逻辑顺序移动到下一个／上一个可见格，跳过合并覆盖槽；边界不绕回或丢字。格内 Enter 到下一逻辑行的同列，Shift+Enter 插入换行；末行 Enter 仅在显式表格、完整拓扑及预算允许时追加一行并进入新格，入口提示该行为。不支持追加时保原位置并给新增行命令的限制说明。Tab 到整表边界转到表外可达焦点，不暗中插行。 |
| 选区与清空 | 网格态方向键移动，Shift 扩展矩形；格内方向键保文字编辑。Delete／Backspace 在网格态只清空所选内容，保行列、合并及表头；在文字态遵从文字选区。删除行／列／整表是另有明确名称的命令，显示真实范围。 |
| 行列入口 | 表格边缘新增按钮、行列把手及更多菜单在 hover／focus 时可发现；触屏有等价按钮。把手先选中整行／列，再显示插入、移动、删除、表头等适用动作。拖动显示实际插入线和移动范围；无效目标给原因，Esc 取消。键盘移动提供同一结果，完成后保选择与可见位置。 |
| 合并与转置 | 合并／拆分前显示内容去向，转置入口明确“整张表格”，不暗用局部选择。无损且范围明确的普通操作直接执行并可撤销；需要损失选择、重设格式或扩大范围时才弹出确认。存在未完成组合输入或陈旧来源时保留输入并阻止旧提案。 |
| 三种粘贴目标 | 格内粘贴编辑文字；网格范围粘贴按尺寸／合并兼容性处理；正文插入 HTML 表格是独立目标。尺寸变化需显式选择扩展，不能平铺重复填充、静默追加或把网格粘贴送到隐藏源码。缺读取权限时提示使用系统粘贴或可用替代，不把复制可用当作粘贴可用。 |
| 复制与降级 | 菜单分别提供所选范围、整表及 HTML／TSV／CSV 输出，显示实际范围。剪切先确认剪贴板写成功再清空；不能提供富格式时由用户选择明确的纯文本退化，说明合并与格式损失，取消不改源。自动 HTML 转换沿 §4.1，不将第一行无条件提升为表头。 |
| 源码与恢复 | “编辑此表源码”定位当前准确源；切换视图保持 Draft、选区与滚动。冲突、权限变化或映射失败时保留用户输入及原因，提供已有恢复入口；不能把表格重建解释为用户取消。普通操作不反复要求保存文件或确认对话框。 |

工具栏命令执行时保留已聚焦的原按钮，用忙碌／不可用状态阻止重复执行；复制状态和成功提示保留在原表面。呈现租约只属于仍有效的文字输入、组合输入或依据当前原生快照的未完命令／手势；闲置网格或工具栏焦点不阻挡 Undo／Redo 后准确的新投影。表格快照仅由已证明的原生变换接续，源或代次变化后的新映射不能重新授权旧控件或租约。无新投影的状态通知不重挂表格；真正延迟的新投影只在原会话、源代次、展示与权限依据仍有效且输入租约释放后安装。显式切换或撤权退休旧请求，保留草稿。

连续行列把手可用 Shift 单击或 Shift 方向键扩选，已有组的把手拖动保整组。完整轴选区形成成组插入、删除和移动；新增数量等于所选组数量，移动目标指完成后的组首，删除后至少保留一行和一列。单格或局部矩形的轴命令只针对当前行／列，并显示实际范围。一次轴变换只产生一个准确整表补丁和一次 Undo，不循环提交单行／列；拆开合并格、移动跨越表头分区、无法保留参数／trivia 或依据失效时整次拒绝。拖动展示实际插入线和范围，Esc、来源／选区改变或组合输入取消旧手势。

相同手势的行为必须同时验证短表、长表、空格、合并格、中文组合输入和失效来源。新增行与结构变换是一项可撤销命令，之前的文字编辑保原撤销边界；移动焦点本身不新增 Undo。表格图片导出、转结构化记录及其它未纳入操作不因对标而自动增加。

## 5. 输入与迟到投影

原生输入控件即时显示尚未验证的本地输入，不逐键等待整文编译；共享 source buffer 是唯一 Draft。parser/compile/layout 在 worker。结构变换每个 controller 最多一个在途，冻结旧 basis 与目标，后续输入有序保管。回应仅在对应 serial/generation 仍适用时安装；后继输入存在时，只在可证明可重放的队列上重算，否则保新稿及未应用文字供源码修复。旧响应不得替换新 source、选区、焦点或清 clean；没有“最后返回者获胜”。

IME begin/update 仅 native preedit；composition commit 是一个 Draft 操作与一个 Undo。宿主 final-input 的重复事件去重，cancel 保未提交文字恢复机会。组合中 save/Enter/slash/格式、潜在链接转换、窗口切换和虚拟化不得抢组合 owner 或提前提交；失焦行为按真实宿主验证。active/focused/composing 节点不被回收。权限变化或 adapter 失败保用户新输入的恢复稿，但不再从缓存回显失权原文。

浏览器原生 `historyUndo`／`historyRedo` 与快捷键、写作工具共用同一份 DraftUndo。组合期间或最终 DOM 变更尚未读入时，只接收历史请求并阻止浏览器另行修改正文；待最终输入读入后再执行，不以旧 source 执行撤销而覆盖待提交文字。只有该落定过程完成，才释放等待组合结束的切档／保存动作。来源／权限退休和销毁取消尚未执行的历史请求，不清除已存在的共享历史，也不在新会话补做旧操作。

layoutEpoch 只描述当前几何，不改源 serial。当前草稿语义未验证时明确 pending，旧预览可显式看且标版本，不给 current 编辑/批注目标。语法、类型/应用控制有效性、编译、layout、预算、权限、保存与投影新鲜性分别报告。合法语法但编译失败的正文可在 Core 对当前格式/控制/字段校验通过时保存为有诊断的稿；syntax-invalid 若 Core 尚无正式 checkpoint 能力只进恢复稿，不能虚报普通保存成功。源码导出保准确 bytes，可独立于编译。

## 6. 标题与副标题的唯一含义

文档标题使用官方 title，章节使用官方 heading；无标题合法，文件名/路径/摘要只是 UI 回退，不补作者 title。默认新建带标题笔记用一个 document.title 值和 `#title()` 呈现；属性面板改同一个源值，导出读取同值。直接 `#title[Title]` 是合法原生作者形式：无 document.title 时可把唯一直接 title.body 作为标题来源，不强迫双写；两者显式不同则分别显示“元数据标题/显示标题”，不给无损统一按钮，源码保留。复杂生成 title 可排版与读取实际值，只有能证明唯一源地址时面板可写。重复 title 或混乱 role 是应用诊断，不能据此删除合法 Typst 源。

```typst
#set document(title: [研究设计])
#title()
#block[一项定性与定量研究] <weftext-subtitle>

= 背景 <background>
普通正文。
```

副标题采用原生 block 与唯一 label `<weftext-subtitle>`。应用约定它是唯一文档 title 的附属 frontmatter，独立于 title.body、heading counter、outline、编号与章节级别；不用冒号、字号、位置邻近来猜。面板创建副标题需有唯一标题；删除标题时明确预览同时删除关联副标题或将它保留为普通 block 并移除角色 label，一次操作。无 title 的同名 labelled block 保源并报关联缺失，不自动变章节标题。多个同名 label、非 block 或不可确定关联时不提供副标题 writer。作者可改排版，控件不要求字号/间距参数。template 可复用 document.title/title()/该 block 而不维护另一份业务 title。源码可用标签自行引用副标题，应用不把它当 section ref。

上面是建议采用的轻量应用约定，需要 SOURCE/schema owner 同步；label 只说明角色，不是持久身份或权限。官方说明 title 与一级章节的区别及 frontmatter 应在 title.body 外；本方案在此基础上定义应用副标题关联。[Typst title](https://typst.app/docs/reference/model/title/)

## 7. 同级逐标题混排与完整层级

每个 section heading 保 native heading 身份、真实 level、原 counter、outline 与 label 引用。普通 1–9 控件以外的合法 10+ 可读、可查询、可导航、可保源；深度输入用正整数，不压成 H5/H6/H9。渲染使用 role=heading 与准确 aria-level，不强迫有限 HTML h1–h6 代表完整模型。字号独立于角色。[Typst heading](https://typst.app/docs/reference/model/heading/)

单个 heading 的“单段/接正文”选择写原生 labelled show 规则到作者源，默认选 label；已有唯一作者 label 可复用，没有则产生不冲突的普通 label 并显示在 Source 预览。它只选择这一个 heading，不使用 heading.where(level: N) 强制整级。独立样式是默认规则；同行规则输出原计数器与 heading body 后接普通空格，紧随同一原生首段。无需第二计数器、隐藏 block ID、间距尺寸或共享 presentation sidecar。

```typst
#set heading(numbering: "1.1")
#show <methods>: it => context {
  strong[
    #if it.numbering != none {
      counter(heading).display(it.numbering)
      text(" ")
    }
    #it.body
  ]
  text(" ")
}

== 研究背景 <background>
独立标题的正文。

== 访谈方法 <methods>
同行正文并保留 *作者强调*。

== 问卷方法 <survey>
独立标题的正文。编号引用 @methods。
```

应用 writer 对这项受控 native 规则提供唯一识别和反转。开启先证明 heading 后有可接的普通首段及准确 scope；有空段时预览移除恰该段落边界，有列表/表格/另一个 heading 或不明构造时不吞它，解释并让用户选择合格正文。未知 show、counter reset/自定义 numbering 或模板接管同目标时先保原源，不能覆盖；可证明的原生规则才给控件。关闭只去本规则并恢复必要段落边界，新增 label 保留以免破坏作者引用。两次切换不重复注入规则。保存/同步/恢复携带同一 `.typ` 源，所以跨设备呈现不靠本机状态。

增删/移动/改级保持选中 label 和原生 counter；不写固定数字。outline 用 heading body，不带同行正文；原生编号引用与链接分别处理。无编号 heading 的默认 @ref 不承诺自动可用：有限实验已见官方报错，提供明确 label #link 形式；不暗改作者引用。单段和同行混用统一编号是已执行有限证据；深层、长段落、孤行、非拉丁、分页及交互仍需验收。

### 7.1 编号控制与标题结构体验

REQUIREMENTS §5.15／UX05 在 v0.6.1 增加可发现的编号控制：预览中文／层级方案、起始值、排除及单篇覆盖。**文档编号**修改可证明的原生 numbering／counter／样式槽并进入共享 Draft／Undo，参与引用和输出；**个人辅助显示**仅改变当前用户呈现，不改作者源、原生引用或导出。控件明确两者的作用范围，不把辅助显示的序号当真实引用编号。

已有实体前缀只在有明确识别规则与准确文字范围时提供个人隐藏／避免重复的预览，仍保源和可访问文字；无法确定则不隐藏。批量写入／清理实体编号属于另一个显式源操作，不能从显示开关顺带执行。未知函数、show 或自定义计数规则保源并解释控制范围，不能拿通用方案覆盖它们。题注、脚注／尾注与交叉引用复用 §2.5–2.6；实际输出按 NC01–10 验，不把个人视觉效果计为 Word 编号成功。

v0.6.3 的只读标题结构视图复用同次原生标题与显示关联，保真实层级、折叠、搜索、缩放、子树和回跳；标题、目录节点与业务关系图分别呈现。生成标题无写地址时仍可在有证据的显示位置阅读／导航，不能凭标题文字猜源码。结构图拖动只改变布局，不隐式重排正文。

该视图已接入 0.6.3-rc.1 工作树，保留独立文档根及标题角色／编号；准确主源标题可定位源码，生成标题仅沿同次实际可见渲染节点导航，缺失则明确不可用。当前预算为 5,000 标题。实现与显示组件回归不替代最终候选的实际客户端任务；真实 IME、K 候选原跨档撤销异常及平台辅助技术仍保原验收限制。

#### 7.1.1 编号面板、引用及标题视图的具体流程

编号面板固定显示当前笔记及作用范围，分“个人显示”和“文档编号”两组。个人显示可选择跟随个人默认、此篇显示／隐藏，恢复默认只清除个人覆盖；切换即时预览，不改源。文档编号先显示原生规则的有效值及来源，再选择方案、层级、起始／重启与排除范围；复杂未知规则显示保留状态，不能用空值覆盖。预览列出代表性标题的前后编号与实际影响，只有“应用到文档”进入一次 Draft 修改；取消返回原输入位置。个人显示不改变文档编号预览或导出结果，文档设置不得被伪装为个人偏好。

题注插入从实际图／表／公式对象菜单进入，同一控件也可从插入菜单到达；显示所选对象、题注类别、上下位置与编号来源。引用目标与引用出现项使用可区分的名称／标记，不只靠颜色；悬停和键盘聚焦展示获权的目标信息，点击／Enter 导航并支持返回。复制稳定交叉引用先复用已有稳定标记；需要新增标记时单独展示原生修改并确认，不能因一次普通复制而静默改目标。剪贴板失败不报告复制成功，已经明确应用的标记变更仍可在原稿撤销。

标题结构图从大纲和命令搜索打开；单击选择，双击／Enter 跳转，独立展开按钮只折叠分支。提供整篇／所选子树、层数、搜索命中前后遍历、平移、缩放、100% 与适应视口；搜索不改真实子标题计数，清空后恢复原折叠状态。文档根与同名一级标题分别存在，缺编号时显示真实层级，标题与题注分类可辨。返回笔记后保草稿与位置；结构图拖动不重排正文。v0.6.1 验编号／引用，v0.6.3 验标题结构，键盘和触控入口随切片提供，平台实测沿原排期。

## 8. 原生双目标：最终消费树、样式与来源

Core `compile(sourceSnapshot,environment,target,budget)` 供应固定官方 Rust build、fonts/packages/assets 及已获权只读 World，返回该次 CompileSnapshot。普通连续阅读选择官方 Html，分页预览/PDF/打印选择官方 Paged，不新增作者语言或伪 target。每份产物绑定准确 source、环境、target、依赖及权限；同源不意味着两个 target 有相同正文、计数器或读取集合。切换 target 是新编译，不拿另一份结果替换当前投影或恢复旧写资格。[官方 target](https://typst.app/docs/reference/foundations/target/)

**最终消费是唯一入口。** 从成功编译返回的官方 `HtmlDocument` 根开始，只遍历其实际 `HtmlNode` 子边，按原序给最终出现项分配本投影内的 key。不能遍历所有 evaluate/realization 事件、Tag 原始 body 或 Introspector 元素并假称这些都显示了。尺寸测量后丢弃的 link 不进入 RenderedLink；表格中只显示一次的 cell 不因测量产生多条；同源真正输出两次仍保两次。原生最终节点是阅读结构输入，序列化 HTML 是交付格式，两者都不是新的作者源。

三个产品分域：AuthoredLink 来自可识别作者构造；RenderedLink、正文检索、逻辑复制、可见批注摘录和离线链接 route 来自所选 target 的最终消费投影；heading 产品来自该次最终 native Introspector，保真实 level/label/counter 及其显示对应或无显示状态。show 删除 heading 仍可能保 introspection，不能把它补成可见文字。原生 HTML 的 h2 等标签不能反推业务 heading level；由原元素的真实语义和实际消费关联取得。任意 show 输出只保实际 return，不把入口 strong/heading 的角色强加给返回的普通文字。

**有界原生样式适配。** stock HTML 主要输出语义结构，不能据它成功就声称原生字体、字号、列表 marker 或表格边框已保留。适配器在官方 HTML 元素实际生产点消费已有 effective StyleChain/已求值参数，把具名可表示属性转为受控 CSS/角色/来源旁信息，随所产生的节点进入最终树。不能扫描作者 set 文本重造优先级，不能为样式再执行 show/query/context，不以所有稳定日志做文字匹配回填。基础正文/列表/表格的库默认、note 和局部覆盖须实测；支持表随实现版本发布，未知单位/paint/自定义排版不静默忽略。此适配是内部目标转换，不要求作者写 CSS 或另一套样式配置。[官方 HTML 范围](https://typst.app/docs/reference/html/)

生产适配优先使用官方公开的 `Library.rules` / `NativeRuleMap::replace` 注册接口；文字转换确需内部信息时才保最小 hook。研究 observer、事件日志和 CLI 导出不默认进入产品。固定版本并记录实际修改符号，不预先承诺零 fork，也不把研究补丁整体当作产品后端。

最低 renderer 仍须让普通中英/RTL段落、title/subtitle、heading、strong/emph/strike、列表、raw/code、链接/引用、图像 alt/caption、普通及 header/span 表格连续滚动并随 320px 重排，宽二维内容仅局部横滚。基本公式优先消费官方 MathML，再验证实际 AT；必要原生 frame/SVG 带准确数学或文字替代，不以图片冒无障碍通过。HTML 标签/属性/样式/资源均经安全的 typed 转换；脚本、任意宿主文件/网络和不受控事件处理器不执行，受影响的合法原源保留并明确报告显示限制。只有 Core 获权资源句柄可被 renderer 读取，HTML URL 不能绕过 World/资源交付权限。

**局部排版与 target 边界。** 页面计数、绝对定位、浮动和复杂图不保证与可重排流式布局等价。已明确的原生 `html.frame` 在同次 Html 编译内调用 Paged，其内部 `target()` 实际为 paged；记录这个边界并消费官方返回的 frame，不从另一份整篇 PDF 按坐标截出片段。能够在当前官方调用链中安全形成局部 frame 的内容可显示为带替代的版式岛；没有合法局部替代时明确该段或该文的 Flow 不可用，保 Source 和独立 Paged 预览。不得把一般段落、列表、表格都降成图片或整篇 PDF 来声称满足普通阅读。任意自由排版保源与可用的官方输出，并不等于所有原生效果都有无损重排。

**来源与验证。** 最终节点携带可验证的 native source/construct 关联时，再与§3当前官方 AST、唯一作者槽和实际 show 作用域证明结合，产生富编辑能力。只有 span、相同字串、DOM位置或一次出现仍不够。计算字符串、多次输出、动态替换和 include 均保实际出现项，缺唯一逆映射只给来源入口；不从 PDF/截图反推源。透明库 entry 中的真实 note 与普通用户 include 区分，不能因宿主 wrapper 存在而取消所有普通正文编辑，也不能扩大 imported source 写权。

旧 [11 例观察实验](probes/semantic-bridge/README.zh-CN.md) 仍证明其有限无副作用/缓存重放事实，但独立 measure/table 反例已否定“稳定事件合集就是阅读树”。后续 final PDF consumer 改善了选择，却仍缺可靠的布局前段落分隔关联，因此本候选撤回从 Paged trace 构造默认流式树的选择。新路线须对最终 HTML tree、同源重复、测量丢弃、表格、库样式覆盖、target/frame、counter/依赖及只读来源逐项做有界证据；不以 experimental 标签直接否决，也不以几例编译宣称全 E1。固定 compiler/适配版本，升级重跑必要回归，维护范围不得扩为另一套 Typst 求值和排版器。当前实验与独立裁决见 REVIEW。

### 8.1. 一个普通模块与一个自动编译入口

选定方案：库级默认样式存于普通 `.typ` 模块，Core 库设置仅选择该获权 module EntityRef 与启用状态；模块 bytes 是样式权威，设置只负责选择，不另存一份字体/边框事实表或新 style DSL。设置界面编辑模块中的可识别 native set/show-set 参数，通过模块自身的 Core Plan 保存。高级源码可编辑完整合法样式；未知规则保源并标明该控件不可无损编辑，不全文件规范化。

每次笔记编译由 Core 自动构造可查看的临时 entry，**用户不需每篇手工 import**。entry 导入选定 module，执行它的标准内容包装函数，再 include 获权 realnote。entry 是派生编译输入，不写进笔记、没有笔记身份，不成为第二正文权威。禁默认入口和笔记隐式重复应用同一 module；笔记显式引用相同 module 时说明其额外 native scope，不能猜测去重删除作者源码。

```typst
// library-style.typ：模块结构示例；发行默认还须落实 §8.6 中文字体与语言
#let library-style(body) = {
  set text(font: "New Computer Modern", size: 11pt)
  set list(marker: [•])
  set table(stroke: 0.5pt)
  show list: set text(size: 10pt)
  body
}
```

```typst
// entry.typ：Core 自动生成且可查看
#import "library-style.typ": library-style
#show: library-style
#include "notes/realnote.typ"
```

模块入口函数名/调用 profile 是应用集成约定，源码仍是普通 Typst，不是新作者语言。初始化库可供应默认模块，用户只在库设置修改一次；禁每篇偷偷补写 import。用户明确选择不采用库样式则该 compile profile 无 wrapper，界面说明实际环境。当前被选样式损坏/失权时报告准确 layout unavailable，保笔记 Source/Draft；不能偷偷回退另一版/default 模块并冒同一输出。

### 8.2. 原生覆盖语义，不编造通用优先级

库默认尽量用 set 和 selector show-set 组合，字体、边框等属性不要放进重建元素的 transformational show 内部。单篇用 set/show-set，内容块内的规则只作用该块；单个 table 的 stroke 等显式参数可覆盖该默认。作用域、选择器、规则顺序、显式元素参数和 transformation 都遵循官方求值，不定义“单篇永远胜过库、局部永远胜过一切”的 CSS 式规则。单篇一般 text set 也不承诺覆盖所有库级 selector show-set；需要对应 native 选择器或明确局部元素属性。

官方特别建议将可组合的 show-set 与 transformational show 分开，因 transformation 内部 set 不再可由后续 show-set 覆盖。本轮最小实验证实这个反例，库 UI 应提示不透明/固定变换对覆盖的影响。用户仍可用高级原生 transformation；不能为了控件能力删掉它。[Typst Styling](https://typst.app/docs/reference/styling/)

列表的 marker、字体与正文等可分别设置，表格的 text 与 stroke/fill/inset 等分别使用标准 text/table/selector 参数。只向 UI 暴露有清楚 native AST 及 source writer 的属性：改默认只写 module，改单篇只写 note，改局部只写该 scope；每次一个明确 DraftUndo 与 Core 事务，不把三种改动混成一键不明影响。预览列受影响 scope，尊重已有原生显式参数。[Typst Table](https://typst.app/docs/reference/model/table/)

### 8.3. 源身份、相对路径、编辑与阅读

SourceSnapshot 和应用身份/字段资格始终来自真实 note 原 bytes/官方 AST，控制声明仅由该 owner 的源判读。wrapper/module 中出现 metadata、id/title 相似值不能出生笔记、覆盖控制字段或授权限。应用不从 synthetic entry 的 AST 重扫身份，也不因统一 wrapper 使所有笔记成为新源对象。

entry 的 source map 声明 designated authorSource=realnote；只有 Core 生成、完整证明恰一次包含当前 note 的入口才能让 bridge 把这层系统 include 认作该会话的作者源。仍须以 realnote 当前 AST、ReadBasis/Draft serial、实际 show scope 和唯一可逆来源检验富编辑。笔记自己写的 include/import 仍是独立来源，重复/include/generated/multi-origin 不授当前笔记 writer。不得把 realnote 因 wrapper include 一律变只读，也不能用此例外将任意 included 文件变可写。此桥消费与区分系统 entry 的实现仍须实测。

relative read/image/import/include/bibliography 等按照真实源 FileId 与所在 source 的位置解析：note 的 read("asset.txt") 找 note 旁资产，module 的相对路径找 module 旁资产，不能改为 wrapper 所在位置。Core World 用受控原路径映射提供获权 exact bytes；移动 note 的 native 相对路径含义与既有链接/资源规则一致，不偷偷补全或改写源码。包括绝对/包路径都受 World policy，无 ambient 读写/网络。样式控制呈现；dark/zoom/high contrast 是个人阅读层，默认不进入作者样式 module/官方导出环境；不可访问颜色/字体可在阅读层调整并明确与分页输出的差别。

### 8.4. 冻结依赖与样式改版

CompileSnapshot/Environment 与 DependencySet 记录实际库设置选择、style module RevisionId/bytes、entry profile/digest、真实 note/Draft、实际 module import/package/font/asset World 读及 target/budget。无权 style 不用已缓存内容续编译；包不静默取 latest。文件源有效性和源码保存独立于默认样式能否编译，样式错误不允许毁坏 note。

样式模块保存得到新 RevisionId，但不生成每篇笔记的假修订或修改 note AST/ID。模块/库选择改变后，依赖该样式的 preview、layout map、可视编辑资格、编译派生Query以及待交输出标 stale；新读/编译重建实际影响，未消费 style 的静态字段查询不受无关失效。已保存旧产物可显式看旧版，不冒当前。迟到 v1 preview 不可安装成 v2，不能改 Draft/Undo/选区；外部字体/资产/模块当前性变化同理。

Core 产品验收应实际冻结 v1 compile→提交 v2 module→交迟到v1→确认拒绝current安装→新compile采用v2，同时 note revision/bytes不变；ACL撤权、缺module、wrapper错误与换target分别测试。本文 CLI 只证明两次真实编译的差异，没有运行 Core cache invalidation 或当前授权门。

### 8.5. 准确源码导出与独立使用

准确 note `.typ` bytes 导出仍交原件，明确它不单独携带库样式。另提供“含库样式的独立 Typst 工程”完整 bundle/entry：获权 note 原 bytes、固定 style module/实际import与assets、可查看 entry、所需环境/包/字体清单和许可/loss，保持相对 source 路径或完整可验证路径映射。编译默认入口为 entry，绝不将 wrapper伪作原 note。只能交获权完整依赖；不可分发字体/包或闭包不完整时具名 loss/route unavailable，不声称独立无损可复现。不能仅导单个note再承诺同样样式。

PDF/可编辑 DOCX 和其他呈现输出消费同一冻结 style dependency；DOCX 必须另行验证 effective styles 映射，普通 native defaults 可转成 template/paragraph/run/table 样式，任意 show 不能当成全可表达。Job 固定 exact staged bytes 与 loss；style改版使未冻结预览/待准备内容失效，已确认文件下载续交仍是原 exact bytes并检查权限，不因全库样式变动重编译换内容。此处不扩为独立 Word 样式优先级协议。

### 8.6. 中文默认、字体与语言交付

[REQUIREMENTS](../REQUIREMENTS.zh-CN.md) §5.5 的正常路径不要求逐篇“启用中文”。初始化库启用 §8.1 的普通默认样式模块，以原生 text/set/show-set 提供字体、语言和地区；新笔记只写内容即可。设置面板修改同一模块，不增加笔记级中文开关、第二配置权威或新语法。明确禁用库样式遵守 §8.1，不偷偷重启模块；中文源仍可编辑、保存。源码控件也须有中文字体和 IME，其个人显示字体不写入作者样式。

初始化采用用户选定的库语言/地区；未另选时取初始化时界面语言并记录在模块，之后切换界面语言不暗改文档。简体中文中国地区示例是 `text(lang: "zh", region: "CN")`；其他地区依真实选择，不从汉字猜国别。汉字显示不依赖 lang=zh；语言设置还影响语言相关字形、引号和 AT 朗读。单篇/局部可原生覆盖；未声明片段继承文档语言，不声称自动识别每段语言。[Typst text](https://typst.app/docs/reference/text/text/)

| 内容 | 默认字体职责 |
| --- | --- |
| 正文、标题、列表、表格 | 拉丁字体配明确的简繁 CJK 候选；初始中文方案采用相应地区的 Noto Serif CJK，无衬线外观可选 Noto Sans CJK，用户可在库设置替换。 |
| raw/code | 等宽代码字体配 CJK 等宽候选，如 DejaVu Sans Mono 与 Noto Sans Mono CJK；实测汉字/ASCII/标点/tab 对齐，不把所有字硬压成同宽，不改代码字符串和缩进。 |
| 公式 | 数学结构保有效 OpenType MATH 字体，默认 New Computer Modern Math；中文字符串/text 由可覆盖汉字的文字字体/回退呈现，不以普通中文字体替换全部数学字体。 |

`raw.lang` 只选择高亮，与 `text.lang` 分开；中文注释/字符串不需额外标记。公式中文使用 `$ "总价" = "单价" times "数量" $` 等原生表达或 text 内容。公式文字控件若提供，生成同样原生表达；不增加中文专用命令。选定 compiler 版本必须实测 raw/math 的取字形路径，不能由正文字体成功推断它们也自动继承。[raw](https://typst.app/docs/reference/text/raw/)、[math](https://typst.app/docs/reference/math/)

**字体交付。** 默认字体随产品/离线安装包提供，发行清单列实际字体文件、版本、地区/字重、覆盖范围及再分发许可。无需用户安装或公共 CDN，也不依赖宿主偶然存在的字体。Core 通过既有 Environment 提供固定字体集合；浏览器从获权同源资源加载实际字体，并分别落实 raw、MathML/数学文字的映射，不能只写 CSS family 名称就声称交付。字体未就绪/失败标明呈现状态，保编辑和草稿；作者字体 URL 不获任意网络访问。

基本简繁汉字、常用标点和中英混排须覆盖。显式字体、fallback:false 和自定义模块仍遵循原生行为；缺字体、检测到缺字或覆盖外字符给出实际位置/字符与修复入口，不替换原字、不丢源、不偷偷覆盖作者选择。诊断使用实际字体/字形结果；编译 exit0 或文本可提取不证明没有方框。不同输出的布局度量可不同，文字、语言及声明的样式映射不能因此丢失。

PDF 核实实际字体与文本提取；DOCX 保可编辑文字/公式及可表达的东亚字体、语言和有效字符样式。嵌入字体须具备许可和目标支持，否则明确目标端依赖或替代/loss，不承诺任意 Office 客户端同版式。独立 Typst 工程按 §8.5 交付允许分发的字体及准确入口/字体路径说明，单独 note 原件不自动包含库默认。字体集合/版本改变走既有 Environment 失效，不改 note bytes、身份或批注范围。

### 8.7. 界面、文档与本次处理的语言地区设置

REQUIREMENTS §5.12 细化 §8.6 的设置体验。当前“库样式”已有 `text.lang`／`text.region` 原生字符串控件，发行默认为 `"zh"`／`"CN"`；完整友好选择、初始化选择、界面语言切换及处理策略不得据此标成已交付。v0.6.1 完成文档与现有导入／校对入口，v0.7 完成界面语言切换和平台交互。

库初始化与“库样式”提供人类可读的语言／地区选择及代码说明，地区可以未指定；保留高级源码入口。初始化时界面语言只提供清楚展示的初值，用户可改，采用后写入同一原生样式模块；之后切换界面不修改模块。只展示实测可映射的组合，不将文字体系擅自写成不存在的 Typst 参数。既有自定义模块或复杂／动态作用域不能安全回写时保源、说明实际限制，不用控件猜值覆盖。

单篇／局部覆盖仍写原生源，按真实 Typst 作用域求值，不能另存“文档 locale”副本制造第二权威。可证明时展示当前选区的有效语言与来源；混合、不明及禁用库样式分别显示，不假称库默认就是全部正文的语言。日期／数字的个人显示偏好与任务时区、作者字段实际值分开，改界面语言不能变更已存日期、排序依据或提醒时刻。

“输出与导入”和“校对”显示本次处理语言、文字体系（已知时）、地区（可未知）、方案和每项设置来源；规则建议展示适用条件及覆盖范围。采用 FEATURES §10.3 的处理优先级，不发明原生样式优先级。混合语言允许多选及按可证明片段处理；不确定检测只供确认，界面语言不能兜底启用地区专用方案。原文标记、处理语言和新文档输出语言发生差异时分别显示，不把识别选择当作翻译或全篇重标记指令。

先预览结构变化、字段提取及损失，再选择是否运行独立校对；校对仍生成结果／批注建议，接受后才改正文。设置、词典或输入变化使旧未提交预览及迟到结果失效；取消保留原件和草稿，未知提交查原操作。导入确认的范围含新源、资源、可证明语言标记及审阅映射，不附带更改库默认。v0.6.2 的 OCR 入口仅显示真实已安装识别语言／模型及实际执行端，尚未实现的识别或专用方案不能以可点击控件冒充支持。

### 8.8. v0.6.2 资料提取、识别与导入预览

REQUIREMENTS §5.13 的入口复用“输出与导入”和现有资源视图，先选保留资料、提取文本或生成可编辑笔记，再选页／区域、识别语言和可选方案。显示实际执行端、模型可用性、语言／地区适用范围与预计处理范围；未支持格式或缺模型不伪装空文档，仍可按已有能力保原件。共享库中本次选项不暗改其他用户的默认值。

对照预览一侧为准确原页／图片，另一侧为提取文字、阅读顺序和结构／字段候选，支持点击结果回到原区域。逐页显示文本层提取、OCR、跳过、空白、失败和待核对状态；整份的完整／部分状态来自页与区域覆盖，不能以有文字就算完整。低可信标记只反映后端实际提供的信息，无分数时显示未知，不伪造统一百分比。用户可调整阅读顺序、排除页眉页脚、确认段落或普通表格，并逐项接受字段／编号变化；所有候选修改可撤销且保留原文对照。

确认前分别预览原件保留位置、新笔记／资源／字段、可编辑和仅图片内容、未转换项以及是否接受部分结果。原始识别结果是只读依据，确认后的文字修改落在唯一作者源；已有原页批注留在原件媒体目标，不能猜测迁到 OCR 文字。取消与迟到结果不改新草稿；模型、方案、设置或输入变化按 §8.7 使未确认结果失效。未知提交查原操作，重试识别与重试提交分别可见；导入完成后校对另行开始，不在导出过程中偷偷改正文。

## 9. 渲染与权限安全

编译 worker 无 ambient workspace、任意路径、网络、凭据、Action 或作者写能力。Core 只供应实际获权依赖与冻结环境；未获权 include/package/resource 不返回内容，错误不泄隐藏路径/数量。编译受时间、内存、递归、输出和进程树预算；失败保稿，worker exit0 不等于输出可交。

阅读树生成宿主固定节点与样式，文字是 text 节点；作者 HTML/CSS/JS 不直接进入特权 DOM。SVG/实验 HTML 经 allowlist 验证，禁 script/event handlers、foreignObject/主动嵌入、表单、外部 font/fetch 与未准协议；资源使用 Core 受控地址，链接交 resolver。WebUI CSP/隔离无特权 origin/sandbox，Desktop webview 同样无文件/进程桥。清洗影响合法内容时明确 loss/local unavailable，不能默默删除称保真。

渲染/缓存/搜索摘要/thumbnail 都绑定实际消费 scope 及当前 auth。撤权停止新交付、异步安装和装饰，隐藏受保护缓存；已由用户键入的恢复稿保留。只字段权限不产生正文摘要、title 投影以外的整源或缩略图。不同 source/annotation/resource 各自授权，源读取不顺带授下载/发布。环境 cache key 包括实际依赖版本、schema 和 target；旧成功产物仅显式旧版本阅读，不提供 current 操作资格。

WebUI 的纯输入恢复与保护草稿分域：源码以共享 CodeMirror ChangeSet 的原基线位置、本人插入文字和不可证明片段记录来源，随同一历史的 inverted effects 撤销／重做，不另建正文或 Undo。原生 patch、旧历史全文和拖移文字不能自动成为本人新字；可视入口、面板及 IME 以实际输入载荷证明新增字，程序赋值和无准确证据的历史只保已证明的纯字供独立复制。恢复记录不持久旧 Base／保护全文／Schema／预览／凭据；异步回复不能重新授予旧来源资格。新认证后仅当同一稳定目标、准确基线摘要、当前代次和记录版本全部成立时才允许重放；未知原保存先核定原编号。存储失败显示仅内存保留，显式移除在超预算时可逐步自救，但未写入时不能声称旧持久记录已删除。无文档的结构捕获仍由其后续 Core 捕获稿合同承接。

## 10. 可访问性与上下文

键盘、触屏与 AT 有等价的标题操作、来源入口、表格操作、冲突/错误入口、返回和潜在链接候选选择。logical order 来自 bridge，不按视觉 x/y 或 DOM 临时次序拼。caret 维护逻辑点及视觉 affinity；Left/Right 依宿主视觉方向，词移动/删按共享逻辑字素，copy 按逻辑顺序。RTL 隔离 path/email/code 不改 bytes；表格列 identity 不镜像颠倒。

大纲保持实际深度、过滤/折叠/当前节/聚焦；聚焦和专注不删源。导航→列表→正文及窄屏返回保 Draft、Undo、筛选和可恢复位置。local 命名布局与 NAV01–05 列表偏好仅记个人呈现及可重新解析目标，不存结果、权限或旧地图；恢复重新授权，目标失效不猜同名。迟到缩略图/preview 不抢输入焦点。潜在链接只是提示；多个同范围/交叉范围及溢出都可显式选，不能最长匹配吞掉其它候选，转换继续走链接 owner。

每个平台分别测真实 CJK IME、Arabic/Hebrew 混排、emoji/combining、键盘/触屏、screen reader、200/400% zoom、320px、高对比、减少动画。live region 不逐字报 preedit；focus/composition 节点不因虚拟化消失。缺某 surface 能力准确标 unavailable；CLI 不宣称图形验收。

按 REQUIREMENTS §4.1 分负载校准性能。原输入反馈 p95≤50ms、layout≤100ms，Desktop 10MiB/100k lines、Mobile 1MiB/10k lines、单行1MiB及 steady memory 256/128MiB 保留为研究目标，不作为所有档位、任意 Typst 程序及全部进程同时满足的已定支持承诺。继续使用 WORKFLOW 的现有测量入口和原 1000 事件、冷／热各三轮；普通写作、大源码、复杂排版、查询分别记录源码／产物、设备、模式、实际大小、分位数、峰值与稳态内存的进程范围。UI、Core、WebView 与 worker 的内存不能以单进程数冒总占用。当前源码／请求容量限制按实际接口报告，不因研究目标较大就宣称已经支持。

根据实际结果明确可支持范围与预览降频、按需加载或只读复杂区域；新的性能预算须说明负载与依据，保留原失败，不能回写旧结果或放松原检查获得通过。超限检查包括原十倍负载探测：在接纳前安全拒绝或保留已接纳输入，不承诺无限加载、计算或任意大输入均可持久化；已有草稿不得丢失。降低预览频率不能冻结输入、吞掉撤销或把过期结果当当前结果。未运行项仍为未验。

## 11. 独立批注的协调边界

独立 JSON 存批注、回复、解决状态和目标历史；不把它混为正文或呈现权威。persisted target 由 Core 在已提交的获权源版本上建立精确文档/元素/范围或 PDF/image/audio/video 区域，Draft/DOM/projection key 不持久化。正文变更仅通过 Core 可证明 unchanged-range 映射延续；覆盖、gap、歧义则 orphaned/candidate，保讨论，不相似猜重锚。生成/多源 display 可整文批注或显式选真实来源，不能造源 range。

annotation 读取只交自己的已存摘要/正文/历史，不自动读取已隐藏目标、截图或重算 context。manual reattach 明确选新目标并使建议需重新确认。建议 apply 通过统一多实体 Core 事务同时修改准确当前源与 accepted 状态；其中一个失败整次未成功。reject 只需批注资格，零额外 target read。只读来源可引用到可写目的，引用复制的文字是目的作者内容，不证明来源仍 current。批注 source mapping、媒体精度与多实体提交仍是 Core/annotation owner 的实际实施门；本文不复活旧 locator/transform wire。

## 12. 可编辑 Word 默认与已知边界

DOCX 是 Weftext 自有转换器，不是 Typst 官方内建输出。默认语义转换 profile 消费一次冻结 Html 编译的最终语义树、同 target 的标题/引用产品及准确来源关联、获权资源；不自己重跑 Query、猜第一表或混入另一份 Paged 输出。自定义 show 后未显示的 native heading 不能凭 introspection 补成幽灵段落。明确选择 Paged 语义转换时是另一个具名 profile，预览与输出均注明 target，支持范围单独验证。局部 html.frame 保同次 Html 编译的来源边界。转换保真实段落、run、table、bookmarks 与可编辑资源；无法表达的复杂布局明确 loss/unavailable。标题映 Title、关联副标题映 Subtitle；不进 section counter。此路线与 FEATURES §11 一致，最终语义生产者仍受 E1 验证门约束。

转换器拥有的核心是冻结语义、精确映射和损失判断，不要求自建全部 ZIP/OOXML。默认先比较成熟离线 DOCX writer 加定向后处理与纯 Rust 后端：两者消费同一派生导出 IR，不重新解析 Typst 猜语义。用混排行标题、模板继承、引用、中文和表格样本在实际 Word 中更新目录并再编辑后选择；WPS/LibreOffice 单独验收。后端选择不会创建第二作者源。

1–9 级 section 映真实 Heading N、outlineLvl=N−1 与同一多级编号。独立 heading 和同行 heading 共用编号定义。同行默认是一整个 Heading N paragraph，前部 title runs，后部 body runs：这正是已认可方案。正文字符格式来自模板正文占位符/Normal 的**有效字符属性**，解析 docDefaults、theme、basedOn、字符样式与直接属性继承；显式复位 Heading 继承的 bold/italic 等，再叠加作者强调。不能 copy 空 raw rPr 就称复制了有效样式，也不硬编码字体/字号。段落级缩进、行距、keepNext 等仍是 Heading 段属性，预览须如实展示。[Microsoft 段落样式](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-create-and-add-a-paragraph-style-to-a-word-processing-document)

默认 Word TOC/导航按整段 Heading/outline 处理，可能把同行后部正文收进去；正文 run 换字体不会改变段落范围。输出预览/说明必须写明这一点，不能冒称默认目录只含标题。编号引用用准确 heading bookmark 与原生字段，不固定数字。[Microsoft 标题多级编号](https://support.microsoft.com/en-gb/word/number-your-headings)

“只标题目录”是可选细化：style separator 或显式 title bookmark/目录生成均须具名 route、真实应用验证及 loss 说明，不是默认完成的条件。默认保原生 Heading 和多级编号，不以写死编号或整篇图片掩盖问题。9级以上的 Word 标准 outline 无同等级别可映射：保源真实深度，明确该导出不具备原生深层大纲/编号等价；用户不接受此损失则 DOCX route unavailable。可选择保实际层级信息的自定义样式/可编辑文本，但不能命名 Heading9 冒等价，也不声称动态编号全保。[Microsoft outlineLvl 的 0–8 层与 9 无大纲语义](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.outlinelevel?view=openxml-3.0.1)

Job 完整生成并验证准确文件与 loss，再显示结果；内网下载不以外部发布为前置。确认固定源、模板、依赖和 staged bytes；resume 只交同 bytes，每 chunk 复验当前 auth，过期再生成是新计划。保存、打印、下载、保存 Resource 与外部发布各报告自己实际结果，不以参考渲染图冒 Office 成功。

## 13. 当前证据、决定与实施门

有限实验：Typst 0.15.1 官方 compile/query 已验证单个 labelled 同行 heading 与同级独立 heading 共享 counter/outline/ref；增删、移动、提升/降低自动更新，size-free 样例无必填尺寸；subtitle block+label 可查且不入 heading。空段打断同行、无编号默认 ref 报错也有反例。独立 DOCX 有 10 项 OOXML 检查，保 Heading2、真实九层编号、正文字符复位/强调及 TOC/REF 字段，但只是受控样例。32 个旧有限 Rust 检查及少数源 splice 不覆盖完整 editor。新方案没有重跑这些实验，更没有生产通过。

本轮另执行七个官方 CLI 样例与独立官方 AST 枚举：default、自定义 heading show、删除 heading show、剥离 strong 的 show、重复 include、loop 生成 heading、Paged/Html 分支。自定义 show 的 query.body 只有原标题，而 PDF 实际有 PREFIX/body/SUFFIX；删除 show 后 query 仍有 GoneHeading，PDF 无该标题；重复 include 有两个实际 heading/counter[1]/[2]，root AST 无 included text 槽。两次 query 相等只是有界可重复性，不证明内部收敛轮；剥离 strong 样例未测字体/role。CLI/AST 不产生流式桥通过。这些反例促成 §8 的最终消费树路线，当前有限证据与未跑范围见 REVIEW。

本轮新增 [Html 最终树与样式探针](probes/html-flow/README.zh-CN.md)：16 例关闭适配与官方 Html 字节一致，开启适配的串行/并行最终树一致，三种 Paged PDF 字节一致；消除 discarded measure，保重复 include 和不同 show 的真实出现项。库→笔记→局部字号、字体候选、强调/斜体及简单单元格边框和对齐有实际值证据。它没有实现浏览器 renderer、逆向编辑、复杂表格拓扑或全部样式；动态 marker 反例增加一次诊断源读取，World 顺序只在 15/16 例一致。局部 html.frame 的原生 Paged 内容可见，不证明其流式复制或无障碍树。产品适配开关必须属于固定 worker/environment/cache profile，不能在同一缓存中改变进程环境开关；探针标记不是可信来源或写资格。

规范 DOCX renderer 未找到 PATH 上 soffice，真实安装探测见 Office/LibreOffice；因此是“规范渲染不可用且实机未跑”，不是“机器无 Office”。ReportLab reference 图不是 Office renderer。真实 Word/WPS/LibreOffice 的字段更新、TOC 范围、导航、字体继承、style separator、保存再开和深级行为全部 UNRUN。

可直接进入协调候选的决定：唯一 Typst 源；共享会话与一个 DraftUndo；basis 新鲜性与统一 Core 提交；局部保源/不捏造生成写地址；title 与 heading 分域、轻量副标题 label；逐标题原生 show 而非整级设置；普通用户无间距参数；Word 默认整段 Heading N 与有效正文字符格式，并明示目录范围。E1 已有可运行的有限桥样例，仍需独立确认可实施边界；E5 是输出关键实施门，不能拿现有 OOXML 图替代。具体性能参数、样式分隔符可选路线与 hook 维护成本可随原型修订，需求本身不因此消失。

## 14. 需求覆盖与替换范围

本提案直接承担 RQ01–07、18、25 和 NAV01–02 的编辑/阅读交互；RQ08–11 属性、RQ12–14 链接、RQ15–17 Query/任务、RQ19 模板、RQ20–24 Core/转换/权限由各新 owner 供数据与动作，本文明确其会话、源、焦点、依据、loss 和权限消费。NAV03–05 统一 Query 与 local 偏好由导航 owner 协调，不建编辑器专用事实或查询语言。

对旧 EDITOR §§1–12 全部用本文新会话/地图/桥/输入/批注交互/门替换，不保其 wire、closed union、history decoder 或版本 pin 义务；旧正文仍保留为固定输入记录。FEATURES §§7–8 的用户输出/导入/下载结果保留，新 conversion/Core owner 另定机制，本文替换标题与 Word/editor 消费。SOURCE 的旧 title 单一 writer 限制、旧 carrier/locator 与强制格式资格不自动进入新机制。没有真实兼容对象就不虚构解码器；后来发现真实用户数据则保原件，单独确定导入与恢复范围。作者方案必须再做需求覆盖与非作者复核，不能把原 CLOSED 复制为本轮通过。


## 15. 当前托管正文消费者

v0.6 的托管正文复用 SourceEditor / WritingController 与原生结构适配器，不建立远端富文档源。准确稿地图、编译树、补丁及权限复验边界见 [SERVER：五档正文的托管授权](../SERVER.zh-CN.md#五档正文的托管授权)。会话 serial 与 actor 代次共同拒绝迟到结果，只有主文档来源产生本会话编辑入口，最终写入仍由原 Core 保存承担。Query、库样式、批注及其他独立消费者的权限接入继续另行完成；正文五档接入不替代它们的验收。
