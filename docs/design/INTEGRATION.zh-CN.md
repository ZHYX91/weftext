# 合同整合与重构顺序

状态：**本地有界实现已落地，v0.6 分批集成与验收中**（2026-10-15）。固定旧基线的独立设计接受保持为历史事实，[REVIEW](REVIEW.zh-CN.md) §8 的修订／实验边界不作为当前产品未实现的总状态。实际开发能力与未完成项见 [MVP](../MVP.zh-CN.md) 和 [ROADMAP](../ROADMAP.zh-CN.md)；分批通过不代表完整 v0.6 或发布。

## 1. 一份方案

[需求清单](../REQUIREMENTS.zh-CN.md)决定结果与边界。SOURCE 唯一定义作者角色及 Type/Value/schema；CORE 唯一定义 EntityRef、RevisionId、ReadBasis、SourceSnapshot、Plan、Receipt、CommitManifest、Environment 与 Job；EDITOR 定义 Draft、官方求值来源与交互；FEATURES 定义 Query、业务动作、链接、批注和输出的消费方式。重复说明不能创建另一套类型或授权入口。

持久版本证明某份历史内容，当前 ReadBasis 证明这次读写的依据；两者不能互换。只读投影和结果行都不是写能力。写动作重新 prepare，所有内部持久变更经过同一 Core 事务；外部网络效果保留独立 Job 责任。源和索引也不能互换：索引可重建，正文、结构化值、批注和已发生操作责任不能靠索引恢复。

新方案整体替代前轮 SOURCE/CORE/EDITOR/FEATURES/INTEGRATION 的技术约束。前轮 `replacements.json`、原词典和接受记录仍只描述其固定候选，不控制新运行时。新系统将来已发布数据的升级责任仍须实施；真实旧资料先保原件、识别格式、显式导入与说明损失，不通过想象旧协议已部署来扩大正常解码器。

## 4. 实施顺序与准入

下列顺序保留依赖关系，不再表示所有阶段尚未开始。当前已有 Windows／NTFS 本地写作、结构化信息和跨对象能力；Server 的五档、Query、批注、配置、媒体、结构、知识链接、既有格式交换与所有者恢复资料消费者已分批接通并完成相应 HTTP／后台浏览器检查。同所有者同步已有离线副本、部分安装、显式合并、收到历史和普通外部编辑接纳；CR14 稳定片段已完成有界修复。最新 Compound 已有界接通移动树外新 Node 父级及自有资源嵌套目录，真实 HTTP／后台浏览器已验新父级与原 Compound／Rules 路径；配置组合的真实 HTTP／浏览器仍只验 Rules 加两次移动。Native 包装目录从同一次原 CreateTree 预览取得准确修订和 Directory 身份；成功导入／同步克隆及原操作重启重试已完成固定程序的有界真实 HTTP 验收，受影响的原生／文献输出、冲突和 DOCX 导入回归通过。移动树内新增 Node、普通 Directory 新父级及独立移动、重叠／交换／循环位置、克隆回收对象、成员退役／旧文件删除组合、完整语义依赖复验和最终组合验收仍留在当前 v0.6，不能把正在实现或隔离测试计为可用，也不能移给后续增强版本。

1. **有界修订与选型原型。** 落实当前需求/合同修正，保留固定旧基线的审查事实。先做真实来源映射与输入闭环，具体行为见 EDITOR §2.2；补 CEL 真实执行器对照。按实际失败修复和针对性复核，不自动重开整套 Pro 全局终审。
2. **纵向最小闭环。** 并列验证工作区笔记与库外普通文件打开 → 单 Draft/源保存/恢复 → 基础五档与流式阅读 → 节点稳定身份/链接。真实外部编辑竞态、迟到编译与故障从首片进入测试。原型只证明明确范围，不冒全部五档和平台已完成。
3. **结构化与组织。** 集中 schema、属性表单、丰富类型、Query/导航/列表/任务视图；同项数组查询、未知值、精确值和安全局部编辑同时验收。
4. **跨对象能力。** 独立批注、模板/复制/导入、标题与 Word/表格导出、内网下载，以及数据保全和可恢复 Job。v0.5 补齐 REQUIREMENTS §5.7：批注与基础修订合同 → 本地校对／批量批注 → Word 批注导出 → Word 正文／批注导入 → 基础修订往返 → 真实 Office 验收；范围和完成门以 [ROADMAP](../ROADMAP.zh-CN.md) 为准。
5. **多端与部署。** 按共同 Core 完成 Server 多用户/权限与同步，再验证客户端/离线/撤权/故障组合。平台可分批交付，未支持的平台或后端明确标识；不把研究原型当正式可用。

2026-10-14 补充的版本顺序为 **v0.6 → v0.6.1 → v0.6.2 → v0.7**。当前 v0.6 继续完成既定多用户／同步／权限闭环；其后按 REQUIREMENTS §5.8、§5.10–5.12 实施 v0.6.1：LaTeX 公式转换与 Word 原生公式验收 → Mermaid 源码／预览及 DOCX 图片 → DOC／WPS 可选外部软件适配 → 原生引用体验、关系分类、脚注／尾注与题注输出增强 → 文档语言地区及导入／校对适用机制 → 新消费者同步、权限和撤权回归。EDITOR 负责输入、转换确认和源／预览一致性，FEATURES 负责格式映射、图片输出及损失，CORE 负责原件与资源持久化、事务、同步和获权工件交付。具体完成门统一见 [ROADMAP](../ROADMAP.zh-CN.md)；v0.7 再补界面语言切换、各目标平台的依赖与执行端验收。此次计划补充不修改当前 v0.6 的完成条件，也不代表新增功能已实现。

§5.13 在 v0.6.1 后由 v0.6.2 接续：定版独立后端／模型／许可证、语言组合、首批地区方案与票种／字段及质量样例 → PDF 文本层、逐页状态和来源映射 → PNG／JPEG 与扫描／混合页 OCR、去重及基础结构 → 公文编号／字段和发票精确字段候选 → EDITOR §8.8 对照核对与 Core 原子导入 → IM01–09、LC09。FEATURES §10.4 拥有路由、规则适用和覆盖／损失，Engine／导入适配器提供准确文字、几何及来源，SOURCE／CORE 在实现前定版来源证据、Job 结果与适用字段映射；不另造可编辑识别正文。每阶段验证权限、离线、取消、部分失败和原操作恢复，先在独立 Windows 本地／自托管环境闭环；v0.7 按 IM10 验各平台模型安装升级、资源预算和交互。初始范围不包含 OFD／XPS、扫描仪采集、复杂表格、手写／公式 OCR 或所有票种。产品维护自己的规则、依赖清单和获准使用的样例，沿用 WORKFLOW 与 MVP 记录实际完成状态。

阶段可重叠开发，但后阶段不得绕过前阶段的身份、事务和权限合同。公开接口、实际持久格式、后端能力与运行环境在对应实现切片开始前定版；没有真实必要时不先造多代 wire。重构准入要求核心机制足够明确、重大设计缺口已解决且关键选择有证据；产品发布还要求真实平台验收，有限实验不替代后者。

真实资料在重构前先做可恢复备份，原型/旧格式从副本导入，输出逐项损失报告和恢复办法；未获得确认不自动改写原库。没有提供真实旧资料时，不为不存在的迁移对象阻塞新设计，也不声称已完成迁移。

## 5. 本轮修订的针对性验收

- `Inbox/loose.typ` 与无主文件目录可见、可展开并标不管理；显式子树不管理停止 Node 发现但不阻止普通浏览；已接纳 Node 缺主文件保身份诊断；ignored 不偷偷变 Node。
- 库外 `.typ` 无 ID 可打开保存/另存，相对依赖准确，原目录不新增控制文件；外部改动保双方稿，WebUI 下载副本不冒原位保存。
- CEL 换序/exists/all/filter/条件 guard 与宿主中止按 FEATURES §5.4；预算/授权失败不能被 true 吸收。
- A 当前 r2、B pinned A/Q@r1 的复制保原历史目标且预览依赖；独立复制明确拒绝，不暗换 r2。
- 紧凑 schema 拒绝作者签名覆写/未知操作/错误 ABI；展开后全部原业务字段/约束和值规则保持。
- Agent 的读、内容出站、写、外部效果、费用分别检验；免费只读模型也不能绕过出站范围。

上述为设计验收要求。实际执行情况按 REVIEW §8 与各 probe README 报告；未运行的操作不得计为通过。
