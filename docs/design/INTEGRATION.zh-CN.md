# 合同整合与重构顺序

状态：**0.6.0 Windows／NTFS 既定 v0.6 范围的实现与最终优化程序验收已完成，尚未正式发布**（2026-10-16）。固定旧基线的独立设计接受保持为历史事实，[REVIEW](REVIEW.zh-CN.md) §8 不代替本轮产品实测。实际能力、同一程序的 HTTP／浏览器／NAS 检查及平台限制见 [MVP](../MVP.zh-CN.md)，后续版本见 [ROADMAP](../ROADMAP.zh-CN.md)。

## 1. 一份方案

[需求清单](../REQUIREMENTS.zh-CN.md)决定结果与边界。SOURCE 唯一定义作者角色及 Type/Value/schema；CORE 唯一定义 EntityRef、RevisionId、ReadBasis、SourceSnapshot、Plan、Receipt、CommitManifest、Environment 与 Job；EDITOR 定义 Draft、官方求值来源与交互；FEATURES 定义 Query、业务动作、链接、批注和输出的消费方式。重复说明不能创建另一套类型或授权入口。

持久版本证明某份历史内容，当前 ReadBasis 证明这次读写的依据；两者不能互换。只读投影和结果行都不是写能力。写动作重新 prepare，所有内部持久变更经过同一 Core 事务；外部网络效果保留独立 Job 责任。源和索引也不能互换：索引可重建，正文、结构化值、批注和已发生操作责任不能靠索引恢复。

新方案整体替代前轮 SOURCE/CORE/EDITOR/FEATURES/INTEGRATION 的技术约束。前轮 `replacements.json`、原词典和接受记录仍只描述其固定候选，不控制新运行时。新系统将来已发布数据的升级责任仍须实施；真实旧资料先保原件、识别格式、显式导入与说明损失，不通过想象旧协议已部署来扩大正常解码器。

## 4. 实施顺序与准入

下列顺序保留依赖关系，不表示这些阶段尚未开始。Windows／NTFS 本地写作、结构化信息、跨对象能力及 v0.6 既定的 Server／多用户权限／同所有者同步均已实现。托管消费者继续按各自权限、撤权和原操作恢复验证，个人草稿不随副本传输；CR14 稳定片段保留原有界接受。

原 Compound 已接普通 Directory、移动树内外创建、新父级、交换／循环重排、祖先抽取与嵌套最终位置、退休 Clone、多根回收／恢复和资源成员保全，并沿同一 Plan 保原 FI、准确修订、资源、批注、Draft／Undo 和历史。缺失 Rules／Schema／settings 可与结构／内容同计划补齐；真正语义依赖变化须显式 RevalidateSync，不能确认绕过。原生最终产品、Native 外部采纳、移动 include、Style／Settings 及 live／Trash／混合 after World 复用真实 Engine／Data 和原资格／正负依赖，不另造语义权威。

同一最终优化程序已通过完整 HTTP 矩阵、受影响浏览器和真实 NAS HTTPS；草稿保全、原身份与资源、原请求恢复及分别授权的消费者按本轮范围验收。实际系统 IME、完整辅助技术、实际断电和其他 OS／NAS 浏览器仍未验，不由 Windows／NTFS 结果推定。后续 v0.6.1／v0.6.2 增强、v0.6.3 日常体验和 v0.7 平台按下述顺序继续；CORE 保持动作合同，MVP／WORKFLOW 说明实际支持与交付条件。

1. **有界修订与选型原型。** 落实当前需求/合同修正，保留固定旧基线的审查事实。先做真实来源映射与输入闭环，具体行为见 EDITOR §2.2；补 CEL 真实执行器对照。按实际失败修复和针对性复核，不自动重开整套 Pro 全局终审。
2. **纵向最小闭环。** 并列验证工作区笔记与库外普通文件打开 → 单 Draft/源保存/恢复 → 基础五档与流式阅读 → 节点稳定身份/链接。真实外部编辑竞态、迟到编译与故障从首片进入测试。原型只证明明确范围，不冒全部五档和平台已完成。
3. **结构化与组织。** 集中 schema、属性表单、丰富类型、Query/导航/列表/任务视图；同项数组查询、未知值、精确值和安全局部编辑同时验收。
4. **跨对象能力。** 独立批注、模板/复制/导入、标题与 Word/表格导出、内网下载，以及数据保全和可恢复 Job。v0.5 补齐 REQUIREMENTS §5.7：批注与基础修订合同 → 本地校对／批量批注 → Word 批注导出 → Word 正文／批注导入 → 基础修订往返 → 真实 Office 验收；范围和完成门以 [ROADMAP](../ROADMAP.zh-CN.md) 为准。
5. **多端与部署。** 按共同 Core 完成 Server 多用户/权限与同步，再验证客户端/离线/撤权/故障组合。平台可分批交付，未支持的平台或后端明确标识；不把研究原型当正式可用。

2026-10-16 更新后的版本顺序为 **v0.6 → v0.6.1 → v0.6.2 → v0.6.3 → v0.7**。v0.6 已按既定 Windows／NTFS 范围完成多用户／同步／权限闭环；其后按 REQUIREMENTS §5.8、§5.10–5.12 实施 v0.6.1：LaTeX 公式转换与 Word 原生公式验收 → Mermaid 源码／预览及 DOCX 图片 → DOC／WPS 可选外部软件适配 → 原生引用体验、关系分类、脚注／尾注与题注输出增强 → 文档语言地区及导入／校对适用机制 → 新消费者同步、权限和撤权回归。EDITOR 负责输入、转换确认和源／预览一致性，FEATURES 负责格式映射、图片输出及损失，CORE 负责原件与资源持久化、事务、同步和获权工件交付。具体完成门统一见 [ROADMAP](../ROADMAP.zh-CN.md)；v0.7 再补界面语言切换、各目标平台的依赖与执行端验收。此次计划补充不修改当前 v0.6 的完成条件，也不代表新增功能已实现。

§5.10 的实施顺序为：复用 SOURCE §1.2 的绑定／publication 数据并核原生引用分类 → EDITOR §2.5 的统一插入、显示文字、形式／定位补充与交叉引用选择器 → FEATURES §10.1.1 的来源笔记分组及引用位置视图 → 独立 Typst 依赖与 DOCX 域／链接／文字／损失分类 → ROADMAP CR01–16。Engine 提供同次目标的实际语义，Knowledge 区分绑定、作者引用与显示出现项；Core 重用同稿保存、权限、同步和原操作恢复。控件不另建文献数据库或全库别名身份表，索引不反写双链，导出不增加未经证明的 Word 自动更新承诺。引用键复用／显式改名与链接标题更新分别按 FEATURES §10.1.1／§3.2 保证范围、同稿及撤销；新增 Web 深链先落实可信部署来源和实际路由，再开放复制入口。原 hosted 带片段 URI 的解析缺口已按 CR14 在 v0.6 完成有界修复及真实 HTTP／后台浏览器验收，后续引用交互复用并回归其准确范围，不把应用 URI 解析通过推广为部署 Web 深链通过。当前引用缺陷和 v0.6 已承诺的消费者闭环按原完成门修复；新增能力在 v0.6.1 当期验证权限，v0.7 补平台交互。MVP 只记录实测能力，现有检查入口与候选记录继续复用。

v0.7 进一步按 REQUIREMENTS §5.9 与 FEATURES §7.1 实施：Windows 原生托盘／通知／小窗口与 MSIX 小原型 → 单实例常驻及碎片保存恢复 → 独立于截止的分钟级提醒意图 → 调度、失效与恢复汇总 → MSIX 安装更新及平台验收。SOURCE 在实现前确定可选提醒字段与时间语义；FEATURES 负责提醒生命周期、去重／未知送达及视图；EDITOR 复用 Draft/Undo 提供独立碎片窗口；CORE 保持唯一写入、原操作恢复、权限与同步，并管理设备状态；应用入口实现原生桥、单实例／激活，产品打包入口负责 MSIX、签名、运行时依赖与升级。先验证 WebView2 等具体平台手段再定绑定，不为托盘重写完整产品。新提醒消费者当期验证 v0.6 权限／同步合同；Windows 结果不替代其他平台，也不以打包成功代替安装、卸载后用户数据保全。DSK01–10 及执行记录入口统一在 ROADMAP／WORKFLOW，不另建账本式验收文档。

## 5. 本轮修订的针对性验收

- `Inbox/loose.typ` 与无主文件目录可见、可展开并标不管理；显式子树不管理停止 Node 发现但不阻止普通浏览；已接纳 Node 缺主文件保身份诊断；ignored 不偷偷变 Node。
- 库外 `.typ` 无 ID 可打开保存/另存，相对依赖准确，原目录不新增控制文件；外部改动保双方稿，WebUI 下载副本不冒原位保存。
- CEL 换序/exists/all/filter/条件 guard 与宿主中止按 FEATURES §5.4；预算/授权失败不能被 true 吸收。
- A 当前 r2、B pinned A/Q@r1 的复制保原历史目标且预览依赖；独立复制明确拒绝，不暗换 r2。
- 紧凑 schema 拒绝作者签名覆写/未知操作/错误 ABI；展开后全部原业务字段/约束和值规则保持。
- Agent 的读、内容出站、写、外部效果、费用分别检验；免费只读模型也不能绕过出站范围。
