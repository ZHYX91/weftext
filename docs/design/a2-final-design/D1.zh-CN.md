# A2 D1 产品表面、能力边界与发布证据

状态：A2 第一批的 current D1 设计候选。

## 1. 权威范围与当前裁决

D1 负责产品表面、运行模式、能力归属、进程/信任/网络边界、状态所有权以及发布/证据次序；D2–D10 分别负责自己的领域协议。

当前 D1 把固定 S 的表面/发布合同与后续 file-authority afterimage 合成一份正文。材料变化明确为：一个逻辑 Workspace 可以有多个已登记物理副本；每个物理副本至多一个本地持久 commit holder；一个托管后端跨进程和 failover 重叠窗口也至多一个 Server commit holder；Server 允许多个用户会话；全局 execution responsibility 与普通内容副本分域。

数据库、同步 Provider、worker、Agent、自动化、连接器、缓存或 UI 都不得成为第二条作者写入权威。

## 2. 五个正式产品表面

### 2.1 Desktop

Desktop 是完整本地文件工作区表面，也是可选 Server 客户端。它负责设备 UI 状态、文件授权、Draft、选区、无障碍和交互状态。本地模式调用本机 Core；远端模式调用 Server。WebView 不直接写工作区文件、portable metadata、durable control 或 derived index。

### 2.2 WebUI

WebUI 永远是 Server 客户端。浏览器存储可以留存明确未提交的 Draft 或缓存，但不是托管工作区权威，也不把本地目录变成产品写入边界。

### 2.3 Server

Server 负责托管认证、授权执行、审计、托管备份恢复、客户端 API 与多会话协调，同时调用同一 Core。多个用户可并发读取、持有 Draft、prepare 或编辑同一/不同文档。持久提交只按真实 write/dependency 范围排序，旧 Base 永远不能覆盖更新 source。

### 2.4 CLI

CLI 支持本地与远端模式并消费相同 Core 结果。破坏性、外部、冲突解决或批准敏感操作必须有显式输入，不能隐藏确认。

### 2.5 Mobile

Mobile 是独立正式表面，不是 WebUI 包装。本地模式只有在平台后端证明所需安装/耐久合同后才能写，否则明确 unavailable；远端模式是 Server 客户端。当前 Mobile 仍不承担 conversion 执行、Agent session、automation scheduling 或 connector credential/run 管理；能力矩阵允许时只能消费已提交 connector 结果。

## 3. 总体不变量

1. 一个物理本地副本任一时刻至多一个持久 commit holder；一个托管后端跨 Server 进程、实例和重启重叠也至多一个。
2. 不同已登记物理副本可各自离线提交普通内容，但这不复制全局 execution authority。
3. Desktop、WebUI、Server、CLI、Mobile 共享 Core 的领域结果、诊断、计划和提交语义。
4. WebUI 不成为本地文件作者边界。
5. Desktop、CLI、Mobile 的远端模式不得用本机 Core/缓存重新解释远端结果。
6. 文件同步只运输普通文件和 portable metadata。外部变化只使依赖受影响 observation/range 的资格失效，不把整个 Workspace 永久改成只读。
7. worker、Agent、自动化和连接器只产生输入、结果或提议；作者提交仍经 Core 或 Server Core。
8. capability state 来自版本化产品状态，不从按钮、OS 猜测、缓存历史或一次成功推导。
9. unsupported、未交付、未配置、offline、版本不兼容、未授权或 policy denied 均不得回退为近似写入。
10. 平台支持声明必须有真实构建、安装、启动和场景证据。
11. 当前公开工件不声称生产平台签名、公证或商店身份；开发签名不是发布能力。
12. 产品必须区分 input retained、not saved、reliable、durable observed-only、recovery unknown 与 portable publication pending/published。observed-only 只允许 D6 已闭合的受信交互、单一既有 live Document、普通 whole-source save 路径。

### 4.3 Mobile 委派与排除

Mobile 使用相同领域语义，但可以把托管操作交给 Server。它不能因为委派而获得 conversion worker、Agent、自动化调度或 connector 凭据 authority。按钮隐藏或不可用不能改变这些边界。

## 5. 运行模式、并发与执行托管

### 5.1 本地副本与普通同步

每个已登记物理副本都有自己的 replica epoch 和本地 commit domain。同一物理副本上的 Desktop/CLI/Mobile 进程必须竞争一个持久提交资格；不同副本可以同时离线编辑。

文件同步只是 transport，不是 collaboration。partial arrival、placeholder、source-before-metadata、metadata-before-source，以及并发 content/structure/lifecycle/policy heads 都必须进入当前 D3/D6 completeness/conflict 规则。不得用 mtime、path、filename、digest、last uploader 或 arrival order 自动选 winner。

外部变化只使受影响 SourceObservation/cut/install 范围失效。重新取得资格后，无关文档和操作继续；observed-only 绝不能覆盖已经观察到的竞争写。

### 5.2 Server 多会话

托管后端只有一个持久 commit holder，但不是只有一个用户。同文档的多个非实时 Draft 可以并存；A 先从 r5 保存到 r6 后，B 的 r5 Base 必须 stale/conflict，保留 B Draft 与差异。不同文档读取/prepare 可以并行，提交只按真实依赖排序。

failover 必须同时 fence control storage 和作者文件写路径。只 fence SQL、仍让旧实例 rename/replace 文件不合格。

### 5.3 Execution custody 独立分域

Approval-use 次数、Money、external-unknown 责任、Automation execution 与 stop responsibility 需要连续且 fenced 的 execution-responsibility domain。复制工作区文件或 portable metadata 绝不复制这些可消费责任。没有 execution custody 的副本仍可普通编辑。

### 5.4 用户可观察状态

各表面区分 T_first_open、T_first_edit、input retained、T_first_reliable_save、durable_observed_only、recovery_unknown、portable publication pending/published、T_full_search_ready 与 T_OCR_ready。

Preview、Prepared、Draft persistence、HTTP success、同步上传、worker success 或 durable-control planned 都不是文件保存成功；observed-only 延迟也不能填入 T_first_reliable_save。

## 6. 信任、授权、披露与索引

权限在真正持有 backend 的边界重验。客户端“已授权”、同步 Provider 状态和 index completeness 都不是授权证据。

普通操作只读取实际需要的 source/identity/structure/policy 范围。强 Action 必须按对应 downstream owner 证明完整正/负范围。partial index 只能做候选加速；无法证明 complete range 时只阻断该强操作，不阻断无关普通保存。

policy denied 必须遮蔽 component/config/network/version/temporary-health 细节。撤权与提交在 authority holder 线性化，一个参与者的权限不能替另一参与者输入提供 authority。

## 7. 能力协商与 unavailable 语义

### 7.1 稳定 major 协商与只读兼容

任何工作区读取、capability description 或 commit 前，双方先通过跨 major 稳定且只读的 bootstrap 语义交换支持 major 集并选择共同 major。无共同 major 时，只返回 incompatible_version 与双方支持 major 集。

选定 major 后，未知 capability ID 是 unsupported_feature。Client/Server major 不匹配时默认拒绝读写；只有 release manifest 明确批准的精确组合才允许 read-only interoperability，客户端不能凭“看起来可读”自行放行。可选 worker/provider 版本不匹配只影响实际消费它的能力。

### 7.2 封闭 unavailable reasons

capability state 只有 available 与 unavailable。unavailable 只允许以下十个 reason：

| 优先级 | Reason | 含义 |
| ---: | --- | --- |
| 1 | unsupported_feature | capability ID 不在所选 major |
| 2 | unsupported_surface | 已知能力被产品禁止进入该表面 |
| 3 | not_in_release | 产品方向存在，但当前协调 release 未交付 |
| 4 | policy_denied | 主体/部署策略拒绝，并遮蔽后续部署细节 |
| 5 | user_action_required | 需要用户授予明确本地/网络/设备权限 |
| 6 | missing_component | 必需可选组件不存在或已移除 |
| 7 | not_configured | 已交付组件存在但尚未配置 |
| 8 | offline | 必需本地/网络承载边界不可达 |
| 9 | incompatible_version | 边界可达，但 caller/Server/worker/provider 版本组合不允许 |
| 10 | temporarily_unavailable | 边界、配置和版本都有效，但能力内部暂时失败 |

### 7.3 优先级、遮蔽、重试与修复

一次探测只返回第一个成立 reason。静态产品/发布数据决定 1–3；policy_denied 在探测 component/config/network/version/health 细节之前判定并停止披露；offline 与 temporarily_unavailable 由承载边界是否可达而互斥。

结果还携 capability ID、是否可重试和不泄密的修复类别。probe success 不是授权票据；真实操作仍重验 policy、backend qualification、observation、frontier 与 dependency。strict 请求不能静默降级为 observed-only。

workspace busy、stale revision、target conflict 等属于 downstream operation error，不扩张 D1 reason 集。

## 8. 发布声明与证据

### 8.1 G1、G1.1 与 G2 工件

| 阶段 | OS / CPU | 工件 | 可声明 | 明确不声明 |
| --- | --- | --- | --- | --- |
| G1 | Windows 11 x86_64 | 无生产签名 NSIS Desktop exe + x86_64 ZIP CLI | 已列本地 Desktop/CLI 能力 | Windows ARM64、macOS/Linux Desktop、Server/WebUI、Mobile、conversion、Agent、协作 |
| G1.1 | Ubuntu 24.04 LTS x86_64 | tar.gz CLI | 已列本地 headless 工作区能力 | Linux GUI、其他发行版/CPU、Server |
| G2 | Ubuntu 24.04 LTS x86_64 | Server + embedded WebUI tar.gz；可选同内容 OCI image tar | 已认证托管工作区、WebUI、backup/recovery、已列 API | 其他 Linux/CPU、托管 SaaS、实时共同文本编辑，除非另有独立证据 |

WebUI 随 Server 交付，不是本地文件下载包。Mobile 仍是正式表面，但本文不声称普通用户 iOS/Android 生产安装包。

### 8.2 每个 Supported 行的证据

一个 Supported 行必须同时具备：

1. exact tag/commit、锁定 toolchain/lockfile、对应 native OS/CPU clean runner 构建；
2. machine manifest 写入 artifact name/version/target triple/byte length/SHA-256/SBOM/licenses/NOTICE/known limitations；
3. 无源码/开发工具的 clean machine 安装或解压、启动、最小端到端场景、重启、卸载/清理，并给平台原生 digest 校验命令；
4. automated package smoke + 独立人工 clean-install 都绑定同一 digest；
5. GUI 还要键盘、IME、缩放/高对比度和真实系统 warning；Server 还要持久卷、认证、backup/restore 和受测浏览器精确版本；
6. runtime capability 与包内容一致；
7. 缺证据/失败行必须移到 Experimental/Unsupported，不得拿其他平台 Core 测试代替。

### 8.3 无生产签名、warning、完整性与回退

公开 release artifact 不声称生产 publisher signing/notarization/store identity。SDK、CI、模拟器或登记测试设备要求的 debug/development signing 只服务开发证据，不进入公开 GitHub Release 或 Supported claim。

Release 首屏写 Included、Not in this release、How to verify。Windows 说明记录真实 warning 与 continue/cancel 路径，不要求关闭 SmartScreen 或忽略 digest mismatch。

G1 不承诺 silent install、auto update 或后台提权。手工更新、可见 rollback 说明和 workspace backup 步骤是必需项。供应链 provenance 可补充 SHA-256，但不等于生产 publisher identity。

### 8.4 依赖图

共享 Core 后先 G1。G1.1 CLI 证据与 Server security foundation 在 G1 后并行，G1.1 不阻塞 G2。Server security → WebUI → G2。实时协作在 G2 后，不阻塞安全的非实时托管发布。

Mobile local 依赖 shared Core + D8 mobile interaction，不依赖 Server；Mobile remote 依赖稳定 Server API。conversion 依赖 D9，不阻塞 G1/G2 基础能力。Agent/automation/connector 依赖可复用 Action/permission/audit，也不阻塞基础表面。

## 9. 大库行为

打开、编辑和保存活动文档不得等待完整 metadata、full search 或 OCR。实现应使用渐进、有界、可续建 derived index；需要 complete range 的 Action 必须通过扫描或 current qualified index + reread 证明，否则明确拒绝。没有实测证据前不承诺具体秒数。

## 10. 实时协作边界

实时协作属于 G2 后续。未来接口必须区分 participant/session epoch、input sequence/Base、IME preedit/final input、transient broadcast 与 durable checkpoint，并处理撤权、断线、重连和 gap reset。协作算法只向 Core 交付一份 managed source proposal；本文不冻结 OT/CRDT，也不让 collaboration log 成为作者 source。

## 12. 实施与验收义务

### 12.1 固定 S Implementation Impact 十三项测试

固定 S D1 Implementation Impact 的 13 个 source-qualified test 全部保留：

1. Core 无 UI/Server/worker/Agent/provider/network dependency，surface 也无禁止直连。
2. 本地 Desktop/CLI/process contention 只有一个 commit holder。
3. 双 Server 重叠/failover 全程只有一个 hosted commit holder。
4. external/partial sync change 使旧不安全资格失效，不 silent merge。
5. startup major negotiation 在 capability/workspace read 之前 fail closed。
6. unavailable reason 按十项顺序归一并遮蔽。
7. 同一 fixture 在五表面得到等价 canonical result。
8. remote client 不在本机解释/commit hosted workspace，browser 不取得 hosted path。
9. worker/broker 无可写 workspace mount 或第二 submit authority。
10. 每个 Supported artifact 有 build/hash/SBOM/license/smoke/clean-install/warning evidence。
11. public artifact 不声称生产签名，development-signed Mobile artifact 不进入公开支持行。
12. public prose 不出现无证据的跨平台 Desktop、Mobile production、sync-as-collaboration、本地 WebUI、signed、conversion/Agent built-in 声明。
13. retirement scan 拒绝 obsolete prototype name、alias、fallback、dual path 与 bridge 回归。

### 12.2 Current owner afterimage 验收

后续 owner 另要求 registered replica、range-scoped invalidation、Server 同/不同文档会话、撤权/重连/重启/failover、partial-sync/placeholder、first-open/edit/reliable-save/search/OCR 分开测量、P/I no-body-replica 以及未实现 collaboration 的 not-in-release。

其 implementation-impact negative matrix 还要求：move/edit 与 Trash/edit conflict；portable metadata copy 不重复 Approval/Money；删除 I 不丢 authority fact；丢 P 不从当前 source 猜 external unknown/receipt/Money；只 fence DB 的 failover 必须失败；partial index 不能证明 complete Action；Draft autosave/background/reconnect 不触发 observed-only；narrow permission 不升级 whole-source permission；observed competition 进入 stale/conflict；strong/bulk/D3 structural/Automation/approval/Money 禁止 observed-only。

## 13. 历史与审查边界
