# A2 D7 Query, View, Action, and DynamicBlock Integration

Status: current D7 author candidate for A2. It is not independent acceptance, implementation, activation, release, or product-test evidence.

## 1. Authority, precedence, and retained owner text

D7 owns the author definition and execution semantics of Query, pure View presentation, explicit Action preparation, immutable preview/effect delivery, result paging and subscriptions, Narrow Field qualification, Definition Transfer, and the inert DynamicBlock binding surface. Core remains the only interpreter and author-effect authority. D7 introduces no second parser, renderer computation engine, durable Query/View/Record identity, ledger, CAS, or file authority.

The complete coordinated D7 owner afterimages are copied byte-for-byte under the local d7/owners subtree, including their bilingual main texts and the 34-concept, 8-binding terminology Registry. Those retained files remain normative for every clause not named as superseded here. This file and D7-SCHEMAS are the current A2 overlay for fixed97 successors, current D2 product consumption, and SEARCH-01 through SEARCH-08. When a retained owner file names an older outer version, this overlay wins only for that named current successor; the historical decoder and recovery duty remain intact.

## 2. Current version dispatch and recovery split

Fresh unseen execution uses the actual current outer families from fixed97: D3 wire13, InputDescriptor/3, DependencyProof/3, PreparedIntent/3, InstallationNotice/3, ContentCompletionProof/4, ChangeRecord/1, D7ActionPrepareRequest/3, D7ActionSpec/2, D7ActionInput/3, PreparedActionBinding/4, D7ProposedInput/3, EffectManifest/3, and EffectBytes/3. Genuine saved, planned, unknown, or already committed predecessor records dispatch by the exact version that created them. PAB3 and D7ProposedInput/2 retain their original annotation-value decoder and pins; they are never repinned or re-encoded as PAB4/Input3. Old Result, evidence, selector, Draft, map, source token, preparation, or preview transport cannot be refreshed into current authority merely because equal bytes are still visible.

## 3. Identity and address domains

EntityRef, durable D3 Locator, LogicalOccurrenceKey, ResultRowHandle, internal provenance, and ActionEvidence are separate domains and never coerce into one another. Node, Resource, and Annotation are durable content domains. A Task is an ordinary Node with the source-declared tasks/task Facet. Template is a Core meta-kind. Current D5 creates no durable Record or RecordCollection and reserves no RecordRef; there is likewise no TaskRef, ViewRef, or FieldRef.

D4 authored provenance is a complete authorized author value, not execution authority. A Ref or provenance value may be displayed while resolution or write permission is unavailable. Path, filename, title, digest, result rank, index row, source coordinate, or equal payload bytes never create content identity or write capability.

A portable QueryRef, DefinitionAddress, recipe address, or Resource region that contains a persistent Locator is usable only by the D3 stable production-version address flow: authenticate the recorded production binding, obtain a fresh current SourceObservation whose complete sourceVersion is byte-equal to that production version, then validate owner, profile, coordinates, disclosure, and final read barrier. Equal bytes or equal revisions alone are insufficient. This new read never rewrites the saved address or revives old runtime evidence.

## 4. Author definitions and D2 carrier

Saved Query, View, and DynamicBlock definitions are authored occurrences in the current D2 SavedDefinition block family. Their owner is the real D2 source owner, including a managed include when the occurrence lives there. Definitions do not gain a durable ViewRef or another author file. Native AsciiDoc is parsed once by D2; D7 consumes the typed product and never reparses exact source to recover semantics.

The retained author schemas for QuerySpec, ParameterSpec, TypedLiteral, TypeSpec, TerminalSchema, ViewSpec, ActionSpec, Query calls, defaults, feature gates, and errors remain closed. Unknown members, duplicate JSON keys, illegal null, or a value outside the declared decoder fail closed. Numeric validation remains owned by the exact field decoder: D7 arbitrary integer and decimal values use their canonical textual domains; D3/D6 counters keep their bounded integer rules; JSON Boolean is never accepted as an integer; negative zero, exponent forms, overflow, or nested numeric forms are accepted or rejected only where that exact declared decoder permits them. The six retained caller profiles keep their prior authorization-before-sensitive-read and exact numeric decode order; this integration does not globally widen numbers by changing an outer version.

## 5. Query DAG, canonicalization, and execution order

A Query is one strict author DAG with local author node IDs. Canonical form is independent of author ID spelling: dependencies are validated first, then a deterministic topological order is chosen by the retained canonicalOrdinal rules, expression AST member ordering, unsigned UTF-8 member ordering, numeric list/index ordering, sharing identity, and the separate call namespace. Cycles, duplicate local IDs, missing predecessors, invalid sharing, and query_ref recursion fail before execution.

Every semantically reachable branch keeps strict decode, type, feature, authorization, execution, and terminal checks. total and may_error are semantic properties, not optimizer hints. Budget exhaustion and cancellation are explicit outcomes. Optimizations may fuse or reorder only when bag multiplicity, output order, negative dependencies, authorization, errors including late errors, cancellation, and charged work remain observationally equal. Runtime budget is never rewritten into take, and an optimizer cannot skip a branch merely because earlier data appears sufficient.

## 6. Query algebra, K, and FactOrigin

The retained algebra remains bag, unnest with left and inner behavior, filter, project, sort, take, aggregate, distinct, query_ref, traverse, related with any and none, scalar, and graph. Generic join, window functions, and quantile stay deferred; a View or UI may not simulate them and claim D7 equivalence.

Structural one-hop traversal, D2 links, and D4 Field relations consume their real owners and complete positive and negative ranges. A symmetric D4 relation remains one authored fact at its canonical owner; a derived inverse or graph edge is explicitly derived. Computed equality never manufactures FactOrigin, a relation, or an implicit join. FactOrigin is either the actual asserted source fact or a named derivation with its dependencies. K remains internal execution identity and is never a public Ref, result handle, or author value.

Projection may erase action lineage only under the retained rules proving that no later Action selector, provenance, or evidence requirement depends on it. A displayed value can therefore be simpler than the internal execution record without granting the display value a write path.

## 14. Definition Transfer

Definition Transfer retains complete static typed traversal. It enumerates every typed Ref and every complete DefinitionAddress Locator root declared by the D7 schema, recursively through Optional, object, list, and union TypeSpec members. Ref-free recognized payloads still produce one transfer with slots empty. Paths order member segments by exact UTF-8 bytes, index segments numerically, and reject duplicates or ancestor/descendant overlap.

Ordinary text, labels, CEL source strings, free JSON, and UUID-looking literals are never scanned for identity. A source typed root is either mapped, explicitly preserved under the original same-Workspace rule, or a valid saved-definition Locator reissued under the two-pass rule. Cross-Workspace unprotected preservation rejects. Owner/locality and Resource/Annotation owner rules remain complete.

Q covers only the exact saved-definition payload span from the real complete source pin and binds the complete transfer. Materialization decodes the whole payload, verifies all slots, performs the first pass with an internal nondeliverable zero-coordinate template, parses the full candidate source, inserts real spans in the second pass, reparses, and requires span stability and unique occurrence resolution. Q, C, D4 typed transformation, provenance coordinates, and the final source share one revision basis and one commit.

Mutual references among existing definitions being copied or forked are supported through the same candidate map. Brand-new author definitions cannot fabricate direct symbolic references to not-yet-allocated fresh Nodes; that unsupported case remains a closed negative path. An unknown saved payload may remain as exact D2 source for reading, but typed transfer as a whole rejects and a full fork cannot silently omit or rewrite it.
