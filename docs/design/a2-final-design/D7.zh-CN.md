# A2 D7 Query、View、Action 与 DynamicBlock 整合

状态：这是 A2 当前 D7 作者候选；不构成独立接受、实现、激活、发布或产品测试证据。

## 1. 权威、优先级与保留的 owner 正文

D7 负责 Query 的作者定义与执行语义、纯 View 呈现、显式 Action 准备、不可变 preview/effect 交付、结果分页和订阅、Narrow Field 资格、Definition Transfer，以及保持惰性的 DynamicBlock 绑定层。Core 继续是唯一解释器和作者 effect 权威。D7 不新增第二套 parser、renderer 计算引擎、持久 Query/View/Record 身份、ledger、CAS 或文件权威。

已经协调完成的 D7 owner afterimage 逐字节复制到本目录 d7/owners，其中包括中英文主文以及含 34 个 concept、8 个 binding 的术语 Registry。除非本稿明确具名 supersede，复制内容继续是规范正文。本稿与 D7-SCHEMAS 只负责 fixed97 successor、当前 D2 产品消费方式以及 SEARCH-01 至 SEARCH-08 的 A2 当前补充层。若保留 owner 文件仍写旧 outer version，本补充层只在具名 current successor 上优先；历史 decoder 与 recovery 责任仍按原记录保留。

## 2. 当前版本分派与恢复分支

新的未见执行使用 fixed97 的真实当前外层类型：D3 wire13、InputDescriptor/3、DependencyProof/3、PreparedIntent/3、InstallationNotice/3、ContentCompletionProof/4、ChangeRecord/1、D7ActionPrepareRequest/3、D7ActionSpec/2、D7ActionInput/3、PreparedActionBinding/4、D7ProposedInput/3、EffectManifest/3 与 EffectBytes/3。Query 的外层执行仍是 wireVersion2；QuerySpec/1 与 ViewSpec/1 继续使用保留 D7 规范选定的作者 schema 版本。MinimumMapping/3 不机械升版。

真实 saved、planned、unknown 或已经 committed 的 predecessor record 必须按创建它们的精确版本分派。PAB3 与 D7ProposedInput/2 保留原 annotation-value decoder 与 pins，绝不能重新 pin 或改编码成 PAB4/Input3。旧 Result、evidence、selector、Draft、map、source token、preparation 或 preview transport 也不能因为当前仍能看到相同 bytes 就刷新成新权限。

## 3. 身份与地址分域

EntityRef、持久 D3 Locator、LogicalOccurrenceKey、ResultRowHandle、内部 provenance 与 ActionEvidence 属于不同数据域，不能互相强制转换。Node、Resource 和 Annotation 是持久内容域。Task 只是普通 Node 加 source 明确声明的 tasks/task Facet；Template 是 Core meta-kind。当前 D5 不建立持久 Record 或 RecordCollection，也不预留 RecordRef；同样不存在 TaskRef、ViewRef 或 FieldRef。

D4 authored provenance 是经过完整授权的作者值，不是执行权限。一个 Ref 或 provenance 即使当前不能 resolve 或写入，也可能仍被允许显示。path、filename、title、digest、result rank、index row、source coordinate 或相同 payload bytes 都不能创造内容身份或写权限。

包含 persistent Locator 的 portable QueryRef、DefinitionAddress、recipe address 或 Resource region，只能通过 D3 的稳定生产版本地址流程使用：先认证已记录的 production binding，再取得一份 fresh current SourceObservation，要求其完整 sourceVersion 与该生产版本逐字节相等，然后验证 owner、profile、coordinates、disclosure 和最终读取屏障。仅仅 bytes 或 revision 相同并不足够。这次新读取不会改写保存的地址，也不会复活旧 runtime evidence。

## 4. 作者定义与 D2 承载

保存的 Query、View 和 DynamicBlock definition 都是当前 D2 SavedDefinition block family 中的作者 occurrence。owner 必须是真实 D2 source owner；若 occurrence 位于 managed include，就属于该 include owner。definition 不会获得 durable ViewRef，也不会多出另一份作者文件。原生 AsciiDoc 只由 D2 parse 一次；D7 直接消费 typed product，不重新解析精确 source 来找回语义。

保留的 QuerySpec、ParameterSpec、TypedLiteral、TypeSpec、TerminalSchema、ViewSpec、ActionSpec、Query call、default、feature gate 和 error author schema 继续保持闭合。未知成员、重复 JSON key、非法 null 或超出声明 decoder 的值都必须失败。数值验证仍由具体字段的精确 decoder 所有：D7 的任意精度 integer/decimal 使用自己的 canonical 文本域；D3/D6 Counter 保持各自有界整数规则；JSON Boolean 不能冒充 integer；negative zero、指数形式、overflow 或嵌套数值表示只由对应的声明 decoder 决定是否合法。六个保留 caller profile 继续遵守“先授权，再读取敏感数据”和各自精确的数值解码顺序；本整合不会借外层版本变化全域放宽数值。

## 5. Query DAG、规范化与执行顺序

Query 只有一套严格的作者 DAG，并使用作者局部 node ID。canonical form 不依赖这些 ID 的拼写：先验证依赖，再根据既有 canonicalOrdinal、expression AST member 顺序、unsigned UTF-8 member 顺序、数值 list/index 顺序、sharing identity 和独立 call namespace 选择确定的拓扑排列。cycle、重复局部 ID、缺失前驱、非法 sharing 和 query_ref 递归都必须在执行前失败。

所有语义上可达的分支都保留严格 decode、type、feature、authorization、execution 和 terminal check。total 与 may_error 是语义属性，不是优化提示。预算耗尽和取消都是明确结果。优化只能在 bag multiplicity、输出顺序、negative dependency、授权、包括 late error 在内的错误、取消以及计费工作量都保持可观察等价时进行融合或重排。runtime budget 不能被改写成 take，optimizer 也不能因为早期结果“似乎足够”就跳过仍然可达的分支。

## 6. Query algebra、K 与 FactOrigin

保留的代数继续包括 bag、left/inner 两种 unnest、filter、project、sort、take、aggregate、distinct、query_ref、traverse、related 的 any/none、scalar 与 graph。generic join、window function 和 quantile 继续延期；View 或 UI 不得自行模拟这些运算后声称与 D7 等价。

结构 one-hop traversal、D2 link 和 D4 Field relation 必须消费各自真实 owner 及完整正负范围。symmetric D4 relation 仍只有 canonical owner 上的一份作者事实；派生 inverse 或 graph edge 必须明确标记为 derived。computed equality 不能凭空制造 FactOrigin、relation 或隐式 join。FactOrigin 要么指向真实 asserted source fact，要么是具名 derivation 及其依赖。K 只是内部执行身份，不是 public Ref、result handle 或作者值。

只有既有规则已经证明后续 Action selector、provenance 或 evidence 不再依赖 action lineage 时，projection 才能擦除该 lineage。因此显示值可以比内部执行记录更简洁，但显示值不会因此获得写路径。

## 7. D2 产品来源：标题、标题层级、正文与原生表格行

当前标题读取 D2DocumentMetadata/3。原生 title 可以不存在；filename、path、first paragraph、placeholder text 或 NodeRef 都不能补造标题。subtitle 使用已经选定的原生 Asciidoctor 2.0.26 title-separator 语义。默认仍是冒号加空格；显式 double-colon 形式继续合法，但本 D7 整合不会擅自把 double-colon 设成新的模板默认值。

当前 headings scan 严格解码 D2DocumentSnapshot/3，在最终 D7 读取屏障验证完整 evaluation binding，要求 projection available，并通过 D7 TypeSpec 的 integer canonical decimal 使用 D2Heading/3 effectiveLevel。合法 effective level 是任意精度非负整数；旧 int64 result schema 只属于历史。H6–H9 以及 leveloffset 产生的更大 effective level 都继续合法。

body_text 递归消费完整 D2DocumentBody/3 和 D2ProductInline/3 family，包括 list、原生 table、block cell、literal/source payload、link/label、passthrough、STEM、media 语义、惰性的 saved-definition block、run-in/deep heading 结构，以及全部 source-origin/currentness 依赖。它输出语义文本，不是精确 source，也不是可写映射。若某个合法 D2 arm 没有 body_text 投影，该 source adapter 必须报告 unavailable，不能因此缩小 D2 语法、调用 to-string 压平，或重新解析 source。

原生 table row/cell Query 使用当前 D2 locator 与 physical grid 语义，同时保持 D5 的 occurrence-only row domain；它不会建立持久 row identity。

## 8. Annotation 文本与当前读取屏障

当前 Annotation body Query 必须先完成实际 read profile 要求的 Annotation disclosure、annotation_read、aggregate/currentness 以及 target-resolution gate，之后才读取当前 PortableAnnotationRecord/4。body 缺席映射为空 D7 text。合法 body 返回 R6 semantic text，例如 source 中的 *Alice* 返回语义文本 Alice。Annotation 精确 source 只通过 D8 read/Draft 入口暴露。若已经获权并取得当前 record 后发现 R6 非法，整次 D7 读取返回既有 source-unavailable 结果；不得回退到历史 plain-text 或自行剥离标记。

如果 Annotation 本身可读而 target 不可用，只能暴露 Annotation read profile 已经授权的信息。不能为了生成 Query snippet 而额外读取 target bytes。

## 9. Value、CEL、D4 bridge 与时间值

既有 D7 Value/CEL profile 继续是唯一 expression language。constructor、expected type、literal/nonliteral、Optional、union、list bound、任意精度 integer/decimal、Unicode profile、lazy、total、may_error、overload、禁止 null、Equality 与 Order 都保持保留 owner source 的精确定义。host double、locale collation、host date library 或隐式数值升型都不能补充缺失语义。

D4 Field value 保留作者顺序、qualifier、note、完整 provenance 与 raw Entry bytes。Optional absence 不是 null 或 empty。动态 calendar 与 quantity comparison 必须使用已验证的 D4 Registry basis、unit、calendar comparator、timezone/tzdb evidence 和精确 numeric bridge。D7 不从本地化标签或 column heading 猜测 Field type。

DerivedDuration 归 D4 所有且只读。bounded date range 依据已验证 calendar basis 产生 calendar units；bounded instant range 产生精确 elapsed seconds；open range 只有在其它必要 provider gate 通过后才产生具名 unavailable 结果。它永远不是作者替代事实。

Recurrence 与 DerivedPeriodRange 消费完整 D4 recurrence source、七成员 period identity、series identity、五种 ISO civil profile、Registry/temporal-rules proof、有限 coverage、endpoint rule 与 negative dependency。endpoint_out_of_domain 与 unsupported_calendar 必须保持显式。Calendar 和 Timeline Query 要区分正常正向选择与 all-items-unavailable；provider 缺失时不能静默裁剪范围、建立第二 cut、隐式创建 Event/reminder fact 或使用 host timezone 默认值。

## 10. SearchContribution 与搜索整合

SearchContribution 继续是 D7 所有的纯数据对象，由 D10 的 view contribution envelope 承载；它不是 ViewSpec，也不会新增 search ContributionKind。active set 由 D10 activation generation、Capability Catalog digest 和准确 D4 RegistryBinding 共同绑定。显式选择绑定准确的 contributionId/version 行；all 绑定该 generation 下的完整集合。Contribution 增删、owner 变化、descriptor 变化、version 变化或 Registry 变化都会使旧 search dependency/result 失效，不能静默换字段。

每个已选 Contribution 指向一个当前 Field 和经过验证的静态 textPath，其终点只能是 text 或 Optional text，role 只能是 name、alias 或 content。Optional none 表示缺席，不是 empty text。D10 carrier 不授 field read、index-private payload、network、secret、script、alias-source 或 author-write 权限。执行仍是 scan、显式获权读取、既有 D7 match/rank、显式 sort/project；若请求完整结果，还必须有完整 query_scan proof。若选中的 Contribution 缺失或不可用，使用既有 D7 unavailable 结果，不能跳过后报告“空搜索成功”。

面向用户的搜索设计以及 SEARCH-01 至 SEARCH-08 由 D7-SEARCH 规范化。Search 只是把便利交互编译到同一 Query 语义，不是第二执行器，也不是第二持久权威。

## 11. Narrow Field 资格

Narrow Field 资格从完整当前 Registry 出发，在读取任何隐藏数据前，为精确 Field、value path、qualifier、provenance root、constraint、relation/calendar requirement 和 requested mutation 计算潜在依赖闭包。source_envelope_state 与 commit_sequence_state 是两项独立授权事实，互不自动授予。当前来源资格使用 owner_fields profile 下完整 SourceObservation/Ref evidence。

phone 正例只修改第二个被选中的等值 Entry 的 text member。FieldId、occurrenceKey、qualifier、note、provenance、其它 Entry、未触及 Ref bytes、comment、whitespace 与 source trivia 全部逐字节保持。若 unresolved authored Ref 的 target state 与该 member edit 无关，就不能添加 target-state 依赖。Core 必须逐项比较完整 before/after/effects/replay 的公开结果、授权 metadata 和随机 token coupling。不能信任一个 Boolean 来声称“这是窄操作”，也不能先读取隐藏值后再决定范围。

若静态潜在闭包或实际 read tracking 无法证明与未授权范围独立，就使用真实完整范围或失败。Narrow qualification 不会放宽 D4 type/requiredness、D6 install protection 或 D7 preview 要求。

## 12. 当前 Action 准备与 binding

当前 Query 外层 wireVersion2 与当前 Action prepare wireVersion3 彼此独立。D7ActionSpec/2、D7ActionPrepareRequest/3、D7ActionInput/3 不是 QuerySpec/1 或 ViewSpec/1 的机械升版。PreparedActionBinding/4 携带 Descriptor3、Proof3、PreparedIntent3 observation proof、精确 request、完整当前语义 preview、source/definition/Registry/rule/proposed inputs 与 BudgetBinding。MinimumMapping/3 以及保留的 inner definition type 使用各自真实版本。

D7ProposedInput/3 只接受 D7-SCHEMAS 定义的当前 payload/encoding 组合。当前 concrete Annotation 后像 pin 完整 Value/4；symbolic D3 分支保留 Result/9。历史 Input2 继续保留自己的 annotation-value3 bytes；当前 decoder 不能把新字节塞进旧 tag。

新的 bindingToken 随机生成，并单向关联完整冻结的 request、owner record、input map、guard 与 PreparedActionBinding。不存在 request-hash cycle、第二 ledger、第二 CAS、提前 content ID 或 seal 前 ChangeId。所有 request/call/definition/rule/Registry/source/proposed input、pins、proof、budget 与 preview 都在原 planning boundary 原子冻结，并继续遵守 minimum disclosure。

## 13. Source plan 角色与唯一 final decision

inner source plan 保持真实 owner version：ordinary/fresh managed source 使用 SourceRevisionPlan/1；guarded D3 canonical-conflict materialization 使用 /2；D6 source_merge 或 choose_source_head 使用 /3。外层版本升级绝不能把这三个角色统一重编号。

SourceVersion 是生产历史地址；SourceObservation 是当前接收端资格。Definition Transfer 的 C/Q materialization 在 publication 前冻结 private candidate map、proposed stable revision token、source plan 与两遍处理。只有 winning original planning CAS 和 final P 可以产生唯一 seal、outbox item、source artifact、managed SourceVersion 与 ChangeId。losing、aborted、reused 或 stale plan 不能借用另一 decision 的 H+1、seal、token 或 result。

## 14. Definition Transfer

Definition Transfer 保留完整的静态 typed traversal。它枚举 D7 schema 声明的每个 typed Ref 和每个完整 DefinitionAddress Locator root，并按照 TypeSpec 递归进入 Optional、object、list 与 union。已经识别且 Ref-free 的 payload 仍生成 slots 为空的 transfer。path 中 member segment 按准确 UTF-8 bytes 排序，index segment 按数值排序，并拒绝 duplicate 或 ancestor/descendant overlap。

普通文本、label、CEL source string、free JSON 和看起来像 UUID 的 literal 都不能扫描身份。source typed root 必须是 mapped、按原 same-Workspace 规则显式 preserve，或按两遍规则重新签发的合法 saved-definition Locator。未受保护的跨 Workspace preserve 必须拒绝；owner/locality 与 Resource/Annotation owner 规则全部保留。

Q 只覆盖真实完整 source pin 中准确的 saved-definition payload span，并绑定完整 transfer。materialization 先完整解码 payload 并核对全部 slots；第一遍使用内部且不可交付的 zero-coordinate template，解析完整 candidate source；第二遍填入真实 span 后再次解析，并要求 span 稳定以及 occurrence 唯一。Q、C、D4 typed transformation、provenance coordinate 与 final source 共用同一 revision basis 和同一次 commit。

copy/fork 中既有 definition 之间的 mutual ref 通过同一 candidate map 正向支持。全新的作者 definition 不能伪造直接指向本 operation 尚未 allocation 的 fresh Node 的 symbolic ref；该不支持情况必须保持闭合负路径。未知 saved payload 可以作为准确 D2 source 保留读取，但 typed transfer 整体拒绝，full fork 不能静默省略或自动重写。

## 15. Result、分页、缓存与订阅

Result 保留既有 schema、Value encoding、bag/order guarantee、paging epoch、result authorization generation 与完整 dependency cut。page 不是 result；empty nonterminal page 不是 EOF。scalar none 继续使用既有的单项 scalar result 表示，而不是改变结果 cardinality 语义。Graph output 继续按确定顺序先输出 nodes 再输出 edges，并保留 asserted/derived edge origin。

result handle、cursor、row handle、cached index row 或旧 ActionEvidence 都不是当前权限。schema、authorization generation、完整 cut dependency 或 epoch 任一变化，都按既有规则 reset。numeric transport 必须保持精确，不能经 host 浮点舍入。

Subscription replacement 是原子过程：先验证完整 new epoch，再把 remove-all old rows 与 upsert-all new rows 作为一个可观察 replacement。gap、unknown equivalence、schema drift 或 authorization-generation change 必须 reset，不能混用 epoch。不同 result epoch 之间不存在永久 row identity。

## 16. Action 与 target set

Action 必须显式，并与 View 呈现分离。all_result 绑定完整 terminal result，绝不是 current page。pre/post query、TargetSet、selector、FieldSelection、Facet operation、native checklist/table、collection create/remove、D3 operation 与 bulk Field Action 全部保留真实 owner interface 与 limit；当前 D5 的 target/row 上限不变。

fresh Action 不需要旧 Query token；它可以对同一闭合 definition 在当前授权下执行新的完整 Query。反过来，旧 ResultHandle、ActionEvidence、selector 或 row handle 永远不能续权。从 result 选择目标时冻结精确 targets 与当前 result epoch；sort、page、refresh、reset 或授权变化使旧 evidence 失效，不能按屏幕位置重新绑定新行。

默认确认仍是在完整 preview 后由用户显式进行。D10 unattended single-field-member 例外只允许 Core 在 fresh complete D7 prepare 和 Narrow Field qualification 都成功后机械消费；它不新增 caller approval flag，也不放宽 parser 或 selector。fixed97 当前 prepare 使用 PAB4/Effect3，即使更早 D10 文字仍提到 predecessor PAB3/Effect2；历史 automation record 继续按原 decoder 恢复。stop association 是受保护的内部 execution responsibility，不新增 ActionSpec member。

## 17. 纯 View 与惰性 DynamicBlock

View 只对完整 result 做纯呈现。layout、option、结果类型要求、ordering、geometry、basis/domain、panel/series、empty/zero/sparse/missing、late error、budget、accessibility、RTL、keyboard/mobile 与 export projection 都按既有 View 规范闭合。View 不能为了“显示更好”而额外读取隐藏数据，也不能执行 Query 未定义的 join、unpivot、aggregate、relation discovery 或作者写入。

circle/layered network 必须保留 isolated node、self edge、parallel edge、cycle、asserted/derived fact 与 literal relative。nodeDetails 只是既有 relative 的字面呈现，不进行新的 relation lookup。RTL 只改变容器布局，不改变 Query sort、edge from-to、technical token、timeline direction 或数据含义。

DynamicBlock 只保存真实 Query/View call 以及既有作者 schema 允许的 declared binding。它不保存 result handle、当前 evidence、source token、preview token、UI preference、personal direction、cache state 或授权。refresh 必须在当前资格下建立一份全新的完整 call。

## 18. EffectManifest、EffectBytes 与交付

EffectManifest/3 是 fresh current Action 的当前共享语义 effect family；preview 与 committed 是同一原始 decision 的不同 phase。每个 item 和 byte slot 都必须在 publication 前完成验证。conditional effect 要保留真实的 source-change/version 分支，以及该 Action 实际需要的 source/entity/control/restore/bootstrap/typed-transfer/canonical/full/narrow owner effect。遗漏 item 不能从当前文件补算。

EffectBytes/3 是有限且独立的读取权限。打开字节槽时要重新检查真实 role、phase、delivery epoch、pin、当前 disclosure、byte range、decoder 与 budget；header metadata 或 digest 本身不能暴露 payload。因此整页读取与单独 slot 读取都要分别授权，但语义必须一致。

重新打开 planned preview 或 committed effects 时，只有先定位原始 request 和受保护 record，才能签发新的有限 delivery epoch。这个动作不改变 decision、request、OperationId、binding token、旧 transport epoch 的 TTL、mutation 或 effect bytes。effects_unavailable 必须保留原始 saved fact 和仍需的 last-reference pins；Core 不能重做 mutation，也不能拿相等的当前文件代替历史 effect。

## 19. 历史数据、migration 与 activation

saved outcome 在针对原 disclosure scope 通过当前交付授权后，重放原始 receipt/error/effect bytes。planned 恢复原始 request、descriptor/proof、binding、pins、Notice、install state、source plan、candidate map、OperationId、custody、clock、budget、outbox 与 installation evidence。unknown 保留 Approval、Money、claim、external-effect、stop 以及“不重复 effect”的责任。只有真正 unseen 才进入当前 successor gate。

新的 unseen eligibility rule 不能追溯拒绝或改写旧 plan。旧设计文字存在并不能证明 prototype 实际部署过，因此不能据此制造永久 migration；反过来，真实 old record 的义务也不会因为另一个 prototype 未部署而消失。candidate schema 发布、implementation、activation、migration 和 independent acceptance 必须保持分层。

## 20. Terminology 与 Registry
