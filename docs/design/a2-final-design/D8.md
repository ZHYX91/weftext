## 1. One authority, independent state axes, and version boundaries

D8 has one Core parser, one current Source authority, and the original D3/D6 commit/CAS/P path. Desktop, CLI, local Mobile Core, and Server Core use the same semantics; WebUI calls Server. UI, renderer, DOM, index, cache, Worker, Agent, and plugin code cannot become a second parser, Query engine, source store, or author ledger.

An edit session keeps four independent axes.

1. Base/author cut binds the exact current SourceObservation/1, production SourceVersion/2, document_format, authorization/control/range dependencies, and the corresponding source bytes.
2. Draft is a nonauthoritative proposal with a monotonic draftSerial.
3. Input state binds native input/composition generation, inputSerial, selection, the single in-flight transform, and the complete successor input log.
4. Access/submission binds current read/write capability, prepared binding, preview, confirmation, D6 decision, and recovery state.

A receipt proves only the real decision of the original request. It never overwrites local Draft or selection. Revocation, stale Base, or response arrival cannot advance Base early. After an authorized real receipt is consumed, Base may advance to the actual after-image; buffer clean/dirty is then derived by exact equality between the current Draft and after. Undo may return to bytes equal to after and therefore become clean, but draftSerial remains a newer value. Equal bytes never revive an old production version, Observation, OperationId, Annotation token, selector, or CAS identity and never relax ABA protection.

Current versions are intentionally not uniform.

- Document read, Draft projection, text replacement, and Draft write remain D8 wireVersion 2.
- Current author preparation uses D8EditPrepareRequest/3, D8EditInput/3, and PreparedEditBinding/3.
- Current D6 preparation uses InputDescriptor/3, DependencyProof/3, PreparedIntent/3, and d6_commit_request/2.
- Current preview uses EffectManifest/3 and EffectBytes/3.
- Current portable Annotation uses PortableAnnotationRecord/4, D3-Annotation-Value/4, and AnnotationInlineBody/1.
- Annotation read/draft remains the separate D8 /1 family.
- Presentation policy uses the logical D8WorkspacePresentationPolicy/1 view over immutable /2 records/head graph and D8PresentationPolicySetRequest/2.

Genuine historical wire1/wire2 edit families, PreparedEditBinding/1-/2, Value/3, old D2 Annotation profiles, and older effects remain recoverable only through their recorded decoder, bytes, pins, permissions, and recovery order. No current decoder mechanically widens them.

## 2. Current D2 AsciiDoc: complete Source and optional rich adapters

Current managed Document semantics come from D2DocumentSnapshot/3 and the product projection generated from the fixed Asciidoctor Ruby 2.0.26 baseline. D8 does not preserve the historical H1-H5, 16-body/5-Inline, no-bold/no-math/no-macro reduced dialect.

Current legal Source includes title, subtitle, and titleless documents; authored H1-H9, arbitrary-precision effective levels, discrete/float headings, paragraph/run-in presentation; strong, emphasis, strike, links, citations, references, STEM, Mermaid, and their real backend/profile boundaries; and the complete current D2 attribute/include/substitution/provider semantics.

Native AsciiDoc tables retain header/footer, column specifications, colspan/rowspan, multiline and block cells, advanced cell styles, ragged rows/trivia, and legal nested block content. A legal shape may lack a rich editing adapter without becoming invalid.

Every current product value keeps the real sourceOrigins supplied by the D2 owner. Managed includes bind the current Observation and complete product-evaluation dependencies of the included source. Generated, multi-origin, ambiguous, or non-author values can remain readable while rich structured editing is unavailable.

When the current D2 product does not provide a unique writable origin and complete source range, D8 does not infer one from displayed text, HTML, DOM, or renderer output. Source view/read, exact-source Draft, ordinary exact-source save, and explicit repair remain available under their original authorization and semantic gates.

## 3. Draft Edit Map, coordinate domains, and byte invariants

d8_draft_projection carries proposal-local flows/plainRegions/sites plus independent navigation origins. None is a Ref, Locator, durable paragraph identity, or cross-revision address. A map is bound to ownerNodeRef, baseObservation, draftSerial, and source; changing any member requires a fresh projection.

### 3.1 Editable mapping

Every addressable body or Inline slot is identified by a schema BodyPath. Repeated cells, equal text, and identical labels remain distinct by path and are never disambiguated through display-string search or DOM order.

A flow covers one complete logical Inline slot. A segment is directly writable only when Core proves a scalar-for-scalar relation to one raw Source span. Escape, join, atom, generated, and multi-origin content stays read-only for scalar editing even when it has a real navigation origin. U+FFFC is only a local coordinate placeholder and never enters author Source.

A plainRegion is one maximal contiguous raw ordinary-text region under one parent. It preserves spaces, tabs, LF, CRLF, CR, BOM context, trailing EOLs, and every unselected byte. CRLF is indivisible. The region may be empty, blank-only, or EOL-only when the exact current parse permits it.

A site is a Core-proved legal sibling boundary. Empty body, blank-only state, non-column-zero EOF, header/carrier/comment endings, anchor boundaries, and protected structures are handled through sites and full reparsing rather than string concatenation.

UTF-8 bytes, DOM UTF-16 code units, Unicode scalars, extended grapheme clusters, logical EOL units, and visual caret positions are separate coordinate domains. Every conversion uses the same exact string and validates its boundaries.

Navigation origins and editable mapping are separate. Escape/join/atom/generated values can navigate back to real source ranges without thereby gaining scalar write authority. Fuzzy relocation, latest-source substitution, or DOM-order recovery is forbidden.

### 3.2 Write equivalence

d8_draft_text_replace edits only one proved writable flow segment. d8_draft_write has only splice_plain, break_plain, and insert_at_site.

A successful operation must prove all of the following.

1. Every byte outside the selected Source slice is unchanged.
2. Complete reparsing succeeds.
3. After stripping only transient Locators/coordinates, all non-target metadata, carrier state, body structure, sourceOrigins, and raw values remain equal.
4. New nonblank text remains ordinary inert text and does not silently create a heading, list, table, macro, comment, anchor, protected construct, or parent change.
5. Every new scalar originates in this operation.
6. The returned caret is uniquely reconstructible in the successor map.

insert_at_site evaluates the nine combinations in which prefix and suffix contain zero, one, or two selected EOL units. It chooses the candidate with the least total generated EOLs and then the least prefix count. Only generated EOLs use the local EOL policy; existing and explicitly pasted EOLs are preserved byte-for-byte.

Deleting the final nonblank text, retaining only spaces/tabs, entering an empty body, ordinary Enter, paragraph split, paragraph merge, deleting blanks, and retyping must remain representable and reversible Draft states. Write never normalizes CRLF to LF, cleans unrelated trivia, or serializes rich display text back into Source.

## 4. Async input, IME, and Draft Undo/Redo

Each controller has at most one Core transform in flight. The transaction freezes before Source, before selection, native after text, native after selection, generation, inputSerial, draftSerial, and the complete successor input log. A late response can finish only its own generation and cannot overwrite or drop later native input.

IME begin/update is preedit. It may be displayed locally but is neither the current projection nor preparable content. IME end/final input becomes one complete input transaction and one Draft Undo group. Enter, slash commands, structural commands, save, and submit cannot preempt active composition. Cancel, blur, backgrounding, revocation, or owner switch cannot fabricate an author write.

One host owns composition for a logical editor. DOM and Core cannot both mutate the same composition stream. Screen-reader live regions must not announce every preedit character as a committed edit.

Source/Write/Read for the same owner share one Draft Undo/Redo stack and the system Undo adapter. Undo/Redo always allocates a new monotonic serial and requests a fresh projection; it never restores an old serial or map. External/background author commits, other-owner changes, sync changes, and Agent results do not enter that stack. They may instead make a later prepare stale and require a fresh rebase/reprepare.

## 5. Clipboard, cut, paste, and cross-owner data

Copy Text emits logical readable text. RTL visual order never reverses the copied or replacement character order. Copy Source Fragment emits only currently authorized real Source origins; synthetic joins, display-only labels, and renderer text are not substituted for Source.

Explicit native-table or row TSV copy is inert logical text. Paste defaults to text/plain and enters the ordinary Write path as inert input. HTML, RTF, script, code, links, or macros are never executed merely because the clipboard carries them.

If no plain flavor exists, current D8 is unavailable. Future rich clipboard support must use D9 isolated conversion, typed mapping, explicit loss reporting, and a separate editing adapter; it cannot silently change default paste semantics.

An unrepresentable paste fails as one transaction; it cannot apply the representable subset. Cut first proves the real OS clipboard write succeeded and only then deletes the frozen selection. Clipboard failure leaves Source unchanged.

Cross-owner Resource or attachment copy/download keeps the original read/download authorization. A displayed ResourceRef, path, or textual token grants no Resource-byte capability.

## 7. Committed Undo and Redo

Single-Source committed Undo is available only when current authorization is still valid, the original request/receipt/effects are recoverable, the original decision had exactly one source change and no other control/identity/entity effect, all required before/after pins remain, and the current production version and bytes both exactly equal the original after-image.

Undo produces a fresh inverse plan, fresh OperationId, complete preview, explicit confirmation, and fresh CAS/P. Redo is another fresh forward operation. Neither rolls back another actor's later commit, treats byte-equal ABA as the original production version, revives an old Draft map/selector/ActionEvidence/PAB, resurrects an old capability, or promises cross-Workspace atomic rollback.

### 11.1 Current View builder lifecycle and author route

The View builder is a non-authoritative editor over the **current D7 closed contracts**. It consumes only the current D7 Query/Definition owner, the query's current terminal schema, `ViewSpec/1`, and (where the authored occurrence is a dynamic block) the existing `DynamicBlock/1` binding. It does not create a D8 View schema, parser, Registry row, ledger, durable UI record, Query language, or second persistence authority.

Opening the builder first performs the normal current definition read and qualification, strict-decodes the exact recorded ViewSpec version, obtains the current terminal schema from the real Query/Definition owner, and runs only the **definition-save gate** before enabling controls: closed ViewSpec shape plus current definition authorization/owner/revision, terminal schema, and static layout/binding/type/option compatibility. This gate consumes no ResultHandle pages or values and does not inspect semantic keys/order, numeric/domain/hierarchy data, renderer budget, provider state, or delivery state. A stale definition, moved owner, permission loss, unavailable current Query/schema, unknown ViewSpec version/member, or static definition failure leaves the exact authored bytes untouched and routes to a typed error or the advanced/source editor; the builder never repairs or normalizes such input on open.

A basic control may edit only members it can express without loss: the current closed `layout`, the layout's declared bindings by stable `columnId`, and the declared common/per-layout options. Query transforms, filters, grouping, aggregation, derived values, and sort remain Query edits and are changed only through the existing D7 Query author route. Legal ViewSpec members that a basic control cannot represent are retained byte-for-byte in the working value and are surfaced through the advanced ViewSpec route. Changing another basic member cannot silently delete, default, reorder, or rewrite those retained members.

New definitions initialize only from a user-selected current Query/Definition plus its validated terminal schema and a complete statically valid `ViewSpec/1`; there is no ambient “best” layout or hidden inferred binding. Cancel discards the builder draft and restores the exact opened definition. Save re-runs that same definition-save gate, rechecks current authorization/owner/revision, and submits through the **existing SavedDefinition/DynamicBlock owner action and its D6 commit path**. It does not require a Query execution, complete result, or renderable current data. Stale or revoked definition state, owner movement, or terminal-schema change requires a fresh read/reopen/reprepare; no blind overwrite is allowed. Reopen decodes the actually saved owner bytes and must reproduce the same expressible controls plus the same retained advanced members.

Runtime View validation is separate and begins only when a current ResultHandle is rendered or externally exported. It follows the existing D7 View §7 order unchanged: closed decode → current result authorization/epoch → complete result → exact schema → layout/binding types → whole-data structure/order → domain/numbers → budget → current delivery gate. Runtime failures such as `incomplete_result`, `duplicate_key`, `invalid_order`, `negative_value`, hierarchy/domain failure, budget failure, offline/provider/data unavailability, or renderer failure suppress that render/export and never invalidate or rewrite an otherwise statically legal saved definition. For example, a statically legal pie ViewSpec can be saved while the current Query result contains -1; execution/render then returns `negative_value`, draws no chart, and leaves the definition unchanged.

The fixed-S candidate spelling `.weftext-query view=...` is **not** promoted to a new current author schema: no current owner definition for that spelling exists in this candidate. Genuine saved/historical bytes continue only through the decoder and recovery rules that actually created them. Current authoring emits the current D2 SavedDefinition/D7 definition forms. If an implementation encounters that legacy source spelling, exact Source remains readable/editable under its real owner; the UI may offer an explicit conversion only when the current D7 Definition Transfer/current owner can prove a complete supported mapping. Otherwise it remains source/advanced-only and is never silently migrated, re-encoded, or discarded.

`DynamicBlock/1` is retained as the current inert author entry described by D7: it stores only the real Query/View call and declared bindings. Editing its View opens the same builder over its current `ViewSpec/1`; saving updates the authored DynamicBlock/SavedDefinition through its existing owner operation. Result handles, preview/currentness evidence, cache state, device interaction, authorization, and builder state never become DynamicBlock members.

Surface parity is semantic rather than pixel-identical. Desktop, WebUI, and Mobile may expose the graphical builder when that capability exists; all three must offer a lossless advanced/source route for legal members the basic UI cannot express. WebUI uses Server Core. CLI and Server expose the same strict ViewSpec read/validate/save semantics and typed errors without claiming graphical rendering. ## 13. Performance, budgets, and virtualization

The original D8 gates remain unchanged.

- Input-to-visible feedback p95 <= 50 ms.
- Layout feedback p95 <= 100 ms.
- At least 1000 events per measured group, with three cold and three warm runs.
- Desktop: 10 MiB and 100000 lines.
- Mobile: 1 MiB and 10000 lines.
- One line: 1 MiB.
- A 10x over-limit case must reject or degrade deterministically rather than crash or claim success.
- Navigation: 100000 Nodes.
- Query/edit grids: 10000 rows with transport page <= 200.
- Steady editor memory: Desktop <= 256 MiB, Mobile <= 128 MiB.

Narrower D5/D6 policy or strong-operation budgets may reject earlier but never widen these limits. Budget failure preserves the complete Draft and dirty state, never truncates Source, splits a transaction, or clears dirty state.

CPU-heavy parse/layout work cannot block the UI thread. Incremental parse/map/layout is a legal optimization only when its complete parse tree, diagnostics, ranges, and sourceOrigins equal the full computation. Virtualization is presentation only and never a second authority or proof of complete Query membership.
