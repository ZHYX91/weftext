Status: **author-resolved-pending-independent**. This candidate inherits the bounded D1–D7 conclusions already independently closed before fixed `26be071d4c2075343d9ebf272e00f23769ce0d64`. ## 1. One authority, state axes, and version boundaries

D8 has one Core parser, one current Source authority, and the original D3/D6 commit/CAS/P path. Desktop, CLI, Mobile local Core, and Server Core use the same semantics; WebUI calls Server. UI, renderer, DOM, index, cache, Worker, Agent, and plugins cannot become a second parser, Query engine, source store, or author ledger.

An editing session keeps four independent state axes: (1) the exact Base/author cut with current SourceObservation/1, production SourceVersion/2, document_format and authorization/control/range dependencies; (2) nonauthoritative Draft plus monotonic draftSerial; (3) native input/composition generation, inputSerial, selection, one in-flight transform and successor input log; and (4) access/submission state including current capabilities, prepared binding, preview, confirmation, and D6 decision/recovery.

A receipt proves only the original request's real author decision; it never overwrites the local Draft/selection. Loss of authorization, stale Base, or response arrival cannot advance Base early. Base changes only after an authorized real receipt is consumed; buffer cleanliness is then exact Draft-vs-after equality. Undo may return to after and become clean while retaining a newer draftSerial. Equal bytes never revive an old production version, Observation, OperationId, Annotation token, or CAS identity.

Current versions are intentionally nonuniform: document read/Draft projection/TextReplace/DraftWrite remain D8 wireVersion2; current author prepare is D8EditPrepareRequest/3 → D8EditInput/3 → PreparedEditBinding/3 → InputDescriptor/3 + DependencyProof/3 + PreparedIntent/3 → d6_commit_request/2 with EffectManifest/3 and EffectBytes/3. Current Annotation is PortableAnnotationRecord/4 + D3-Annotation-Value/4 + AnnotationInlineBody/1; Annotation read/draft is its own /1 family; presentation policy uses a logical /1 view over immutable /2 records/head graph and D8PresentationPolicySetRequest/2. Genuine older wire/Edit/PAB/Value families recover under their recorded decoders only.

## 2. Current D2 AsciiDoc: complete Source, optional rich adapter

Managed Document semantics come from D2DocumentSnapshot/3 produced from the fixed Asciidoctor Ruby 2.0.26 baseline. D8 does not preserve the obsolete H1–H5, 16-body/5-Inline, no-bold/no-math/no-macro dialect. Current Source includes title/subtitle/titleless, authored H1–H9 and deep/discrete/run-in semantics, strong/emphasis/strike, links/citations/refs, STEM/Mermaid under their real backend boundaries, full native tables including spans and block/multiline cells, complete attribute/include/substitution products and per-value sourceOrigins, plus byte-preserving unknown/inert constructs.

A legal Source never becomes invalid because no rich adapter exists. Rich Write is available only when the current D2 product supplies a unique writable origin/range and real write qualification. Otherwise Source read/view, exact-source Draft/save/repair remain legal. D8 never reverse-engineers Source from display text, HTML, DOM, or renderer output.

## 3. Draft Edit Map, coordinates, and byte preservation

d8_draft_projection carries proposal-local flows/plainRegions/sites plus independent navigation origins; none is a Locator, Ref, or cross-version address. BodyPath follows the closed D2 schema, equal text never disambiguates occurrences, flow uses coordinate placeholders only locally, plainRegion is maximal raw exact ordinary text under one parent, and site is a Core-proved sibling boundary. UTF-8, UTF-16, scalar, grapheme, logical-EOL, and visual caret coordinates are separate validated layers. CRLF is indivisible, BOM/mixed EOL and every unselected byte survive exactly.

Navigation is independent of editability: escape/join/atom/generated content can map to real source origins without granting scalar write. Every map is bound to ownerNodeRef/baseObservation/draftSerial/source and becomes unusable when any member changes.

TextReplace and splice_plain/break_plain/insert_at_site succeed only if the selected source slice is the only changed byte range, full reparse is valid, all non-target semantics/raw values remain equal, new nonblank lines stay inert ordinary text, every new scalar comes from the edit, and the returned caret is uniquely represented in the successor map. Empty/blank/space/tab states, paragraph split/merge, deleting the final nonblank text, and retyping remain representable Draft states without trivia/EOL normalization.

## 4. Async input, IME, and Draft Undo

One controller has at most one Core transform in flight. Each request freezes before/after native text, selection, generation, inputSerial, draftSerial, and the successor input log. Late responses finish only their generation and cannot overwrite or discard later native input.

IME begin/update is preedit, not a preparable projection. Final composition is one input transaction/Undo group. Enter, slash/structural commands and submit cannot race active composition; cancel/blur/background cannot fabricate an author write. One host owns composition. Screen-reader live regions do not announce every preedit mutation.

Source/Write/Read for one owner share one Draft Undo/Redo stack and system-Undo adapter. Undo/Redo always allocate new serials and fresh projections; old maps/serials do not revive. External/background/other-owner author commits stay outside that stack.

## 5. Clipboard

Copy Text emits logical readable order. Copy Source Fragment emits currently authorized exact source origins, including real run-in trivia rather than synthetic joins. Explicit table/row TSV is inert logical text only.

Paste defaults to text/plain and inert Write. HTML/RTF/script/code/link/macro content is never executed. With no plain flavor, current D8 is unavailable; future rich clipboard must pass D9 isolated conversion/mapping/loss plus a separate editing adapter. An unrepresentable transaction fails wholly. Cut writes the real OS clipboard first and deletes Source only after success. RTL display never reverses replacement bytes. Resource/attachment copy/download uses its own authorization.

## 6. Save, PreparedEditBinding/3, preview, recovery

Legal one-Document ordinary+replica_local saves may use D6 local_source. observed_only is limited to the trusted interactive existing-Document full-source case with exact current Base and no other identity/control/shared-policy/Registry/etc. effect. Annotation, Undo, structured/bulk/collection/automation/managed_atomic operations remain strict and use their actual workspace_constraints/complete proof. Missing strong proof blocks only the operation that needs it, not ordinary source read/Draft/repair/save.

Current prepare freezes the complete PreparedEditBinding/3: real request and OperationId, SourceObservation/sourceInputs, proposed pins, Registry inputs, DependencyProof/3, PreparedIntent/3 observationProof, budget/TTL, EffectManifest/3 and EffectBytes/3. Confirmation requires the complete preview inventory/pages/byte ranges/epoch; a summary or one page is not the preview.

Saved/planned/unknown recovery dispatches the original record version first and restores exact bytes, pins, request, OperationId, planToken, decoder, and responsibility. Unknown outcomes are not retried under a new ID and historical records are not upgraded to an undeployed candidate.

## 7. Committed Undo / Redo

Committed Source Undo is allowed only with current authorization, recovery of the exact original request/receipt/effects, exactly one source change and no other control/identity/entity effect, complete before/after pins, and exact current production version plus bytes equal to the original after. It then creates a fresh inverse plan and OperationId through full preview/confirm/CAS/P. Redo is another fresh operation. It never rolls back somebody else's later commit, treats byte-equal ABA as the old version, reuses old Draft/selector/ActionEvidence/PAB, or provides cross-Workspace atomic rollback.

Draft edits only the editable proposal subset. AnnotationInlineBody/1 is the fixed one-paragraph R6 Asciidoctor 2.0.26 inline profile; invalid rich body preserves exact source+diagnostics and has no plain_text or second-parser fallback.

Document/document_element/document_range/resource/resource_region targets retain distinct stale/current rules. Stable production address and this receiver's current Observation are separate. Fresh qualification never rewrites the persisted target or revives old Draft/map/PAB/PreparedIntent/ActionEvidence. Resource regions additionally require the D9 d9rg1 profile. Trash may suspend; restore requires fresh qualification. Manual reattach and reconfirm are explicit current operation classes.

## 9. Six row domains and structured interaction

D8 preserves six distinct row domains: native Document table occurrence, D4 Field Value Occurrence, NodeRefCollection row, D7 derived Query row, external/import IR row, and Resource preview row. Collection/Query interaction distinguishes page/epoch/all; page200 is transport only. Aggregate/derived rows or arbitrary Ref cells are not automatically writable. Duplicate Nodes are not merged by display value. Board/calendar/timeline/form interactions only create already-defined closed intents, with six-caller semantic parity and explicit platform capability differences.

## 12. Unicode, bidi, RTL, accessibility

Unicode source fidelity, bidi editing, RTL shell and RTL localization are four separate capabilities. Editing uses Unicode18.0.0, UAX#9 rev52 and UAX#29 rev49; D7 CEL's Unicode15.1 stays scoped to its frozen NFC profile. Version change requires named spec/data/fixture evidence.

Direction precedence keeps authored native D2 direction, View textDirection, D8 scope/session/device preference, and App locale separate. auto uses the defined first-strong rule with explicit neutral fallback; numeric content does not independently choose direction. Device/session preference never becomes portable source or execution authority.

Caret state is logical position + upstream/downstream affinity + layoutEpoch. Visual and logical movement are distinct; Home/End is visual-line unless modified. Backspace/Delete remove logical Unicode18 graphemes and never split CRLF, combining sequences, emoji ZWJ or isolates. Equal logical positions can have two real visual stops. Technical Ref/CEL/path/email/citation tokens retain LTR isolation without changing source/copy order. Shell mirroring follows the explicit component table and never indiscriminately flips brand/media/math/data axes/relation arrows.

AT exposes real role/name/state/selection/focus, reads logical content order, keeps virtual focus identity independent of DOM and pins composition appropriately. 200/400% zoom, 320 CSS px, high contrast, reduced motion, keyboard-only, 2-D table alternatives, CJK/RTL/emoji, and non-noisy IME live regions are implementation acceptance obligations. Correct Unicode persistence is not evidence that Arabic/Hebrew UI is implemented.

## 13. Performance and budgets

Retain p95 input-to-visible feedback ≤50ms and layout feedback ≤100ms over at least 1000 events, cold/warm three runs each; Desktop 10MiB/100000 lines, Mobile 1MiB/10000, one 1MiB line, deterministic 10× over-limit behavior, 100k navigation Nodes, 10k row grids with page≤200, and steady-state editor memory Desktop≤256MiB/Mobile≤128MiB.

Narrower D5/D6 policy/strong budgets may reject earlier but never widen these limits. Failure preserves the Draft and does not truncate source, split a transaction, clear dirty state, or continue after TTL. CPU-heavy parse/layout does not block UI. Incremental parse/map/layout is valid only when it equals full parse tree/errors/ranges/source origins. Virtualization is presentation only and never proves complete result authority.
