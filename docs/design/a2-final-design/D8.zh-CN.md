## 1. 唯一权威、状态轴与版本边界

D8 只有一套 Core parser、一个当前 Source authority 和原 D3/D6 commit/CAS/P。Desktop、CLI、Mobile local Core 与 Server Core 使用同一语义；WebUI 只通过 Server。UI、renderer、DOM、索引、缓存、Worker、Agent、插件都不能成为第二 parser、第二 Query engine、第二 source store 或第二 author ledger。

一个编辑会话同时保持四个独立状态轴：

1. **Base/author cut**：
准确 current SourceObservation/1、生产 SourceVersion/2、document_format、授权/control/range 依赖与对应 source bytes；
2. **Draft**：非权威 proposal，带单调 draftSerial；
3. **input transaction**：native input/composition generation、inputSerial、selection、单在途 transform 与后继输入日志；
4. **access/submission**：当前 read/write capability、Prepared binding、preview、confirm、D6 decision/recovery。

receipt 只证明原 request 的真实 author decision；它不能覆盖本地 Draft/selection。授权丢失、Base stale 或 receipt 到达都不能提前把 Base 更新成 after。真实 commit receipt 到达并重新获权后，Base 才能更新；buffer 是否 clean 由当前 Draft 与 after 的 exact equality 决定。Undo 恰好回到 after 可以 clean，但 draftSerial 必须继续使用新值；生产版本、Observation、OperationId、Annotation token 和 CAS 不因字节相等而复活，禁止 ABA shortcut。

current 版本按实际 owner 分开：
- 文档 read/Draft projection/TextReplace/DraftWrite 继续使用 D8 **wireVersion 2** 与 complete SourceObservation/1；
- current author prepare 使用 D8EditPrepareRequest/3、D8EditInput/3、PreparedEditBinding/3、InputDescriptor/3、DependencyProof/3、PreparedIntent/3、D6
d6_commit_request/2、EffectManifest/3 / EffectBytes/3；
- current Annotation 是 PortableAnnotationRecord/4 + D3-Annotation-Value/4 + AnnotationInlineBody/1；
- D8 Annotation read/draft 是独立 /1 family；
- presentation policy 使用具名 D8WorkspacePresentationPolicy/1 逻辑视图、不可变 /2 record/head graph、D8PresentationPolicySetRequest/2。
历史 wire1/wire2 Edit、PreparedEditBinding/1-/2、Value/3、旧 D2 Annotation-v2 等均只按真实记录版本恢复，不原地扩 decoder。

- authored H1–H9、effective arbitrary-precision level、discrete/float、段内/特殊 heading 与 run-in presentation；
- strong/emphasis/strike、link/citation/ref、STEM、Mermaid 及实际 backend/profile 边界；
- 原生 table 的 header/footer、colspec、span、rowspan/colspan、multiline/block
cell、advanced cell styles、nested legal block；

## 3. Draft Edit Map、坐标与原字节不变量

d8_draft_projection 的 map 继续是 proposal-local flows/plainRegions/sites 加独立 navigation origins。它不是 Locator、Ref 或跨版本地址。

### 3.1 可写 mapping

- 每个可地址 body/Inline 槽按 schema BodyPath 唯一定位；重复 cell、等值文本、相同标签不通过字符串搜索消歧。
- flow 覆盖完整 logical Inline 槽；raw-scalar span 可双向映射，escape/join/atom 只读。U+FFFC 仅为局部坐标占位，不写 source。
- plainRegion 是 maximal、单 parent、raw slice exact 的 ordinary paragraph/blank/EOL 区域；
保留 space/tab/LF/CRLF/CR、BOM 与所有未选 bytes。
CRLF 不可拆。
- site 是 Core parser 证明的合法 sibling boundary；empty body、blank-only、non-column-zero EOF、header/carrier/comment EOF 都使用九种 prefix/suffix EOL 候选做完整 reparse，而不是拼字符串。
- UTF-8、UTF-16、Unicode scalar、extended grapheme、logical EOL 和 visual caret 是不同坐标层；所有转换显式并验证边界。
- Source navigation 与 editable mapping 分开：escape/join/atom/生成值可以导航回真实 origin，但不能因此获得 scalar Write。
- map 绑定完整 ownerNodeRef/baseObservation/draftSerial/source；任何一项改变都必须 fresh projection，禁止 fuzzy/latest/DOM order 续用。

### 3.2 写入等价

d8_draft_text_replace 只允许一个 proven nonnull flow segment；d8_draft_write 的 splice_plain|break_plain|insert_at_site 只允许完整 region/site 合同。成功必须同时证明：

1. selected source slice 之外字节完全相同；
2. 完整 reparse 有效；
3. 去掉 Locator/坐标后，非目标 metadata/carrier/body structure/raw value 完全相等；
4. 新非空行仍是 inert ordinary text，不偷偷产生 heading/list/table/macro/comment/anchor/protected structure；
5. 每个新 scalar 都能追到本次 replacement/insertion；
6. 返回 caret 在新 map 中唯一可证明。

删除最后非 blank、只剩 spaces/tabs、empty source body、Enter→第二段、合并段落、删空再输入都保留可逆 Draft 状态。Write 不“清理” trivia，不规范 EOL，不把 CRLF 改 LF，也不把 rich display 写回 source。

## 4. 异步输入、IME 与 Undo 栈

每个 controller 最多一个 Core transform in-flight。请求冻结 before source/selection、native after、generation、inputSerial、draftSerial 与完整 host input log。迟到响应只能完成自己的 generation；不能覆盖后来 native input，也不能丢掉后继输入。

IME：
- begin/update 是 preedit，允许本地显示但不是 current projection、不能 prepare；
- end/final input 与完整 host before/after/selection 形成一个 input transaction；
- Enter、slash command、save/submit、structural action 在 composition 未结束时不得抢占；
- cancel/blur/background 结束 preedit 但不制造 author write；
- host 的 composition ownership 只有一个；不允许 DOM 和 Core 两个 composer 同时改同一 text；
- 每次 composition commit 是一个 Draft Undo group；screen reader live region 不朗读每个 preedit 字符。

同一 owner 的 Source/Write/Read surface 共享一套 Draft Undo/Redo 栈和系统 Undo adapter。每次 Undo/Redo 都生成新的 serial 并 fresh-project；旧 map/serial 不复活。跨 owner、外部后台 commit、同步/Agent 结果不进入这个栈。真实 committed Undo 见 §7，只能反转自己的单 Source decision。

## 5. Clipboard：逻辑文本、准确 Source、inert Write

Clipboard 有三个明确输出：
- **Copy Text**：logical/readable text，保持逻辑顺序；RTL 只改变显示，不倒序 replacement；
- **Copy Source Fragment**：仅在 current authorization 下复制真实 origin/raw Source，包括 run-in 的真实 heading/trivia/body 片段，不复制合成 join；
- **table/row logical copy**：显式 TSV 只作为 inert clipboard text；只有目标适配器能证明所有字段可表示时才能 paste。

Paste 默认只消费 text/plain 并作为 inert Write 输入。不得执行 HTML、RTF、脚本、代码块或 clipboard 中的链接/宏。没有 plain flavor 时当前 D8 返回 unavailable；future rich clipboard 必须进入 D9 isolated conversion/mapping/loss 再经独立 editing adapter，不能偷偷改变默认 paste。

不可表示的整个 transaction 失败，不能只 paste 可表示子集。cut 的顺序固定为：先完成真实 OS clipboard write，再删除 selected Source；clipboard failure 时 Source 不变。跨 owner Resource/attachment 复制需要各自 read/download qualification，clipboard 文本不授 Resource 能力。

## 6. Save、PreparedEditBinding/3、preview 与历史恢复

ordinary/complete 与 strict/observed_only 是两个彼此独立的轴。

合法的 existing-Document whole-source save 可以使用 D6 local_source。只有 trusted interactive、恰好针对一个现存 live Document 的 full-source save，且**在 planning 前已经明确选择 observed_only**，才可进入 observed_only：它必须完成完整 source read/replace，Base 必须等于所选 current Observation，并且不得同时产生额外的 identity、parent、order、lifecycle、shared-policy、Registry、Calendar-scope 或 cross-entity effect。不能因为“只是 ordinary save”就自动降级为 observed_only。

Annotation、committed Undo、structured table/Field、bulk/collection action、automation、managed_atomic、Approval/Money 以及其它 strong path 都继续保持 strict，并获取各自 owner 要求的真实 workspace_constraints 或 complete proof。缺少与 ordinary Source 无关的 whole-Workspace proof，不能阻断一个本来合法的 Source read/Draft/repair/whole-source save；反过来，strong operation 也不能把自己重标为 ordinary 来绕过 strong gate。

结构化 row target 1000 等 D5/D7 budget 不能套到 generic whole-source Source save 上；反过来 generic Source 也不能冒充 structural operation 绕 budget/authorization gate。

current edit prepare 必须生成完整 PreparedEditBinding/3，冻结真实 request、OperationId、SourceObservation/sourceInputs、proposed pins、Registry inputs、DependencyProof/3、PreparedIntent/3 observationProof、budget/TTL、EffectManifest/3 与所有 EffectBytes/3。UI 在确认前必须能够分页读取**完整** preview manifest/byte ranges/effect pages/epoch；一页、摘要、旧 preview 或 copied manifest 都不能替代完整 preview。

saved/planned/unknown recovery 先按记录版本恢复原 decoder、bytes、pins、OperationId、planToken、request 和责任，再判断是否继续原 decision。不能创建新 OperationId 重试未知结果，也不能把未部署候选“迁移”到当前 schema。缺少历史 decoder/pin/evidence 时 fail closed。

SourceTransform 的 profile/compilation 可用性继续只是上游 producer 条件，不产生新的 D8 保存权威。若 producer 把 emission 冻结为 disabled/unavailable，只要普通 Source 保存本身仍合法，就可以继续通过原有 D8/D6 门提交；不得伪造空事件或 artifact，恢复也不能把 disabled emission 升级为成功。D8 只消费这一现任 save/prepare/recovery 前提，不复制 SourceTransform producer contract。

## 7. committed Undo / Redo

单 Source committed Undo 只对满足以下全部条件的原 decision 可用：

- 当前仍获权；
- 恢复到原 request/OperationId/receipt/effects；
- 原 decision 恰有一个 source change，且无 identity/control/shared-policy/Registry/其它 entity effect；
- before/after 与完整 pins 可取得；
- 当前 production version **和 bytes** 都 exact 等于原 after；
- 当前 authorization/format/Observation/installation qualification fresh；
- 不依赖旧 Draft map、selector、ActionEvidence 或 PAB。

Undo 生成**新的** inverse plan 与新 OperationId，经完整 preview/confirm/CAS/P；Redo 再生成新的 forward operation。它不能撤销别人后来的 change、跨 Workspace 形成“原子回滚”、把 current byte-equal ABA 当原版本、或恢复旧 selector。

### 11.1 Current View builder 生命周期与 author 路由

View builder 只是**现任 D7 closed contract 的非权威编辑器**。它只消费 current D7 Query/Definition owner、该 Query 的 current terminal schema、`ViewSpec/1`，以及作者 occurrence 为动态块时既有的 `DynamicBlock/1` binding；不得新建 D8 View schema、parser、Registry row、ledger、持久 UI record、Query language 或第二套 persistence authority。

打开 builder 时，先完成正常的现任定义读取与资格校验，严格解码实际记录的 ViewSpec 版本，再从真实 Query/Definition owner 取得现任 terminal schema。启用控件前只执行**定义保存门**：验证封闭的 ViewSpec 形状、现任定义的授权/owner/revision、terminal schema，以及静态的 layout/binding/type/option 兼容性。这个门不消费 ResultHandle 分页或数据值，也不检查语义键/顺序、数值/领域/层级数据、渲染预算、provider 状态或交付状态。定义过期、owner 移动、权限丢失、现任 Query/schema 不可用、未知 ViewSpec 版本/成员、不在现任 D7 封闭集合中的 layout，或其它静态定义校验失败时，精确作者字节都保持不动。若它属于 current SavedDefinition/ViewSpec occurrence，严格 D7 decoder 必须返回 owner 的类型化错误（延期 layout 对应 `unsupported_layout`），并阻止 current ViewSpec 保存；高级/源码路径不能扩展现任 union，也不能把这些字节变成合法 v1 定义。相同 exact bytes 若位于 raw Source 或真正 historical/future record，只能按真实 owner 与记录版本 decoder 读取、编辑和保全，不能自动升级。builder 打开时不得偷偷修复或规范化。

basic control 只能修改自己可以无损表达的成员：current closed `layout`、该 layout 声明的 stable `columnId` bindings，以及 closed common/per-layout options。Query transform/filter/group/aggregate/derived value/sort 仍只能经 existing D7 Query author route 修改。这里的“合法”只指现任 D7 decoder 已接受的 ViewSpec member。basic control 无法无损表达这种合法现任 member 时，必须在 working value 中逐字保留并通过 advanced ViewSpec route 暴露；修改其它 basic member 不能静默删除、默认化、重排或改写。延期/unknown layout 或 member 不能借该路径变成合法 current member。

新定义只能从用户显式选择的现任 Query/Definition、其已验证 terminal schema 与一个完整且静态合法的 `ViewSpec/1` 初始化；不得存在环境中的“最佳布局”或隐藏推断 binding。取消会丢弃 builder draft，并恢复打开时的精确定义。保存时重新执行同一个定义保存门，再检查现任授权、owner 与 revision，并通过**既有 SavedDefinition/DynamicBlock owner action 及其 D6 commit path**提交；保存定义不要求执行 Query，也不要求存在完整结果或当前可渲染数据。定义状态过期或撤权、owner 移动或 terminal schema 改变时，必须重新读取、重开并重新准备，不得盲写。重开必须解码真实已保存的 owner 字节，复现同一组可表达控件与全部保留的高级成员。

运行期 View 校验与定义保存完全分离，只在渲染或对外导出某个现任 ResultHandle 时开始，并保持 D7 View §7 的既有顺序不变：封闭解码 → 当前结果授权/epoch → 完整结果 → 精确 schema → layout/binding 类型 → 全量数据结构/顺序 → 领域/数值 → budget → 当前交付门。运行期出现 `incomplete_result`、`duplicate_key`、`invalid_order`、`negative_value`、层级/领域失败、预算失败、离线/provider/数据不可用或 renderer 失败时，只拒绝本次渲染/导出，绝不能使原本静态合法的已保存定义失效或被改写。例如，一个静态合法的饼图 ViewSpec 即使当前 Query 结果含 -1 也可以保存；执行/渲染时返回 `negative_value`、不绘图，并保持定义不变。

fixed-S 候选拼法 `.weftext-query view=...` **不升级为新的 current author schema**：本候选中没有这个拼法的现任 owner definition。真实 saved/historical bytes 只按当初产生它们的 decoder/recovery 继续存在；current authoring 只发出 current D2 SavedDefinition/D7 definition 形态。若实现遇到该 legacy source 拼法，exact Source 仍按真实 owner 可读/可编辑；只有 current D7 Definition Transfer/current owner 能证明完整受支持 mapping 时，UI 才能提供显式 conversion。否则保持 source/advanced-only，绝不静默 migrate、re-encode 或丢弃。

`DynamicBlock/1` 按 D7 继续作为 current inert author entry：只保存真实 Query/View call 与声明 bindings。编辑其中 View 时打开同一个 `ViewSpec/1` builder，保存通过既有 DynamicBlock/SavedDefinition owner operation 更新作者 occurrence。ResultHandle、preview/currentness evidence、cache、device interaction、authorization 与 builder state 都不能成为 DynamicBlock member。

跨 surface 要求语义一致而非像素一致。Desktop、WebUI、Mobile 在 capability 存在时可展示 graphical builder；三者都必须为 basic UI 无法表达的合法 member 提供无损 advanced/source route。WebUI 使用 Server Core。CLI 与 Server 提供同一 strict ViewSpec read/validate/save 语义和 typed error，但不声称 graphical rendering。Mobile 可使用同完整 data 的 table/list renderer fallback；缺 graphical builder/renderer 不能改变 ViewSpec、Query meaning、validation、permission order 或 saved bytes。所有 surface 读取同一个 saved definition，并返回同一 owner/currentness error。

### 11.2 Mandatory §15.7 builder/interaction oracle

Mandatory §15.7 的十个 fixture 分别绑定 D8-ACCEPTANCE 中唯一 ID `VIEW-BLD-01`–`VIEW-BLD-10`。对现任封闭 layout，fixture 继续把 definition-save 静态验证与运行期 View 门分开：静态合法定义的保存不消费 ResultHandle，完整结果、数据与 renderer 检查只在 render/export 时执行。`VIEW-BLD-03` 中 pie zero-total 是 D7 具名的合法 empty-total 状态；负值、重复 key、类别或预算超限、隐式 Other/Top-N/drop 等既有运行期失败只阻止渲染，不能改写已保存合法定义。`VIEW-BLD-04..06` 则专门验证 explicit defer 边界：tree/treemap/sunburst、Gantt、boxplot/quantile 都不是现任 ViewSpec/1 layout，因此 current definition 必须在静态门返回 `unsupported_layout`，不能进入运行期数据 validator 或 renderer。§15.7#4 的 two-roots/missing-parent/self/cycle/same-id-label、#5 的 mixed date/instant/end-before-start/progress/dependency/predecessor、#6 的 quartile-order/raw-observation 完整义务都保留给未来具名 successor，不能虚构成 current validator。现任 network、timeline、table 只保留各自真实既有语义；raw Source 与真正 historical/future bytes 继续按真实 owner/decoder 保全，但不因此成为 current ViewSpec。

## 12. Unicode、bidi、RTL 与可访问性

四种能力分开：
1. Unicode source fidelity；
2. bidi text editing；
3. RTL application shell；
4. RTL localization。

current 文本编辑使用 Unicode **18.0.0**、UAX #9 rev52、UAX #29 rev49；D7 CEL 的 Unicode 15.1 只用于其自身固定 NFC profile，不能拿来偷偷改变编辑 segmentation。版本升级必须具名新规范/data/fixture evidence。

direction precedence：
- author native direction（若 D2 真正拥有）只按 D2 source semantics；
- View textDirection 只作用数据 label；
- document/flow/block/session/device ltr|rtl|auto 按 D8 Direction 既定 precedence；
- App language/locale 与 content direction 分开；
- auto 由该 scope 的 first-strong 决定，all-neutral 用明确 fallback；数字不单独决定方向。
device/session preference 不写 portable source/隐藏 sidecar，也不改变 Query ordering/authorization。

caret 使用 logical position + upstream/downstream dual affinity + layoutEpoch。soft wrap/字体异步重排只更新 layout state；若仍有同 logical stop，clamp 到条件 inverse，否则重建。Left/Right 是视觉移动，Ctrl/Meta+Arrow 是逻辑词/行移动；Home/End 是视觉行端，带修饰符才到 logical document edge。Backspace/Delete 按 Unicode18 grapheme 逻辑前/后删除，CRLF 原子；CJK、emoji ZWJ、combining、bidi isolates 都不能拆。相同 logical point 可以有两个真实 visual stop，不能按 DOM index collapse。

Ref、CEL、path、email、citation、ASCII/数字技术 token 保持 LTR isolation，
但 source bytes/逻辑 copy 不倒序。
tree/pane/menu/grid/icon mirroring 按显式表；
brand/media/math/data axes/relation arrows 不机械 scaleX。
native table 的 logical Tab/navigation/edit 不随视觉镜像改 Field/column identity。

AT：
真实 role/name/state/selection/focus；
screen reader 按 logical content order；
focus trap 可逆；
virtualized item 的 logical identity 不依赖 DOM；
composition pin 保留 active editor，
reset 时明确通知；
live region 不刷 IME preedit。
200%/400% zoom、320 CSS px、high contrast、reduced motion、keyboard-only、二维表替代、CJK/RTL/emoji 都是实现验收。
保存 Unicode 正确不等于 Arabic/Hebrew UI 已实现。

## 13. 性能、budget 与虚拟化

保留原 D8 性能门：
- 输入→可见反馈 p95 ≤ **50ms**，layout feedback ≤ **100ms**；
- 至少 **1000 events**，cold/warm 各 **3** run；
- Desktop：10 MiB / 100,000 lines；
- Mobile：1 MiB / 10,000 lines；
- 单行 1 MiB；
- 10× over-limit 必须稳定拒绝/降级，不 crash/假成功；
- navigation 100k Nodes；query/edit grid 10k rows；transport page≤200；
- editor steady-state memory Desktop≤256 MiB、Mobile≤128 MiB。

任何更窄 D5/D6 policy/strong budget 都可以更早拒绝，但不能扩宽。budget failure 保留完整 Draft，不截断 source、不拆 transaction、不清 dirty、不过 TTL 后偷偷继续。CPU-heavy parse/layout/normalization 不阻塞 UI thread。incremental parse/map/layout 只有在完整 parse 的 tree/error/range/source-origin 逐项相等时才是合法优化；否则 fallback full computation。virtualization 只是呈现，不是第二 authority，也不能把 page 当 complete result。

## 15. 证据边界

本候选是设计整合，不是产品实现证据。实际 Core parser、GUI、IME、OS clipboard、AT/screen reader、Desktop/Mobile/WebUI renderer、真实 multi-replica/CAS/crash、D9 worker/provider、D10 runtime、性能、migration/activation/deployment 全部保持 **UNRUN**，除非 D8-IMPACT/PR handoff 明确列出某一实际执行证据。

完整 source/case/current-owner 库存在 D8-SOURCE-MAP.json；closed schemas 在 D8-SCHEMAS；interaction acceptance 在 D8-ACCEPTANCE。source-map 导航实际上已经是 54/54 个 section-level target，宽泛整文件 target 为 0；这只是库存/导航事实，不等于语义接受。逐项 FC 分类与 historical→current disposition 仍需非作者复核。本修订只把四个具名 SourceTransform 普通保存/恢复同族项调整为与 FC34-ST-02 相同的 upstream-current-prerequisite，不把库存完整或 CI 变绿冒充语义闭合。只有后续固定 SHA 的非作者 D8 增量复审可以接受这些残余修订。
