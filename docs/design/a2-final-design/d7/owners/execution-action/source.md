# D7 Execution, Action and DynamicBlock

## 1. Compilation, execution and typed results

Every D7 object in this document is closed and uses the main contract's strict decoder. Embedded D3/D4/D6 objects retain their original decoders and member names. Token has D6's fixed 43-character canonical lexical form with a separately stored server tag; equal shapes are not interchangeable. Authenticated PrincipalContext comes from the host, never self-reported author JSON.

`d7_query_execute` is exactly `{wireVersion:2,kind:"d7_query_execute",workspaceRef,commitDomain:CommitDomain/2,expectedFrontier:Frontier/2,call:QueryCall,budget}`. QueryCall is exactly `{query,arguments,context}`, each appearing once at that level. query is `{kind:"inline",spec:QuerySpec}` or `{kind:"saved",definition:DefinitionAddress}`. arguments uses the main TypedLiteral object. context contains exactly the inferred required members among now/timeZone/calendarVersion/tzdbVersion: now is a zoned_instant TypedLiteral, others nonempty text. Missing members produce context_unbound and extras context_unused. There are no device locale/time/timezone defaults. Definition closure and D4 Registry/temporal rules come from the same Core AuthorizedCut, never a client-supplied trusted read context.

budget is exactly `{maxRows,maxValueBytes,maxResultBytes,maxWork,maxDependencies,maxTemporaryBytes,maxElapsedMs}`, all Counters, using the per-dimension minimum of request, managed policy and host. Any zero explicitly rejects; it never means unlimited. Hard protocol bounds: QuerySpec 1 MiB and complete saved closure 8 MiB; per Query at most 128 relations, 64 scalars and 64 parameters; 64 total invocations, depth 16; one expression at most 65536 UTF8 bytes, 4096 AST nodes and nesting 64; at most 64 columns per terminal/intermediate row; maxRows 1,000,000, maxValueBytes 16 MiB, maxResultBytes 256 MiB, maxDependencies 1,000,000, maxTemporaryBytes 1 GiB, maxWork 1,000,000,000 and maxElapsedMs 3,600,000. Checked add/multiply charges before allocation. Graph nodes+edges and actual recurrence/unnest expansion count toward maxRows. Streaming/spilling is allowed, incomplete delivery is not.

Work counts one for each logical AST evaluation node, input item processed by an operator, relationship candidate check, complete-range scan item and parsed UTF8 octet, according to normative batch logic. Optimization cannot avoid required logical charges through fewer physical reads; cache hits face the same logical-cost qualification. Resource feasibility may reject early when a budget is provably insufficient, but cannot read hidden facts to determine and disclose their count. Cost/failure exposes only budget_exceeded, not unauthorized precise counts. Elapsed is wall time for an execution attempt and can change availability, not the mathematics of successful results. Parallelism/restart cannot accumulate unlimited retries; D6 budget binding applies.

Only after complete success, `d7_query_result` is exactly `{wireVersion:2,kind:"d7_query_result",resultToken,cursorToken,schema}`; cursorToken selects the transport start. Producing has only asynchronous runtime pending status, without rows, counts, schema-derived secrets or reusable tokens. The normative interface may block until complete; host-associated cancellation is not an author Action. Failure `d7_query_error` is exactly `{wireVersion:2,kind:"d7_query_error",diagnostic}`, with diagnostic defined in the main contract.

TerminalSchema is closed:

- rows: `{kind:"rows",ordered:bool,columns:[{columnId,type}]}`, columnId is the terminal name and columns retain terminal schema order.
- scalar: `{kind:"scalar",type:T}`.
- graph: `{kind:"graph",nodes:RowsSchema,edges:RowsSchema,nodeRef,sourceRef,targetRef,relationColumn,derivationColumn}`; the final five values are corresponding columnIds.

D6's `d6_result_page` envelope remains unchanged; D7 defines its rows. Each rows-result item is exactly `{kind:"row",rowHandle,cells:[V...]}`, cells matching schema count/types and rowHandle a tag=result_row Token. Scalar has exactly one `{kind:"scalar",value:V}` item, including none as an item rather than zero rows. Graph items are `{kind:"graph_node"|"graph_edge",rowHandle,cells:[V...]}` transported in two sections, nodes then edges. D6 may return an empty nonterminal page: consumers must continue to terminal and never infer EOF from empty arrays or fewer than pageSize items. d7_query_result supplies the first cursorToken; no fields are added to D6's existing request. It is neither a Query author member nor a semantic limit.

Scalar page assembly cannot duplicate/omit the value. At graph terminal, nodes/edges must each be complete and conform to schema. Wrong tags/cells, duplicate rowHandles or cross-result rowHandles reject the whole consumer. Tokens/rowHandles have no durable semantics. Core binds result+epoch+internalkey and does not use a row-value hash as unique identity; two equal bag rows have different handles.

## 3. Delivery, cache and subscriptions

The closed events are `d7_delta` exactly `{wireVersion:2,kind:"d7_delta",subscriptionToken,epoch,sequence,fromResultToken,toResultToken,changes}`, `d7_reset` exactly `{wireVersion:2,kind:"d7_reset",subscriptionToken,epoch,sequence,code:"reset_required"}`, and `d7_subscription_idle` with only the same token/epoch/sequence. Errors use D7 query error, limited to not_visible/result_expired/reset_required/cursor_invalid/result_unavailable. Delta sequence increases exactly one and fromResultToken must be the last completely accepted result. changes contains `{kind:"remove",rowHandle}` or `{kind:"upsert",rowHandle,cells,position}` for rows results only; position is a zero-based Counter in the complete destination result. Scalar/graph changes always reset, without claiming incremental support.

A conservative legal rows-delta algorithm uses full replacement. Only after Core proves identical schema/auth/definitions/Registry/rules/continuity and comparability of both complete batch results within the same semantic scope may it remove every old rowHandle and upsert all new rows in target order, using new tagged handles bound to toResult. changes has at most 2*maxRows entries and obeys result/output budgets. The client validates old set, unique handles, continuous gap-free positions, types and destination completeness in a temporary full copy before one switch. It cannot expose mixed epochs during receipt. Minimal-change optimization requires the same proof. Lost dependencies, subscription gaps, schema changes, insufficient resources, unknown equivalence, Counter overflow or failed source reads always reset, never guessed delta. Old evidence in the epoch is invalid before the reset is actually sent; a lost reset cannot permit old operations. Resubscription needs a new complete Query result.

Bag duplicates are distinguished by internal occurrences and addressed with public opaque handles. New results cannot reuse old handles. Remove-all/upsert-all has an explicit bandwidth cost but makes no unsupported stable-row-identity promise. sequence is private to the subscription and discloses neither D6 internal contentSequence nor a specified CommitDomain's domainCommitSequence.

Exact next semantics: if afterSequence equals the latest formed event sequence and no new event exists, return idle. Otherwise return only the saved complete event at afterSequence+1. Repeating afterSequence replays identical event bytes while current qualification and retention hold. A future afterSequence or a needed event missing from the finite log yields reset_required, never guessing what the client received. Subscription inherits finite result TTL/budget without automatic extension; event log/new result pins count against it. Exhaustion immediately invalidates the epoch and resets. `d7_unsubscribe` is exactly `{wireVersion:2,kind:"d7_unsubscribe",subscriptionToken}`. After current audience validation, revoke runtime subscription, release releasable pins and return `{wireVersion:2,kind:"d7_unsubscribed"}`. No author source/decision changes; unknown/wrong-audience tokens remain not_visible.
