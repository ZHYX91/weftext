# D7 Typed Transfer of Saved Definitions

This contract is an atomic source transformation of D7 portable payloads, explicitly carried by this package's D3 wire12/Result9. D2 continues treating saved blocks as inert. D3 owns identity mapping, Result materialization, the original decision and receipt. D7 only proves which members of its closed payload are typed references and their unique transformation. UUID-like body text is never replaced and no Query entity is added.

## 1. The unique typed-reference traversal

After completely decoding SavedQueryDefinition, ViewSpec or DynamicBlock with its D7 schema, traverse static schema paths: DefinitionAddress.owner and its recognized D3 Locator; node/resource/annotation_ref values identified by TypedLiteral.type, recursively through Optional/object/list/union; CollectionCreationPolicy.parent; saved View/Query call addresses; Query Selector literals, QueryRef arguments, parameter defaults, fixed View Domain TypedLiteral and DynamicBlock literal/context bindings. Ordinary CEL expression strings, labels, plain text and lexical this bindings are excluded and remain byte-identical even when containing UUIDs. Never recursively scan unknown JSON to infer Refs.

Every typed Ref uses the original complete D3 decoder and slot/owner/locality gates. Refs inside the identity map become the corresponding complete fresh Refs. Complete same-Workspace Refs outside the map remain only under explicit preserve policy. An outside-map cross-Workspace Ref cannot remain a typed Ref of the current Workspace: the whole operation rejects cross_workspace_identity_preservation, without dropping defaults, substituting none or converting the Ref to text. Missing source mappings cannot be inferred from owners/paths. Resource/Annotation mappings include their complete owner; incompatible new owners reject rather than replacing only the leaf UUID. this.node remains lexical and resolves in the actual destination Node at execution; copying does not freeze the former NodeRef.

Ordinary TypedLiteral objects follow this rule only for Ref members declared by TypeSpec. An object resembling a Locator is not promoted to a resolvable Locator by member names. Only actual D7 DefinitionAddress.at.locator accepts Locator reissue below. Copying D4 author provenance retains D4/D3's original typed carrier contract; D7 ordinary objects cannot re-sign its ActionEvidence or reinterpret historical author values.

## 2. Sources, results and explicit slot lists

D3 wire12 inherits wire11's tenth plan array, `definitionTransfers`, whose element is exactly `{kind:"d7_definition_transfer",sourceContainer,inputOccurrence,resultContainer,resultOccurrence,payloadFormat,slots}`.

sourceContainer is an existing_entity_subject(NodeRef) or artifact_part_subject. inputOccurrence is a nonnegative Counter selecting the SavedQueryViewDefinition ordinal in source order in the completely bound D2 source/artifact part. resultContainer is an existing/mapped/new Node subject; resultOccurrence selects the corresponding ordinal in the complete result D2 source. payloadFormat is only weftext.saved-query/weftext.view/weftext.dynamic-block. Unknown formats cannot enter this adapter. Ordinary copy/fork cannot use ordinary-import conversion to upgrade an old QuerySpec: its source must be a completely validated current payload.

Slots are uniquely sorted by the typed-path comparator: compare segments, member-text tag rank zero by original UTF8 bytes and Counter-index tag rank one by D3Integer numeric value, shorter path first after a shared prefix. Do not sort whole D3-CJ/3 serialized paths; index 2 precedes 10. Each element is exactly `{path,before,after}`. path is an array of `member name text|Counter index`, valid only at a typed Ref or DefinitionAddress Locator root discovered by the complete schema traversal. Ancestor/descendant overlap is forbidden. before is an original D3 Ref or complete original DefinitionAddress Locator with its variant confirmed by the original decoder. after is `{kind:"map",subject:PayloadSubjectKey}`, `{kind:"preserve"}` or `{kind:"reissue_locator",ownerSubject:PayloadSubjectKey,targetOccurrence:Counter}`. map accepts only mapped/new subjects of the same kind. preserve satisfies the same-Workspace outside-map rule. reissue_locator accepts only an original DefinitionAddress DocumentElementLocator, bound to its exact current target SavedQueryViewDefinition occurrence with owner mapping determined mechanically. Every typed Ref/Locator in the payload has exactly one slot, not just changed references. A Locator root already contains owner, so a separate nested owner slot is forbidden. Anchor addresses use an ordinary Ref owner slot; the anchor name remains unchanged and must resolve uniquely at the destination.

definitionTransfers sort by `subjectCanonicalKey(resultContainer),resultOccurrence`; each result pair is unique. A source pair may appear in explicitly separate copy mappings but still binds each result separately. Every member enters the original canonical D3 request/fingerprint. The complete source payload is not whatever slots claim: Core independently recovers it by inputOccurrence from the complete source pin selected by the original preimage/source_artifact payloadBinding, enumerates its D7 schema and compares slots exactly. It independently recovers the complete result too. Missing/extra slots, unequal before, wrong type or exchanged owners fail stage14 identity_map_incomplete. Even a valid saved payload containing no Refs requires a slots=[] transfer proving its complete format was read rather than skipped as opaque.

### Newly authored definitions and transfer scope

definitionTransfers describes only copying/forking/identity-bearing importing of existing payloads. Entirely new SavedQueryDefinition/View/DynamicBlock payloads in a new Node are not transfers from a nonexistent source. A newly authored payload containing only valid currently existing Refs/DefinitionAddresses can remain in B, but stage14 still completely validates D7 decoding, read permissions, all references/Locators and all D2/D4 gates. It cannot claim a transfer effect from an old definition. D9 ordinary import must first produce a complete current D7 wrapper; this contract does not infer old formats.

Newly authored payloads directly cross-referencing this decision's unallocated fresh Nodes are outside this input shape: TypedLiteral and DefinitionAddress have no symbolic public variant. The entire request rejects unsupported authored payload, mapped to original stage14 identity_map_incomplete; never invent UUIDs. Existing copied/forked definitions may cross-reference through Q and the existing source mapping below; the new-authoring restriction cannot reject them. D9 can propose another explicit version for tools authoring several mutually referencing new definitions, but this version will not split two commits while claiming atomicity.

## 3. The Q segment in Result/9

Result/9 completely inherits Result/8's B/M/N/E/S/C partition, lengths, explicit slots, C carrier and original decoder restrictions, adding only tag Q. Magic becomes ASCII `D3-Symbolic-Result/9` plus NUL; subsequent header and partition algorithm remain unchanged. Q is allowed only for the **payload span** of a D2 SavedQueryViewDefinition in exact_source_document, excluding outer attributes/opener/closer and anchor. It cannot apply to Resource, Annotation, Field carrier or ordinary literal/body, and cannot overlap B/M/N/E/S/C spans.

Q body is D3-CJ/3 exactly `{transfer:<完整definitionTransfers元素>,inputPayload:<原inert UTF8 payload文本>}`: transfer is the complete definitionTransfers element and inputPayload the original inert UTF8 payload text. start/end bind the complete payload span in the result base; bodyLength counts actual Q body bytes. inputPayload equals the real original sourceContainer/inputOccurrence bytes and its completely decoded format equals payloadFormat. Q and definitionTransfers correspond one-to-one. Every recognized saved payload in copy/fork/identity-bearing import requires Q and cannot remain in B to bypass transfer. payloadBindings.result binds complete Result/9 bytes. The unique materialize function below produces UTF8 JSON replacing that span. Outer D2 raw and ordinary CEL/text values remain byte-identical. JSON formatting may change only within the explicitly selected whole inert payload, and preview must show that formatting change.

materialize(inputPayload, slots, original cut, original D3 candidate map) completely decodes and enumerates, substitutes typed Refs mechanically according to map/preserve, and handles reissue_locator through the same original complete D3 source and target-occurrence mapping. It writes this portable payload with D3-CJ/3 canonical JSON, preserving original UTF8 text values and newline characters while normalizing JSON source whitespace within the selected payload. Complete final Query/View/DynamicBlock decoding, Workspace/ref/Locator, parameter types, full D2 source/carrier and D4 validation must all pass; valid JSON alone is not a valid Query.

## 4. Revision and position closure

The original D3 stage12 ephemeral candidate map first fixes internal Ref mapping. Every source requiring a new managed after uses the same native plan's SourceRevisionPlan/1. Revision is only checked H(D,E)+1 in the destination production CommitDomain, and one only with complete empty-history proof. externalSequence, other production domains' revisions and observationEpoch changes neither donate to nor reset H. A true raw no-op retains the complete old SourceVersion/2. Absent after on deletion and pure structural changes create no managed source version. Proposed tokens come only from that plan's SourceStamp/1 and RevisionTokenBinding/2: they are not sealed SourceVersions, contain no ChangeId of this decision and grant no early Locator capability. Seal produces the complete managed SourceVersion/2.

A reissue_locator target must be an originally validated SavedQueryViewDefinition occurrence with exactly one corresponding result occurrence in the complete transformation. Deleted, ambiguous or noncurrent-preimage Locators reject, never approximate. D7 reissues only DocumentElementLocators targeting SavedQueryViewDefinition. D2 requires each saved block opener and closing delimiter to occupy its own physical line. Q's D3-CJ/3 serialization writes the entire JSON payload on one line with string-internal newlines escaped. Thus the width of coordinate numbers cannot change the block's boundary line/column. Materialization uses exactly two passes:

1. Fix complete Ref/revision tokens and other original D3/C non-D7-position transformations. Use an internal zero-coordinate template for Q positions to be reissued; canonical JSON still occupies one line. Assemble the complete source, then use D2 to obtain every mapped SavedQueryViewDefinition's complete actual SourceSpan. The internal template is neither deliverable nor a valid resolvable Locator.
2. Substitute all actual spans simultaneously into their Locators, serialize Q again and reassemble the complete source. Parse every target element span again with D2 and require byte equality with pass one. Each final Locator then proves the same owner/revision/elementKind/exact target occurrence through the original D3 decoder/resolver. Any mismatch, lost/ambiguous target or budget overflow rejects the whole operation; no iterative guessing or intermediate delivery.

This algorithm covers positions of complete saved-definition elements, not arbitrary payload bytes or body ranges. An ordinary preserved external Locator remains byte-identical and validates its original current target, without updating to latest. Annotation and D4 provenance positions handled by D3/C retain their respective original acceptors and must bind the same final source. They cannot succeed in separate commits or break Q's one-line canonical-JSON premise. If a same-plan transformation cannot prove compatibility with this two-pass boundary, stage14 rejects the whole plan. No free script reorders source.

## 5. Complete effects and unknown payloads

The original D3 receipt and D6 effects carry D7's `D7DefinitionTransferEffects/2` under the same decision, exactly `{kind:"d7_definition_transfer_effects",version:2,decisionKey:DecisionKey/2,operationId,transfers}`. Each transfer is exactly `{sourceContainer,inputOccurrence,resultOwner:NodeRef,resultOccurrence,beforePayload:text,afterPayload:text,slots}`; each slot is `{path,before,after}`, with after the actual complete Ref or reissued Locator, no longer a symbolic subject. Array order equals request definitionTransfers. Every item is independently recovered and verified from the actual complete before/after sources, never merely repeated from the request. This extension enters neither D3's authored node_link/citation slot union nor referenceLifecycleTransitions and creates no durable definition identity.

If a containing Node has an unknown or undecodable D7 payload, ordinary D2 reading may preserve raw bytes, but **the whole typed transfer rejects** rather than claiming executable-reference meaning was preserved. Full fork cannot omit the Node or delete its block. A user may separately repair it or explicitly turn it into an ordinary inert literal in another author edit before submitting a new operation; no automatic conversion occurs here. Recognized reference-free payloads still validate the complete schema with slots=[] and preserve text values. Equal UUID strings in ordinary body/source/literal text do not participate. Old result handles, ActionEvidence and preview/effects tokens are not legal portable schema members: unknown members reject rather than moving them to a new Workspace.
