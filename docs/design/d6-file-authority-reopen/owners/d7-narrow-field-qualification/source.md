# D7 Narrow Field Qualification and Public Results

This normative D7 document requires coordinated acceptance with the explicit D6 replacement in this package. It defines a constructible phone-only positive path; field_read/field_write never automatically grants metadata or other author-content permissions. D6 Main and Control Interfaces must adopt the same contract before activation; until then this remains an unaccepted candidate.

## 1. Explicit metadata permissions

Current D6 Policy/3 already defines two closed capabilities without parameters: `{kind:"source_envelope_state"}` and `{kind:"commit_sequence_state"}`. Neither is implied by source_read, field_read, field_write or policy_admin, and neither implies those capabilities. source_envelope_state accepts only workspace or ref_set scope and, like entity_state, checks the complete supplied Ref and current policy first; it does not use subtree scope or first look up parentage. commit_sequence_state accepts only workspace scope. Deny overrides allow, and an absent explicit allow is insufficient. Policy/1 does not automatically upgrade or acquire grants; only a normally authorized current policy edit can install Policy/3, and this document adds no grants to old Policy/1 or /2. Bootstrap uses its frozen complete profile version and never expands historical grants during replay.

source_envelope_state expressly authorizes observation of the complete source's revision and changes, byte length, physical-line/depth/count capacity boundaries, whole-D2 structural/container validity, availability/validity of whole-source D4 validation under the current Registry, and the effects of those limited states on source-edit success/failure and CAS. It does not authorize body, title, other Fields, Facet names, precise hidden error locations, values, refs or matching constraint members. The exact public schema follows. This permission deliberately reveals whether another edit changed that owner's source; it does not promise invisible source activity.

domainCommitSequence is D6's successful author-decision sequence in one complete CommitDomain/2, not a Workspace-wide counter across replicas/authorities. A fresh domain starts at 0. Each final committed D3/D6 decision in that domain, including contractually admitted control_only/no_op, checked-increments it at the same P seal; replay, recovery attempts, preparation and rejection do not. A complete DecisionKey increments it at most once; MAX never wraps. Counts from different ReplicaEpoch/authority domains cannot be added, ordered as versions or used to infer source H. Domain changes require current fence/continuity qualification. The capability's workspace scope limits the Workspace; the actual read binds the request's specified CommitDomain, not other domains' sequences or any decision content. A phone editor with this explicit permission can observe that domain's commit activity, so it is not a strict secret. Production source version, Frontier and internal contentSequence remain different facts.

Current `d7_source_envelope_read` is exactly `{wireVersion:2,kind:"d7_source_envelope_read",workspaceRef,commitDomain:CommitDomain/2,expectedFrontier:Frontier/2,ownerNodeRef}`. Closed decode and current Workspace/entity_state/source_envelope_state plus required Registry/Field disclosure precede current domain/continuity/exact-cut validation, which precedes source and aggregate-validation reads. Valid success is exactly `{wireVersion:2,kind:"d7_source_envelope",ownerNodeRef,sourceVersion:SourceVersion/2,sourceVersionRef:SourceVersionRef/1,sourceBytes,maximumPhysicalLineBytes,maximumDepth,entryCount,validation:"valid"}`. The invalid/unavailable variants have the same members except validation is invalid/unavailable and sourceVersionRef, maximumDepth and entryCount are forbidden. Physical sourceBytes/maximumPhysicalLineBytes still require a real complete read; unknown values are not zero. Unproved source/domain continuity or physical read produces no successful envelope and maps through the original D7 query-error/2 diagnostic to source_unavailable/result_unavailable. Missing, non-live or unauthorized state follows the original current-state masking as not_visible without hidden reasons.

sourceVersion is the actual complete production address; production domain/generation can differ from the request's current domain and cannot be replaced by sourceRevision alone. A valid sourceVersionRef comes only from the real D6 SourceObservation/1 producer: entityRef/sourceVersion exactly match this response, observerDomain equals the request domain, and current FileObjectBinding, complete pins and source/control/Registry proof belong to the same cut and satisfy this document's static qualification. It is not a D7-signed token and grants no body, other Field, public source bytes or write permission; every subsequent consumer still checks its actual authorization and purpose. Invalid/unavailable produces no token usable for preparation. This exposes aggregate state only, never hidden reasons/locations/values/Refs; detailed diagnostics retain original repair/audit qualification. Existing FieldSelector/EntityTarget Counter values compare only with a managed revision proved by the current observation, never externalSequence. Qualified ordinary external reads and human admission remain with their actual owners.

Real old wire1 source_envelope_read/source_envelope retains its original decoder and sourceRevision/count meanings. An old saved handle is neither given a new domain nor upgraded into current Action evidence. New requests use /2 only; an undeployed draft with no record evidence creates no fictitious permanent storage obligation.

First read only the authenticated complete Registry definition graph, enumerating every Field/Facet/alias and constraint constructor, without reading owner author values or current membership to choose qualification. Unknown, unavailable or uncovered constructors make proof impossible. Scope is not a caller-supplied qualified flag.

Compute this closure for touched Field F entirely from validated schemas and closed intent shapes:

1. Include F and all alias, qualifier, unit/code/external-scheme and contribution dependencies. If any reachable value/qualifier/provenance can introduce a typed Ref/Locator or relation, and the adapter cannot prove from the intent that those members remain byte-identical, reject this narrow proof and require the real larger scope. For union_variant_equal, if the closed mutation does not prove the original root union variant unchanged, the other Field and actual Facet applicability would be required; this minimal path conservatively rejects that potential change. Real source_envelope_state-authorized validation determines complete prior D2/D4 validity, not a request/cache assertion.
