# D7 View Contract

## 1. Input, identity and presentation only

ViewSpec is exactly `{format:"weftext.view",version:1,inputSchema,layout,bindings,options}`. inputSchema is the complete Query TerminalSchema defined by Execution. columnId is the stable, case-sensitive terminal column name, **not a D4 FieldId**. A View binds by columnId and exact TypeSpec; changing a label does not change columnId. Deletion, rename or type change produces schema_mismatch, never rebinding by position, similar label or first-row inference. Binding values are columnIds; literal variants are allowed only for explicitly supported thresholds/fixed formats. Unknown layouts, members and bindings reject.

A View has no CEL, SQL, filter, sort, take, group aggregate, bin, quantile, fetch, script, arbitrary renderer configuration, Action or source authority. Grouping lines, bar geometry, panel partitions and graph connections consume explicit data keys without merging facts. Renderers cannot fetch titles, names, avatars, resource bytes, tooltip details or hidden endpoints. Opening entities and downloading resources are separate currently authorized operations; rendering does not trigger them. Author Refs and historical Locators displayable under Value §5.1 show only their projected original members, without adding current-valid/visible flags or querying targets; clicks separately pass the complete current gates.

Input must belong to one completed ResultHandle that is currently deliverable. All pages and the complete typed envelope must be verified before drawing a semantic chart or publishing an export. Data-independent frames/loading may appear earlier; first-200-row provisional lines, sampling, estimates and an "other" bucket may not. A successful Query followed by failed View validation rejects that View, not the Query's complete rows; another valid View may consume the same Query.

## 2. TerminalSchema and common options

A rows schema contains an ordered Boolean and ordered columns `{columnId,type}`; scalar contains type; graph contains the nodes/edges rows schemas and key contract. Labels come only from the View's `options.labels` object: keys are existing columnIds, values plain text of at most 4096 Unicode scalars; an omitted label displays the original columnId. Common options are exactly `{title,description,labels,textDirection,numberFormat,partition?}`. title/description are plain text and may be empty. textDirection=ltr/rtl/auto affects data labels, not the App language. numberFormat is `canonical`; v1 has no locale floating-point formatter, custom template or unit conversion. Every View obeys this common object plus the explicitly listed layout options.

partition applies only to bar/line/scatter/pie/heatmap and is exactly `{columnId,scale:"shared"|"independent"}`; the column is nonoptional and equatable. Complete rows group by equality of that column in first-appearance order in sorted input. Each row belongs to exactly one panel; null/missing cannot occur, no empty panel is invented, and authorization-removed groups leave no trace. Each panel retains its layout's unique-key and budget requirements. shared axes use extrema of complete geometry across all panels; independent axes use each panel and explicitly label independent scales. The term is “分面板” / Panel Partition, not Facet, to avoid confusion with D4 classification. It is neither a dashboard nor filtering across Queries.

Query sort must establish every chart's row order explicitly. Category, series, legend and panel order follows first appearance in ordered input, never locale, hashmap or renderer defaults. line additionally verifies strictly increasing x within each series; it cannot silently sort x. table/list may display unordered results using Core's stable transport order with an “unspecified semantic order” indication; that order grants no take or drag-reordering semantics.

## 3. Closed layout set

The table lists binding members; `?` means optional, and unlisted members are forbidden. Additional options beyond the common object are explicit, never a free object.

| layout | result / bindings | Additional options and semantics |
|---|---|---|
| table | rows; `columns:[columnId...]`, nonempty and unique | None; display complete cells in the declared order; virtualization does not make partly loaded rows complete |
| list | rows; `primary`, `secondary?`, `target?` | None; primary/secondary are text or Optional<text>; target is EntityRef or Optional, with no implicit target read |
| task_list | rows; `title`,`status`,`target` | None; title is text, status exactly the tasks/status code type, target NodeRef; a read-only Task projection. Checking uses a separate D8 Action intent; Query still validates tasks/task |
| board | ordered rows; `key`,`lane`,`title`,`target?` | None; key nonoptional equatable and globally unique; lane text/code, title text; lanes follow first appearance; dragging neither changes Query nor writes a Field directly |
| calendar | ordered rows; `key`,`start`,`end`,`title`,`target?` | Required text `timeZone`,`tzdbVersion`,`calendarVersion`; endpoints are both date or both instant, positive duration and end-exclusive; a period is not an event and no reminder is automatic |
| timeline | ordered rows; same as calendar | Same as calendar; layout differs, without inferred duration or dependency scheduling |
| gallery | rows; `title`,`resource`,`target?` | None; resource is ResourceRef/Optional; display only projected metadata. A separately authorized Resource consumer obtains cover bytes; failure does not read another resource or owner |
| metric | quantitative or Optional<quantitative> scalar; bindings=`{}` | Required plain-text `unitLabel`, possibly empty; not a Gauge; no first-row selection or sum from multiple rows |
| bar | ordered rows; `category`,`value`,`series?` | `orientation:horizontal|vertical`,`mode:grouped|stacked`,`valueDomain:Domain`,`unitLabel`; value quantitative and nonoptional |
| line | ordered rows; `x`,`value`,`series?` | `xScale:linear|date|instant`,`xDomain:Domain`,`valueDomain:Domain`,`unitLabel`,`timeZone`,`tzdbVersion`,`calendarVersion`; missing value must be Optional and creates a gap, never a line across it |
| scatter | ordered rows; `x`,`y`,`key`,`series?`,`size?` | `xDomain:Domain`,`yDomain:Domain`,`unitLabelX`,`unitLabelY`; key globally unique, x/y nonoptional quantitative; size nonnegative numeric, zero has no area but keeps the accessible data point |
| pie | ordered rows; `category`,`value` | `unitLabel`; value nonnegative quantitative and nonoptional; category unique; zero values remain in the table and zero-total uses an empty-total state without division by zero |
| heatmap | ordered rows; `x`,`y`,`value` | `valueDomain:Domain`,`unitLabel`; x/y text or semantic_code and pairwise unique; value nonoptional quantitative; absent (x,y) is missing, never zero |
| network | graph; bindings=`{nodeLabel,edgeLabel,layerConstraint?,nodeDetails?}` | `placement:circle_v1|layered_v1`,`flow:up|down`; labels are text columns of their respective tables; layered requires a text layerConstraint column, circle forbids it. Query graph defines keys/endpoints; no user code or physics |

numeric means int64/integer/decimal; quantitative means numeric or quantity. bar category/series, line series, scatter series and pie category are nonoptional text/code. line x is nonoptional quantitative/date/instant according to xScale. An optional target binding only references an existing EntityRef cell; opening it requires fresh authorization and the cell carries no rights. Calendar key is globally unique. Query first generates explicit dates through Algebra §11; unavailable branches require a complete state table or explicit filtering, never View computation or row loss. A month/week viewport of the same terminal does not rewrite period identity; no undefined mode is added to ViewSpec. Calendar/timeline reject milestones (end==start); Gantt remains deferred, and zero duration cannot masquerade as an event.

Domain is exactly `{kind:"auto",zero:bool}` or `{kind:"fixed",minimum:TypedLiteral,maximum:TypedLiteral}`. Fixed endpoints match the axis type and min<max; any data outside the domain rejects the entire View with `domain_excludes_data`, without clipping. auto includes all data; zero applies only to quantitative values and adds zero with the same basis. Empty auto input gives an empty state without numeric ticks. A single value stays a single point/value annotation, never fabricated ±1 data. line date/instant forbids zero=true. Quantity zero uses the verified basis; numeric line/scatter auto zero is an explicit author choice. There is no reverse/log/symlog or renderer-default “nice” domain. Tick labels use actual extrema and explicit zero if present, with canonical numbers and no implicit timezone. D8 may add visual tick optimization that preserves the domain under a separate interaction contract, never writing Query values.

bar's unique key is (category,series), or fixed single when no series; duplicates are not aggregated. stacked requires nonnegative magnitudes. Missing series within a category keep a missing position, without zero-fill or connected area. Stack height is the geometric sum of explicit values, not a new exported fact; the accessible table retains original values. line keys are unique (series,x), x strictly increases within each series even when series interleave, and 0/1/2 points are legal. Optional.none breaks the line at that x and marks missingness instead of skipping then reconnecting. Pie geometry uses value/complete sum and cannot substitute for a business percentage that Query must supply. Exact integer/decimal ratios precede final screen-coordinate conversion; floats never overwrite source values. Scatter sizes cannot represent negative area. Sparse heatmaps are not zero-filled.

An all-missing line retains x and missingness without a line. Zero rows are empty; scalar none is no-value; scalar zero is zero. These states differ. Ordinary empty and authorization-filtered empty share the same presentation, without counts of hidden rows. Producing, error, cancelled, expired/reset and empty differ. Previously delivered local output may be marked stale, but cannot gain new delivery, export or actions; refresh creates a new result.

## 4. Wide tables, order, color, interaction and accessibility

v1 charts require long form. A wide `month,revenue,cost` table can use original Query `derive points=[{series:'revenue',value:row.revenue},{series:'cost',value:row.cost}]→unnest→project→sort`; the two list objects have the same type. No unpivot syntax or renderer melt is needed. Different measure types/units require an explicit Query conversion with a proved common type, or separate Queries/Views. Equal unit labels alone never justify stacking.

Color hashes a visible series/category key's Equality canonical bytes with UTF8 `D7-Palette/1\0` using SHA-256. The first eight bytes interpreted unsigned big-endian modulo 12 select a fixed palette slot. The twelve slots are named styles, not arbitrary CSS. A key is stable across refresh/order/device; collisions are allowed but require explicit labels and distinguishable accessible markers. No series uses fixed slot zero. An inaccessible color cannot be fixed by changing Query. D8 chooses actual colors/textures meeting contrast requirements. Legends follow input order. Temporarily hiding a series is explicit, reversible, nonauthoritative local presentation state marked as partial display. Export must identify either “current display” or complete data; it cannot omit a series while claiming the full original chart.

Tooltips/details use only projected columns of the current row. This version has no free tooltip expression, threshold line, reference band, target overlay or click-triggered Query. A separate explicit interaction can launch another Query/Action; this is not a ViewSpec effect. Every meaningful item and its exact original cells are keyboard accessible. Each chart has an accessible table with the same data/order and plain-text title/description; color, position or animation alone cannot carry meaning. Screen-reader order follows Query and panel order. CJK, Arabic/Hebrew and mixed RTL contents remain unchanged; App RTL does not reverse identifiers or axis semantics.

All layouts support reduced motion, high contrast, zoom, legible print/export alternatives. If Mobile lacks room, a table/list fallback uses the same complete data and explicitly reports layout unavailable; sampling/truncation cannot count as support. CLI/Server emit typed data and View validation status without claiming rendered graphics. Missing Desktop/WebUI/Mobile renderers follow D1 capability errors. D8 owns actual pixel, keyboard-focus, screen-reader and RTL acceptance; this contract claims no existing implementation.

## 5. Graph data and determinism

network consumes only a complete Query graph result, including isolated nodes. Every edge has visible valid source/target; Query authorization removes an edge with a hidden endpoint as a whole rather than letting View invent an anonymous hidden node. Parallel edges, self edges and cycles are allowed when the original D4 relation permits them, each with its unique edgeKey and label. View does not hide type or asserted/derived status. circle_v1 indexes nodes by Query's sorted order i=0..n-1 at angle 2πi/n (one node is centered); connections follow edge input order, self edges are explicit loops, parallel curves occupy slots by edge order within their endpoint pair. D8 preserves the corresponding keys/order. If nodeDetails exists, it is a nonempty unique ordered array of graph.nodes columnIds, all present in the nodes schema. It displays only each node's already-projected complete typed cells, recursively in declared column order, object schema-member order and original list order. It preserves repetition, empty text/lists, Optional.none and exact values; it does not filter/flatten into another relation, create facts, sort or invent target Refs. Existing list items may appear as read-only terminal detail cards attached to the owner node with nesting preserved. These cards have no graph vertex/edgeKey, navigation or relationship-expansion ability. Family text relatives display their original text/relation in such unexpandable cards; no Ref means no click-resolved target. Complete accessible tables/exports retain original nodes cells. This binding changes neither rank computation, graph endpoints nor the single-terminal contract. Algorithm and seed are fixed without randomness or persisted source coordinates. Scaling for pixel size preserves semantic/accessibility/export data; distance implies no fact.

Each layered_v1 edge supplies an explicit layerConstraint column value `none|forward|reverse|same`; no FieldId is inspected to infer it. none imposes no layer constraint but remains visible. forward requires rank(target)=rank(source)+1; reverse requires rank(source)=rank(target)+1; same requires equal rank. Fact endpoints and asserted/derived direction remain unchanged; layout constraints generate no inverse author facts.

The fixed algorithm first forms equivalence classes from same edges. On these classes, forward becomes source→target and reverse target→source solely for strict-layer graph validation. A strict self-loop or directed cycle yields cycle_not_supported. Within each undirected component of all non-none constraints, assign potential zero to the earliest node in Query order, then propagate exact difference equations in edge-input order. A conflicting existing potential yields layout_constraint_conflict; never delete an edge or move a spouse to force a fit. Subtract the component's minimum potential to obtain nonnegative ranks; isolated nodes or nodes connected only by none have rank zero. The result does not depend on DFS/BFS or physical partitioning. Nodes within a rank retain Query order; flow=down increases rank downward and up increases it upward. Translation affects geometry only, not author Query values; horizontal position at a rank does not imply ancestry.

The Family Tree template uses explicit D4 graphProjection=family parent facts (child→parent) with reverse, and explicit spouse/sibling facts with same. Equations for a child place multiple parents on one level; collateral relatives connect through real edges, and isolated nodes remain. Other relative literals have no NodeRef and cannot become entity endpoints. The template explicitly projects complete relationship labels and author text into literal_relatives in the same graph.nodes table and binds nodeDetails to it for the terminal cards described above. It neither claims a second rows terminal nor wraps text relatives in hidden entity placeholders. Friends/professional are excluded from the family template; a general network may show them with explicit none. View cannot permit self-facts rejected by D4. Other relations allowing self appear as loops in circle; layered allows satisfying none/same self constraints but rejects strict self constraints. Parallel facts and labels remain; repeating a constraint does not add facts or change layers.

These general geometric constraints also serve organization hierarchies and other directed graphs without new business-specific layout enums. A contradictory family graph may show all valid facts in circle only after the user explicitly selects another View. A failed layered View cannot hide contradictions or silently switch layouts and report success. tree/treemap and Gantt remain deferred below; multiparent Family Tree data is not forced into a forest.

## 7. Complete View validation, errors and resources

Validation order is closed decode→current result authorization/epoch→complete result→exact schema→layout/binding types→whole-data structure/order→domain/numbers→budget→current delivery gate. Errors are exactly `invalid_view|unsupported_layout|schema_mismatch|invalid_binding|incomplete_result|duplicate_key|invalid_order|negative_value|invalid_interval|missing_endpoint|cycle_not_supported|layout_constraint_conflict|domain_excludes_data|budget_exceeded|renderer_unavailable`. circle_v1 can display upstream-valid cycles. A strict-layer cycle in layered_v1 actually emits cycle_not_supported; inconsistent difference equations emit layout_constraint_conflict. Neither repairs data automatically.

Current authorization failures use Execution/D6 not_visible/reset order without hidden rowId/endpoint/key or counts. View errors may name static bindings, not data values. Points, series, categories, panels, nodes, edges, labels and output bytes each have finite budgets equal to the minimum of request/policy/host. Checked addition charges before allocation; exceeding any limit fails the entire View. All accessible-table output counts too; first-N-row delivery cannot bypass limits. Rendering or publishing an external export rechecks current result authorization. D9 workers receive only finite complete input, with no Core write rights.

## 8. Complete quantity basis and geometric axis domains

View validates TypeSpec and dynamic basis across every present value in the entire axis group. Quantities require identical dimensionId/unitId; dates require identical calendarId/calendarVersion/precision and the corresponding verified comparator retained by the current ResultHandle. Fixed endpoints participate. Shared panels validate together; independent panels may have different bases but must show each complete basis explicitly, never hide it under one unitLabel. A line series cannot invent another undeclared axis; any incompatible value on the same axis rejects invalid_binding. Numeric unitLabel is explanatory plain text. Quantity automatically displays full unitId and date its explicit calendar/version/precision. A unitLabel neither proves a unit nor triggers conversion.

Compute complete axis extent by the following exact mathematics before applying Domain once. Quantity arithmetic uses only same-basis magnitudes and preserves basis. Checking individual raw values cannot prove the layout fits.

| layout/axis | Complete extent included in domain |
|---|---|
| bar grouped | Every actual bar's zero baseline and value endpoint, negative values extending negatively; even zero=false includes the actual zero baseline |
| bar stacked | All exact nonnegative prefix sums in series display order for each (category,panel), and zero; maximum is that category's complete sum |
| line | x includes all x; value includes every present y, none creates a gap without y; include zero only for domain.auto.zero=true |
| scatter | Every actual x/y; size controls area without silently expanding axes or acting as a coordinate |
| heatmap | Every actual value; missing cells have no number |
| pie / metric | No axis; pie's exact sum is only a geometric denominator, zero-total a distinct empty state; quantity still requires a complete common basis |

After geometry extent per panel, shared takes their union and independent handles each separately. Fixed must cover the complete extent or fail domain_excludes_data, without clipping or expansion. Auto takes exact min/max and author-permitted zero; completely empty has no ticks, and a singleton stays a singleton without invented data. A stack `6+6` has extent [0,12]: fixed [0,10] rejects and auto's upper bound is 12. This 12 is a layout-validation value; accessible and exported typed data still contain exactly the two original sixes. Grouped [-3,2] has actual extent [-3,2]; fixed [1,3] rejects for both negative value and zero baseline. Any exact intermediate computation exceeding finite resources fails the whole View with budget_exceeded, never producing a drawable false domain through floating overflow or truncation.

## 9. Current result transport and source qualification

ViewSpec/1 and every layout, validation order and deferred disposition above keep their original closed sets. The current Query wireVersion2 envelope consumes the actual version of the same D6 ResultHandle/ResultCursor, without inferring an inner token upgrade from the outer number. Every page, View validation, export or Action continuation obeys Execution's same-cut, current-authorization, domain/epoch and complete-result gates. SourceVersion/2 and SourceObservation/1 are Core source/dependency evidence, not cells that a renderer can re-sign. The renderer cannot replace a current observation using equal revision, path, hash or a visible Ref.

For unavailable source state, insufficient continuity across domains or portable Locators whose named requalification is unresolved, View consumes the Query's actual delivery status. It cannot manufacture a valid current source or silently omit failed rows. Previously delivered output may be marked stale under the existing rules, but stale output, partial subscriptions, one page or incompletely read effects cannot constitute Action confirmation. D8 Draft/full preview and D9 Worker export retain their separate entries and actual capability gates, without private execution arms in ViewSpec.
