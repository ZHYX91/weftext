Fixed-S scope and evidence: not accepted or activated. ## 1. Product choices and scope

Users need to bring PDFs, workbooks, and office documents into their information workspace, and use ordinary text placeholders in templates made with existing office software to produce usable documents and spreadsheets. Choose a Weftext-owned conversion coordinator, closed typed Import IR, Core mapping, and the original transaction protocols; converters need not be pure Rust. Default file-level document import produces one document-level Node. Per-page Nodes are an explicit structural transformation, not the extraction default.

D9 specifies architecture and bounded first-generation profiles: the common probe/worker/IR/loss/proposal chain, distinct page and workbook representations, explicit table mapping, ordinary Office templates, one-time Node Template construction, DOCX/ODT heading mapping, export publication, and resource-region profiles. Each format/function/platform still needs independent implementation evidence before availability. This work declares no new conversion available and supplies no production worker.

Not opened in this generation: arbitrary script/expression templates; automatic rich HTML/RTF clipboard import; Office formula evaluation/rewriting; unconditional lossless round trips; continuous external synchronization or bidirectional writes; a production ICS conversion profile; all CAJ variants; unproved semantic relocation; Mobile conversion execution, delegation, monitoring, or approval. Later clauses assign these boundaries and failure outcomes explicitly; “generic IR support” cannot substitute for a missing format profile.

This candidate includes explicit coordinated amendments: D3 template-result handling and its mirrored preparation clauses, D7 PreparedActionBinding/3, and version-consumption references for D6/D7 effects. The amendment document gives the complete changes. Existing upstream authority remains until acceptance; D9 cannot be activated alone while omitting these files. New requests consume D3 wire12/Result9 and D6 commit/2. Real old wire/receipts, original stage order, and the single transaction authority recover under their producing versions.

## 8. Complete alternatives and acceptance conditions

Direct third-party AST reuse minimizes adaptation but imports its schema/version/omitted cells or identity into the product: rejected. A universal paragraph/table tree loses workbook holes/formulas/merges and PDF geometry: rejected. Separate Core transactions per format create a second write authority: rejected. Converting everything to PDF cannot meet Office structure/typed-table needs; it is only a separate explicit-loss page route. Templates executing Query/CEL/scripts or enhancing Office's data model create hidden author powers: rejected. Finite profiles, typed IR, pure templates, explicit mapping, and original transactions mean some formats/rich formatting/formula fidelity remain unavailable; capabilities and preview must show that cost.

Independent final review must assess simpler complete alternatives, upstream/naming/semantic/wire consistency, path/data permissions, transactions/restart/side effects, actual format facts, and every scenario. Acceptance requires explicit accept/pass and zero open P0/P1. Bounded local tests, vendor format lists, and architecture prose are not product acceptance.
