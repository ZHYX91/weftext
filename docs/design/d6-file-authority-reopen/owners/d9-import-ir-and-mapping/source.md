# D9 Import IR and Mapping

Fixed-S scope and evidence statement: every type here describes input evidence or conversion proposals, not managed-content algebra. Version `1` in this document is the target profile; the old implementation's `weftext.import-ir.v1` receives no compatibility identity and must be replaced as a whole during implementation.

## 1. Frozen and extensible boundaries

The common envelope, source coordinates, typed content, loss/unsupported items, completeness, and Core mapping obligations are frozen. No third-party AST is frozen, and these three branches do not claim to represent every future format. A new format structure that cannot be expressed needs a new profile and admission. Unknown kinds/versions reject rather than entering an `any` field. IR may represent more than D2; mapping to D2 requires explicit loss or rejection.

`ImportIR/1` is exactly `{format:"weftext.conversion-ir",version:1,sources,profileId,documents,resources,issues}`. sources is the bound SourceArtifact catalog in probe order; documents is a nonempty finite array, resources the extracted-artifact catalog, and issues all detected issues. Keys are continuous Counter ordinals from zero within this IR, without duplicates or holes. They are local representation addresses and never enter D3 identityMap. Array order expresses the source/profile order; object iteration or digest sorting cannot reorder reading sequence.

`document` is exactly `{key,sourceIndex,title,content}`. title is observed original text or null. Missing title must be supplied explicitly in mapping, not silently derived from a filename. content has three variants:

- page is exactly `{kind:"pages",pages:[Page...]}`.
- flow is exactly `{kind:"flow",blocks:[FlowBlock...]}`.
- grid is exactly `{kind:"workbook",dateSystem,sheets:[Sheet...]}`. dateSystem is `none|excel1900|excel1904|odf`, never inferred from host defaults.

One input can produce multiple documents, such as a package, and mapping must choose a disposition for each. Pages/sheets do not automatically materialize as Nodes. A PDF defaults to one document, XLSX to one workbook; showing a sheet does not make it a persistent entity.

A resource is exactly `{key,sourceIndex,mediaType,byteLength,sha256,outputSlot,origins}`. outputSlot is an opaque Counter in isolated worker output, issued by the host after checking actual regular-file bytes. Arbitrary paths, URLs, or large embedded base64 are not accepted. Descriptor length/digest must equal actual bytes. Two semantic resources with equal bytes may remain separate; mapping decides explicit reuse rather than digest-based provenance merging.

An IR issue is exactly `{feature,locations,message}`. feature uses §7's minimum closed vocabulary, locations is a nonempty SourceLocation array, and message is nonempty plain text. Workers report observations, not user choices, authority, or accepted severity. Core derives LossReport from independent coverage/mapping and includes every worker issue. A whole-input issue uses a bytes location covering that complete source. A valid empty CSV may form an empty workbook; unparseable empty output cannot use this exception.

## 2. Sources, confidence, and completeness

`SourceLocation` is a closed union:

- `{kind:"bytes",sourceIndex,start,end}` uses half-open bytes with 0≤start≤end≤original source byteLength; it does not claim text scalar coordinates.
- `{kind:"page",sourceIndex,page,rect}` uses an actual zero-based page index. rect is `{x,y,width,height}`, all integer millionths, with 0≤x,y<1,000,000, width,height>0, and each endpoint≤1,000,000. Its basis is the defined normalized upright reading-page space. A bounding box is not a text selection.
- `{kind:"cell",sourceIndex,sheet,row,column}` uses actual zero-based logical worksheet/sheet/row/column coordinates, never filtered visible positions.
- `{kind:"part",sourceIndex,part,elementPath}` uses a package name validated by the canonical OPC/ODF part-name validator; elementPath is a nonnegative child-element-index array from that XML part's root. The format profile has validated namespaces. This is evidence location only, never a workspace path or cross-version address.

`Observation` is exactly `{origins,confidence,method}`. origins is a nonempty SourceLocation array, confidence is null or Counter 0..10000 in basis points, and method is `extracted|ocr|inferred|user_supplied`. Null means trustworthy confidence was not supplied, never 100%. Method follows the executed route and actual observation; a worker cannot mark OCR/inference as user-authored original text. The same text may have several source regions, and equal text does not merge observations.

The IR validator checks graph acyclicity, complete indices, source ranges/owners, issue references, unknown members, actual resources, format profile, and budget. This alone does not prove the parser omitted nothing. A separate format-coverage validator must verify page/sheet counts, all selected package parts, selected cell ranges/content, reading order, and unsupported-feature catalog. Every discovered unrepresentable object becomes an issue, with staged source retained for inspection. Empty IR cannot masquerade as success. Unproved coverage or unrecognized format returns invalid_output/unsupported_profile. Production-profile acceptance needs real corpora and independent parse/render comparisons; current finite fixtures establish only counterexamples and representation feasibility.

## 3. Page branch

`Page` is exactly `{index,widthMicrometres,heightMicrometres,rotation,items}` with continuous index, positive Counter physical dimensions, and rotation=`0|90|180|270`. The profile's region basis already applies original rotation; item rects describe the upright displayed page. Rotation records conversion metadata and is not applied again by the consumer.

`PageItem` is exactly `{key,observation,rect,content}` with keys continuous across all items in its document. content is closed: `{kind:"text",text}`; `{kind:"image",resourceKey,alt}` where alt is text|null; `{kind:"table",rows}` with a rectangular CellValue array; or `{kind:"unrepresented",feature}`. Text is logical reading text retaining scalars, never glyph-visual-order reversal for RTL. Item order follows the route's declared reading sequence; inferred/multicolumn ambiguity produces an issue. Sorting geometric y/x is not proof of reliable semantics.

A page table is an extraction observation without Field schema or header authority. Merged cells/nesting unrepresentable in this branch need issues and may retain the original image. Failed detection or low OCR confidence cannot fabricate content, and any OCR output must be previewed. A screenshot/scan image Resource and OCR text are separate sourced results; extracted text is not claimed as exact original text.

### Image physical-dimension profile (image_physical_size/1)

Physical dimensions here are display dimensions explicitly declared inside the source. They do not prove the physical size of the subject, scanned paper, or camera. Missing metadata is not filled from format/host defaults. image_page_v1 physical dimensions come only from exact-byte declarations verified by a format decoder: PNG pHYs with unit=metre, or JPEG JFIF density/EXIF XResolution, YResolution, ResolutionUnit. Pixel dimensions are not physical dimensions. PNG unit=unknown, JPEG aspect-only/missing density, and EXIF without a usable explicitly recorded absolute unit mean absolute dimensions are missing; never substitute 72/96 DPI, OS defaults, or preview size. Invalid/zero/negative density, invalid rational denominator, or conflicting absolute declarations returns invalid_output. No source is picked arbitrarily, and explicit output dimensions cannot hide format ambiguity. Every named production decoder must completely check these metadata; unsupported density variants cannot be guessed.

Convert each axis to exact rational pixels per metre: pixels/inch ×5000/127, pixels/cm ×100, and PNG integer ppm unchanged. Multiple absolute declarations agree only if each reduced rational axis is exactly equal. Physical micrometres equal pixels×1000000/ppm, rounded with exact arithmetic to nearest integer, ties to even. The result must be a positive Counter within route budget; zero after rounding or overflow is unrepresentable. Noninteger rounding creates an actual precision issue/loss rather than a lossless claim. Compute original pixel/physical axes first, then apply validated EXIF orientation: orientations 5–8 swap width/height, others do not. With no valid direction declaration, the format's specified unrotated default applies; invalid/conflicting directions reject.

Relative density (PNG unit=0, JFIF unit=0) fixes only displayed aspect W×dy/(H×dx), never an absolute unit. Relative and absolute aspect declarations must agree or return invalid_output. With no density/aspect declaration, this profile explicitly uses square-pixel display aspect W/H only as a layout basis, without inventing physical dimensions. Upright orientations 5–8 invert it. Office explicit-size fidelity compares this displayed aspect, not a guess from total pixels. Small aspect changes caused by quantizing valid absolute dimensions are precision loss rather than a second independent aspect loss.

A valid image without absolute density cannot supply this generation's Page physical dimensions; image_page_v1 conversion returns unrepresentable. The original may be saved as an inert Resource. An Office image asset may still be laid out with frozen explicit dimensions as specified in Templates; that layout selection does not become IR source observation. This generation provides neither a default image-Page DPI nor a user-supplied physical-dimension entry.

Normalized Resource Regions depend only on exact decoded pixels/orientation and original Resource revision, never physical dimensions. Missing DPI does not prevent region issuance when the geometric profile is otherwise satisfied. Physical-dimension policy cannot alter d9rg1 or outer l1.

## 4. Flow branch

`FlowBlock` is exactly `{key,observation,content}`; keys are continuous in whole-document tree preorder. content is:

| kind | Exact other members |
|---|---|
| paragraph | text |
| heading | level,text; levels 1..9 observe the source format, while D2 targets remain limited to five |
| list | ordered:Boolean,items:[{text,children:[FlowBlock...]}...] |
| table | rows:[[CellValue...]],merges:[{row,column,rowSpan,columnSpan}...] |
| literal | text,language:text or null |
| quote | text |
| image | resourceKey,alt:text or null,caption:text or null |
| break | None |
| unrepresented | feature:text |

Flow input does not carry trusted AsciiDoc in source_text. The first Flow profile has no dedicated structure for complex inline formatting, footnotes, math, tracked changes, or embedded objects. These require issues plus explicit flatten/original-retention/rejection; visually readable output is not necessarily lossless. Header/footer/comment/footnote text that the exporter cannot independently map does not get mixed into body. A future richer Flow profile may replace this profile, but unknown properties cannot smuggle it in.

## 5. Workbook branch and CellValue

`Sheet` is exactly `{index,name,visibility,rows,columns,hiddenRows,hiddenColumns,cells,merges}`. index is continuous in workbook order, name is exact without trimming, and visibility is `visible|hidden|very_hidden`. rows/columns are the finite logical rectangle selected by this profile; dimension metadata does not directly authorize allocation. Actual sparse cells are unique and sorted by (row,column). Each `cells` element is exactly `{row,column,value,formula,styleClass,observation}`. A nonexistent coordinate is **absent**, distinct from an existing blank cell. formula is null or exactly `{text,cached}`, with cached CellValue or null for no cache. value is formula cache or blank and must agree with cached when a formula exists; `data_only` cannot silently discard the formula fact. styleClass=`general|text|date|time|datetime|other` is only a source display hint, not a typed value.

`CellValue` has exact variants `{kind:"blank"}`, `{kind:"text",text}`, `{kind:"boolean",value}`, `{kind:"number",lexeme}`, and `{kind:"error",code}`. A numeric lexeme retains the source format's finite decimal/exponent ASCII spelling without binary-float conversion. The format decoder first bounds length/exponent; Core mapping then explicitly converts to a D4 canonical decimal/integer. This is source evidence rather than a D4 value; NaN/Infinity are forbidden. Error code retains its original legal profile text and never becomes an empty value. XML shared/inline rich text joins in logical run order with formatting loss recorded, retaining original text whitespace. Missing text and empty string remain distinct.

hiddenRows/hiddenColumns are arrays of exact half-open source-ordinal intervals {start,end}, with 0≤start<end≤the corresponding rows/columns. Intervals increase without overlap, and adjacent intervals must merge. No hidden range is []; sheet visible/hidden/very_hidden is independent. Format coverage independently proves both arrays complete from actual row/column declarations, including compressed/repeated ranges, rather than messages. CSV/TSV use []. The finite logical range includes every actual cell, merge, and declared hidden range; dimension metadata cannot omit hidden content. Exceeding budget rejects.

Merge rectangles stay inside the sheet with positive spans and no overlap; anchors retain actual values and covered cells are not copied automatically. Formulas/merges are not expanded while reading. Typed fields preserve all hidden sheet/row/column facts and a hidden_content issue with exact SourceLocation. Rich text/comments/drawings/validation/filter/external links/pivots still produce complete issues. Workers do not choose include/exclude; only the mapping rules below do.

CSV/TSV is one sheet of text cells, preserving every input character without numeric/date inference. The CSV profile uses strict UTF-8, records any optional UTF-8 BOM explicitly, and follows user-selected CRLF/LF and RFC4180 quote/double-quote rules. Delimiter/header are explicit rather than sniffed. Invalid quoting, ragged rows, and NUL reject. Empty file is 0×0; one empty record is one empty-text cell. TSV splits fields at tabs and rows at selected CRLF/LF. The first profile supports no quote escapes or tab/newline within a field; such bytes cannot be called lossless TSV. One final terminator does not add a row; whitespace and consecutive empty fields remain. Columns use ordinals and duplicate/empty headers are not unique keys.

## 6. ImportMapping/1

Mapping is exactly `{version:1,documents:[DocumentMapping...]}`. Every IR document has exactly one entry in key order, with no omission/duplicate. DocumentMapping is a closed union:

- `{documentKey,kind:"omit",reason}` uses an explicit nonempty user reason and produces omission loss.
- `{documentKey,kind:"document_node",destinationParent:NodeRef,destinationOrdinal,title,bodyPolicy,retainOriginal}` uses a nonempty title compilable to D2; bodyPolicy=`strict|plain_text|page_images`, retainOriginal is Boolean. strict accepts only observations completely mappable to D2; plain_text requires confirmation of every loss. page_images requires complete page-image evidence in pages and creates each page image as a Resource of this Node; an unrendered page is not an empty image.
- `{documentKey,kind:"rows_to_nodes",destinationParent:NodeRef,destinationOrdinal,sheet,range,header,titleColumn,facets,columns,hiddenPolicy,retainOriginal}`. range is exactly half-open `{startRow,endRow,startColumn,endColumn}`. Selected source rows are explicit, header is Boolean, titleColumn is an absolute source-column ordinal, and facets is a sorted unique D2 FacetId set. Each columns entry is exactly `{column,fieldId,conversion,emptyPolicy,formulaPolicy}`. Registry must define FieldId; a display label is not accepted. conversion=`text|integer|decimal|iso_date|boolean`, emptyPolicy=`reject|omit|empty_text`, formulaPolicy=`reject|cached|literal`. One source column may explicitly map to multiple different Fields; duplicate target Fields require schema repeatability and a complete entry plan, never last-win.
- `{documentKey,kind:"table_document",destinationParent:NodeRef,destinationOrdinal,title,sheet,range,header,formulaPolicy,hiddenPolicy,retainOriginal}` creates a D2 native table in a new Node body. Every cell must be inert and D2-representable; no row identity is created.

Workbook supports only rows_to_nodes/table_document/omit, never document_node; flow/pages support only document_node/omit. Core computes multi-file destination ordinals within the batch by original D3 forest rules. Conflicting proposals reject rather than assigning the same position by UI order. Empty/blank/unadjudicated-formula/invalid titleColumn fails instead of inventing “Untitled row N.” rows_to_nodes creates one fresh Node per data row, including distinct objects for duplicate rows. retainOriginal for rows_to_nodes would require an explicitly additional wrapper Node; this first variant fixes it to false. True returns mapping_required for a separate attachment intent, never hidden wrapper creation. The other two variants attach original Resources to their new Node.

Both workbook mappings require exact hiddenPolicy {sheet:"exclude"|"include",rows:"exclude"|"include",columns:"exclude"|"include"}. UI initially selects exclude for all three, but actual requests explicitly save all three choices. Selecting a rectangle does not mean include. Authorization precedes disclosure of hidden ranges.

1. If sheet.visibility is not visible and sheet=exclude, the selected result is empty with no Node/Resource. retainOriginal=true in that combination returns mapping_required rather than an implicit attachment Node. Complete analysis reports whole-sheet exclusion. Only include proceeds to row/column calculation.
2. Within original half-open range axes, exclude removes indices intersecting typed hidden intervals; include retains them. The resulting source-row and source-column lists strictly increase. Source ordinals are never renumbered before bindings apply. rows_to_nodes titleColumn and every columns.column must remain in the retained column list, otherwise mapping_required; never shift to the next visible column or silently delete a Field.
3. header=true selects original range.startRow, not “the first retained row.” If hidden exclusion removes it, return mapping_required. The header itself produces no Node; header=false reads no header semantics. Each remaining source data row produces one fresh Node in original order, including separate Nodes for equal rows.
4. table_document compacts retained row list × column list into a rectangle in original order, preserving original cell origins. A merge intersecting selection/exclusion that cannot remain complete is unrepresentable. A fully retained merge is flattened according to the existing table output, with merge-layout loss explicitly accepted and without copying its anchor value. An empty axis produces no table/Node/Resource; retainOriginal=true again returns mapping_required. No fabricated header or empty “untitled” Node is produced.
5. Actual excluded content creates hidden_content requires_choice, identifying the exact sheet/row/column and projection effect. Included content generates only a notice that visibility does not become D2 author-hidden state, with separate formatting loss if the target lacks that presentation. Changing hiddenPolicy requires new d9_import_analyze and complete recomputation of objects, ArtifactObjectKeys, groups/batches, and preview. Old analysis/loss acceptance does not carry over. Equal ranges with different hiddenPolicy remain different inputs even when this input has no hidden objects.

Conversion rules: text remains exact. integer accepts only ASCII canonical integers without thousands separators, locale digits, decimals, or exponents. decimal uses exact arithmetic for the D4 canonical string, and every lexical change enters loss. iso_date accepts only explicit complete ISO date text and produces D4 calendar_date with calendarId=calendar/iso8601, calendarVersion="1", precision=day, and a lexeme validated by the original decoder. It creates no kind=iso_date/date and does not infer from styleClass. boolean accepts a source Boolean or explicit text `true|false`, never 1/0. empty_text is allowed only for text targets, with the original blank/absent/empty-text distinction reported as loss. omit produces zero Entries, never null. Error cells cannot become Field values in this profile; only an explicitly supported text-literal conversion with loss could admit them, and absent that specific conversion they reject.

First-generation rows_to_nodes iso_date cannot consume numeric date serials. A separate explicitly selected `date_serial_to_iso` mapping-preview profile would be required, and it is not open yet. Export date policy is in Workers and Export. Excel1900 serial60, timezone/non-Gregorian interpretation, and precision are never guessed. Formula cached mode needs an actual cache and states freshness=unverified without recalculation; literal imports only original formula text, missing cache rejects, and formulas never become CEL.

Complex/multi-valued D4 objects, relations, quantities, and People names cannot be forced into these scalar mappings. Retain the original or use a separate complete Core typed proposal. A Field without a closed mapping is explicitly unsupported_profile, not downgraded to a string; manual typed D7 Actions remain possible.

D2 table generation proves each final inline cell parses as the requested inert text. It handles pipes/backslashes correctly and rejects CR/LF, macro/attribute forms, or other values that cannot be represented losslessly. Rejection never truncates, splits rows automatically, or repairs ragged input. This authorizes explicit conversion into a new Document only, not D8 batch paste into an existing table.

All IR text, titles, list items, quote/literal text, and template replacements are text data. Concatenating them and checking only D2 validity is insufficient. Core first constructs the expected D2 semantic AST from explicit mapping, safely encodes complete source, then independently parses and compares structure, text, metadata, typed refs, and their positions item by item. They must agree except for explicitly chosen loss transformations. Input such as “== text,” macros, or carriers cannot create unintended structure. Unrepresentable inert semantics returns unrepresentable. Unknown kinds or incompletely handled blocks are blocking, not made valid by ignoring fields.

## 7. LossReport/1

This section applies only to file import and Node Template construction. Export uses the separate ExportLossReport/1 from Workers and Export §3a and does not widen this locations union, TemplateConstructionInput, or PreparedActionBinding.

The exact shape is `{version:1,items}`, with each item exactly `{lossKey,feature,locations,effect,severity,allowedChoices}`. lossKey is a continuous Counter within this complete proposal, bound with input/mapping. File-import locations are a nonempty SourceLocation array; Node Template construction uses Templates' TemplateLossLocation array. The domains cannot mix, nor may arbitrary strings address another file. effect is a nonempty readable explanation, severity=`notice|requires_choice|blocking`, and allowedChoices is an array from the closed `accept_loss|reject` values.

The first choices adjudicate an already complete fixed proposal and execute no conversion. blocking has allowedChoices=[reject] and cannot prepare; notice has []; requires_choice has [accept_loss,reject]. accept_loss retains the real effect and records accepted notice in a new analysis. reject returns cancelled without a new author request. Conversion itself must be expressed by ImportMapping bodyPolicy/retainOriginal/formulaPolicy/hiddenPolicy/omit or explicit TemplateConstruct selections; changing them reruns analysis. There is no generic retain_original/flatten_text/omit choice, and especially no loss-choice bypass of rows_to_nodes retainOriginal=false. One complete selection covers every requires_choice and blocking item; blocking can only reject and cancel the whole selection. Old analysis is immutable and new loss never inherits old acceptance.

The minimum feature vocabulary is `formatting|layout|reading_order|ocr_uncertain|heading_depth|merged_cells|formula|formula_cache|precision|date_semantics|hidden_content|unsupported_object|metadata|control|field_semantics|references|annotations|signature|active_content|omission|direction`. Unknown features need a new profile rather than a free-text code concealing undefined semantics. Reports include every detected actual loss and do not claim undiscovered content was preserved. Original-artifact integrity and provable target semantics are reported separately.

Preparation retains the complete initial LossReport before choices and all lossChoices. Showing accepted notices in current analysis does not delete the original report. Every Core revalidation confirms complete equal effects from the same input/profile/fixed mapping before consuming original lossKey choices. Any new or changed loss requires renewed analysis/confirmation, never old acceptance applied by ordinal.

Features are classified by the fixed target effect. Unclear safety/format, uncertain coverage, missing rights, invalid D2/D4, and active templates are blocking and cannot be overridden by accept_loss. Loss caused by explicit unselected content or a fixed representable projection—formatting/layout/reading order/OCR/heading depth/merge/formula cache/precision/date/metadata/control/Field/reference/Annotation/signature/omission—is requires_choice. Pure source/direction explanations with no information loss are notice. Every loss needs actual source and a concrete output difference; an effect that cannot be defined is blocking. Keeping the original is an independent Resource mapping choice and never erases other loss. Apply this classification together with the single allowedChoices matrix; UI/free messages never define conversion programs.

## 8. Resource Region Profile/1

Only `pdf_display_rect/1` and `image_display_rect/1` are frozen. `regionToken` is `d9rg1.` plus canonical unpadded base64url of `ASCII "D9-Region/1" + NUL + D3-CJ/3(RegionBody)`; it is not a host-private registry handle. RegionBody is exactly `{version:1,profile,page,rect}` and holds only non-identity geometric facts. The original outer D3 ResourceRegionLocator completely binds exact ResourceRef/revision, then uses original `l1` encoding as the D2 regionLocatorToken. d9rg1 alone is not a complete Locator, and RegionBody cannot repeat an unallocated fresh Ref. Core verifies geometry against exact Resource bytes and issues the outer owner/revision through original fresh-subject materialization. page is positive and explicitly converts this IR's zero-based page by +1. Images permit page=1 only; multiframe images reject rather than silently selecting the first frame. rect uses §2's positive-area millionth rectangle.

The PDF basis is the exact Resource page's CropBox clipped to MediaBox, with /UserUnit and /Rotate applied to upright display, origin top-left, x right and y down. Invalid boxes, nonpositive dimensions, rotation not divisible by 90, or indeterminate pages reject. Image basis is the actually decoded upright image after EXIF orientation, also top-left; invalid/ambiguous orientation rejects. Core validates normalization for a supported decoder profile, while UI supplies only selection intent. Issuance rounds x/y down and right/bottom up to millionths, clips to [0,1000000], and rejects zero area. Equal source/profile/rectangle inputs produce one token.

d9rg1 contains no zoom, DPI, viewport, glyph index, or filename. Changed image/page direction that changes bytes creates a new revision and makes old complete l1 stale. View zoom/RTL shell does not change a Locator. copy/fork/owner changes require original D3 reissuance of complete outer owner/revision; d9rg1 geometry may remain only when verified against the same exact content profile. PDF→PNG or OFD→PDF creates another Resource without automatic Annotation transfer. Users may explicitly create a new target, retaining the old target unchanged.

Original D3 resolver lexical/failure ordering is unchanged: nonempty regionToken remains opaque and does not run geometry decoding at stage1 or before authorization. Original owner/entity and mayDiscloseLocatorState qualification precede exact revision and profile geometry checks. Unverifiable same-revision regions map to original resolver stale/operation stale_locator. Only a new D9 issuance entry may use unsupported_profile/invalid_output; these do not enter the existing D3 resolver. d9rg1 differs from the D2 ResourceRef outer r1 token and is not interchangeable.

Accessible alternatives: existing plain Annotation body remains visible under its original rules; UI reads page number and percentage rectangle and offers keyboard selection of the whole Resource. It does not claim exact readable text from a rectangle. OCR alternatives are separately marked inferred and remain subject to Resource read permission. A region grants neither editing nor cross-version positioning nor a body-source range. Parsing, issuance, and actual screen-reader use still require implementation acceptance.

## 9. Assessment of the second structural validation

PDF pages have geometry, reading order, and OCR uncertainty. XLSX workbooks have sheet order, typed cells, absent/blank distinction, formulas/caches, merges, and date systems; a paragraph/table-string model cannot preserve them losslessly. Actual fixtures extracted PDF bytes and XLSX ZIP/XML bytes into the respective branches and tested schema/mapping/loss rejection without depending on a third-party IR identifier. CSV quoted-newline/ragged/duplicate-header examples further checked the distinction. This demonstrates that the common boundary does not force these structures into one representation; it does not prove every PDF/XLSX, full official conformance, Office-application interoperability, or production isolation. New formats still require admission per profile.

## 10. Current outer protocol and stable original IR

ImportIR/1, ImportMapping/1, SourceArtifact, SourceLocation/Observation, CellValue, LossReport/1, image_physical_size/1, and Region Profile/1 retain their original shapes and every format/safety/loss obligation. Observation here is external extraction evidence, not D6 SourceObservation/1; it has no Workspace/CommitDomain, managed revision, or author qualification. The main and coordinated documents define complete current D9/2, ConversionInput/2, original D3 wire12, and single DecisionKey bindings when importing author content. Worker output cannot become source-version proof.

Only real strong authorization, same-cut complete Registry/dependencies, D2 parse, and all D4 admission can prepare author effects. Complete current sourceObservation proof remains distinct from D4 inner revision; externalSequence is not a managed revision. Current TemplateLossLocation consumes Templates /2 complete production addresses/authorized omission directory and is decoded explicitly by the enclosing construction version. This neither changes file IR's SourceLocation union nor admits author addresses into external IR.

The workbook mapping header selects input first-row semantics only. The target is still an ordinary D2 native table with no attribute/header option. Display-only purposes cannot generate such an option either. A retained row of ordinary text is encoded as actual ordinary cells, without a separate header type or a batch-paste path forbidden by D5/D8.

d9rg1 geometry is not rewritten when current CommitDomain changes. For an outer D3 ResourceRegionLocator, current use follows D3's repaired order: prior Resource/locator disclosure, exact Frontier and lifecycle; require D6 validation of the exact signed `RevisionTokenSealArtifact/1`; resolve its authenticated binding to the exact production SourceVersion; prove this receiver's current Resource Observation has exactly that sourceVersion; then validate the original ResourceRegionLocator revision plus this profile's page/rect geometry and final read barrier. D9 geometry never authenticates the revision token. The returned locator/regionToken is not rewritten, and d9rg1 alone grants no capability. Equal bytes, geometry, Counter or digest never supplies version/event proof. A converted Resource, changed bytes/orientation or different production version stays stale. Actual fresh copy/fork sources still use the original candidate map/SourceRevisionPlan/seal. This consumes the authored PL-IR-01 repair and remains pending independent review; historical regions/profiles/receipts retain their original decoder and are never re-signed as current runtime evidence.
