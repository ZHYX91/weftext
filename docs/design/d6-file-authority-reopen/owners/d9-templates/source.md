# D9 Templates

Fixed-S scope: distinguish Node Templates producing fresh Nodes from Office templates producing external files. Neither continuously controls its results, executes Query/CEL/scripts, or creates template-specific content identity.

## 1. The single ordinary-text placeholder grammar

Office profile=`weftext.office-template/1`. Inputs are DOCX, ODT, XLSX, and ODS; format/operation capabilities remain separate and cannot be declared available before acceptance. The same grammar applies across formats without content controls, bookmarks, named ranges, Excel Tables, Office data sources, macros, or plugins.

```text
{{ meta.title }}
{{ header.description }}
{{ field.user/report-code }}
{{ content.body }}
{{ view.bibliography }}
{{ ↓ data.orders.product }}
{{ → data.months.amount }}
```

An ordinary token is exactly `{{ ` + path + ` }}`, with one ASCII space on each inner side; no tab, NBSP, extra spaces, or newline. A repeat token is exactly `{{ ↓ ` or `{{ → ` + data-path + ` }}`. Paths contain no spaces/operators/expressions/defaults/functions. Each token is at most 1024 UTF-8 bytes; each template at most 10000 tokens. All structure/generated output additionally obey the common budget.

Scan logical text scalars once left to right: `{{{{` produces literal `{{`; `}}}}` produces literal `}}`; every other `{{` must start a complete legal token and every other `}}` is a syntax error. Single braces are ordinary characters. Thus `{{{{ meta.title }}}}` outputs literal `{{ meta.title }}`. Never rescan substituted values: template syntax inside a value is text, not injected loops/fields. Consume escapes before token recognition and never across containers. Any invalid token fails the whole template; unreplaced markers cannot remain under a success result, except explicitly escaped literal markers.

The first path segment is closed to `meta|header|node|field|content|view|asset|data`. Reject old bare names, `attr`, `record`, case aliases, and loose spacing. The UI provides insertion/inspection commands. Language/software versions do not change token semantics. Users may format the token itself with font/color and other styles.

## 5. Repeat regions, direction, and collisions

Repeat tokens allow only `data.SET.COLUMN` and occupy the whole logical cell text. Ordinary scalars may occupy other prototype-band cells, but no surrounding text in a repeat cell. This profile repeats **one complete table row or column**, never a partial band within a rectangle. The container is the DOCX/ODT table or the XLSX/ODS sheet's entire occupied rectangle. At most one band and SET per container: ↓ selects the unique token row, → the unique column; all direction tokens in that band agree in direction/SET. Different tables/sheets may each have one. Reject nested table repetition, crossing bands, or multiple bands in one container to avoid uncertain displacement order.

↓ copies the prototype row per snapshot item without changing columns; → copies its column without changing rows. Direction means increasing logical indexes; RTL does not reverse → data. Repeat cells read item columns; static cells/ordinary scalars copy their values. Zero items delete the band. Remove DOCX/ODT tables left with zero rows/columns; retain XLSX/ODS sheets, possibly empty. Preview lists this explicit empty-region behavior.

Coordinate transform for band b, item count n: axis i<b unchanged, i=b copied to b..b+n-1, i>b shifted to i+n-1; n=0 deletes b and shifts successors by -1. The other axis stays fixed. Classify every object before computing target footprints. Prevalidate row/column limits, cumulative cells, output size, and collisions, then create the copy rather than discovering overflow mid-write.

Copy cell formatting, borders, row heights/column widths, and all supported presentation properties. Merges may be copied only wholly inside the band. Other template formulas also obey the next paragraph. Reject coordinate-dependent images/charts/drawing anchors/named ranges/Excel Tables/validation/conditional formatting/print ranges in repeat containers; claim no automatic movement. The whole first-generation Office template forbids macros, executable fields, formulas, external relationships/data sources, embedded OLE, scripts, remote images, and digital signatures.
