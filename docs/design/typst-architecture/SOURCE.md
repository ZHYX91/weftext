# Typst author source and centralized schema: redesign candidate

Status: design candidate, neither implemented nor accepted. [REQUIREMENTS](../typst-native/REQUIREMENTS.md) defines outcomes and [REVIEW](REVIEW.md) records validation. This file owns author source, application roles and the single field type system. Representative schemas and examples are not a ceiling on business capabilities.

## 1. Author source and application roles

A note has one `.typ` author source. The coordinated Core design owns stable note identity, centralized schema authority, independent annotations, resources and the actual directory tree. This document owns source roles, value semantics and consumer boundaries; it does not reuse the old Pin, Proof, Entry, carrier or SourceRevisionPlan families.

Standard `#metadata((id: "...", types: (...), ...)) <weftext>` carries author properties. `id` is a lowercase UUIDv4 allocated by Core and admitted only after a successful creation transaction. It is not authorization. Rename/move preserve it; copying or importing as a new note allocates a new ID. External ID changes are identity conflicts requiring admission. Core supplies source paths from its directory authority: metadata does not duplicate path/parent/children. Missing declarations or partial synchronization never authorize identity regeneration.

The official Rust `typst-syntax` library is the sole parser. An AST checker verifies application roles without regex header parsing, a second lexer, or an embedded YAML/JSON dialect. Exact UTF-8 bytes, BOM, comments, line endings, literal spelling and unknown values are preserved. Source, dependencies and compiled outputs have their own versions. Outputs cannot become additional author authority.

Root recognition proceeds as follows:

1. Parse the exact complete root source. A direct call to bare `metadata` at root markup level has exactly one positional dictionary argument, followed by the exact `<weftext>` label with only whitespace/comments between them. It is not inside context/function/loop/conditional/include/show. It need not be on the first line.
2. Prove that the bare name still denotes the fixed official standard-library `metadata` at that position. Check the preceding root AST scope: no binding/assignment/import/include/show/context/arbitrary call. Permit trivia, passive markup without embedded code, and explicitly static standard title/set expressions whose argument trees contain no user code or bindings. An uncertain prefix makes root qualification unavailable while preserving legal source. New notes place metadata before the first other code expression. Expanding the safe-prefix set requires AST counterexamples and official semantics experiments; executing the prefix and guessing is insufficient.
3. Exactly one control candidate in the complete root AST has the direct-root call position and exact label above. A second direct candidate is ambiguous; uncertain candidate binding/literal qualification makes control authentication indeterminate instead of choosing the first. Functions/unexecuted branches/includes/generated metadata or Labels do not become direct-root control authority. Strings/comments/raw are not declarations either. Later shadowing does not change binding at the recognized position. Native label conflicts may independently fail compilation; runtime query never authenticates note identity.
4. The root dictionary uses direct named/keyed entries with officially decoded, exactly unique keys. `id:` and `"id":` are duplicate keys. Spread/dynamic keys are unsupported for the root role. `id` is a direct string; absent types means the empty set; present `types` is a direct string array. `()` and `("task",)` mean empty and singleton arrays. Computed ID/types do not qualify.
5. ID/types are control keys. Schema interprets other business keys. Do not merge case or Unicode-normalized spellings; reserve `weftext-`. If broken syntax prevents excluding a second declaration, report indeterminate qualification rather than choosing the first occurrence.

Legal Typst outside this managed role remains readable and saveable as source. Existing notes enter draft/explicit repair states rather than receiving fresh identity. The complete language and the editable static-field subset are separate. Body imports, functions, computations and complex tables remain legal. Source saving, control qualification, field validation and compilation have distinct outcomes.

The coordinated editor design owns document title/subtitle/heading roles. Business names, formal publication titles and document titles have distinct meanings; filenames are display fallbacks. When the formal publication title also serves as the document title, generate it from the single publication field and edit that field through the form. Do not require two authored copies or fabricate a writable location for the generated title.

### 1.1 Direct declarations for saved Queries

Saved Queries use the same official AST, standard metadata binding proof and static native decoder. Their role is a direct root-markup `#metadata((kind: "weftext.query", key: "...", binding: ..., scope: ..., types: ..., where: ..., select: ..., order: ...)) <weftext-query-work-phones>`. FEATURES owns the closed query fields; SOURCE does not persist another CEL/Query AST. Kind/key must be direct strings. Core allocates the lowercase UUIDv4 key once in an explicit definition-creation transaction. Identity is owner+key, not another note ID or permission. An externally supplied bare key requires Core admission rather than birth authentication by string alone.

Call shape, exactly unique dictionary keys, no spreads/dynamic keys, complete source and binding proof follow §1. All query data must belong to the §2 static domain. In addition to the §1 safe prefix, preceding authenticated standard metadata declarations with entirely static argument trees are allowed, including the root and other Queries. Computed root values are never executed to prove a safe prefix. User calls/bindings in argument trees make definition qualification unavailable while preserving source and preventing application execution.

A definition has an exact native label with reserved `weftext-query-` prefix. Its complete label is unique among direct application-declaration Labels across the root source. The suffix may change without changing the key. All direct query-role keys are exactly unique within the owner/source; duplicates are ambiguous, not last-wins. Nested/included/generated metadata, dynamic labels and lookalike strings do not acquire definition identity. A recognized key cannot override indeterminate remaining source. Missing labels, duplicate keys, shadowing and computed declarations remain legal source but do not qualify as executable saved definitions. Copies allocate new keys using Core's frozen owner/key map and update saved definition references in the same transaction. FEATURES owns current/pinned reads, parameters, evaluation and navigation; historic definitions never revive writers.

### 1.2 Persistent associations for native citations

The author source may contain one owner-local direct declaration:

```typst
#metadata((kind: "weftext.citations", entries: (
  (key: "chen2026", work: "weftext-node://WorkspaceId/NodeId"),
))) <weftext-citations>
Native @chen2026 or #cite(<chen2026>) remains in the body.
#bibliography("weftext.citations.bib")
```

The dictionary is closed to kind/entries. Central CitationBinding/CitationEntry definitions make each entry exactly key/work. Key uses citation_key; work is a stable NodeRef whose typed citation target must have library/work, including paper. The same direct metadata/static-tree/standard-binding proof as §§1/1.1 applies. Exactly one fixed `<weftext-citations>` Label occurs among direct application declarations in the complete root, with exactly unique entry keys; an empty array is valid. No additional UUID/definition key is allocated: identity is this owner's unique role, not another bibliography. Unknown members, duplicate keys/labels, computed or shadowed declarations remain legal source but provide no usable application association. Missing declarations never trigger Work lookup by a matching native key.

Citation insertion authorizes a stable Work and writes the entry and native citation in one Draft/Plan. An existing key for the same Work can be reused; another Work cannot claim it. publication.citation_key suggests only a new entry, and later suggestion changes do not retarget existing declarations. External entry edits explicitly change the target and admission validates the complete declaration/target. Missing/revoked/dangling targets cannot become complete citation success. Core copies remap actually copied Work references while retaining native keys. Owner merging resolves collisions with an explicit preview of new keys and all proven native citation edits, never searches raw/string lookalikes. Cross-library missing targets/dependencies preserve source and report unavailability without inventing Works.

Each compilation generates one frozen read-only virtual `weftext.citations.bib` resource from the declaration and current authorized Work publication snapshots. Entries use their authored keys, preserving contributor order and NodeRef dependencies; cold rebuild uses these actual author inputs rather than an editable Bib mirror. This version does not promise per-entry pinned revisions. A real resource with the same name, duplicate keys or insufficient citation data causes an explicit failure/loss instead of overwriting a file. Independent native bibliography files remain ordinary resources without automatic merging.

Application citation extraction proves standard cite binding and a static Label key. Native `@key` is a ref; only exact authorized compilation semantics can establish that it resolved as a citation. A matching entry cannot turn a heading reference into a Work citation. Complex/computed citations remain legal and require an explicit read-only producer for accurate classification. Document-label/Bib-key collisions cause an official ambiguity error and cannot be guessed away. This role persists associations without granting Work/source access; FEATURES and Core authorize snapshot generation, export and inverse citation views.

## 2. Native values and exact semantics

The recursively editable static domain contains strings, booleans, none, official i64 integers, finite binary64 floats, official decimals, standard datetimes, integer-second durations, arrays and dictionaries. Dictionary keys are exactly unique and author order is preserved. Arrays preserve order and repeated values without per-value UUID wrappers. `(value)` is not a singleton array. Standard constructors require proven standard bindings and constant arguments; user functions are not executed.

| Schema semantics | Author representation and consumer rules |
| --- | --- |
| text / enum / phone / email / identifier / URL | Native strings with explicit semantic codecs. Do not trim, normalize or rewrite phone/identifier spelling; phone numbers remain text. Unknown enum members are invalid or explicitly open-enum values, never silently removed. |
| int / float | Official i64; the writer uses `int("-9223372036854775808")` for i64MIN and verifies official readback. No bool/int/float coercion. Float preserves exact bits including negative zero; nonfinite values are forbidden and floats are not money. |
| decimal / exact_decimal | Prefer `decimal("0.30")`, preserving value, scale and source spelling. Values exceeding the native range use an explicitly declared canonical decimal string codec with exact coefficient/exponent comparison, never float. Schema selects the representation, not heuristic value inspection. |
| quantity / money / range | Ordinary records hold exact amount/value, explicit unit/currency and optional precision/source. No implicit home currency. Comparison/conversion needs a named unit service. |
| date / time / local_datetime | Standard `datetime(...)` for a day, a time or civil local datetime. Never infer a device zone or turn local time into an instant. Official constructors validate real dates. |
| instant | Explicit RFC3339 string with offset or Z and exact fractional seconds. Reject unknown offset `-00:00`, leap seconds and missing offsets. Preserve the original offset representation; compare exact normalized UTC values. |
| partial_date / temporal_range | Native records explicitly name calendar/precision. Years, year-months, month-days and ranges do not fabricate missing parts. A yearless birth event uses `(month: 5, day: 12)`. Endpoint meaning is domain-specific: absent During endpoints are unknown, its explicitly nullable none endpoints are unbounded; absent Range endpoints are unbounded. A generic empty-value rule cannot erase this distinction. Schema defines interval boundaries and granularity. |
| zoned_civil / recurrence | Records hold local datetime, IANA zone and optional disambiguation. A temporal service supplies tzdb/version, recurrence and DST handling. Rule records are not a new executable author language. Calendar months/years are not integer-second durations. |
| node_ref / target_or_text | Native strings or records decoded only in qualified schema positions; ordinary URI-like strings are not scanned for references. See §4. |
| list / record / union | Native arrays/dictionaries. Union branches need disjoint native domains or an explicit discriminator; no first-match behavior. Preserve unknown record members as unbound, without declaring them validated or discarding adjacent known members. |

Absence, none, empty strings, empty arrays/dictionaries, zero and false differ. Requiredness checks presence; nullable only permits none after presence. Defaults write real source during explicit creation/template use, never on reading existing notes. Sources, validity periods and state histories are optional business records where useful. Every ordinary value does not need confidence or a generic fact ledger.

Static reading does not compile the entire body. Direct recursive arrays/records are decoded completely; complex expressions are computed. If an element cannot be projected, the whole Field is unavailable rather than a truncated successful list; adjacent Fields remain independently available. Unknown members survive without acquiring typed action authority. Computed expressions remain legal and are not materialized or overwritten automatically. Compiled semantics may be a read-only projection bound to the exact authorized snapshot and all actual dependencies. They are not writable author Fields. A named producer must explicitly qualify any computed Field for typed Query rather than treating final metadata query results as new authority.

## 3. Closed centralized schema

Schema is standard JSON non-executable configuration managed and versioned by Core, not an embedded .typ language. Notes do not repeat schema or internal FieldIds.

Schema has exactly `version, definitions, fields, types, aliases, relations, validators, providers, series_policies`, with version 1. Unknown configuration members/versions and duplicate JSON keys reject installation. Only author Record values have an explicit unknown-member policy. IDs/keys/aliases are exactly unique without case/NFC rewriting. Core owns SchemaRef/RevisionId, installation authorization and byte fingerprints; no additional ledger, signature tree or self-reported birth is introduced.

Shapes retain scalar/enum/list/record/union/use. The closed scalar codecs are `text,nonempty_text,phone,email,identifier,doi,url,language_tag,citation_key,node_ref,resource_ref,tag_ref,schema_ref,config_revision,bool,int,float,decimal,exact_decimal,duration,exact_seconds,date,time,local_datetime,instant`. Schema/config revision codecs occur in application definition bindings; Core resolves their exact identities. Similar ordinary strings do not become references. Record has exactly `{kind,members,unknown,constraints}`; unknown is preserve or reject. Preserve retains unbound author members; reject is used for QueryBinding and validator parameters. This does not open configuration structures themselves.

Members are exactly `{shape,required,nullable}`. Field is `{id,key,shape,nullable,default}`, with absent or native constant source defaults. Type is `{id,fields,requires,conflicts,constraints}`; field contributions are `{id,required}`. Shared Fields have one value, requiredness combines by OR and type order is not precedence. Person/Organization/Work business fields are optional; Task.status is required. Period.period and Range.range are required. Event requires Range rather than copying time data. Paper requires Work. Projects remain ordinary task.project targets, without a new mandatory Project schema.

Union discrimination is closed: null, member(keys), tag(key), or record_presence(key,present,absent). Null requires disjoint native domains; member requires exactly one branch member; tag identifies one fixed enum branch. Record-presence selects record branches using exact variant indices; other native branches are distinguished by native domain first. EventTime is date, instant, CalendarDate or MonthDay: a record with calendar selects CalendarDate, otherwise MonthDay. This prevents unknown preservation from making a full calendar date also match the month-day branch. Selected branches validate completely without first-match fallback.

Path is an ordered array of `{kind:"member",key}` or `{kind:"each"}`, applied to officially projected values, not executable source. Constraint is exactly `{validator,inputs,parameters}`. Input selectors are local(path), field(id,path), or context(name): current record, a Type-owned Field, or fixed Core owner. The only context names are owner and resource_metadata. The latter is Core's authorized metadata Cell snapshot for explicitly declared resource inputs, not arbitrary workspace access. Validator is `{id,provider,operation,inputs,parameters,result}` with fixed slot signatures, reject-unknown parameter Record and valid-invalid-unavailable result. Installation checks exact slots, selector types and parameters. Unknown operations do not execute. There are no author functions, branches, arbitrary access paths or expression scripts.

Local validators read only their record/Field. Type validators explicitly name cross-Field inputs. Reads/actions/narrow writes authorize that entire closure rather than silently inspecting another hidden Field. Missing required type/shape/constraint dependencies for the operation produce unavailable, not empty success. Saving bytes and publishing typed results remain separate.

```text
Scalar {kind:"scalar", semantic:closed-codec-name}
Enum {kind:"enum", values:[string...], open:bool}
List {kind:"list", items:Shape, min:nonnegative-int, max:int|null}
Record {kind:"record", members:{key:{shape:Shape,required:bool,nullable:bool}},
        unknown:"preserve"|"reject", constraints:[Constraint...]}
Union {kind:"union", variants:[Shape...], discriminator:
       null|{kind:"member",keys:[string...]}|{kind:"tag",key:string}|
       {kind:"record_presence",key:string,present:variant-index,absent:variant-index}}
Use {kind:"use", name:definition-name}
Field {id:string,key:string,shape:Shape,nullable:bool,default:
       {kind:"absent"}|{kind:"native",source:native-constant-source}}
Type {id:string,fields:[{id:FieldId,required:bool}],requires:[TypeId...],
      conflicts:[TypeId...],constraints:[Constraint...]}
Constraint {validator:ValidatorId, inputs:{slot:Selector}, parameters:closed-record}
Selector {kind:"local",path:Path}|{kind:"field",id:FieldId,path:Path}|
         {kind:"context",name:"owner"|"resource_metadata"}
Path [{kind:"member",key:string}|{kind:"each"}...]
```

Exact top-level array/object representations are fixed by the [complete normative schema](examples/schema.json). Every structural member is required, including empty constraints arrays. Definitions are finite and acyclic; aliases map exactly to TypeIds. Keys, IDs and aliases compare exactly. Native creation defaults undergo the restricted official §2 decoder and the same shape/validator checks; reads never supply defaults. This version has no UI-hint configuration whose wording could alter semantics.

Installation checks all closed members/codecs and acyclic uses first. Reject duplicate IDs/keys/aliases, registered control keys, missing Fields/Types, requires cycles, asymmetric conflicts, overlapping/malformed unions, invalid defaults/enums, selector paths/slot/parameter types and excessive budgets. Verify provider ABI/data under §3.1, then relationships/series and Type read closures, without installation precedence. Scalar codecs are fixed trusted host implementations, never created by configuration. citation_key is a native nonempty ASCII string matching the entire `[A-Za-z][A-Za-z0-9_-]*` grammar for deterministic Bib/Label generation. publication.citation_key remains an optional ordinary text suggestion; creating a binding validates the suggestion with this codec. Phone/email preserve nonempty spelling without proving reachability/existence. DOI/URL/language_tag use fixed syntax checks without network access. Unknown closed-enum values are invalid. Unknown open-enum strings remain valid and unregistered for literal filtering/grouping, but actions do not guess their meaning.

Multiple Types combine their requires closures without priority; shared Field requiredness is OR. One FieldId has one definition/key and different IDs cannot compete for a key. Conflicts never produce last-wins or implicit intersections. Preserve unknown Type tokens and independently readable known Fields; complete validation is unavailable. Duplicate alias/full-ID declarations of one Type are diagnosed. Central aliases provide short names; absent schema never triggers seed downloads.

### 3.1 Closed validators/providers and algorithms

Provider is exactly `{id,family,implementation,data,exports,limits}`. Implementation is only `{kind:"builtin",id,abi}`, exactly matching the trusted id/version pair (v1/abi1 or v2/abi2 in this configuration), matched to Core's approved Rust registry and fixed ABI, without author scripts/URLs/modules. Exports are `{name,inputs,result,effect:"pure",query_name:string|null}`. Input/result interface tags must match the trusted implementation exactly; they are not free author-selected type strings. Validator inputs/parameter Shapes also match the operation's trusted signature. An operation called int-range cannot claim text inputs. Query names are globally unique; calendar primitives have no public query_name and the temporal/rules router alone exposes periodBounds. Provider order is never resolution precedence.

Positive integer limits are max_steps/max_bytes/max_expansion. Execution is bounded, pure, and has no IO/network/clock; inputs contain authorized values and frozen configuration data. Configuration grants no extension rights. Missing implementations or approved data prevent activation, while source may still be preserved and affected typed consumers remain unavailable.

All fourteen used validators are configured:

| Validator | Fixed inputs/parameters and behavior |
| --- | --- |
| core/int-range | Int or absent value; i64 min/max and integer exclusions. Absence passes; present values validate exactly. |
| core/decimal-range | Decimal or absent; exact decimal-text min/max. Confidence is 0..1, without float. |
| core/custom-code | Code text and custom text/absence; parameter custom code. Custom requires a nonempty custom value; other service codes do not gain a second service identity from it. |
| core/owned-resources | Owner NodeRef, resource/scalar-list/absence and authorized resource_metadata Cells; Boolean owner_required. Avatars must belong to the source owner. Work may explicitly reference shared resources without claiming ownership. Missing current resource evidence is unavailable. The provider checks supplied Cells without Core/file IO. |
| temporal/month-day | Real month lengths, February 29 allowed without a fabricated year. |
| temporal/calendar-date | Exact installed calendar key/version; precision/member/range/leap-month validation. Missing lower precision parts are not filled. |
| temporal/during | During uses TemporalEndpoint; closed same-grain ≤, mixed-precision proofs and absent-unknown/none-unbounded rules follow §3.1.1 and fixed v2 algorithms. |
| temporal/range | At least one bound; same domain; strict start<end; half-open. |
| temporal/period | Frozen series policy, calendar/zone versions, kind/rule compatibility and provider-backed key/bound validation. |
| temporal/recurrence | Daily/weekly/monthly/yearly; interval≥1; declared weekStart codes; valid months, byMonthDay ±1..±31 excluding zero, weekday ordinals ±1..±5 excluding zero; positive count, at most one count/until; consistent date/instant dates/exceptions; actual calendar/zone versions; explicit earlier/later fold and skip gap. Invalid civil dates are skipped. |
| temporal/exception | Cancel forbids replacement data. Replace contains a real range/title/status/note change. Onset always denotes the original occurrence, not its rescheduled start. |
| temporal/event | Explicit range+recurrence Fields. Absent recurrence is valid. A present rule requires bounded range; their domain must agree. Anchor is **derived only from range.start through frozen calendar/zone**, not duplicated author time. Until/dates/exceptions/replacements share the domain. Date durations are civil days; instant durations are exact elapsed seconds. |
| units/quantity | Exact value/precision, registered unit, nonnegative optional precision. No default currency/unit or implicit conversion. |
| units/measurement | Height has length dimension, weight mass. Observation time is independent and multiple observations/sources remain intact. |

Decode shape before invoking validators. Signature checking does not recursively rerun the same Record constraints. Unbound/invalid/unavailable inputs cannot produce valid. Unknown author members remain unbound outside known read closures. Pure callable functions are only compareTemporal, duringDuration, containsDate, nextCivilDay, rangeOverlap, rangeDuration, periodBounds, expandRecurrence and registered calendar/zone primitives. Range/During durations retain years/months/days or exact seconds and compareTemporal follows §3.1.1; open/unknown duration is unavailable without now. FEATURES.resolvePeriod orchestrates periodBounds with authorized Query/creation and is not a pure provider call.

Data families are closed: none, unit-table, gregorian, calendar-table, zone-table. Unit entries are key/dimension with no automatic conversion. Gregorian data has key/version/min_year/max_year. Calendar tables have key/version/epoch_date/consecutive years; each year has ordered months with number/leap/days. Validate positive lengths, unique number+leap, continuous coverage and checked cumulative sums. Epoch plus table determines ordinal conversion; outside coverage is unavailable. Approved non-Gregorian packs can be imported, but a calendar string alone does not establish lunar-calendar support.

Zone tables have key/version/from/until/initial_offset_seconds/strictly increasing transitions(at,offset_seconds). At is an exact instant; offsets are bounded seconds and coverage/order checked. ToCivil uses the actual interval; ToInstant finds all candidates: zero means gap/skip, two use explicit earlier/later. Outside coverage is unavailable. An approved loader turns frozen IANA tzdb into this table with source/version retained; device-current tzdb is not frozen authority. Core dependencies authorize the complete pack. Synthetic test providers establish only the table mechanism.

Gregorian builtin defines 0001..9999, leap/ISO week-year/quarter rules. UTC has explicit coverage. The schema includes these algorithm descriptors, a synthetic finite non-Gregorian test pack and a unit table; activation still requires matching approved actual implementations. No existing Rust code is claimed. Series policy scope is library or node_subtree(root NodeRef), with unique/many multiplicity, as portable non-executable data. Calendar/zone keys plus versions are unique within families and cannot be rebound silently.

Frequency phases/default selectors are fixed temporal/recurrence and temporal/event algorithms, not author provider scripts. Interval is 1..65535; count is 1..2147483647; until cannot precede the derived anchor. Anchor is always the first base candidate even when explicit selectors miss it; subsequent candidates are at or after anchor. Daily uses civil-day distance, weekly the distance between anchor-containing week buckets, monthly month-ordinal distance and yearly year distance, selecting interval multiples. Absent weekStart defaults to MO and affects weekly buckets only.

Without byWeekday, weekly uses the anchor weekday. Monthly without byMonthDay/byWeekday uses the anchor day. Yearly with all three selectors absent uses the anchor month; without day/weekday it uses the anchor day. Yearly day/weekday selectors without month examine every month. Values within a dimension union; dimensions intersect. An explicitly empty selector yields no further candidates while retaining the first anchor. Negative month-day selectors count from month end; nonexistent dates skip without clamping or consuming count. Optional weekday.ordinal is an explicit new month-relative ±n weekday refinement, allowed only for monthly/yearly and evaluated separately within each candidate month, never an annual ordinal or a claimed historical requirement.

Instant candidates resolve frozen-zone fold/gap then deduplicate/sort by exact UTC before counting; civil enumeration order is not UTC order. Count/until termination needs a proved earliest-UTC bound for future civil candidates using validated offset bounds and complete zone coverage; the first over-until candidate is insufficient. Missing coverage/proof budget gives unavailable/partial. Failure to find an onset in the current window is not whole-series nonmembership. Exception membership uses this same base algorithm.

Occurrence keys are dates or exact UTC instants, so different offset spellings of one instant do not create separate keys. Generate base B from range.start and apply count/inclusive until before exclusions/exceptions, then union RDATE set R. R does not consume the base count and may extend beyond count/until. Each original B∪R key has at most one exception whose onset must be proved a member. Cancel and replace for one key make source invalid; cancel cannot conceal an invalid replacement. Nonmatching EXDATE values retain author intent. One decisionFunction chooses cancel > replace > EXDATE > template for every original key, including replacements moved into the window from outside. Filtering EXDATE first must not discard a replacement. Membership validation/expansion uses the same frozen calendar/zone and budgets; insufficient coverage/budget yields unavailable/partial, not invalid or complete zero. FEATURES then filters actual occurrence intervals using its window algorithm while retaining accurate origins.

A series policy is exactly `{id,key,calendar,zone,kinds,rule,scope,multiplicity}`. Calendar/zone are exact ProviderIds; kinds is a nonempty unique supported-kind array. Scope is exactly `{kind:"library"}` or `{kind:"node_subtree",root:NodeRef}`. Installation validates provider families/versions/rules and root identity. Core authorizes Query scopes and proves unique negative ranges; providers do not inspect directories.

Registered period rules are exactly Gregorian `iso8601` and finite calendar-table `table-ordinal-v1`. Gregorian keys are YYYY-MM-DD, ISO week-year YYYY-Www, YYYY-MM, YYYY-Qq and YYYY, checked against actual Gregorian bounds/week-53 rules. Table keys are Y<canonical-int> for year, Y<year>-M<positive ordinal> for month, with -D<positive day> for day, and Y<year>-Q<positive ordinal> for quarter (successive groups of three ordered months, possibly a shorter final group). Week is W<canonical-int>, with zero beginning on the Gregorian Monday containing epoch_date and seven-civil-day buckets thereafter. Month ordinals include separate leap months; matching month numbers cannot merge them. Frozen tables/epoch determine bounds; crossing pack coverage is unavailable. This finite-table algorithm is an explicit new design, not proof of complete named calendar-pack implementation. Bounds are Gregorian date half-open ranges. Consumers needing zoned instant bounds explicitly use the frozen zone instead of the device zone. Unsupported rules reject installation rather than running text as code.

#### 3.1.1 Preserve the knowledge precision of interval endpoints

`TemporalEndpoint` has disjoint native date, instant and CalendarDate branches and is used by During.start/end and Range.start/end_exclusive. CalendarDate retains calendar/version/precision/year and precision-dependent month/day/leap_month. Year never gains invented month/day; month never gains an invented day. Yearless MonthDay is not an ordered interval endpoint. Date is a complete Gregorian civil day; instant is an exact UTC point, without implicit conversion. Task.start/due also use TemporalEndpoint, preserving the selected date branch’s year/month/day precision; completed_at remains an exact instant. Source accessed keeps this candidate’s DateOrInstant choice. Measurement observed_at already preserves precision through EventTime; matching names do not expand unrelated domains.

Fixed calendar `dateBounds(CalendarDate)` returns a read-only computed cell `{calendar,version,precision,ordinal,min_day,max_day}`. Ordinal is that calendar/version's year, cumulative ordered month (including separate leap months) or day ordinal. Min/max are the closed Gregorian-day-ordinal envelope of this knowledge bucket. Gregorian uses actual leap/month lengths; finite tables use actual months/days and checked epoch accumulation. Native dates normalize only for computation to the fixed Gregorian day basis and can share an interval with Gregorian CalendarDate(day). Source spelling is unchanged. Bucket bounds are proof aids and **never written back or presented as actually known start/end dates**.

Shared `compareTemporal(a,b)` returns value(-1|0|1), invalid or unavailable. Authorized valid endpoints with the same calendar/version/precision compare their ordinals, so common year/month comparisons work normally. Full-day endpoints in different calendars can compare exact Gregorian day ordinals when both frozen providers are available. Coarser mixed calendars/versions are unavailable rather than ordered by year numbers. Missing approved providers/coverage/authorization are unavailable; known invalid dates/extra precision members or date/instant mixing are invalid. Instants compare exact UTC.

Mixed precision within one calendar/version uses computed envelopes [Alo,Ahi], [Blo,Bhi]: Ahi<Blo proves -1, Alo>Bhi proves 1, otherwise unavailable, never equality inferred from overlapping buckets. Internal ≤ proves true when Ahi≤Blo and false when Alo>Bhi; < proves true when Ahi<Blo and false when Alo≥Bhi; other cases are unavailable. Equal precision uses ordinal relations directly: this compares recorded granularity, not asserted exact boundary days. Ordinary structural equality retains calendar/version/precision and branch rather than deduplicating years/months into days. Explicit temporal comparisons provide chronological order/day equivalence without adding a default order for arbitrary records.

Call-level common-basis qualification precedes infinity substitution and three-valued conjunction. Core first authorizes the complete required Fields/point and exact frozen provider data. Non-value Cells or unavailable dependencies follow existing invalid/unavailable/EvaluationIssue handling without unauthorized reads. The fixed temporal builtin collects **every actual finite, non-none endpoint across all arguments** (including the point for containsDate), fully decodes it and validates its provider/coverage, not merely the endpoints later visited by one inequality. All-instant calls use exact UTC; any civil/instant mixing is invalid without a host-zone conversion. All civil endpoints sharing calendar/version qualify **without requiring equal precision or provable ordering of arbitrary endpoint pairs**. Internal profiles bind exact sourceRevision/generation, SourceSchemaBasis/current compatible schema, authorization and selected spans. Public projections expose approved Fields/affected input closures/epoch without hidden body, offsets, size or AST. The closure contains only registered constraints actually affected by the change: selected Fields, their cross-Field validators and explicit relationship-target/resource metadata inputs must all be authorized. A narrow change cannot revalidate unaffected hidden Fields or body. Missing authorized closure denies qualification. The service neither compiles/evaluates hidden body nor uses hidden-value predicates for public validation.

The minimal controlled implementation is a trusted Server fenced writer. Qualification is explicitly published beforehand. Narrow requests validate only authorized values/constraint inputs, consume an opaque FieldBasis and use Core prepare/commit to fence actual sourceRevision/trusted generation. Internal variable-length exact splices preserve every nonselected byte. Body code consuming the changed Field may produce different hidden compiled output; this is an existing dependency on the authorized Field, not an additional body-author-byte write. The narrow caller receives no right to that derived output. Structural readback checks declaration/patch invariants without compiling body and disclosing its diagnostics.

The opaque FieldBasis public CAS compares authorized Field before-images, authorized constraints and the published profile contract; an internal whole-source revision change alone never produces a visible stale result. After hidden-only source changes the Server internally reauthenticates/relocates and fences the actual current revision. It neither reuses old offsets nor revalidates unaffected hidden values for rebasing. Changes to the selected Field or authorized semantics produce the relevant public conflict. Failed requalification uses only authorized discloseable lifecycle states/uniform unavailability, not an oracle for whether hidden body changed.

Callers receive no whole-source diagnostics, offsets, detailed progress or size, using Core's uniform asynchronous Operation/Job and unavailable outcomes. Background audits and renewed publication are separate authorized actions. Control-key creation/deletion or missing unique static spans cannot use this writer. Open local files without trusted generation cannot infer unchanged hidden body from watcher silence/equal fileID/hash; qualification must renew or whole-source authorization is needed. Insufficient authorized constraint closure/fencing produces uniform unavailable without silently expanding rights.

The contract makes public semantic outcomes independent of unauthorized content, without claiming perfect constant-time behavior. Residual splice/IO timing requires measurement/deployment review. Fixed capacity/padding and whole-body allowlists are not author formats or default protocols. Actual producer/concurrency/revocation/fault behavior remains a product gate.
