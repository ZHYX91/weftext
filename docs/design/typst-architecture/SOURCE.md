# Typst author source and centralized schema: redesign candidate

Status: design candidate, neither implemented nor accepted. [REQUIREMENTS](../typst-native/REQUIREMENTS.md) defines outcomes and [REVIEW](REVIEW.md) records validation. This file owns author source, application roles and the single field type system. Representative schemas and examples are not a ceiling on business capabilities.

## 1. Author source and application roles

A note has one `.typ` author source. The coordinated Core design owns stable note identity, centralized schema authority, independent annotations, resources and the actual directory tree. This document owns source roles, value semantics and consumer boundaries; it does not reuse the old Pin, Proof, Entry, carrier or SourceRevisionPlan families.

Standard `#metadata((id: "...", types: (...), ...)) <weftext>` carries author properties. `id` is a lowercase UUIDv4 allocated by Core and admitted only after a successful creation transaction. It is not authorization. Rename/move preserve it; copying or importing as a new note allocates a new ID. External ID changes are identity conflicts requiring admission. Core supplies source paths from its directory authority: metadata does not duplicate path/parent/children. Missing declarations or partial synchronization never authorize identity regeneration.

The official Rust `typst-syntax` library is the sole parser. An AST checker verifies application roles without regex header parsing, a second lexer, or an embedded YAML/JSON dialect. Exact UTF-8 bytes, BOM, comments, line endings, literal spelling and unknown values are preserved. Source, dependencies and compiled outputs have their own versions. Outputs cannot become additional author authority.

Root recognition proceeds as follows:

1. Parse the exact complete root source. A direct call to bare `metadata` at root markup level has exactly one positional dictionary argument, followed by the exact `<weftext>` label with only whitespace/comments between them. It is not inside context/function/loop/conditional/include/show. It need not be on the first line.
2. Prove that the bare name still denotes the fixed official standard-library `metadata` at that position. Check the preceding root AST scope: no binding/assignment/import/include/show/context/arbitrary call. Permit trivia, passive markup without embedded code, and explicitly static standard title/set expressions whose argument trees contain no user code or bindings. An uncertain prefix makes root qualification unavailable while preserving legal source. New notes place metadata before the first other code expression. Expanding the safe-prefix set requires AST counterexamples and official semantics experiments; executing the prefix and guessing is insufficient.
3. Exactly one actual Label AST node in the entire root source is `<weftext>`. Another one inside an unexecuted branch or function is still ambiguous. Identical strings, comments and raw text are not labels. Later shadowing does not change the already recognized declaration. Included or dynamically generated elements do not become root declarations. Compiled query output never authenticates identity.
4. The root dictionary uses direct named/keyed entries with officially decoded, exactly unique keys. `id:` and `"id":` are duplicate keys. Spread/dynamic keys are unsupported for the root role. `id` is a direct string; absent types means the empty set; present `types` is a direct string array. `()` and `("task",)` mean empty and singleton arrays. Computed ID/types do not qualify.
5. ID/types are control keys. Schema interprets other business keys. Do not merge case or Unicode-normalized spellings; reserve `weftext-`. If broken syntax prevents excluding a second declaration, report indeterminate qualification rather than choosing the first occurrence.

Legal Typst outside this managed role remains readable and saveable as source. Existing notes enter draft/explicit repair states rather than receiving fresh identity. The complete language and the editable static-field subset are separate. Body imports, functions, computations and complex tables remain legal. Source saving, control qualification, field validation and compilation have distinct outcomes.

The coordinated editor design owns document title/subtitle/heading roles. Business names, formal publication titles and document titles have distinct meanings; filenames are display fallbacks. When the formal publication title also serves as the document title, generate it from the single publication field and edit that field through the form. Do not require two authored copies or fabricate a writable location for the generated title.

### 1.1 Direct declarations for saved Queries

Saved Queries use the same official AST, standard metadata binding proof and static native decoder. Their role is a direct root-markup `#metadata((kind: "weftext.query", key: "...", scope: ..., types: ..., where: ..., select: ..., order: ...)) <weftext-query-work-phones>`. FEATURES owns the closed query fields; SOURCE does not persist another CEL/Query AST. Kind/key must be direct strings. Core allocates the lowercase UUIDv4 key once in an explicit definition-creation transaction. Identity is owner+key, not another note ID or permission. An externally supplied bare key requires Core admission rather than birth authentication by string alone.

Call shape, exactly unique dictionary keys, no spreads/dynamic keys, complete source and binding proof follow §1. All query data must belong to the §2 static domain. In addition to the §1 safe prefix, preceding authenticated standard metadata declarations with entirely static argument trees are allowed, including the root and other Queries. Computed root values are never executed to prove a safe prefix. User calls/bindings in argument trees make definition qualification unavailable while preserving source and preventing application execution.

A definition has an exact native label with reserved `weftext-query-` prefix. Its complete label is unique among actual Label AST nodes across the root source. The suffix may change without changing the key. All direct query-role keys are exactly unique within the owner/source; duplicates are ambiguous, not last-wins. Nested/included/generated metadata, dynamic labels and lookalike strings do not acquire definition identity. A recognized key cannot override indeterminate remaining source. Missing labels, duplicate keys, shadowing and computed declarations remain legal source but do not qualify as executable saved definitions. Copies allocate new keys using Core's frozen owner/key map and update saved definition references in the same transaction. FEATURES owns current/pinned reads, parameters, evaluation and navigation; historic definitions never revive writers.

## 2. Native values and exact semantics

The recursively editable static domain contains strings, booleans, none, official i64 integers, finite binary64 floats, official decimals, standard datetimes, integer-second durations, arrays and dictionaries. Dictionary keys are exactly unique and author order is preserved. Arrays preserve order and repeated values without per-value UUID wrappers. `(value)` is not a singleton array. Standard constructors require proven standard bindings and constant arguments; user functions are not executed.

| Schema semantics | Author representation and consumer rules |
| --- | --- |
| text / enum / phone / email / identifier / URL | Native strings with explicit semantic codecs. Do not trim, normalize or rewrite phone/identifier spelling; phone numbers remain text. Unknown enum members are invalid or explicitly open-enum values, never silently removed. |
| int / float | Official i64; the writer uses `int("-9223372036854775808")` for i64MIN and verifies official readback. No bool/int/float coercion. Float preserves exact bits including negative zero; nonfinite values are forbidden and floats are not money. |
| decimal / exact_decimal | Prefer `decimal("0.30")`, preserving value, scale and source spelling. Values exceeding the native range use an explicitly declared canonical decimal string codec with exact coefficient/exponent comparison, never float. Schema selects the representation, not heuristic value inspection. |
| quantity / money / range | Ordinary records hold exact amount/value, explicit unit/currency and optional precision/source. No implicit home currency. Comparison/conversion needs a named unit service. |
| date / time / local_datetime | Standard `datetime(...)` for a day, a time or civil local datetime. Never infer a device zone or turn local time into an instant. Official constructors validate real dates. |
| instant | Explicit RFC3339 string with offset or Z and exact fractional seconds. Reject unknown offset `-00:00`, leap seconds and missing offsets. Preserve the original offset representation; compare exact normalized UTC values. |
| partial_date / temporal_range | Native records explicitly name calendar/precision. Years, year-months, month-days and ranges do not fabricate missing parts. A yearless birthday is `(month: 5, day: 12)`. Omitted endpoints are unrecorded; none is unknown only where explicitly nullable. Schema defines interval boundaries and granularity. |
| zoned_civil / recurrence | Records hold local datetime, IANA zone and optional disambiguation. A temporal service supplies tzdb/version, recurrence and DST handling. Rule records are not a new executable author language. Calendar months/years are not integer-second durations. |
| node_ref / target_or_text | Native strings or records decoded only in qualified schema positions; ordinary URI-like strings are not scanned for references. See §4. |
| list / record / union | Native arrays/dictionaries. Union branches need disjoint native domains or an explicit discriminator; no first-match behavior. Preserve unknown record members as unbound, without declaring them validated or discarding adjacent known members. |

Absence, none, empty strings, empty arrays/dictionaries, zero and false differ. Requiredness checks presence; nullable only permits none after presence. Defaults write real source during explicit creation/template use, never on reading existing notes. Sources, validity periods and state histories are optional business records where useful. Every ordinary value does not need confidence or a generic fact ledger.

Static reading does not compile the entire body. Direct recursive arrays/records are decoded completely; complex expressions are computed. If an element cannot be projected, the whole Field is unavailable rather than a truncated successful list; adjacent Fields remain independently available. Unknown members survive without acquiring typed action authority. Computed expressions remain legal and are not materialized or overwritten automatically. Compiled semantics may be a read-only projection bound to the exact authorized snapshot and all actual dependencies. They are not writable author Fields. A named producer must explicitly qualify any computed Field for typed Query rather than treating final metadata query results as new authority.

## 3. A minimal implementable centralized schema

Schema is portable, non-executable configuration managed by Core. Standard JSON configuration is an implementation choice, not another `.typ` author language. Core configuration versions/transactions manage schema revisions. Reads freeze the definition fingerprint, actual installed source and authorization without rebuilding predecessor-proof trees. Notes neither spell internal FieldIds nor copy schema definitions.

The closed Schema object has `version`, `definitions`, `fields`, `types`, `aliases`. This minimal schema has no label/UI-hint members; UI may display keys. Additional display configuration needs its own closed definition and cannot affect semantic matching. Unknown schema structure/versions reject installation; unknown **author data** is preserved. `definitions` contains finite acyclic named shapes. Named uses reuse configuration rather than execute source.

```text
Scalar {kind:"scalar", semantic:closed-codec-name}
Enum {kind:"enum", values:[string...], open:false|true}
List {kind:"list", items:Shape, min:nonnegative integer, max:integer|null}
Record {kind:"record", members:{key:{shape:Shape,required:bool,nullable:bool}},
        unknown:"preserve", constraints?:[Constraint...]}
Union {kind:"union", variants:[Shape...],
       discriminator:null|{kind:"member",keys:[string...]}|{kind:"tag",key:string}}
Use {kind:"use", name:existing definition name}
```

A Field has permanent semantic `id`, exact author `key`, shape, nullable and explicit creation default: exactly `{kind:"absent"}` or `{kind:"native",source:native-constant-expression-string}`, validated by the restricted official decoder and the same schema at installation. A Type has `id`, `fields:[{id,required}]`, `requires`, `conflicts`. Aliases map exactly to TypeIds. Member discrimination requires exactly one listed branch member; a record containing both ref and text cannot exploit unknown preservation to pass both branches. Tag discrimination requires a fixed enum tag identifying exactly one branch. Without discrimination the native domains must be disjoint. Named relationship/import operations handle target types, uniqueness and cycles rather than hidden arbitrary schema expressions.

The closed builtin codec list is `text, nonempty_text, phone, email, identifier, doi, url, language_tag, node_ref, resource_ref, tag_ref, bool, int, float, decimal, exact_decimal, duration, exact_seconds, date, time, local_datetime, instant`. Text codecs apply the declared business format. Phone/email preserve nonempty author text and spelling; format suggestions do not prove dialability or existence. DOI/URL/language-tag syntax uses fixed public standards without network requests. Core resolves node/resource references. Other native/exact-string rules are in §2. Unknown codecs reject installation, rather than becoming text. Closed-enum unknown values are invalid; open-enum unknown strings are valid extensions marked unregistered, available for literal filtering/grouping, without assigning them specialized action meaning. Nullable controls none.

Shape members are exactly those listed. Only Record may omit constraints, which means an empty array. Constraint is closed `{name,reads}`. The minimal version has exactly `valid_gregorian_partial_date` reading precision/year/month (Gregorian year 1..9999; year precision forbids month, month precision requires 1..12), `valid_month_day` reading month/day (including February 29), `same_temporal_domain` reading start/end, `start_not_after_end` reading start/end, and `bounded_half_open_range` reading start/end_exclusive. The validity record during(start,end) uses the former period constraints with closed boundaries: missing endpoints are allowed, present endpoints validate independently, two endpoints share date or instant domain and start≤end. Calendar range(start,end_exclusive) uses the last constraint: date or instant domain, at least one bounded endpoint, strict start<end when both exist, half-open semantics. Separate fixture records do not apply constraints to nonexistent members. Installation verifies required member types. Unknown names/extra members reject installation. List min/max give length limits; codecs give scalar domains. Other range/measurement/exclusivity/calendar validators require complete named registrations before installation, rather than prose opening closed objects.

Installation rejects duplicate IDs/keys/aliases, control-key registrations, missing uses/Fields/Types, cyclic shapes/type requirements, overlapping unions, asymmetric conflicts, invalid enums/defaults, constraints reading nonexistent members, or exceeded budgets. Installation order is not precedence. The source token `task` never downloads or installs a seed automatically.

Type composition has no precedence: expand the requires closure, union Fields and OR requiredness. One FieldId has one definition and one source key; different IDs cannot claim the same key. Explicitly reject incompatible combinations, without overriding, intersecting definitions or following source order. Preserve unknown Type tokens and read disjoint known Fields; complete type validation remains unavailable. Unknown is not an empty type set. Declaring an alias and its full TypeId twice is a duplicate. Short names such as task/person/organization/paper/project come from centralized aliases.

Saved Queries bind semantic Field/Type identities. Renaming labels/aliases does not rebind them. Authorized configuration transactions preserve prior definition versions. Compatible optional fields/members may retain identity. Requiredness/type/meaning/key changes affecting existing source need an exact impact preview and explicit migration, or a new semantic ID. Definition removal with live consumers, alias rebinding and reuse of retired IDs cannot be silent. Types do not need eternally frozen field lists to grow. Undeployed historical candidates do not justify invented ledger/decoder compatibility.

## 4. Relationships, literal fallback and sources

`target_or_text` is an explicitly discriminated native-record union: `(ref: "weftext-node://WorkspaceId/NodeId")` or `(text: "云山公司")`, exactly one branch. Ref branches do not store a synchronized title copy. If historical/publication wording is useful, explicitly named `credited_as` or `name_at_time` holds author wording with a different meaning and is not overwritten by a target rename. Displaying refs reads currently authorized targets. Unreadable/missing targets give generic status without revealing cached titles. Literal text is preserved and never upgraded by name matching. Only explicit target selection converts it to ref.

Reference URIs give stable note relationships, not arbitrary disk rights or proof of target existence. The relationship schema explicitly decides target-type restrictions. Trash/deletion does not erase source relationships automatically. Cross-workspace copy remaps actually copied targets; external references remain explicit or visibly unresolved.

Relationship definitions minimally contain stable relation ID, source Type/Field, nested target path, target-type restriction, directed/symmetric direction, optional derived inverse display name and integrity constraints. Person engagement records are authoritative; an organization's roster is a derived authorized Query, not a second members field. Organization parent is business structure distinct from directory parent. Task dependencies and publication contributors also have one author direction. Each symmetric assertion is stored once at one explicit author owner, without an automatic write at the other endpoint. Different authors may independently assert relationships and retain their respective sources; these are distinct assertions. Graph display may deduplicate endpoints+relation kind while retaining every assertion source. Editing from either endpoint first selects and reauthorizes an explicit sourceOwner/Field/current itemPath; merged edges or representative rows are not writable. Inverse display names do not imply inverse writes.

Relationship indexes are rebuildable projections. Inverse views disclose only currently readable source records/targets, without hidden-source names/counts. Incomplete scanning is partial. Operation impact checks cover the actually authorized required scope, never claiming no references from incomplete coverage. The inverse engagement view retains the same row's role and period.

Optional ordered `sources` records carry reference (stable note or explicit URL), locator (page/section/source position), accessed date/instant, and author note. They can belong to an engagement/event/import record without becoming mandatory for phones. Confidence, dispute state and measurement precision belong to expressly defined business fields when useful, not a mandatory generic Entry.

There are no automatic cross-version per-value UUIDs. Array rows and observed references locate the exact current source version+Field+AST path. Deletion/reorder/external edits invalidate selection rather than matching equal values. Future independent sharing of an engagement, durable relationship annotations or external keys should first consider an independent note or explicit business key with a defined lifecycle. This draft does not hide per-value identity.

Stable tag identity comes from CORE's centralized TagId registration; author fields store references. Add the closed scalar codec `tag_ref`: its native string is `weftext-tag://<WorkspaceId>/<TagId>`, with both IDs parsed under Core UUID rules. Valid syntax proves neither existence nor authorization. An optional common tags field is an ordered array with a discriminated `(ref: "...")` or `(text: "研究")` item. The former targets a registered tag; the latter is literal text and never upgrades through name matching. The ref branch uses tag_ref and the text branch nonempty_text, with exactly one present. Selecting an existing tag or explicitly creating one can register the TagId and assign its reference in one Plan. Renaming a tag changes no note source. Query, navigation and shortcuts compare full TagRefs; literal tags preserve their text. DirectoryRef remains a Core target identity, without introducing a second per-note directory-property authority.

## 5. Minimal schema and representative source

`examples/schema.example.json` supplies a complete representative minimal schema without optional UI labels. `examples/*.typ` contains person, organization, paper, task and numeric-boundary samples. They demonstrate shapes rather than freezing all supported fields.

| Alias | Fields and requiredness | Usage chain |
| --- | --- | --- |
| person | Optional names, phones/emails, birthday, engagements, histories/events, relationships and sources. Engagement records retain employer/position/department/period/source. | Quick capture may enter one name; add repeated phones or historical roles; correlate employer+time within one engagement; derive organization rosters. |
| organization | Optional names, contacts, parent/other business relations, establishment/dissolution dates, external IDs, events/sources. | Separate business hierarchy from directories and avoid mirrored membership. |
| paper | Publication and its fields may be incomplete. Formal title, entry kind and ordered contributors are operation prerequisites for complete citation output, not requirements for every paper note. Other DOI/URL/container/volume/issue/pages/date/abstract/keywords/language/identifiers/sources are optional. | A paper note is the bibliographic authority; reorder authors in forms and preserve the order through Query and citation output. |
| task | Required status; optional start/due/priority/project/assignees/dependencies/completion instant. | The body is task detail; lists/boards/calendars consume the same fields; status actions target the same note rather than mirrored checklist objects. |
| project | Optional names/status/members/time ranges if selected, without imposing a complete project-management form. | Compose ordinary notes without duplicate Field authority; derive assigned tasks from task.project. |

Names have one business authority in an ordered names array, without mirrored name/preferred_name fields. Roles/language/script/validity/explicit preferred support different contexts. Quick capture adds one row. Display chooses explicit preferred wording or a stated fallback policy without writing it into source. Domain names are not copied automatically to core aliases. Document titles remain distinct.

A publication contributor is `(agent: (text: "张三"), family: "张", given: "三", roles: ("author",))`, or a ref agent with optional credited_as/name components. Corporate names remain literals instead of forced family/given splits. Array order is credit order. Roles and affiliations stay within the same contributor record rather than flattened arrays whose elements could cross-pair. Unparsed imported names remain literals. Entry kinds article/book/chapter/thesis/report/web and further explicitly registered kinds can extend after the type audit.

Citation keys are optional explicit output identifiers; stable references use note identity. DOI is stored only as a publication.identifiers scheme/value entry, without a separate doi mirror. Work and paper share one publication record; paper requires work. Kind, publication_history, resources, contributors, venue, version_of and formal citation data all belong to this record rather than a mirrored Library. DOI is an external identifier, not note identity and not permission to merge drafts/versions automatically. Authorized import previews let the user create/match/update. Preserve unknown data and original files; report unmappable citation fields. Conflicting known/imported values require a choice rather than overwrite.

The BibLaTeX/Hayagriva resource required by native Typst bibliography is a read-only compilation resource generated from an authorized publication-data snapshot, not a second manually maintained library. Body citation/bibliography retain official syntax. Core compilation resource mapping assigns deterministic keys/files for stable note references and checks collisions. An ordinary independently authored bibliography remains a resource, without automatic merging into the note library. DOCX/XLSX/BibLaTeX/CSL-style exports consume the same semantics and explicitly report unsupported sources/precision/roles/multiple values. Unknown values do not become empty successful output. The adapter still requires a bibliography prototype and real Office validation.

## 6. Forms, Query, export and safe editing

Centralized schema drives forms: common groups first, optional groups expandable, arrays add/delete/reorder. Unused history/source fields are not required. Author values, absence, invalidity, unknown data and read-only computations display distinctly. Source/form/rich editing share one Draft/Undo and an exact preview. Simple UI does not discard nested data.

Query preserves scalar/record/ordered-list types and correlated predicates within one element: `exists engagement: employer.ref=O && during contains D` must hold for the same row. It cannot pair one employer with another row's time. Explicit flatten yields read-only rows with owner/current snapshot/list occurrence and visible order, not permanent row identities. Define any/all/count, empty lists, absence, unknown and invalid values. Multi-value filters do not silently inspect only the first item. Sorting a list chooses an explicit rule such as min/max/lexicographic; unavailable is not ordinary empty. Aggregates/computations/inverses are read-only; actions reacquire write authority at the original note.

Initial field permissions cover complete top-level Fields; nested rows are not separate implicit ACL domains. A field-only read returns only that Field's semantics and permitted raw representation, without whole-source byte offsets, neighbors, AST paths or body. Nested permissions would require explicit treatment of constraints/unknown members, not just hidden controls.

Structured writes consume Core's single-use write basis, freezing actual source snapshot/observer incarnation/file generation, schema and current permissions. The default granularity is a complete Field. Member patches require a unique current static AST span and complete container before-image. The writer officially reparses/constructs/readbacks the proposed value, checks root/schema constraints and exact nonselected-byte preservation. Insert/delete/reorder preview commas and comment ownership rather than formatting the entire file. Old paths do not survive revisions; equal hashes cannot revive a write basis.

Narrow writes need proof that every affected constraint/dependency is within authorized scope and that hidden body data cannot determine visible errors/success/output. Core may process source internally in isolation, but must use an administrator-reviewable published static isolation contract based on code/structure dependencies rather than secret values. Form results depend only on authorized values; errors/timing must not disclose secret branches. Grep, one compilation, or covert body inspection followed by visible branch decisions cannot authorize a write. Without sufficient proof, field-only writes return uniform unavailable; users separately authorized for the complete source may use source transactions. This is a prototype gate, not a claimed implemented capability.

Whole-source saves can preserve legal computed Fields, unknown schema/members and bodies that fail compilation, with accurate projection states. Typed operations cannot turn known invalidity/missing required values into success. Explicit raw/repair saving preserves drafts without publishing complete typed facts. Failed compilation never labels an old preview as current and does not block independent static-field Query.

Query/export inputs are read-only semantic projections with currentness/completeness, not write bases. Reopening saved Queries, caches or layouts reauthorizes/reevaluates rather than reviving old rights. XLSX can use a main sheet plus ordered child sheets with owner and sequence columns for contributors/engagements/contacts. Precise numbers and identifiers need explicit target encodings that respect Excel's precision limits.

| Root role | BOM/comments/multiline direct metadata, safe static prefix, later shadowing follow the rules. | Actual second label/unknown prefix/duplicate keys/computed controls do not qualify; preserve source. |
| Native multivalues | Duplicate phones retain labels/notes/order from source through form/Query/XLSX. | Reordering invalidates old occurrence selection without equal-value retargeting. |
| Engagements | Ref/role/period/source remain correlated; derive inverse rosters. | Text does not create refs; partial never claims complete zero; revocation hides source counts. |
| Publications | One authority and ordered authors through forms/Query/citation output. | Preserve unknown names, reject silent import overwrite, avoid mirrored library resources. |
| Type composition | Alias/full-name equivalence, one shared Field, requiredness OR. | No last-wins for conflicting semantics/rebound aliases. |
| Exact values | Integer/decimal/partial date/offset instant remain consistent through editing/Query/export. | No bool→int/money-as-float/device-zone inference/none-as-absence. |
| Safe writing | Current single-use basis, exact range, readback, transaction, shared Draft/Undo. | ABA/late results/reorder/revocation invalidate writes; no hidden-body side channel. |
| Complete source | Imports/functions/computations/complex tables are preserved/readable. | Missing controls do not narrow the language; resource failure is not language illegality. |
