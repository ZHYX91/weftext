# Typst 候选的整合与审查规则

状态：本轮协调设计与独立 Sol 复核已完成，产品未实现、完整全局终审未完成。固定输入为 `af6737a057c7bb69763dfaad0a57da4652e085f3`。本文规定新候选的规范分派与跨模块验收，不更改固定来源、旧报告或实际历史记录。

## 1. 一份候选与明确分工

新笔记的语言、主源和直接消费者由本目录协调定义。本文与四份 owner 是一个候选，不是可自由混用的四套提案：

| Owner | 唯一负责的关切 | 主要消费者 |
| --- | --- | --- |
| [SOURCE](SOURCE.zh-CN.md) | 根声明、原生值、schema、普通业务数据与来源资格 | 属性面板、Query、创建和复制 |
| [CORE](CORE.zh-CN.md) | 格式配置、编译环境、输入证明、持久资格与事务分派 | 所有界面、编译器、同步接收与恢复 |
| [EDITOR](EDITOR.zh-CN.md) | 阅读投影、编辑映射、Draft、批注及可访问性 | Desktop、WebUI、Mobile 与导出 |
| [FEATURES](FEATURES.zh-CN.md) | 链接、Query/View、任务、模板、转换、内网输出及扩展 | Core 领域动作与统一交互入口 |

SOURCE 定义“源里写了什么”，CORE 验证“当前谁可读取或提交”，EDITOR 定义“哪个可见位置可安全回写”，FEATURES 定义“怎样组织与消费这些数据”。任一层都不能代替另一层的证明。

具名替代表由各 owner 给出，机器导航见 [replacements.json](replacements.json)。新规则只覆盖表内明确关切。保留的通用算法以固定 A2 owner 的具名条款为规范引用，不能从旧文件任意挑选相冲突的格式规则。原输入中的路线图、评审状态与历史版本仍是来源记录，不是新的执行指令。

## 2. 复用与删除的边界

保留 [D1](../a2-final-design/D1.zh-CN.md) §§2–12 的五个正式产品界面、统一 Core、本地与 Server 模式、单持久提交者、撤权、不同保证等级、渐进索引和发布证据义务。Typst 编译器是受控能力，不新增第六个作者权威。旧实现的 `X/X.adoc`、AsciiDoc 标记与前代作者协议只描述旧实现或候选，不覆盖新目标。

新的作者语言规则替代旧 AsciiDoc 专有语法、属性块、原生 oracle 与写入适配。人员/组织的普通联系模型按 SOURCE 具名精简；默认不再承担逐值事实身份、复杂限定信息与自动逆向关系承诺。普通关系仍可用获权笔记链接，通用版本历史、数据完整性和权限不随业务模型精简删除。

原生能力与 Weftext 应用能力分开验收。`metadata` 的标准语法不证明身份有效，`link` 不证明目标可读，Typst `query` 不执行全库 Query，编译成功不证明提交成功，富编辑控件不可用也不使合法源成为非法语言。对来源、权限或能力不能证明的特定操作明确不可用，同时保留获准的源码修复路径。

JSON 仍可用于独立批注、配置和内部传输。它们不成为新笔记中的第二作者格式。历史导入必须预览保留与损失、保存原件；不能把未部署候选版本编造成已经存在的运行时迁移需求，也不能把真实旧记录重解释为新协议。

## 4. 审查与证据

先形成协调候选，完成必要文档与示例检查，再固定一次提交交给非作者。作者之间的互相质疑用于消除接口冲突，不算独立接受。非作者须检查当前源规则、直接消费者、简化后的需求，以及旧问题反例在新格式下的实际处置；发现新问题后回到作者修订，再核差量及受影响链路。

固定快照与 `inputs.json` 不变；旧 21 项 CLOSED 继续只属于原固定候选。新候选必须逐项分析其义务是否保留或具名替代，不能把旧通过复制为新通过，也不因相同编号重复制造全新的历史问题。候选提交、检查结果、复核范围与残余统一记录于 [REVIEW](REVIEW.zh-CN.md)。完整 Pro 终审与产品实施各有独立边界。
