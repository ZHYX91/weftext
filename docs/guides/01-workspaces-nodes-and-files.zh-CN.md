# 工作区、节点与附件

## 先理解两个概念

**工作区**是用户选择并由 Weftext 管理的文件夹。**节点**是工作区中的一个目录，目录内有一份与目录同名的 AsciiDoc 文档。例如，`Project/Project.adoc` 是 Project 节点的正文。

每个节点都有保存在 `weftext.id` 中的持久 UUID。重命名或移动节点会改变路径，但不会改变身份。链接、任务关系和其他持久引用因此不需要把路径当作身份。

## 当前基础

工作区根目录的 `.weftext-format` 明确选择 Weftext AsciiDoc 格式。标记缺失、未知或损坏时，Weftext 会安全拒绝写入，而不是猜测格式。创建、采用或导入工作区必须由用户显式发起；本文不把尚未完成的引导界面视为当前能力。

节点目录中的其他普通文件是该节点的附件，包括图片、PDF、办公文件、`.txt` 和 `.md`。Markdown 附件不会被当成节点正文解析；用户可以打开、下载，或明确导入为一个新的 AsciiDoc 节点。

搜索索引、反向链接、关系图、集合和统计都是从工作区内容派生的结果。删除这些缓存不会删除笔记，Weftext 可以重新构建它们。

## 内容边界

Weftext 把内容分成三类：

- **受管节点**参与身份、链接、搜索、Query 和事务。
- **可见的非受管内容**可以在文件视图中看到，但不会获得节点身份，也不会被改写为节点。
- **忽略内容**不进入产品导航和派生视图，但完整备份仍须根据备份契约处理其物理字节。

非受管目录是完整边界。Weftext 不会钻入其中寻找看起来像节点的目录，也不会因为发现 `.adoc` 文件就自动采用它。

## 在工作区外打开文件

**已确定设计：**桌面应用可以显式打开单个外部 `.adoc` 或 `.asciidoc` 文件，作为独立 AsciiDoc 编辑器使用。它不会扫描父目录、创建节点 UUID、写入工作区元数据或把相邻文件自动变成附件。

独立模式只提供安全的单文件编辑、渲染和文件内功能。节点链接、工作区 Query、模板库、任务节点、工作区历史与正式备份等功能会显示为不可用，并解释原因。

## 发布前限制

Weftext 仍处于发布前阶段。Windows 桌面 Alpha、CLI、共享界面和仅限本机回环地址的 Server 基础已经存在，但完整编辑器和可部署的多用户服务器尚未完成。同步文件夹也不等于实时协作服务器。

实现契约见[产品边界](../specifications/01-product-boundary.zh-CN.md)、[节点存储](../specifications/02-node-storage.zh-CN.md)和[应用界面](../specifications/06-application-ui.zh-CN.md)。
