# 多维表格与看板

## 原生表格和多维表格

原生表格是普通 AsciiDoc 文档内容，适合在正文中表达一个相对稳定的小型表格。它跟随文档修订，由文档编辑和格式命令维护。

多维表格是一个特殊的受管节点，适合大量具有固定字段的同类记录。一个多维表格对应一个节点，而不是每行一个节点。记录不是节点，也不能提升为节点。

## 不使用数据库怎样保存记录

**已确定设计：**表格节点的规范文档旁有一份 `weftext.table.json` 伴随文件，用于保存字段和共享视图。每条记录保存在 `weftext.records` 中一个有边界的 JSON 文件里，并按记录 UUID 分片。

这种布局便于同步、备份、冲突诊断和按记录修改，同时保持普通文件是内容权威。索引和计算结果可以重建，不需要把数据库作为第二份事实来源。

链接、富文本和图片可以用类型化 JSON 值保存。节点关系保存稳定节点身份；图片和文件仍是表格节点拥有的普通附件，记录只引用它们。JSON 能表达这些值，但界面不会要求用户直接编辑 JSON。

## 视图和操作

同一组记录可以拥有网格、看板、日历、时间线、图库和表单视图。筛选、排序、分组、显示字段和汇总可以保存为共享视图；列宽、滚动位置、当前选择和临时筛选通常只保存在当前设备。

原生表格可以通过预览操作升级为新的多维表格节点。升级会验证表头和单元格，创建表格节点与记录，并把原表格替换为稳定的 `node:` 引用。整个过程是一笔可恢复事务，不会在失败时留下半张表。

## 看板

看板是数据的一种布局，不是新的卡片数据库。任务看板只是 Query 看板的一个预设；节点、任务和多维表格看板使用各自数据源的真实身份和操作。

横向移动卡片只修改明确的分组字段。任务节点修改状态，简单待办项只能执行其结构支持的状态变更，多维表格记录修改对应的单选字段。每个拖动操作都有菜单、键盘、触控和屏幕阅读器等价入口。

第一版不提供同一泳道内的手动纵向排序。卡片顺序来自 Query 的排序子句或表格视图排序，避免维护一套隐藏排序权威。

## 当前状态

**当前基础：**现有 Core 已提供可供此功能复用的通用文件分类、工作区事务和派生索引机制。目前没有可作为已交付能力使用的多维表格记录存储、编辑器或看板实现。

**发布前限制：**多维表格编辑器、原生表格升级、全部视图和通用看板仍未完成产品级实现与大数据量验收。

详细契约见[多维表格](../specifications/20-multidimensional-tables-and-editor-surfaces.zh-CN.md)和[看板视图](../specifications/21-board-views.zh-CN.md)。
