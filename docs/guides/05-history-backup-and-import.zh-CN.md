# 历史、备份与导入

## 最近历史与正式备份不是一回事

**已确定设计：**最近历史默认保存在当前设备的 Weftext 应用数据目录中，用于查看和比较近期文档版本。它不在笔记工作区内，也不会自动跟随工作区同步到其他设备。界面会明确标记“仅此设备”。

正式备份保存可验证的完整工作区快照。它覆盖受管节点、附件、非受管和忽略内容、回收站项目、模板和多维表格的必需文件。草稿、回收站、事务日志、同步服务的版本记录或同一磁盘上的普通副本，都不能自动被称为正式备份。

## 默认设置与备份位置

新工作区默认没有正式备份目标。界面应显示“备份：未配置”和“最近历史：仅此设备”，而不是给出虚假的安全状态。

用户可以配置本地目录、外接设备、网络位置、受支持的远程后端，或由获准服务器管理的目标。目标和执行备份的设备是两个独立选择：任何获准设备都可以按照同一仓库契约执行备份，但同时只允许一个写入租约。

只在同一磁盘上的备份可以帮助恢复误删，却不能防范设备损坏。同步目录中的副本也不应成为唯一正式备份。

## 无需 Git 的比较与恢复

Weftext 的比较功能不依赖 Git。用户可以比较当前文档与上一版本、历史版本、另一份文档、备份快照或外部冲突草稿。

比较可以使用行内或并排视图，并显示结构上下文。选择“使用左侧”“使用右侧”或“保留两者”只会先创建一个可审阅的结果草稿；最终应用仍是一笔受当前修订约束的 Core 事务。

恢复旧文档版本默认只恢复该文档源文本。需要恢复附件、子节点、模板、多维表格或完整工作区时，必须使用正式备份的完整恢复流程，并先进行无写入预演。

## 导入外部格式

Markdown 可以作为显式导入输入。基础语法由导入器处理；部分扩展语法可以通过有边界、明确版本化的兼容配置识别。Weftext 不会因此把 Markdown 变成第二种受管节点语言。

真实格式导入统一经过探测、受限工作进程、中间表示、预览、事务和回执。PDF 是计划中的首个完整转换流程，并可以按用户授权使用本地 OCR；导入失败不会直接改写工作区。

## 当前状态

**当前基础：**Weftext 已有精确修订、事务恢复、草稿恢复、回收站和备份安全边界的实现基础。

**发布前限制：**统一版本历史界面、跨文档比较、正式备份仓库、完整恢复演练和生产级 PDF 导入仍在实现与验收中。没有配置备份时，用户不应把最近历史或同步服务当作完整恢复保证。
