# Weftext user guide

These pages explain Weftext's core concepts and accepted workflows in plain language. Weftext is still pre-release, so every page distinguishes current foundations, accepted designs, and pre-release limitations. The guide does not present a design target as a delivered feature.

The specifications and architecture documents remain authoritative implementation contracts. If this guide conflicts with a newer specification, follow the [documentation index](../README.md).

## Start here

1. [Workspaces, nodes, and files](01-workspaces-nodes-and-files.md): learn how content is stored and how ordinary files become attachments.
2. [Writing and document structure](02-writing-and-structure.md): learn about the editor, headings, tables, images, and standalone AsciiDoc mode.
3. [Tasks, Query, and templates](03-tasks-query-and-templates.md): learn about lightweight checklists, task nodes, collection views, and the Template Library.
4. [Multidimensional tables and boards](04-tables-and-boards.md): learn about records, views, native-table upgrade, and board actions.
5. [History, backup, and import](05-history-backup-and-import.md): learn about device history, formal backup, comparison and restore, and importing external formats.

## Status labels

- **Current foundation**: a capability that exists in the repository or product prototype and is supported by current implementation evidence.
- **Accepted design**: a public contract has been decided, but complete product implementation and release acceptance are still in progress.
- **Pre-release limitation**: a capability that must not yet be relied on or exposed as a production deployment.
