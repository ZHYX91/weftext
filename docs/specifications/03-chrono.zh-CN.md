# Chrono 节点

状态：已接受的当前 Chrono 边界。

用户选择一个 Chrono 根节点。内部周期名称和路径是固定的；任意路径模板不是格式的一部分。

规范名称是：

- 年份：`YYYY`
- 季度：`YYYY-Qn`
- 月份：`YYYY-MM`
- ISO 周：`YYYY-Www`
- 日期：`YYYY-MM-DD`

所有生成的周期都是严格节点。期间节点位于其年份节点下，以便 ISO 周不会被迫进入可能不正确的月份或季度层次结构：

所选 Chrono 根和每个复用/生成的周期都必须是受管内容。名称看似规范周期名称的非受管或被忽略目录属于边界冲突，不是可复用的周期节点，Core 不会进入或覆盖它。

```text
Chrono/
├─ Chrono.adoc
└─ 2026/
   ├─ 2026.adoc
   ├─ 2026-Q3/2026-Q3.adoc
   ├─ 2026-08/2026-08.adoc
   ├─ 2026-W34/2026-W34.adoc
   └─ 2026-08-21/2026-08-21.adoc
```

配置可从已配置的模板库选择启用周期、时区、创建策略、显示偏好，以及可选的经授权模板根 UUID。它不能重新定义规范周期拼写或相对位置。模板根通过 [`19-node-template-library.md`](19-node-template-library.zh-CN.md) 的契约接收冻结的类型化周期/日期输入。声明任何 `node_name` 的模板均不兼容，并会阻止 Chrono 使用而不是被忽略；Chrono 将每个固定周期基名作为唯一显式目标名称，不接受任何路径模板。Chrono 与选择其根 UUID 一样，路径和层级仍由 Core 拥有。

模板库根、模板根和模板部分被排除在 Chrono 根和周期节点候选之外。 Chrono 实例化使用新的 UUID 创建普通周期节点，重写所选模板的内部链接，复制拥有的资源，默认省略设计注释，并通过一项经过审查的可恢复事务提交完整的缺失周期集。隐藏的、过时的、无效的、不可用的或名称绑定的模板是非公开的，并且在写入之前会被阻止。

Chrono 实现接受选定的节点 ID 作为根，验证一个公历日期，始终包含年份，并在一个可恢复工作区事务中计划所有丢失的请求周期节点。现有的规范节点被重用；冲突和过时的工作区修订将被拒绝。桌面和环回 WebUI 桥公开相同的预览，并且提交使用缓存的计划而不是重新生成身份。
