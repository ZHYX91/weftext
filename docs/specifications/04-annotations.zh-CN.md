# 节点注释和回顾

状态：已接受的伴随文件契约。

批注是可移植的审阅内容，而不是作者编写的文档源文本、frontmatter 属性或仅存在于 Server 的记录。受管节点仅在需要时创建一个保留的伴随文件：

```text
Document/
├── Document.adoc
└── weftext.annotations.json
```

伴随文件将所有者的 `document_id` 作为对 `weftext.id` 的外键校验保存；AsciiDoc 文档仍是节点身份权威。只有受管节点可以拥有此伴随文件。非受管文件、普通资源和非受管目录不能通过此边界获得节点批注。

## 注释模型

一个注释独立地组合：

- 目标：文本范围、插入点、块、完整文档或已审阅的资源区域；
- 一种：评论、标记、建议插入、建议删除或其他版本化审核操作；
- 可选的视觉标记：突出显示、下划线、波浪线或删除线；
- 可选的稳定主题令牌：黄色、红色、绿色、蓝色、紫色、粉色或灰色；
- 标签、可选的评论线程以及开放/已解决/孤立状态。

颜色是呈现，而不是语义。重要、问题、错误和待验证等语义均由标签表达。作者的下划线或删除线是普通 AsciiDoc 源文本；审阅的下划线或删除线是伴随文件中的覆盖层。接受插入/删除建议会调用普通 Core 文档计划和事务。拒绝或解决建议只改变伴随文件。

每个批注和消息都有自己的小写 UUIDv4。重命名、移动和云端复制均会保留它们。将节点复制为不同节点时，批注和消息连同 `document_id` 都会重新设定身份。重复 ID 和同步冲突副本需要显式调和。部分同步期间缺失的伴随文件是不完整状态，绝不授权创建空替代文件。

## 消息主体和参与者

每条消息都存储精确约束的 AsciiDoc 内联源：

```json
{
  "id": "a27fe847-6cf7-48bb-9e85-f672d10461f7",
  "author_id": "70d407dd-8538-45da-bb3d-d2eb4baa8539",
  "author_name": "Zhang San",
  "created_at": "2026-08-24T10:20:00+08:00",
  "body": {
    "format": "weftext.asciidoc.inline.v1",
    "source": "Please verify this _claim_."
  }
}
```

`author_id` 是稳定的协作参与者标识符；`author_name` 是显示快照，绝不是账户查找键。除非在消息中明确写入，账户凭据、电子邮件、会话 ID、角色授予、在线状态、光标状态和未发送草稿均不会进入可移植批注。消息编辑/删除行为和审计保留均由 schema 版本控制；具有破坏性的客户端不得悄然删除审阅政策要求保留的历史记录。

伴随文件只有一种规范的行内正文语言。未知的伴随文件或正文版本必须安全拒绝。

## 锚点

文本锚点保留：

- 精确的基础文件修订；
- 该修订版的 UTF-8 源开始/结束偏移量；
- 准确选择的可见报价；
- 有界前缀和后缀上下文；
- 包含块/部分身份或路径证据（如果可用）。

偏移是证据，而不是永久身份。文档编辑后，只有存在唯一确定目标时，Core 才会基于精确块证据和上下文重新锚定。不明确或缺失的目标会成为 `orphaned`；它们绝不被悄然附着到其他位置或丢弃。UI 将浏览器字符串位置映射为 Core UTF-8 位置，但绝不自行定义持久锚定规则。资源区域批注还存储节点拥有的资源定位符、资源摘要、媒体类型以及适合该资源的版本化坐标/页面/时间目标。资源目标绝不授予批注渲染器文件系统或网络访问。

## 变异和多用户权限

创建、标记、回复、编辑、解决、重新打开、重新锚定、建议、接受和拒绝均是类型化 Core 操作。首次创建使用可恢复的创建文件日志步骤；后续更改使用伴随文件修订检查、已验证的原子替换和启动恢复。当一致性要求时，成功的文档变更及其关联批注转换会在一个可恢复事务中提交。

Desktop 和 CLI 使用相同的 Core 边界。在托管模式下，Weftext Server 对参与者认证和授权，串行化节点伴随文件的并发变更，拒绝过期计划，发布有范围的事件，并记录所需审计证据。浏览器绝不直接写入托管文件。

托管读取先通过参与者的授权节点投影解析请求的 UUID，随后只验证该节点文档、固定伴随文件和同目录批注冲突副本。它不得打开或要求隐藏祖先或无关隐藏节点有效。此范围读取规则不削弱变更权威：每次伴随文件创建或改动仍使用完整托管副本快照、工作区修订、Core 计划和可恢复事务。

同步文件夹会复制伴随文件，但不是多用户协作协议。Server SQLite 可以存储账户、角色、会话、审计事件、在线状态、投递队列和派生的未解决计数/活动索引。它不得成为可移植评论、标记、建议或线程正文的唯一副本。

## 验证

伴随文件 schema 是封闭且版本化的。仅当 schema 明确提供前向兼容的扩展存储时才保留未知字段；未知的必需语义一律安全拒绝。限制覆盖文件大小、批注、消息、正文字节、上下文字节、标签和资源目标。

验收范围包括 CJK/RTL/emoji、混合换行符、重叠批注、并发回复、过期解析或编辑、参与者删除、节点复制/移动/移入回收站/恢复、部分同步、冲突副本、文档编辑时锚点保留或孤立、建议接受与回滚、Server 授权与信息不披露、崩溃恢复，以及精确备份与恢复。
