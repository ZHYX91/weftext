# 同步与派生索引

状态：当前架构契约。

云同步文件夹只复制文件，不提供事务性协作。可移植权威包括 `.weftext-format`、存在时的 `.weftext-rules`、受管节点目录及 AsciiDoc、可见非受管内容、被忽略的物理内容、资源、批注伴随文件、有效的节点本地表格伴随文件/记录存储，以及 `.weftext-trash/_weftext.items` 中的每一个清单/负载字节。搜索、出链、反向链接、潜在提及、别名查找、关系图、表格公式/结果/反向关系、缩略图、监视器状态和缓存均为派生数据，存储在工作区外的本地位置。

设备“最近历史”和正式“备份仓库”也位于工作区外，但二者不是派生索引。“最近历史”是设备本地的精确源恢复证据，绝不随普通工作区同步。“备份仓库”是另行选择、与工作区不相交的本地/远程目标，拥有自身不可变对象/快照权威和执行器；工作区扫描器与内容规则均不得进入它。另一台设备只能通过其自身本地存储、显式附加的只读/授权仓库或 Weftext Server 看到历史，而不是因为当前工作区文件已经同步。参见 [`22-document-history-comparison-and-backup-repositories.md`](22-document-history-comparison-and-backup-repositories.zh-CN.md)。

多用户编辑必须通过 [`07-server-collaboration.md`](07-server-collaboration.zh-CN.md) 规定的 Weftext Server 进行。多个相互独立的客户端写入同一同步目录，是不受支持的协作拓扑。

Core 扫描器区分以下状态：

- 有效节点；
- 有效的多维表格配置：其伴随文件、记录存储布局、记录身份、值和资源定位符均与所属受管节点一致；
- 可见的非受管目录、包括 Markdown 在内的松散文件，以及带有根相对 `/` 定位符、父定位符、可选受管节点 UUID 和可选资源所有者 UUID 的普通资源；
- 忽略边界匹配：仅在内部作为安全屏障保留，不会通过普通产品清单返回；
- 完整的回收站项目：作为封闭的清单/负载权威，为修订、同步、备份、恢复、冲突和迁移保留，但绝不作为活动受管节点或普通文件返回；
- 不完整节点：其 AsciiDoc 或身份元数据封装可能仍在同步到达；
- 无效身份；
- 重复身份；
- 未被任何规则分类时，不兼容的松散文件和未配对内容目录；
- 冲突副本候选项和外部移动。

身份缺失或无效绝不授权扫描时自动重新生成。纳管和修复是显式的预览/提交操作。本地索引可以丢弃，并根据可移植权威重建。

扫描器绝不在非受管或忽略目录下重新进入节点发现，也绝不在 `_weftext.items` 或有效 `weftext.records` 存储下进入活动节点发现。内容规则不能将任一保留存储或其后代分类。链接、反向链接、别名、潜在提及、关系图、Chrono 和节点排序只消费活动受管节点。表格记录关系消费单独验证的已授权表格投影；规范 Query v1 不发现记录域。普通文件/资源视图可消费可见非受管清单和普通节点所属资源，但不得消费表格伴随文件/记录文件或回收站清单/负载。所有公共定位符都是根相对 `/` 字符串；绝对主机路径始终保留在受信任的本地进程内。

链接和别名索引由节点基名、`weftext.aliases` 和文档内容重建。它绝不成为身份权威，也不会只因发现一个候选项就写入链接。候选项排序、重叠、歧义和显式链接操作见 [`10-links-and-potential-mentions.md`](10-links-and-potential-mentions.zh-CN.md)。

内容搜索索引是按工作区 UUID 存放在设备配置目录下的、版本化的派生投影，绝不位于工作区内。它索引活动受管节点名称、可见 AsciiDoc 正文和安全的字面描述性文档头属性；排除 `weftext` 元数据封装、处理器控制属性、非受管内容、忽略内容、表格伴随文件/记录 JSON、回收站特殊节点、每一项目清单及每一负载节点/资源。表格记录使用单独的一次性、具备模式感知的投影，以所属表格节点 UUID、记录 UUID 和权威指纹为键。已解析的显式图标或派生默认图标可复制到结果展示中，但两个索引都不成为图标、字段、记录、公式、关系或属性权威。UUID 和当前相对路径仍是扫描器投影，而非身份注册表。

表格投影在接受新权威前，会验证完整的当前伴随文件/记录关系。伴随文件/分片/文件部分到达，伴随文件/记录模式不匹配，文件名/ID/分片不匹配，重复 ID，冲突副本，无效值，缺失必需伴随文件或记录存储根，或链接/重新解析内容，都会产生类型化协调问题。已验证过的投影可保持可见、只读并标记为过期，但不能授权编辑、汇总、导出或关系建议。公式结果、过滤、稳定排序/分组和汇总均从已授权文件及明确的求值上下文确定性重建。成功的记录/模式事务即使后续投影失败，仍是成功的权威提交，并附带结构化重建警告。

同步而来的回收站项目，只有在其目录名、封闭清单、完整负载清单、永久身份、长度和摘要彼此一致时才能使用。部分到达、清单/负载被篡改、重复或大小写折叠冲突的 `trashItemId`、冲突副本文件名、重复的活动/已回收节点 UUID，或相互竞争的恢复/删除状态，都会产生类型化回收站协调问题。Core 保留所有物理证据并阻止普通回收站变更；它不将冲突归类为忽略/非受管、不按时间戳选胜者、不为永久节点重新设键，也不根据路径修复清单。只有完整副本快照，才能将缺失项目视为已删除。

打开或搜索工作区时，索引会与有效的 Core 清单协调。未变化的文档条目可按 UUID 加文件指纹复用，移动会更新派生定位符，缺失或已回收的条目会被移除。已知文档提交与结构事务还会显式使其受影响 UUID 失效，因此正确性不依赖时间戳粒度，且无关文档无需重新解析。损坏、缺失、不受支持或被手动删除的索引，都会从可移植工作区权威原子重建。资源和批注伴随文件仍是使用它们的派生功能的可移植权威，但第一个内容搜索投影有意不使其字节可搜索。

权威文档或工作区事务的成功或失败，与派生索引维护相互独立。若 Core 提交成功、后续索引刷新失败，调用方收到的是成功提交加结构化索引警告，并标记索引稍后重建。不得将整个请求报告为失败，也不得邀请用户重试已经发生的写入。搜索可报告索引不可用，直至后续刷新/重建成功。

外部索引边界按已解析的文件系统位置检查，而不能只检查词法路径字符串。实现会解析已有索引目标或其最近存在的祖先，应用未解析后缀，并拒绝任何位于已解析工作区内的结果。`..`、符号链接、Windows junction/重新解析点、相对路径，以及别名工作区目录下尚未创建的文件名，都不能绕过这条规则。安全检查不明确或无法解析时必须安全拒绝。“最近历史”和“备份仓库”的目标验证适用同一已解析不相交原则，但保留各自独立的模式、保留、授权和变更边界；二者均不得位于工作区内，且索引绝不能提升为其中任一存储。

结构写入最终需要可恢复的多文件日志，其中包含基础修订、准备/提交/清理状态、在支持时的原子替换及启动恢复。在该日志可用之前，任何没有安全回滚路径的操作仍只是计划，不能假装成持久事务。
