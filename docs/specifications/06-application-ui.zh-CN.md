# 应用程序 UI

状态：当前架构契约。

## 必需客户端

Weftext 为本地工作区提供 Desktop 应用程序，并为 Weftext Server 提供 WebUI。WebUI 不只是管理控制台：它支持常规阅读、编辑、导航、批注和协作。Desktop 也可作为远程 Server 客户端。

首个可用 Desktop 版本包含：

- 支持创建、重命名、移动、复制、项目支持的回收站、恢复/祖先链预览及单独保护的永久删除流程的节点树；
- 标签页、拆分视图、后退/前进、面包屑、最近节点、书签和会话恢复；
- 切换时保持相同语义位置的 Write、Source 和 Read 视图；
- 当前文档查找/替换和工作区搜索；
- 文档头 Properties 编辑及专用 `weftext` 控件，不进行破坏性的 YAML 重新序列化；
- 原生待办项切换、待办项提升为任务节点、类型化任务节点控件，以及涵盖两种行类型的一个规范 Query 派生任务视图；
- 带可视选择器且导航渲染一致的可选可移植节点图标；
- Chrono 根节点选择和固定周期节点创建；
- 高亮、下划线、删除线、评论、未解决锚点和审阅线程；
- 同步/冲突中心、事务恢复、索引重建、安全模式和诊断；
- 键盘操作、命令面板、屏幕阅读器语义、高对比度、减少动态效果及 IME 支持。

首个可用 WebUI 在 Server 权限约束下包含相同的核心节点、编辑器、搜索、Chrono、批注、冲突和导航流程。它还为已授权用户提供登录、会话/设备管理、成员与角色管理、部署健康状况、审计访问和备份/恢复控件。

Core 为受管节点、可见非受管目录/Markdown、节点所属资源和派生图标提供一个共享清单模型。已接受的导航以窄活动栏承载 Explorer、Search 和 Chrono。切换 Hierarchy 与 Contents 模式的是 Explorer，而非活动栏，因为受管节点树和类似 Finder 的当前位置列表是同一工作区的两种投影。任何外壳都不得以独立文件系统扫描实现其中任一投影。完整决定记录在 [`../architecture/05-shared-navigation-information-architecture.md`](../architecture/05-shared-navigation-information-architecture.zh-CN.md)。

### 共享导航外壳

Hierarchy 显示完整受管节点树。它的展开控件展开分支，名称打开节点；一个整行按钮不得同时执行两种动作。Contents 是单个位置的列表，初始跟随聚焦编辑器窗格中的节点。它显示直接受管子项，以及 Core 可见的非受管目录、非受管 Markdown 和资源。它可以浏览可见非受管目录，而不创建节点标签页或改变当前受管文档。Contents 标题和面包屑始终区分所浏览的定位符与聚焦的受管节点，并提供返回动作。

同名的规范 AsciiDoc 文档由其受管节点项表示，绝不重复显示。被忽略内容不出现在行、计数、空状态、搜索、事件、错误、缩略图、最近项目和无障碍说明中。非受管行没有节点 UUID，也不获得仅节点适用的 Properties、图标、Chrono、回收站、排序、批注、反向链接或编辑动作。原始文件编辑和一般文件系统操作需要单独的规范。

Hierarchy 与 Contents 使用同一份 Core 派生父/子投影和受管子项顺序。客户端可在视觉上分组内容类别，但必须保持 Core 对受管子项的顺序，并对非受管组保持稳定的自然名称顺序。若调用方载荷缺少足够的有序关系数据，应扩展共享 Core/API 投影；Desktop 和 Server WebUI 不得实现独立排序权威。手动重新排序和跨父节点拖放不在当前 Explorer 契约内，需要独立的 Core 事务。

中心区域仍显示处于 Write、Source 或 Read 的受管文档。右侧检查器负责 Outline、Properties、Annotations、Backlinks，以及可用时经授权的 Server 权限详情；编辑器不再增加第二个常驻子节点界面。Search、Chrono、最近项目、书签、标签页和两种 Explorer 模式均通过同一 UUID 动作打开节点，并以聚焦编辑器窗格为目标。拆分窗格时，Explorer 选择随焦点变化，但不丢弃任一窗格受控的源文本。替换式导航前，脏草稿持久化和过期修订行为仍是强制要求。

活动项选择、Explorer 模式、展开、滚动、筛选和宽度均为设备本地展示状态。受管导航身份仍以 UUID 为基础。非受管浏览定位符只有在当前 Core 清单验证后才能恢复。Server 响应会先按权限过滤再投影；浏览器绝不会先收到隐藏项目再将其藏起。多角色 ACL 不可用时，身份与会话边界仅支持 Owner。

共享 Explorer 导航契约已在共享 React Desktop/WebUI 源码和 Server 的同源薄 WebUI 中实现。Core 返回从当前清单派生、可重建的版本 1 有序导航投影；Desktop、CLI bridge 和 Server API 均公开同一投影，并由此派生兼容性列表。两个 UI 均以 240 行为增量窗口化大结果，并将交互计时与 Core 扫描分开报告。该实现不会使 Server 薄客户端成为完整共享 WebUI，不增加原始非受管文件动作，也不提供权限检查器。

当前 WebUI 原型具有明确的本地工作区验收模式：原生 CLI bridge 绑定到 loopback，授予一个选定 Weftext 工作区，并给浏览器一个仅片段的随机 token。它加载真实节点树、Core 区块/链接模型和外部派生搜索索引；支持文档读取/保存、精确结构预览/提交、回收站/恢复、属性、可移植图标、批注、资源、Chrono 和过期修订冲突。运行中的 `weftext` YAML 在 Source 外保持隐藏。它不是 Weftext Server，不授予浏览器目录访问，也不代表 Server 或协作已完成。

Windows Desktop Alpha 将相同交互源码作为本地静态资源打包在原生 WebView2 窗口中。用户通过操作系统文件夹选择器授予一个工作区；UI 不获得通用文件系统能力。原生命令验证并恢复工作区，恢复最近工作区和选中节点，执行精确的 Core 读取和事务，并查询存储在工作区外、可重建的增量搜索索引。Desktop 将设备本地、修订绑定的草稿持久化在工作区外，并在任何提交前把过期草稿送至 Recovery Center。安全模式本地持久化并由原生事务边界强制执行，因此 UI 可继续保存恢复草稿，同时文档和结构提交会被拒绝。诊断只暴露恢复数量和问题代码，不暴露文档正文或完整绝对路径。共享受管节点编辑器只公开规范 AsciiDoc 计划；Markdown 仍是导入/导出、非受管内容或节点所属附件。自动化证据确立工程边界，但不完成打包后的手工矩阵。

Source 与结构化 Write 共享一个精确源文本的 CodeMirror 适配器边界。Source 显示精确 AsciiDoc 缓冲区；在被接受时，语法高亮属于展示，而不是第二个解析器。Write 仅隐藏 Core 精确报告的 `weftext` frontmatter 元数据封装，并从 Core 接收语义装饰/范围；它不运行前端文档解析器。CodeMirror 可规范化展示用行尾，但每次编辑和选择都映射回精确受控的 UTF-8 源文本，因而无关字节保持不变。唯一的顶级 `weftext` 映射默认折叠，并有显式且无障碍的切换；无效或结构歧义的元数据封装会展开以供检查。两个适配器均不得解析工作区身份、访问文件、按扩展名选择格式或提交草稿。

## 视图

编辑器提供三个同级视图：

1. Write：基于选定 Core 配置模型直接进行结构化编辑。
2. Source：真实规范源文本，带有配置感知标签、诊断、折叠和已接受的高亮。
3. Read：不可编辑的最终渲染。

Review 是叠加层或模式，而不是第四种文档表示。所有视图都操作于同一源文本修订和 Core 文档模型。

### 相邻标题与正文展示

Weftext 提供一项可选的、工作区可移植设置：将符合条件的 AsciiDoc 章节标题及其相邻普通段落展示为一个行内视觉段落。根节点把默认值存为 `weftext.adjacent_heading_body`；缺失意味着分开展示。启用、禁用或渲染此设置均不重写文档正文源文本。

已接受的解析顺序是每个标题的 `[.run-in]` 角色、每个标题的 `[.separate]` 角色，最后才是根默认值。在根 `run_in` 默认下，正文必须是紧接标题物理行后的普通段落；空行会保持分开展示。完整的适用条件和受保护区块规则见 [`15-weftext-asciidoc-profile.md`](15-weftext-asciidoc-profile.zh-CN.md)。UI 消费 Core 的行内组，绝不自行复现这些规则。

标题和段落在派生的行内组中仍是不同的逻辑区块。标题上的末尾区块 ID 只属于标题；段落上的末尾区块 ID 只属于段落。导航可以滚动共享视觉容器，但会高亮和选择被寻址的逻辑区块。大纲、目录、标题路径、标题重命名和标题链接展示只使用作者写下的标题文本，排除正文与区块 ID。重复 ID 始终是身份诊断，绝不通过分组协调。

Desktop、WebUI、Server 渲染、CLI 派生文档检查、导出适配器、搜索、链接、批注和无障碍树必须消费同一解析后的设置与 Core 区块模型。仅根节点的 `weftext.adjacent_heading_body` 字段是唯一可移植工作区默认值权威；任何客户端都不得以设备本地解释替代它。

### 系统元数据展示

- Write 隐藏保留的 `weftext` 元数据封装，也不将其计入渲染字数、选择、复制或潜在链接发现。
- Read 默认隐藏 frontmatter。
- Properties 展示标题/文档头信息及安全的字面描述性文档属性。别名、图标和排序等 `weftext` 字段使用单独的专用节点控件，而不是普通文档属性编辑。
- Source 仍是精确 AsciiDoc 源文本。它以默认折叠、清晰标注的系统元数据折叠区展示 `weftext`，而非删除或伪造源文本。
- 节点信息和诊断可展示并复制节点 ID 与排序状态。直接编辑系统元数据属于高级操作，仍需修订检查，并在身份无效、重复或 YAML 不受支持时安全拒绝。
- 纯 Markdown 导出可明确提供移除 Weftext 元数据的选项。正常保存、同步、备份和 Weftext 工作区导出均保留它。

隐藏元数据是展示决定，不是访问控制。节点 ID 不是凭据，Server 授权也绝不依赖客户端隐藏 `weftext`。

### 编辑器交互策略

Weftext 采用经验证的文档编辑器交互，但不采用其他产品的存储模型。首个编辑器序列包括：由 Write、Source 和 Read 共享的受控节点草稿；光标和滚动连续性；光标本地的 Core 配置格式化；当前文档查找/替换；带当前标题高亮和筛选的大纲；快速打开节点；以及工作区搜索。聚焦和打字机模式将在具备中文 IME 与无障碍证据后提供。

Write 是普通节点默认编辑界面。其紧凑顶部功能区的 Home/Insert 组，随着配置取得相应能力，提供撤销/重做、语义段落/H1-H9 选择器、格式刷和清除格式、行内强调、列表和待办项、引文/提示、代码、数学和图表、链接和节点链接、节点所属图像、表格及脚注/尾注。选择气泡、斜杠菜单、上下文菜单、键盘快捷键和命令面板可提供相同动作；没有任何一处拥有独立变更逻辑。文档标题和可选副标题仍是专用文档头控件，因为它们是文档头字段，而不是正文标题选择器的选项。

每个操作入口都通过语义动作注册表及 Core 报告的选择能力解析。工具栏按钮不得从渲染 HTML 推断有效性，也不得制造 AsciiDoc 标点。不支持、受保护、格式错误、混合类型或过期的选择会禁用动作，并显示简短原因。工具栏保持可键盘访问，向辅助技术传达按下/不确定/禁用状态，通过无障碍溢出菜单适配窄布局，并且不抢占活动 IME 组合输入。

格式刷复制的是类型化 Core `FormatDescriptor`，不是 CSS、HTML、字面分隔符或任意源文本。一次激活应用到下一个兼容目标；双击激活会锁定以重复使用；`Escape` 取消。共享默认快捷键为用 `Ctrl+Shift+C`/`Cmd+Shift+C` 取样、用 `Ctrl+Shift+V`/`Cmd+Shift+V` 应用；“重复上次格式”动作复用最近的兼容描述符。它可复制语义行内标记及兼容的段落/列表/引文/标题展示。它绝不复制内容、链接目标或节点 UUID、锚点/ID、引文或注释正文、评论/批注、任务状态/日期/依赖、Query 含义、Template 槽位或资源路径。不兼容目标类型会说明原因并安全拒绝；成功应用是针对受控草稿的窄 `DocumentFormatPlan`。

当前文档查找使用字面 Unicode 文本。Write 和 Read 只搜索可见文档正文；因用户明确选择 Source，Source 搜索完整精确源文本。替换是受控草稿的精确拼接，绝不是隐式工作区提交，因此继承设备草稿恢复以及通常的 Core 预览和基础修订检查。大纲排除 frontmatter 和 fenced 内容；真实工作区使用 Core 标题区块和 UTF-8 源范围，任何仅前端提取只是模拟原型回退而非格式权威。切换节点和 Write/Source 视图时，从以工作区和节点 UUID 为键的设备本地状态恢复源选择与滚动。Source 折叠展开状态也按工作区/节点 UUID 持久化；系统范围内的已恢复选择会在定位前先展开该范围。

结构化能力通过类型化 Core Profile 计划及资源事务编辑规范 AsciiDoc 表格并插入节点所属图像资源。图像仅在出现可见目标预览后成为所选节点所属资源；规范引用在资源提交前即被计划，因而语法错误不能留下让用户重试已成功导入的邀请。表格操作仅限 Core 报告的表格区块，不得重排无关源文本。数学、图表、导入/导出、规范 Query 集合、Template Designer、拼写和风格主题不在当前编辑器实现内。其计划边界记录在 [`../architecture/06-content-io-and-rich-rendering.md`](../architecture/06-content-io-and-rich-rendering.zh-CN.md)、[`../architecture/07-collections-query-and-views.md`](../architecture/07-collections-query-and-views.zh-CN.md) 和 [`../architecture/19-expression-query-and-template-library.md`](../architecture/19-expression-query-and-template-library.zh-CN.md)；这些契约并不宣称当前已实现渲染、转换、OCR、Query、Template 或多视图。

表格动作作用于 Core 解析出的逻辑选择，而不是 DOM 坐标。选择首个连续 `N` 行可标记列标题区域；选择首个连续 `N` 列可标记行标题区域；两个区域可共存，其交集仍是一组单元格。非前导或不连续的选择不得声明为标题区域。上下文菜单同时命名动作及效果，例如“将前 2 行用作列标题”，表格检查器也提供相同控件，无需右键。

矩形单元格选择只有在每个选中单元格均属同一表格，且矩形不切穿现有跨格、受保护范围或不受支持单元结构时才能合并。零个或一个非空单元格时直接合并。多个非空单元格时，Weftext 展示精确按行优先内容组合预览并要求确认；绝不丢弃内容。拆分会恢复跨格所占行和列，保留合并内容在首个单元格，并创建其余空单元格。拆分不假装恢复先前分布；立即 Undo 才是恢复合并前网格与内容的精确方式。无效合并/拆分动作仍可见，但会因 Core 原因而禁用。

标题编辑在每个可编辑窗格中使用一个清晰 H1–H9 级别选择器，而非九个相邻按钮。标题上下文菜单在配置允许时提供更改级别、转换为段落、复制章节链接和设置/移除显式锚点；工具栏、键盘和命令面板路径保持等价。改变有后代的标题时必须明确选定 `heading_only` 或 `preserve_subtree` 策略，并在应用前预览结果大纲。子树策略将后代级别按相同增量调整；若任一结果超出 H1-H9 则不可用。仅标题策略若会产生配置拒绝的层级则不可用。会重新设定后代章节父级的段落转换同样需要结构预览。除非该字段本身是明确动作目标，否则两种动作均不改变标题文本、锚点、链接或批注。引文控件将 Core 报告的嵌套深度增减一；绝不从前端样式推断深度。Read 对 H1–H6 使用原生 `h1`–`h6`，对 H7–H9 使用无障碍角色标题及真正嵌套的块引文。大纲与标题路径展示实际级别，不截断。

基于路径的节点身份、将 Markdown 视为节点、仅前端 Markdown 解析器和静默规范文件自动保存都明确不予采用。经规则分类的非受管 Markdown 保持字节不变，且没有节点动作/事务能力。受管节点内的 `.md` 是普通节点所属附件，与 `.txt`、图像和 PDF 具有相同资源动作；其内容不进入节点语义。设备本地草稿可为受管节点崩溃恢复而自动保存；提交到工作区仍需修订检查。

标签页是 UUID 会话而非路径书签。打开已存在于另一标签页的节点时应选中该标签页，而不是为同一节点创建两个状态所有者；每个标签页以工作区 UUID 加节点 UUID 保存视图、选择与滚动。关闭活动标签页时选中相邻仍存在的标签页。后退/前进、可操作面包屑、最近项目和书签只存节点 UUID。可选第二窗格有自己的节点 UUID、视图、选择、滚动、查找/替换及受控草稿状态。工作区路径仍是 Core 提供的当前定位符，绝不持久化为导航身份。

Desktop 或实时 WebUI 重启时，在选择打开文档前先恢复持久化导航。若活动标签 UUID 仍有效、但与后端最后记住的文档不同，客户端通过正常 Core 文档读取边界打开该活动标签 UUID，之后才展示它。活动标签、选中节点、可见文档和编辑器状态绝不能彼此不一致。

每个可编辑窗格均为自己的节点和受控源文本提供显式的修订检查保存/预览入口。关闭或切换脏的第二窗格会保留其设备草稿并传达该状态；绝不静默丢弃。当前恢复草稿可填充该窗格并保持脏状态。过期恢复草稿绝不自动替换磁盘源文本：窗格显示当前磁盘文档，在与主窗格相同的 Recovery/Conflict 边界展示过期草稿，并要求明确恢复选择后才可预览/提交。

### 功能区、Data、Tasks 与 References

功能区契约定义一个紧凑、可折叠的顶部控件，包含六个固定标签：Home (`开始`)、Insert (`插入`)、Data (`数据`)、References (`引用`)、Review (`审阅`) 和 View (`查看`)。Data 涵盖节点集合、任务视图、标题/模板视图、多维表格、筛选、分组、排序和汇总。References 涵盖引文、注释、题注、交叉引用和索引。论文通过模板或工作流表示，不是节点类型。

Table、Image、Dynamic View、Task 和 Template Design 标签是上下文标签，只在兼容的 Core 解析选择存在时出现。选择原生表格会公开标题行/标题列、合并/拆分、题注、插入/删除和提升动作。选择多维表格会公开字段和记录视图命令。选择动态视图会公开规范 Query 构建器与当前布局，而不改变其源域。选择待办项或任务节点会公开常用状态、优先级、截止时间和依赖命令；这不是永久第七标签。每个命令都委托给上下文菜单、斜杠菜单、快捷键、选择气泡和命令面板所用的同一语义动作注册表和类型化 Core 计划。

右侧检查器负责持久上下文详情：Outline、Properties、Annotations、Backlinks、Task 详情、Citation/Reference 详情，以及可用时经授权的 Server 访问。任务节点标题可显示紧凑状态/优先级/截止日期芯片，而完整表单仍在 Task 详情中；原生待办项只显示受支持的简单控件及提升。选择引文会打开出现位置和已解析引用详情，打开参考节点会公开书目字段，文档范围提供引文/参考书目诊断。Review 仍负责评论、建议、拼写和变更解决，而不吞并引文工作流。

Data 有两条明显分离的创建路径。New Multidimensional Table 创建一个受管表格节点，其行是非节点 JSON 记录。Insert Dynamic View 针对明确的 Nodes、Tasks、Headings 或 Templates 源文本写入一个规范 `.weftext-query` 区块。构建器编辑光标处的精确 Query，绝不保存隐藏的并行前端配置。临时筛选、密度、宽度、选择和滚动可为设备本地；只有在当前版本化 Query 源文本可表达时，才提供可移植字段/筛选/分组/汇总/布局变更。完整的文件、视图、原生提升、功能区、无障碍和事务契约见 [`20-multidimensional-tables-and-editor-surfaces.md`](20-multidimensional-tables-and-editor-surfaces.zh-CN.md)。

Board 是Data 界面内可复用的一种视图布局。`Insert -> Dynamic View -> Board` 提供 Task Board、Node Board 和 Custom Query Board；多维表格则在该表格内通过 `New view -> Board` 创建。Task Board 是一个预设：将 `from tasks`、直接状态分组、选定字段、排序和 `view=board` 写入一个精确 Query。它将原生待办项和任务节点一起渲染，同时展示二者不同能力。移动待办项仅可在 To do/Completed 间修补其精确标记；移动到 In progress/On hold/Cancelled 则需要可见的原子提升和状态迁移预览。任务节点移动修补其真实状态。表格 Board 移动修补一个 `single_select` 记录字段。计算/只读 Query 组不得仅因显示为泳道而获得拖动。

水平移动只改变一个类型化泳道字段。V1 不提供垂直手动卡片排序、泳道、WIP 限制、静默待办项提升、通用卡片数据库或仅拖动动作。Query `order by` 或表格视图排序仍是泳道内权威。每次拖动都有“移动到”、键盘、触控和屏幕阅读器等价操作。Completed/Cancelled 任务泳道默认折叠展示，卡片源类型仍以文本清楚区分，Add card 只会在目标构造器明确时创建任务节点或表格记录，所选卡片的真实源详情仍在右侧检查器中。参见 [`21-board-views.md`](21-board-views.zh-CN.md)。

### 独立 AsciiDoc 编辑器

Desktop 可在所有 Weftext 工作区之外，打开一个显式选定的 `.adoc` 或 `.asciidoc` 文件作为 **独立 AsciiDoc** 文档。文件关联、打开文件、拖放及重新打开最近文件都会进入同一单文件授权。打开文件绝不扫描其父目录/同级目录、查找 `.weftext-format`、纳管该目录、创建节点 UUID 或 `weftext` 元数据封装、创建批注伴随文件，或将相对路径变成工作区权威。Markdown 文件不被此编辑器模式接受；它们仍是附件、非受管、导入或导出输入。

独立解析使用共享的安全 AsciiDoc 语法/模型/渲染/格式化引擎，但不进行受管节点元数据封装验证。通用 AsciiDoc 保持精确源文本。Weftext 专有构造，例如 `node:` 链接、规范 Query、Template 角色/槽位、任务节点配置、可移植批注和工作区引文解析，均按原样字节保留，但显示为不可用，不执行、解析、规范化或移除。“添加到工作区”是显式导入动作：它创建一个具有新 UUID 的规范节点，绝不就地重写外部源文本。

六个固定功能区标签保持其位置，避免 UI 在模式间跳动。每个禁用组保持可见，原因均为“需要 Weftext 工作区”：

| 标签 | 独立 AsciiDoc 文件可用 | 已禁用或精简 |
| --- | --- | --- |
| Home (`开始`) | 保存、撤销/重做、文档标题/副标题、段落和 H1–H9 格式、格式刷、清除格式、强调、列表/原生待办项、引文/提示、代码、查找/替换 | 节点属性/图标、持久任务字段、节点动作、工作区保存/提交 |
| Insert (`插入`) | 普通 URL/文件链接、当前文档锚点/xref、按作者相对定位符引用的图像、原生表格、代码/字面区块、数学/图表源文本、脚注 | 节点链接/嵌入、Chrono 笔记、Dynamic View、Template 实例化、资源归属/导入至节点；向文件旁复制资产须等待单独审查过的外部文件动作 |
| Data (`数据`) | 没有 v1 命令；标签保留在原位作为说明性禁用界面 | 节点/任务/标题/模板 Query、多维表格、看板、工作区排序/筛选/分组/统计 |
| References (`引用`) | 当前文档交叉引用、锚点、题注、脚注/尾注，以及安全配置支持时的索引词源文本 | 工作区引文选择器、参考节点搜索/编辑、参考书目解析、跨节点引用 |
| Review (`审阅`) | 拼写/风格检查、比较草稿和已保存文件、可用时的独立最近历史 | 可移植评论/批注/建议、工作区审阅队列、ACL/审计动作、正式工作区备份恢复 |
| View (`查看`) | Write/Source/Read、大纲、拆分视图、缩放、聚焦/打字机、换行、主题、全屏 | Explorer/Search/Chrono、节点 Properties、Backlinks、Graph、Tasks、工作区 Version History 和 Backup 检查器 |

上下文 Table 和 Image 标签会为通用原生选择出现。表格标题/合并/拆分及其他结构安全动作仍可通过精确的独立格式化计划使用；标题级别动作仍可从 Home 和标题上下文菜单使用。可编辑图像源属性，但节点资源归属动作不可用。原生待办项仅公开无身份的切换/编辑控件；提升和持久任务字段不可用。Dynamic View、Task-node 和 Template Design 上下文标签不出现。不得通过仅前端解析器或隐藏伴随文件模拟任何禁用功能。

独立保存绑定最初获授的规范化文件路径、可用时的文件对象身份和精确打开摘要。它在同一目录暂存、保留适用权限、刷新、原子替换、重新打开，并验证精确字节。外部修改、替换、链接/重新解析转换、权限丢失或目标消失会打开 Compare/Save As，绝不静默覆盖。设备本地草稿和最近历史以保护隐私的文件身份为键，不创建同级文件。关闭最后一个独立标签页会释放文件授权。

### Version History、比较与备份状态

产品将修订历史称为 **Version History**，保留 Chrono 给日期节点，保留 Timeline 给数据/视图布局。Review 负责 Compare；右侧检查器负责 Version History。Compare 提供 Previous version、Version History、Another document、Backup snapshot 和 Resolve draft/external conflict。它支持行内/拆分模式、精确源文本/结构上下文、系统元数据折叠、变更导航，以及键盘/屏幕阅读器可用的 Use left/Use right/Keep both 动作。比较在用户创建一个受控结果草稿前只读；最终合并/恢复是一个与修订绑定的 Core 计划，绝不需要 Git。

Version History 合并可用的 `This device`、`Backup`、`Server` 和 `Protected restore point` 条目，同时保持来源和恢复完整性可见。最近历史默认在工作区外启用，并标为 `This device only`；它不随工作区同步。恢复一个文档源文本时，除非选择完整正式备份动作，否则会明确排除资源/伴随文件。比较两个节点时默认折叠仅身份不同的系统差异，绝不将 `weftext.id` 复制到目标。

备份设置会询问备份目标以及“通过何者运行备份”（`This device`、`Weftext Server` 或 `Read only`）。目标选择是具备能力版本的本地/外部/网络/Server/受支持远程后端，而非任意 URL。原始目录仓库只有一个写入者。目标、执行器、计划/保留、上次成功、上次验证/干净恢复、待处理变更和经脱敏的可用性均应可见。

未配置目标时，UI 显示 `Backup: Not configured`、`Recent History: This device only` 和 `Last formal backup: None`。设置不阻塞，且仍可选“暂不设置”，但草稿、回收站、本地历史、同步提供商历史或同盘文件夹均不得产生绿色/安全状态。完整的存储、仓库、比较、合并、恢复、无障碍和不披露契约见 [`22-document-history-comparison-and-backup-repositories.md`](22-document-history-comparison-and-backup-repositories.zh-CN.md)。

### 工作区项目图标

节点图标是可选导航展示，以 `weftext.icon` 中的一个标量存储。该标量要么是一个字面 emoji，要么是一个稳定的 Weftext 自有内置 token。Desktop 和 WebUI 使用同一 Core 解析器与受支持值目录，故任何外壳不得发明独立图标存储，也不得在修订检查的节点动作外写入图标。

图标选择器契约为 emoji 和 Weftext 自有内置符号提供可搜索的可视选择器。从选择器选择会通过窄补丁替换标量 `weftext.icon` 值，清除则删除该字段。提交响应返回 Core 解析的图标，使 Source 编辑可刷新导航而无需前端 YAML 解析器。UI 提供三种紧凑列表位置——节点名称前、节点名称后或隐藏——并有一个独立切换项控制是否在打开文档标题旁显示图标。位置和标题可见性是应用程序或账户偏好，因为不同用户和设备可选不同信息密度；所选节点图标本身仍是工作区可移植的运行元数据。

当节点树、快速打开、工作区搜索结果、最近节点和书签等界面展示图标时，均使用同一解析图标。未知 token 保持精确源文本，但不解析为显式图标。图标仅作装饰，绝不取代无障碍节点名称。尺寸、基线、间距、对比度和标题缩放来自语义 UI token，而非任意的每用户像素值。

展示优先级遵循共享 Core 语义：受支持的显式节点标量；否则为 Weftext 默认受管节点图标；再否则为非受管内容的普通文件夹、Markdown 文件或普通文件图标；最后是既有的特殊根/回收站状态展示。默认值是派生 UI 状态，绝不写入 `weftext.icon`。当前图标契约不继承祖先图标，也不将资源图像解释为图标。不受支持的标量值仍在 Source 和节点诊断中可见，但不会产生损坏图像或缺失符号占位。

受管节点内容项携带仅对该类别填充的可选 UUID；非受管项目不携带。每一项目都有根相对定位符和词法父定位符，资源可携带所属受管节点 UUID。受管节点的规范 `X.adoc` 由节点项表示，不得再次显示为普通文件。非受管行只是非节点展示：创建/移动/复制/回收站/Chrono/图标/属性动作对其不可用。

### 主题

所有组件使用画布、界面层、文本、边框、焦点、选择、批注、警告、冲突、成功和禁用状态的语义设计 token。交互原型以一个参考外观验证这些 token；其他风格预设不在当前契约内。

打包 Desktop 验收覆盖编辑器与事务状态下的浅色、深色和高对比度系统主题。主题不得仅通过颜色传达身份、授权、冲突或批注状态，也不得改变 Core 行为。

## 动作

一个语义动作注册表向上下文菜单、按钮、键盘快捷键、命令面板、CLI 和 Server API 提供动作。每个动作定义其类型化目标、授权、可用性、输入字段、预览、确认策略、事务构造、结构化错误以及撤销/恢复行为。UI 代码不得实现直接文件移动、临时链接重写或第二套目标选择规则。

注册表使用共享导航架构中的单一动作目标解析器。编辑器/当前节点命令捕获聚焦窗格的 `focusedNodeId`；具体的树/内容/资源/回收站行动作捕获该行的显式 UUID 或 `trashItemId`。在当前节点下创建和当前节点 Chrono 命令使用同一聚焦 UUID。捕获的身份在异步预览与提交期间不可变：之后的焦点或选择变更不得重新定向目标，过期或不可用目标必须失败，而非回退到主窗格或当前 Explorer 选择。

面向用户的注册表为 **重命名当前节点**、**移动整个节点分支**、**复制整个节点分支**、**将整个节点分支移至回收站**、**恢复回收站项目**、**将节点所属资源移至回收站**、**永久删除回收站项目**、**将待办项提升为任务节点**、**从模板创建** 以及每项 Template 角色边界转换提供独立条目和确认。重命名不是移动的隐藏模式，回收站绝不显示目标父节点或目标名称字段。恢复仅在 Core 提供明确目标选择时显示目标或替代名称字段。资源移除接受 Core 所有的资源身份，而非非受管文件定位符。永久删除拥有独立破坏性样式、更高授权和绑定字节的二次确认，不能与普通移至回收站控件共用。诸如 `move`、`copy`、`trash` 或 `restore` 的内部动作 ID 与原始名称不是无障碍标签。

节点动作作用于一个 **节点分支**：同名规范文档、每个后代节点，以及该完整受管子树中的节点所属资源和批注伴随文件。它不只意味着当前在编辑器中可见的文档。目标选择器可以说“此分支及其后代不能选作目标”，但也必须说“操作仍包含完整分支”。无障碍措辞必须区分目标筛选与操作范围。

每次重命名、移动、复制、节点移至回收站和节点恢复的预览与确认，都会渲染 Core 封闭、版本化的 `scopeSummary`：`rootNode: { nodeId, displayName }`、不含根的 `descendantNodeCount`、`resourceCount`、`annotationSidecarCount`、精确 `byteTotal`、规范排序的 `affectedDocumentNodeIds` 和 `rewrittenDocumentNodeIds`、`identityPolicy`、`trashItemCount` 及可为空的 `operationId`。对祖先链恢复，`rootNode` 是原子计划恢复的最外层节点，而捕获动作目标仍标识用户选中的项目。精确计划仍在需要时携带字节范围/替换、身份映射、项目 ID 和路径；摘要不得由可见行重新计算。重命名、移动、回收和恢复显示 `identityPolicy: preserve`；复制显示 `identityPolicy: rekey` 及完整旧到新 UUID 映射。回收站计数按项目计算：一条含多后代的分支创建并展示一个项目；一批资源则在同一个 `operationId` 下为每个可独立恢复文件创建一个项目。创建/导入以及仅资源或异构多项目永久删除计划保留其专用类型化证据；不存在单一被操作节点分支时，它们不得伪造 preserve/rekey 节点摘要。

预览成为可执行操作前，共享变更边界将 Core 的精确草稿敏感 UUID 集与权威的当前设备/会话草稿注册表求交。该集合包括源分支中的每个节点、计划替换或重写其规范文档的每个节点，以及回收站资源或项目正被移除、恢复或永久删除的任何保留节点/所有者身份。脏源根、脏后代或脏链接重写文档均会以精确节点列表阻断操作，并要求普通修订检查保存，或明确丢弃草稿后重新预览。复制不能选择复制旧磁盘字节，回收站也不能在草稿仍是未处理编辑时移除活动节点。无关脏节点不阻断。

提交在应用修订绑定计划前会立即重复同一作用域草稿查找。预览后才变脏的草稿产生类型化冲突且不写入；客户端不得用缓存布尔值或确认覆盖通过此门槛。正常保存会改变工作区/文档证据，因而需要重新计划。丢弃是经草稿边界有意移除所标识草稿，而不是在此动作中忽略它。Desktop、本地 WebUI、托管 WebUI、CLI DTO 和 Server DTO 均保留 Core 范围与草稿门证据，不重命名、丢弃或独立计算字段。

破坏性、批量、跨工作区、权限和外部出口动作需要显式预览。复制文本或链接不改变文档，除非所选动作明确创建稳定锚点；剪贴板也只在该事务成功后更新。

### 待办项与任务节点界面

原生待办项行提供精确切换和 **将待办项提升为任务节点**。提升可从上下文菜单、始终可键盘访问的行动作、命令面板和匹配调用方界面使用；右键绝不是唯一入口。命令一次性捕获精确所属节点/修订/源文本出现位置，不追随之后的编辑器焦点或选择。

预览显示生成的任务节点 UUID、标题、可移植名称、默认所属节点父级或明确选定的活动父级、初始状态、从续行/后代提升的精确内容、将重新锚定或阻塞的批注、精确的 `node:` 链接替换、范围/字节数及草稿冲突。`[ ]` 映射到 `todo`；`[x]`/`[*]` 映射到 `completed`，不虚构关闭时间戳。名称冲突需要明确的替代名称或父级；任何客户端都不得静默加后缀。

提交后，原位置是含稳定节点链接的普通列表项，而非复选框。UI 可用当前任务节点状态、优先级或截止日期丰富该解析链接，但点击其状态会编辑目标节点属性，点击其标签会打开目标。引用源文本绝不缓存第二份任务状态，改名目标也不会静默重写作者写下的链接标签。

任务节点详情使用普通节点编辑器、Properties 投影、资源、批注、链接、历史、权限、结构动作和回收站/恢复。任务检查器通过类型化控件及精确预览/提交公开封闭的 `weftext-task` 配置，而不要求用户编辑原始属性。原生待办项和任务节点出现在一个任务视图中，且类型清晰可辨；不可用的待办项字段保持为空，不得填入虚构默认值。任务节点系列/出现项契约被接受前，不提供重复控制。

### 规范 Query 与 Template 界面

Query 编辑器和结果视图只消费 Core 的规范 `.weftext-query` 模型。源选择来自正文 `from` 子句；区块 `view` 属性仅改变展示。行字段采用作者写下的显式别名。`this.node`、`this.document`、`this.heading` 和 `this.query` 是词法解析器上下文，绝不跟随活动窗格、选中行或聚焦编辑器。使用 `this` 的已保存 Query 会公开其显式绑定；缺失绑定显示 `missing_context`。UI 不得将空标题重写为文档标题，也不得静默扩大 `section(this.heading)`。

Template Library UI 契约使用已配置根 UUID 的专用投影。Library 容器、每个直接子级 Template Root 和每个所属 Template Part 始终与普通节点明显区分；Part 展示其所属 Root，且不能独立实例化。节点、任务、标题/大纲、引文、搜索、关系图、Chrono、默认反向链接、最近项目和其他普通视图，不得把这些角色混入其结果集。角色感知清单不可用时，选择器/结果界面显示 `domain_unavailable`，而不是空 Library 或路径派生行。

Template Designer 契约在一个受控精确子树上提供三个同级视图：

1. **Design** 渲染类型化行内/区块槽位芯片，将选择转换为参数，从斜杠动作插入行内或区块槽位，显示参数/模式/绑定/默认值/示例控件，并通过一个精确 Core 事务重命名参数/槽位。
2. **Preview** 接受样例类型化输入/上下文，并显示完整提议生成子树，不写入。
3. **Source** 显示精确 Template Root/Part `.adoc` 与 `weftext.template.json` 字节、配置范围和诊断，而不重新生成任一表示。

诊断识别未使用或缺失的参数/槽位、类型不匹配、重复的 `(scope UUID,name)` 声明、非法行内/区块类型、受保护位置、残留槽位/配置/伴随文件、无效生成 `node_name`、未解析链接/资源、ACL、草稿、过期和边界。一个有效声明的重复出现是有意的芯片，获得同一个只求值一次的值。Designer 绝不执行 Query；Query 派生数据必须以已授权、已冻结的类型化输入到达。

创建节点提供 **空白** 和 **从模板创建**。从模板创建只列出已授权 Template Root，构建模式表单，并提供实时、不写入的完整树预览。Root `node_name` 绑定提供展示的已解析目标名称并移除覆盖控件；没有该绑定时，表单要求一个明确调用方名称。Part 绑定提供其名称，否则使用原型基名。预览显示单一名称权威、节点/资源数量、新 UUID/链接映射、资源复制、设计批注省略、冲突、ACL 和草稿阻塞项，然后提交一个可恢复事务。移入、移出或在 Template 角色间移动使用独立转换预览：展示角色/所有者及伴随文件/源文本变更，并在普通输出前具象化/删除活动槽位；它绝不以惰性的普通语法作为只按路径降级的方式。Template UI 和引擎尚未实现。

### 回收站项目与恢复界面

回收站是 Core `.weftext-trash/_weftext.items` 清单的专用投影，不是隐藏受管子项视图，也不是浏览器文件系统扫描。每行以临时 `trashItemId` 为键，显示类别、原名称、删除时间、总字节数、操作组、按授权可见的永久节点 ID 或原始所有者 ID，以及以下之一：原位置活动、原位置在回收站、原位置缺失、原位置未知或需要协调。产品界面绝不将 `_weftext.items` 公开为普通目录，绝不允许编辑 `_weftext.trash-item.json`，也绝不从展示路径/名称推断原位置。

删除节点时，预览针对完整根子树显示一个项目，而不是每个后代一行。回收站徽章、列表、计数、投影和确认均以 `trashItemId` 为键和计数；负载内后代节点绝不成为行，也不增加删除计数。删除多个资源时，预览显示在同一 `operationId` 下分组、可独立恢复的项目，并逐项给出精确所有者、文件名、大小和摘要。跨边界子树、非受管/忽略文件、保留伴随文件/文档、不安全路径、项目 ID 冲突或工作区修订已变化，都会阻断最终控件，而不是提供部分删除。

恢复只呈现 Core 提供的选择：

- 原始父级/所有者 UUID 仍活动且精确/大小写折叠目标空闲时，恢复到原始父级/所有者；
- 每个所需原位置项目均唯一解析时，原子恢复已审查父项目链和选中项目；或
- 选择已有的已授权目标，并在必要时输入明确的替代可移植名称。

原位置未知/缺失时默认“保留在回收站”；主动作不得创建猜测的 B1，也不得覆盖同名节点/文件。确认显示每个被消费的项目/祖先、目标、重命名、身份、冲突、基础修订和结果计划 ID。提交后客户端重新加载权威清单，而非乐观移除行。格式错误、部分、重复、被篡改或同步冲突的项目只提供协调/诊断动作。

永久删除在视觉和语义上均与普通回收站和恢复分离。它需要更高的 Server/本地策略能力，以及绑定精确项目 ID、负载摘要和总字节数的二次确认；保留清理使用同一已审查 Core 动作。UI 说明回收站是同步删除状态，不是备份。Desktop、本地 WebUI、托管 WebUI、CLI、Server API 和已批准智能体界面消费相同计划类型和可用性原因。

## 智能体会话与审批

启用智能体的 Desktop 或 WebUI 提供专用会话界面，而非将运行器输出混入文档内容。它显示运行器与适配器版本、可用时的模型/配置标签、连接与执行状态、选定上下文范围、工具调用、待审批事项、已提交结果、取消及重连或恢复状态。

每项变更审批展示操作者、智能体来源、目标节点、基础修订、请求能力、确定性变更预览、冲突和外部出口影响。UI 必须区分提议、已批准但未提交的动作、已提交的 Core 事务及普通生成文本。关闭或取消会话不得被表述为回滚已经提交的事务。

DSH 是该界面的第一层运行器。已支持的本地和 Server 路径需要行为一致，但 DSH 专有控件必须置于运行器中立的视图模型后，使另一运行器无需第二套动作或权限 UI。除非用户明确通过普通事务导出选定输出，否则智能体转录和隐藏上下文不会保存到可移植工作区内容。

## 节点导航与移动

移动完整节点分支时，提供明确的“移入此节点”和“移至此节点旁”选择。预览展示 Core 范围摘要、旧父级和新父级、路径变更、受影响链接、冲突、身份保留、草稿阻塞项和必需权限。目标列表因源分支不是有效目标而排除它；该排除绝不缩小被移动的分支。移动不推断或改变用户写下的语义关系。

## 状态范围

每项设置声明其范围：

- application：本地安装默认值；
- workspace portable：开放、同步的工作区配置；
- device local：窗口布局、缓存和设备能力；
- server/account：身份、角色、会话和托管工作区策略；
- secret：操作系统或 Server 密钥存储，绝不进入工作区文件。

锁定或未授权内容不得通过最近项目、搜索计数、缩略图、窗口标题、诊断或已恢复 UI 状态泄露。

## UI 完成证据

仅有组件截图和源测试不足。验收需要使用真实 Core 事务的打包 Desktop 工作流和受支持浏览器工作流，包括中文 IME、纯键盘导航、无障碍检查、失败恢复和跨客户端行为一致性。
