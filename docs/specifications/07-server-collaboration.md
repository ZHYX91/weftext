# Server and collaboration

Status: current architecture contract.

## server foundation foundation boundary

The server foundation defines the transport boundary without claiming the complete Server product or shared WebUI. A native Rust Server hosts one process-selected valid workspace, serves a minimal same-origin thin WebUI for the accepted API flows, and exposes JSON endpoints beneath `/api/v1`. Node operations accept canonical UUIDv4 identity rather than paths. Inventory responses may include workspace-relative locators for presentation but never expose absolute hosted paths.

Document reads, search, canonical-profile preview models, edit planning, revision validation, atomic commit, and verification reuse Weftext Core. The Server adds a process-wide commit serialization boundary but no filesystem-write endpoint, alternate document parser, general node manifest, central identity registry, authoritative content database, or durable revision log. Structural mutation endpoints are deferred until they can expose exact Core workspace plans and transactions.

Document revision is the Core SHA-256 digest of exact UTF-8 source bytes. Preview is non-mutating. A commit carries a base revision and complete proposed source, passes through a Core plan and commit, and returns `409` with stable `stale_revision`, expected revision, and actual revision when the base is stale. Once Core returns a verified commit, response/icon construction and event publication use the verified plan/result without another fallible document read. Router fallbacks and path/query/JSON extractors—including unsupported methods, malformed path/query values, malformed JSON, missing or unknown fields, unsupported media types, and body limits—use the same versioned JSON error envelope. Protocol failures rejected before Axum constructs a routable request remain a transport boundary. Errors use stable codes and do not expose absolute hosted paths.

A successful changed commit publishes an ephemeral SSE notification containing the node UUID and new revision. Broadcast lag produces an explicit resynchronization requirement; first connection, reconnect, and lag cause the thin WebUI to recheck its current UUID/revision. Exact dirty source is retained in revision-bound device-local browser storage before tree/search navigation, and late preview/commit/navigation responses cannot replace a newer node context. The draft namespace and each accepted record bind to an opaque Server-provided workspace scope derived from the canonical hosted location: it survives an ordinary same-location restart, differs for a same-UUID/revision copy at another location, does not disclose the absolute path, and rejects conversion unscoped records. This scope is local location discrimination only—not portable identity, content authority, a central registry, or protection against guessed-path digest correlation. Accounts do not exist in server foundation; authenticated deployments must add an actor/session isolation component. These mechanisms are safety and refresh boundaries, not an edit stream, replay log, presence, durable audit, merge protocol, CRDT, or evidence of multi-user collaboration collaboration.

Before accounts, sessions, authorization, CSRF policy, and rate limits exist, the development binary accepts only loopback IP bind addresses and rejects non-loopback binds explicitly. Its capability response states that authentication and authorization are not available and deployment readiness is false. Reverse proxying or exposing this binary as an unauthenticated intranet service is unsupported. The accepted details and rejected alternatives are recorded in [runtime architecture](../architecture/01-runtime-architecture.md).

## identity and session boundary Owner identity and session boundary

The identity and session boundary adds one local Owner and secure browser sessions without claiming the complete multi-account, role, or deployment model. The Server requires an explicit control-plane directory outside and disjoint from the hosted workspace. Its SQLite state may contain the Owner credential digest, session-token digests, expiry/revocation state, and bounded security events, but never canonical documents, resources, node revisions, a portable workspace identity, annotation bodies, or another content index. The control plane cannot answer content requests; authenticated handlers still invoke Core reads, plans, and transactions.

The one-time bootstrap secret is generated by the operating-system CSPRNG into a control-plane file, is never accepted in a URL or returned by an ordinary API, and is consumed after the first successful bootstrap. Unix creation requests mode `0600`; Windows relies on the explicitly selected control-plane directory's inherited ACL, so the operator must keep that directory private and it is not yet a production secret-store claim. A SQLite immediate transaction and singleton constraint prevent double initialization. Passwords are stored as Argon2id PHC strings with a fresh random salt and explicit reviewed parameters. Session bearer tokens use system randomness and exist only in the host-only `HttpOnly` cookie and request memory; the database stores a domain-separated irreversible digest. Successful authentication rotates the presented session. Logout, Owner-wide revocation, absolute expiry, and idle expiry invalidate it.

Every request must carry the exact process-configured Host. Every state-changing request—including bootstrap and login—must carry the exact same Origin and `X-Weftext-CSRF: same-origin`; missing, `null`, cross-origin, suffix-confusable, or merely same-site origins fail closed. Session cookies are `HttpOnly`, `SameSite=Strict`, host-only, and scoped to `/api/v1`; the future TLS configuration adds `Secure`, but this current contract remains loopback-only and `deploymentReady=false`. Only health, capabilities, bootstrap, login, and static assets are public. Inventory, document open, search, preview, commit, session query, logout/revocation, and SSE require a current Owner session. An established SSE response ends at the session deadline, and the thin client revalidates its session on subscription failure before retaining protected views.

Bootstrap and login have separate bounded in-memory attempt limits and unified failure semantics. Public capabilities do not disclose whether the Owner exists; the UI exposes bootstrap only through an explicit first-use mode. Wrong, missing, or already-consumed bootstrap credentials share one failure response, while absent Owner, wrong login name, and wrong password share another. The control plane records only bounded minimal events for bootstrap success, login success/failure, logout, revocation, and first observed expiry. It records no password, bootstrap secret, raw token, document body, request body, or absolute workspace path. Browser draft records and keys bind both the opaque workspace-location scope and stable Owner actor scope, so logout or a future actor change cannot restore another actor's draft. This remains a minimal server-foundation thin-client extension, not the complete shared WebUI or an invitation/role/ACL system. The contract is defined in [runtime architecture](../architecture/01-runtime-architecture.md).

## hosted content boundary hosted content boundary

The Server does not scan hosted files independently. Startup, UUID lookup, inventory, search, document actions, and future structural endpoints all consume the current Core inventory. The versioned workspace response retains the managed `nodes` view for node navigation and adds one unified `content` view. Each content item has a class, root-relative `/` locator, lexical parent locator, optional managed-node UUID, optional resource-owner UUID, and Core-derived display-icon semantic. Managed canonical `X.adoc` files are not separate content rows. No response contains an absolute host path.

Unmanaged content is visible only through non-node file/resource presentation. A client cannot submit its locator to a node UUID route or acquire create/move/copy/Trash/Chrono/property authority for it. Ignored content is absent from inventory, search, counts, change notifications, and derived results; errors do not disclose its path or existence. The reserved `.weftext-trash/_weftext.items` store is also absent from ordinary node/content projections, but for a different reason: it is portable Trash authority surfaced only through a permission-filtered typed Trash-item API. The minimal thin WebUI displays visible non-node entries without adding mutation controls. The later shared Explorer Contents mode uses this same contract rather than a browser or Server-side alternate scanner; its sibling Hierarchy mode is the managed-node projection of the same Core inventory. Once multi-role ACL exists, authorization filtering occurs before either projection, Trash item detail/count, breadcrumbs, search, recents, or events reach the browser.

## Shared Explorer navigation current contract

The inventory endpoint now carries Core's versioned ordered navigation projection in addition to compatibility `nodes` and `content` fields. The Server does not rescan, reclassify, or resort the hosted directory. Its WebUI consumes that projection for the Explorer/Search/Chrono activity shell, managed-only Hierarchy, direct-child Contents, validated unmanaged-directory browsing, UUID node opening, and a non-authoritative inventory refresh after SSE hints. Outgoing draft-save failure cancels document replacement before the editor, history, or focus changes.

This remains the identity and session boundary Owner-only, loopback-only thin client and continues to report `deploymentReady=false`. The disabled future Permissions inspector is only a layout boundary: no Admin/Editor/Commenter/Viewer capability is presented as available. When ACL is available, the Server must filter the Core-derived projection before sending it; the browser is not an authorization boundary.

## Intranet deployment

The Server deployment contract targets servers and NAS devices through `weftext serve <workspace>` and a container image. The Server serves the WebUI and a versioned API. Deployment guidance must cover HTTPS through a reverse proxy, persistent volumes, secrets, session security, CSRF protection, rate limiting, logging, upgrade, rollback, and restore.

The default deployment has no dependency on a hosted Weftext account or third-party product. Public registration is off by default. First start creates a local Owner; Owner or Admin users invite other members.

## Identity and roles

Local Desktop mode requires no login. A multi-user Server gives each person a local Server identity. The first role model is workspace-scoped:

| Capability | Owner | Admin | Editor | Commenter | Viewer |
|---|---:|---:|---:|---:|---:|
| Read visible content | yes | yes | yes | yes | yes |
| Edit documents and header properties | yes | yes | yes | no | no |
| Create, move, copy, trash, or restore nodes/resources | yes | yes | yes | no | no |
| Add annotations and comments | yes | yes | yes | yes | no |
| Permanently delete | yes | configurable | no | no | no |
| Manage members and roles | yes | yes | no | no | no |
| Delete or reconfigure the workspace | yes | no | no | no | no |

ACL is Server control-plane state. It is not stored in canonical AsciiDoc, annotation sidecars, node IDs, or another user-editable workspace file. Subtree ACL inherits from the parent unless explicitly overridden and must not reveal hidden descendants through search, backlinks, counts, logs, or error details.

Authorized read projections are physically narrow as well as response-filtered. Opening, searching, canonical Query evaluation, validating native checklist/task-node/citation projections, Template Library discovery/preview, or reading a visible node's annotations must not open an unrelated hidden body or fail merely because one is malformed. A visible node's own malformed source, sidecar, duplicate identity, or same-directory conflict copy still fails closed without disclosing a private locator. Workspace mutations continue to validate the complete authority required by their Core plan.

Canonical Query authorization precedes scope resolution, row construction, expression evaluation, heading/Template Root detail, diagnostics that depend on hidden data, groups, counts, ordering, projection, limits, suggestions, exports, and cache population. `this` is bound to the authored query location or an explicit Saved Query embedding, never the request's selected/focused node. Hidden and missing scope targets share one unavailable error. The Server supplies explicit immutable today/now/timezone/locale context; it does not substitute its host clock or browser locale after planning.

When the deferred Template package exists, Template Library authorization precedes root/part discovery, template rows/counts, sidecar reads, parameter schemas/examples, Part ownership, sample preview, external-link/resource validation, collision diagnostics, and instantiation. Library/Root/Part rows are excluded before every ordinary node/task/heading/citation/search/graph/Chrono/backlink/recent projection. A hidden Template Root, Part, source byte, or external target is indistinguishable from unavailable. Before role inventory, `from templates` returns `domain_unavailable`. Query output never flows directly into a Template evaluator: an authorized bounded typed value must first be selected and frozen as template input.

## Authorization

Every Server request resolves an authenticated human actor and optional delegated client. The effective permission is the intersection of the actor role and the client/session capability. WebUI, Desktop, CLI, automation, extensions, and future agents all cross the same Core authorization boundary. No client may expand the actor's rights.

## AI agent clients

An AI agent harness is a delegated client, never an independent workspace identity with implicit write access. Each agent session records the human actor, harness and adapter identity/version, granted capability scope, accessible workspace scope, expiry, and revocation state. A Server-managed DSH adapter and a remote DSH adapter follow the same authorization rules.

Agent reads, search results, backlink counts, diagnostics, and tool errors are filtered before they reach the harness so inaccessible content cannot be inferred. Mutations carry a base revision and use Core previews and transactions. The Server records tool requests, approval decisions, commit outcomes, cancellations, and relevant external-egress decisions in its audit trail without storing secrets or unrestricted prompt content by default.

The hosted workspace directory is never mounted writable into an agent sandbox. If Server-side execution is later offered, its sandbox, network egress, resource quotas, model credentials, retention, and administrator policy are explicit deployment controls. DSH being first-tier does not bypass these controls or make the DSH runtime part of workspace persistence.

## Editing and revisions

Every document operation carries a base revision. The Server either commits against that revision, merges through the accepted collaboration protocol, or returns a structured conflict. It never silently overwrites a concurrent edit.

Every structural operation that a Server release delivers—rename, move, copy, ordering, item-backed Trash, resource Trash, ancestor-chain restore, or permanent deletion—must remain a serialized Core workspace transaction; this sentence does not claim every listed endpoint is already shipped. Accepted Template instantiation and role-boundary conversion must join that same boundary and are not current Server endpoints. Server stores each delivered preview only for the originating session with an expiry, single-consumes it, rechecks authorization and all required revisions plus exact draft gates, and records the resulting item/operation/plan IDs in a bounded audit event. Accepted Template previews additionally bind typed input/context, single-authority resolved names, generated UUID/path mapping, links/resources, and annotation disposition. A real-time text engine cannot directly mutate paths, manifests, payloads, identities, links, resources, Template roles/sidecars, or ACL.

The Server never accepts a caller-authored Trash manifest or raw item-store path. Inventory returns only Core-validated item summaries the actor may know; malformed/partial/conflicted items disclose a generic reconciliation state unless the actor is authorized for diagnostics. Restore accepts a temporary `trashItemId` plus one Core-advertised original/ancestor-chain/existing-target intent, not a legacy path. The accepted Template contract refuses generic Trash of the configured Library root, requires an authorized combined clear/rebind plan, preserves Template payload bytes as inactive authority, and never guesses/rebinds configuration on restore. Permanent deletion additionally requires Owner or configured Admin capability and an explicit confirmation bound to exact item IDs, payload digests, and byte totals. Unavailable, hidden, missing, and foreign-session item/plan failures remain non-disclosing.

## Real-time collaboration

The collaboration release includes:

- concurrent editing of one document with deterministic convergence;
- presence, cursors, selections, and participant identity;
- reconnect and resynchronization after network interruption;
- offline-draft conflict handling;
- live annotations and comment threads;
- durable canonical-document current contracting and crash recovery;
- external filesystem edit reconciliation;
- audit linkage from committed revisions to actor, client, and transaction.

Presence and transient transport buffers are not portable workspace authority. A selected CRDT or equivalent protocol requires an architecture decision, fuzz/property tests, cross-version compatibility rules, and a way to rebuild durable documents without a browser client.

## Local sync versus collaboration

A workspace may live in a cloud-synchronized folder for single-user multi-device replication. This mode must tolerate partial arrival and conflict copies, but it does not provide Server accounts, ACL, presence, or safe simultaneous editing. Users must not point several independent Weftext processes at the same synchronized directory and treat that as collaboration.

## Server data and portability

Workspace content remains exportable as `.weftext-format`, `.weftext-rules`, managed nodes, visible unmanaged content, ignored physical content, resources, annotation sidecars, and complete `.weftext-trash/_weftext.items` manifests/payloads. Server-only identity, ACL, session, audit, revision-log, and presence data live outside portable document source. Backup includes the complete physical portable workspace—including ignored and Trash-item bytes—and the required Server control plane, with documented restore order and integrity checks.

## Acceptance

Server completion requires packaged container/native deployment tests, multiple independent browser sessions, the full negative role matrix, canonical Query lexical-context/time/scope non-disclosure, Template Root/Part discovery and instantiation non-disclosure, item-backed node/resource/Template Trash and restore/ancestor-chain/permanent-delete tests, foreign-session/replay refusal, stale-revision and concurrent-edit tests, sync-conflict non-disclosure, restart/reconnect tests, audit checks, and restoration into a clean instance with intact Template sidecars and Trash manifests/payloads. A Server release claiming DSH support additionally requires delegated-client permission, disclosure, approval, cancellation, audit, version-mismatch, and sandbox-boundary evidence. A single browser demo or shared-folder test is not collaboration evidence.
