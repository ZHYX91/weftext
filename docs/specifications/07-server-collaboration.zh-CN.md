# Server 与协作

状态：当前架构契约。

## Server 基础边界

Server 基础定义传输边界，但不宣称已完成完整的 Server 产品或共享 WebUI。原生 Rust Server 承载一个由进程选定的有效工作区，为已接受的 API 流程提供最小化、同源的薄 WebUI，并在 `/api/v1` 下公开 JSON 端点。节点操作接受规范 UUIDv4 身份而非路径。清单响应可为展示提供工作区相对定位符，但绝不暴露绝对托管路径。

文档读取、搜索、规范配置预览模型、编辑计划、修订验证、原子提交和验证均复用 Weftext Core。Server 增加一个进程级提交串行化边界，但不提供文件系统写入端点、替代文档解析器、通用节点清单、中央身份注册表、权威内容数据库或持久修订日志。结构变更端点延后至能够公开精确 Core 工作区计划和事务时再提供。

文档修订是精确 UTF-8 源字节的 Core SHA-256 摘要。预览不改变状态。提交携带基础修订及完整提议源文本，经由 Core 计划和提交；基础修订过期时，返回 `409`、稳定的 `stale_revision`、期望修订和实际修订。一旦 Core 返回已验证提交，响应/图标构建及事件发布即使用已验证的计划/结果，不再进行可能失败的文档读取。路由器回退和路径/查询/JSON 提取器——包括不支持的方法、格式错误的路径/查询值、格式错误的 JSON、缺失或未知字段、不支持的媒体类型和正文限制——均使用相同的版本化 JSON 错误响应。在 Axum 构造出可路由请求之前被拒绝的协议失败，仍属于传输边界。错误使用稳定代码，不暴露绝对托管路径。

一次成功且有变更的提交会发布一条临时 SSE 通知，内含节点 UUID 和新修订。广播滞后会产生明确的重新同步要求；首次连接、重连和滞后均会使薄 WebUI 重新检查其当前 UUID/修订。精确的脏源文本在树/搜索导航前保留于与修订绑定的设备本地浏览器存储中，迟到的预览/提交/导航响应不得替换较新的节点上下文。草稿命名空间和每条已接受记录均绑定到由规范托管位置派生的、不透明的 Server 提供工作区作用域：它可在通常的同一位置重启后存续；在另一位置的同 UUID/修订副本中不同；不泄露绝对路径；并拒绝将无作用域记录转换而来。此作用域仅用于本地位置区分，不是可移植身份、内容权威、中央注册表，也不防御猜测路径摘要关联。Server 基础中尚不存在账户；经过认证的部署必须增加参与者/会话隔离组件。这些机制是安全和刷新边界，不是编辑流、重放日志、在线状态、持久审计、合并协议、CRDT 或多用户协作的证据。

在账户、会话、授权、CSRF 策略和速率限制存在前，开发二进制程序只接受环回 IP 绑定地址，并显式拒绝非环回绑定。其能力响应说明认证和授权不可用，且部署就绪状态为 false。不支持通过反向代理转发或将该二进制程序暴露为未认证的内网服务。已接受的细节及被拒绝的替代方案记录在[运行时架构](../architecture/01-runtime-architecture.zh-CN.md)中。

## 身份与会话边界

身份与会话边界增加一个本地 Owner 和安全浏览器会话，但不宣称已完成完整的多账户、角色或部署模型。Server 要求一个明确的控制平面目录，该目录位于托管工作区外且与之不相交。其 SQLite 状态可以包含 Owner 凭据摘要、会话令牌摘要、过期/撤销状态和有界安全事件，但绝不包含规范文档、资源、节点修订、可移植工作区身份、批注正文或另一份内容索引。控制平面不能响应内容请求；已认证处理器仍调用 Core 读取、计划和事务。

一次性引导密钥由操作系统 CSPRNG 生成到控制平面文件中，绝不通过 URL 接受或由普通 API 返回，并在第一次成功引导后消耗。Unix 创建请求模式 `0600`；Windows 依赖显式选定控制平面目录继承的 ACL，因此运营者必须保持该目录私密，这尚不构成生产级密钥存储声明。SQLite immediate 事务与单例约束可防止重复初始化。密码以带新鲜随机盐和明确审查参数的 Argon2id PHC 字符串存储。会话 bearer token 使用系统随机数，只存在于仅主机的 `HttpOnly` cookie 和请求内存；数据库存储按域分隔的不可逆摘要。认证成功会轮换当前提供的会话。注销、Owner 范围撤销、绝对过期和空闲过期均使其失效。

每个请求都必须携带进程精确配置的 Host。每个改变状态的请求——包括引导和登录——都必须携带完全相同的 Origin 及 `X-Weftext-CSRF: same-origin`；缺失、`null`、跨源、后缀易混淆或仅同站点的 Origin 均安全拒绝。会话 cookie 为 `HttpOnly`、`SameSite=Strict`、仅主机，并限定在 `/api/v1`；未来 TLS 配置会增加 `Secure`，但当前契约仍仅限环回且 `deploymentReady=false`。只有健康检查、能力、引导、登录和静态资源是公开的。清单、文档打开、搜索、预览、提交、会话查询、注销/撤销与 SSE 都需要当前 Owner 会话。已建立的 SSE 响应会在会话截止时间结束；薄客户端在订阅失败后重新验证其会话，才会保留受保护视图。

引导和登录各有独立且有界的内存内尝试限制，并采用统一的失败语义。公开能力不泄露 Owner 是否存在；UI 仅通过显式首次使用模式公开引导。错误、缺失或已消耗的引导凭据共用一种失败响应；Owner 不存在、错误登录名和错误密码共用另一种失败响应。控制平面只记录有界的最小事件：引导成功、登录成功/失败、注销、撤销及首次观测到的过期。它不记录密码、引导密钥、原始令牌、文档正文、请求正文或绝对工作区路径。浏览器草稿记录和键同时绑定不透明的工作区位置作用域与稳定 Owner 操作者作用域，因此注销或未来操作者变更不能恢复另一操作者的草稿。这仍只是最小 Server 基础薄客户端扩展，不是完整共享 WebUI 或邀请/角色/ACL 系统。相关契约见[运行时架构](../architecture/01-runtime-architecture.zh-CN.md)。

## 托管内容边界

Server 不会独立扫描托管文件。启动、UUID 查找、清单、搜索、文档操作和未来结构端点都消费当前 Core 清单。版本化工作区响应保留供节点导航使用的受管 `nodes` 视图，并增加统一的 `content` 视图。每一内容项包含类别、根相对 `/` 定位符、词法父定位符、可选受管节点 UUID、可选资源所有者 UUID 和 Core 派生的展示图标语义。受管的规范 `X.adoc` 文件不是独立内容行。任何响应都不含绝对主机路径。

非受管内容只能通过非节点文件/资源展示而可见。客户端不得向节点 UUID 路由提交其定位符，也不能为它取得创建/移动/复制/回收站/Chrono/属性权威。被忽略内容不出现在清单、搜索、计数、变更通知或派生结果中；错误也不得泄露其路径或存在性。保留的 `.weftext-trash/_weftext.items` 存储也不在普通节点/内容投影中出现，但原因不同：它是可移植回收站权威，只通过权限过滤的类型化回收站项目 API 公开。最小薄 WebUI 显示可见非节点条目，但不添加变更控件。后续共享 Explorer 的 Contents 模式使用相同契约，而非浏览器或 Server 端的替代扫描器；其同级 Hierarchy 模式是同一 Core 清单的受管节点投影。多角色 ACL 可用后，授权过滤会在任一投影、回收站项目详情/计数、面包屑、搜索、最近项目或事件到达浏览器前执行。

## 共享 Explorer 导航当前契约

除兼容性的 `nodes` 和 `content` 字段外，清单端点现在还带有 Core 的版本化有序导航投影。Server 不重新扫描、重新分类或重新排序托管目录。其 WebUI 消费该投影，用于 Explorer/Search/Chrono 活动外壳、仅受管的 Hierarchy、直接子项 Contents、经验证的非受管目录浏览、按 UUID 打开节点，以及 SSE 提示后的非权威清单刷新。外发草稿保存失败会在编辑器、历史或焦点改变之前取消替换文档。

这仍是仅 Owner、仅环回的身份与会话边界薄客户端，且继续报告 `deploymentReady=false`。被禁用的未来 Permissions 检查器只是布局边界：不得将 Admin/Editor/Commenter/Viewer 的任何能力展示为可用。ACL 可用后，Server 必须先过滤 Core 派生投影再发送；浏览器不是授权边界。

## 内网部署

Server 部署契约通过 `weftext serve <workspace>` 和容器镜像面向服务器与 NAS 设备。Server 提供 WebUI 和版本化 API。部署指南必须涵盖经反向代理的 HTTPS、持久卷、秘密、会话安全、CSRF 防护、速率限制、日志、升级、回滚和恢复。

默认部署不依赖托管的 Weftext 账户或第三方产品。公开注册默认关闭。首次启动创建本地 Owner；Owner 或 Admin 用户邀请其他成员。

## 身份与角色

本地 Desktop 模式不需要登录。多用户 Server 为每人提供本地 Server 身份。首个角色模型以工作区为范围：

| 能力 | Owner | Admin | Editor | Commenter | Viewer |
| --- | ---:| ---:| ---:| ---:| ---:|
| 读取可见内容 | 是 | 是 | 是 | 是 | 是 |
| 编辑文档和文档头属性 | 是 | 是 | 是 | 否 | 否 |
| 创建、移动、复制、回收或恢复节点/资源 | 是 | 是 | 是 | 否 | 否 |
| 添加批注和评论 | 是 | 是 | 是 | 是 | 否 |
| 永久删除 | 是 | 可配置 | 否 | 否 | 否 |
| 管理成员和角色 | 是 | 是 | 否 | 否 | 否 |
| 删除或重新配置工作区 | 是 | 否 | 否 | 否 | 否 |

ACL 是 Server 控制平面状态。它不存储在规范 AsciiDoc、批注伴随文件、节点 ID 或其他用户可编辑的工作区文件中。子树 ACL 从父节点继承，除非明确覆盖，并且不得通过搜索、反向链接、计数、日志或错误详情泄露隐藏后代。

已授权读取投影既在物理访问上收窄，也在响应上过滤。打开、搜索、规范 Query 求值、验证原生待办项/任务节点/引文投影、Template Library 发现/预览，或读取可见节点批注时，不得打开不相关的隐藏正文，也不得仅因后者格式错误而失败。可见节点自身的格式错误源、伴随文件、重复身份或同目录冲突副本仍会安全拒绝，但不泄露私有定位符。工作区变更仍验证其 Core 计划需要的完整权威。

规范 Query 的授权先于作用域解析、行构建、表达式求值、标题/Template Root 详情、依赖隐藏数据的诊断、分组、计数、排序、投影、限制、建议、导出和缓存填充。`this` 绑定到编写 Query 的位置或显式的 Saved Query 嵌入，绝不绑定请求选中/聚焦的节点。隐藏和缺失的作用域目标共用一个不可用错误。Server 提供显式、不可变的 today/now/timezone/locale 上下文；计划完成后不改用其主机时钟或浏览器区域设置。

延后的 Template 包存在后，Template Library 授权先于 Root/Part 发现、模板行/计数、伴随文件读取、参数模式/示例、Part 所有权、样例预览、外部链接/资源验证、冲突诊断和实例化。Library/Root/Part 行会在每个普通节点/任务/标题/引文/搜索/关系图/Chrono/反向链接/最近项目投影前排除。隐藏的 Template Root、Part、源字节或外部目标与不可用不可区分。角色清单落地前，`from templates` 返回 `domain_unavailable`。Query 输出绝不直接流入 Template 求值器：必须先选择并冻结一个已授权、有界的类型化值作为模板输入。

## 授权

每个 Server 请求都会解析一个已认证的人类参与者和可选的委托客户端。有效权限为参与者角色与客户端/会话能力的交集。WebUI、Desktop、CLI、自动化、扩展及未来智能体均跨越同一 Core 授权边界。任何客户端都不得扩大参与者权限。

## AI 智能体客户端

AI 智能体运行器是委托客户端，绝不是具有隐式写入权限的独立工作区身份。每个智能体会话记录人类参与者、运行器和适配器身份/版本、获授能力范围、可访问工作区范围、过期和撤销状态。由 Server 管理的 DSH 适配器和远程 DSH 适配器遵循相同授权规则。

智能体读取、搜索结果、反向链接计数、诊断和工具错误在抵达运行器前即被过滤，使其不能推断不可访问内容。变更携带基础修订并使用 Core 预览和事务。Server 在审计轨迹中记录工具请求、审批决定、提交结果、取消及相关外部出口决定，默认不存储密钥或不受约束的提示内容。

托管工作区目录绝不以可写方式挂载到智能体沙箱中。若将来提供 Server 端执行，其沙箱、网络出口、资源配额、模型凭据、保留和管理员策略均属于明确的部署控制。DSH 为一等运行器并不绕过这些控制，也不使 DSH 运行时成为工作区持久化的一部分。

## 编辑与修订

每个文档操作均携带基础修订。Server 要么按该修订提交，要么通过已接受的协作协议合并，要么返回结构化冲突。它绝不静默覆盖并发编辑。

Server 版本实际交付的每项结构操作——重命名、移动、复制、排序、项目支持的回收站、资源回收站、祖先链恢复或永久删除——都必须保持为串行化的 Core 工作区事务；此句不声称列出的每个端点均已交付。已确定的 Template 实例化和角色边界转换必须加入同一边界，且不是当前 Server 端点。Server 仅为发起会话保存每项交付预览，设置过期时间并单次消费；它重新检查授权、所有必需修订和精确草稿门，并在有界审计事件中记录结果项目/操作/计划 ID。已确定的 Template 预览还绑定类型化输入/上下文、单一权威的已解析名称、生成的 UUID/路径映射、链接/资源和批注处置。实时文本引擎不得直接变更路径、清单、负载、身份、链接、资源、Template 角色/伴随文件或 ACL。

Server 绝不接受调用方编写的回收站清单或原始项目存储路径。清单只返回参与者可知的、已由 Core 验证的项目摘要；格式错误、部分或冲突项目仅公开通用协调状态，除非参与者获授权查看诊断。恢复接受临时 `trashItemId` 加一项 Core 公布的原始/祖先链/现有目标意图，而非旧版路径。已确定的 Template 契约拒绝对已配置 Library 根执行通用回收站操作，要求经授权的组合清除/重新绑定计划，将 Template 负载字节保留为非活动权威，并且恢复时绝不猜测/重绑配置。永久删除还需要 Owner 或已配置 Admin 能力，以及绑定精确项目 ID、负载摘要和字节总量的明确确认。不可用、隐藏、缺失和外部会话项目/计划失败仍不泄露信息。

## 实时协作

协作版本包含：

- 对同一文档的并发编辑，并具有确定性收敛；
- 在线状态、光标、选择及参与者身份；
- 网络中断后的重连与重新同步；
- 离线草稿冲突处理；
- 实时批注和评论线程；
- 持久规范文档的当前契约和崩溃恢复；
- 外部文件系统编辑协调；
- 从已提交修订到参与者、客户端和事务的审计关联。

在线状态和临时传输缓冲不是可移植工作区权威。选定 CRDT 或等效协议需要架构决策、模糊/属性测试、跨版本兼容性规则，以及无需浏览器客户端即可重建持久文档的方法。

## 本地同步与协作

工作区可置于云同步文件夹中，以实现单用户、多设备复制。此模式必须容忍部分到达和冲突副本，但不提供 Server 账户、ACL、在线状态或安全的同时编辑。用户不得让多个独立 Weftext 进程指向同一同步目录并将其当作协作。

## Server 数据与可移植性

工作区内容仍可导出为 `.weftext-format`、`.weftext-rules`、受管节点、可见非受管内容、忽略物理内容、资源、批注伴随文件，以及完整的 `.weftext-trash/_weftext.items` 清单/负载。仅 Server 使用的身份、ACL、会话、审计、修订日志和在线状态数据位于可移植文档源之外。备份包含完整物理可移植工作区——包括被忽略和回收站项目字节——以及所需的 Server 控制平面，并附有记录在案的恢复顺序与完整性检查。

## 验收

Server 完成需要打包容器/原生部署测试、多个独立浏览器会话、完整的负向角色矩阵、规范 Query 词法上下文/时间/范围不披露、Template Root/Part 发现与实例化不披露、项目支持的节点/资源/Template 回收站及恢复/祖先链/永久删除测试、外部会话/重放拒绝、过期修订与并发编辑测试、同步冲突不披露、重启/重连测试、审计检查，以及恢复至一个干净实例且 Template 伴随文件与回收站清单/负载均完整。声称支持 DSH 的 Server 版本还必须具备委托客户端权限、不披露、审批、取消、审计、版本不匹配和沙箱边界证据。单个浏览器演示或共享文件夹测试不是协作证据。
