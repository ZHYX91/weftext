# 数据安全、恢复和备份

状态：当前架构契约。

## 崩溃安全写入

每个规范文档、伴随文件、保留的表格记录文件、资源和结构变更都必须经过 Core 事务。一次持久提交必须：

1. 验证目标类型、路径边界、基础修订和权限；
2. 在支持兼容原子替换语义的位置写入本次请求专用的暂存内容；
3. 验证编码、预期长度和内容摘要；
4. 使用平台支持的最强持久化语义刷新文件数据和必需元数据；
5. 执行原子替换，或执行可恢复的多文件提交协议；
6. 保留足够的日志证据，以便中断后完成提交或回滚；
7. 重新打开并验证已提交修订，然后才能报告成功。

应用程序在启动时检测未完成的事务，不会继续写入状态不明确的工作区。磁盘空间耗尽、文件锁定、权限变化、进程终止、外部编辑、防病毒软件干扰或同步服务干扰，都会产生结构化恢复状态。

## 外部编辑和冲突

外部编辑必须与基础修订比较。双方均有变化且共同基线可以验证时，Weftext 可以提供由 Core 负责且不依赖 Git 的比较与三方合并；根据具体情况，用户可以保留本地版本、外部版本或两者。默认采用最后写入者覆盖不可接受。输入、结构比较、身份保护、合并草稿和受修订约束的应用流程，以 [`22-document-history-comparison-and-backup-repositories.md`](22-document-history-comparison-and-backup-repositories.zh-CN.md) 为准。

云同步冲突副本、远程删除与本地编辑冲突、节点身份冲突，以及重命名或移动冲突，都进入冲突中心。冲突解决本身是一项事务，不能被自动保存覆盖。

## 设备本地草稿

Desktop 的崩溃恢复草稿是版本化的设备本地记录，不属于工作区内容、同步状态、事务日志或备份。v2 记录绑定工作区实例、节点 ID、规范文档配置、精确基础修订、源文本和更新时间。记录通过本次请求专用的临时文件写入，经刷新、原子替换和重新打开验证。替换中断后，最后一份已经验证的记录仍可恢复；损坏或不受支持的记录会显示为恢复问题，不会被静默删除或重新生成。

草稿自动保存绝不写入所选工作区。重新打开文档时，规范配置和基础修订仍与文档匹配的草稿可以恢复到编辑器。若磁盘修订已变化，应用程序保留两个版本，并要求用户明确比较和解决后才能执行 Core 提交。文档提交验证成功或用户明确丢弃草稿后，对应草稿才会删除。草稿保留与清理属于设备本地策略，不改变节点身份。

Desktop 在批准可能修改现有节点的批量导入前，必须由原生边界盘点完整的设备草稿范围。任何与操作范围相交的草稿，以及不可读取或损坏的草稿记录，都会阻止预检，直到用户提交、明确丢弃或解决相关草稿。CLI 进程无法推断另一台设备的私有草稿存储；执行批量变更前，操作者必须关闭或协调其他客户端。

## 最近文档历史

Recent History 是位于操作系统 Weftext 应用数据目录中的独立、有界、设备本地精确源文本存储。它不属于工作区、可移植同步内容、草稿存储、事务日志、回收站或正式备份仓库。成功提交时，它按照规范 22 的版本化内容寻址存储，记录经过验证的提交前与提交后规范文档源。该功能默认启用并标记为 `This device only`；用户可以通过明确的保留与隐私设置清除或禁用它。

工作区提交的成败与 Recent History 捕获相互独立。提交成功后若历史发布失败，提交结果仍为成功，但必须附带结构化警告并显示版本缺口。Recent History v1 不承诺完整恢复资源、批注、表格记录、Template 状态、忽略或非受管字节、回收站、子树或 Server 状态。普通工作区同步不会把这些历史发送到另一台设备。比较或恢复单个源文本版本仍须使用受修订约束的 Core 操作，不能直接从历史目录复制文件。

## 回收站和恢复

普通删除只写入 [`../architecture/17-workspace-trash-item-store.md`](../architecture/17-workspace-trash-item-store.zh-CN.md) 定义的封闭工作区回收站项目存储；该存储是回收站状态的权威源。一个被删除的节点根成为一个项目，并包含其完整且未修改的子树。每个可独立恢复的资源各自成为一个项目，同一批次的项目共享一个操作 ID。任何变更发生前，计划必须绑定工作区修订、生成的项目 ID、精确源清单、清单字节、载荷摘要和禁止覆盖的目标。崩溃或外部编辑不能产生被报告为成功的不完整批次，也不能导致项目 ID 复用、项目覆盖或来源猜测。

恢复会保留永久节点身份和原始资源字节，并通过 UUID 解析原父节点或所有者。如果该 UUID 仍处于活动状态且目标位置空闲，用户可以恢复到原位置。如果父节点或所有者也拥有完整回收站项目，显式预览可以原子恢复所需父链和所选项目。来源缺失或迁移项目标记为 `originStatus: unknown` 时，该项目会留在回收站，直到用户明确选择一个现有目标。旧路径和名称只用于显示，不能证明身份。Weftext 不会创建同名父节点；精确冲突或仅大小写不同的冲突都必须通过显式重命名或选择其他目标解决，绝不覆盖。

Template 契约把回收站载荷视为封闭、非活动且逐字节精确的内容，而不是活动的普通源。普通回收站操作拒绝当前配置的 Template Library 根；将其移入回收站时，必须通过一笔经过审阅的组合事务清除或重新绑定 `template_library_root`。Template Root/Part 恢复到活动 Library 下已经证明的原角色时，可以保留精确字节。恢复到其他位置时，必须执行显式角色转换：物化或删除活动 slot，并移除规范配置与伴随文件；无法安全转换时阻止恢复。只有组合操作的精确回滚回执或新的配置计划可以改变 Library 绑定，恢复过程本身绝不猜测。

格式错误、不完整、重复、被篡改或发生同步冲突的项目进入协调状态，并保留全部证据。永久删除是一项独立、受修订约束且要求更高权限的计划，必须明确确认项目、摘要和字节总数。保留与清理策略必须可见、可测试，并调用同一操作边界。回收站是随同步传递的删除状态，不是备份。

多维表格记录使用独立的表内“已删除记录”生命周期，因为记录不是节点或普通资源，不能隐式扩展封闭的工作区回收站 v1 清单。普通删除会把精确记录从 `active` 修补为 `trashed`，保留原值，并绑定新操作 ID 和明确的 UTC 删除时间。恢复会把同一记录重新变为活动状态。永久删除选定的已删除记录文件，是一项独立的摘要/字节绑定高权限事务；它绝不会通过猜测删除被引用资源。删除整个表格节点仍使用普通工作区回收站，并保留完整规范文档、伴随文件、活动与已删除记录存储、资源、批注、后代和身份。

## 备份

同步不是备份。新工作区默认没有正式备份目标。Recent History、草稿、回收站、事务证据、同一磁盘上的第二个目录或同步服务，都不会改变 `Backup: Not configured` 状态。备份设置不能阻塞工作区使用；在用户选择本地、外接设备、网络、受支持远程后端或经授权的 Server 管理目标之前，界面必须如实显示未配置状态。

备份契约要求：

- 把版本化快照写入用户选择的本地、外接设备、已挂载/网络位置、Server 管理位置或明确支持的远程目标；
- 保留策略和受保护的恢复点；
- 内容和元数据完整性验证；
- 单节点、子树和全工作区恢复；
- 适用时服务器控制平面备份；
- 恢复前执行无写入清单预演；
- 恢复到备用位置；
- 定期自动执行恢复演练并记录结果。

同步服务的版本历史不能作为唯一备份。只有在干净位置打开恢复结果、完成盘点，并与预期身份和内容比较后，复制结果才能作为验收证据。

备份配置在工作区之外记录目标与执行器。执行模式为“此设备”“Weftext Server”或“只读”。直接使用文件系统、网络位置或云同步目录的仓库只能有一个写入方；其他设备以只读方式挂载，或使用独立仓库。托管后端只有通过一个串行执行写入的服务端执行器，才能接受多个请求方。文件或对象仓库使用不可变 SHA-256 对象、完整且不可变的快照清单和受保护标记；Git 和数据库都不是权威源。v1 布局、至少保留 24 个小时点、30 个日点和 12 个月点、写入方接管、最后发布清单、垃圾回收、健康状态以及比较与恢复绑定，以规范 22 为准。

### 内容边界备份不变量

“忽略”表示从 Weftext 产品发现中排除，不表示从备份中排除。被称为备份的完整工作区快照或导出，必须通过专用且会安全拒绝不确定状态的备份盘点遍历物理工作区。盘点范围包括 `.weftext-rules`、根规范文档及其精确 `weftext.template_library_root` 配置、受管内容、每个有效的 `weftext.template.json`、每个有效的 `weftext.table.json` 与完整 `weftext.records` 目录、活动记录和表内已删除记录、可见非受管内容、忽略内容，以及每个 `.weftext-trash/_weftext.items` 目录、清单、空目录和载荷字节。

Template 与表格文档、角色伴随文件或存储、资源、批注，以及包含 Template 或表格的回收站载荷，均属于物理权威；普通语义投影是否排除它们不改变这一点。内容规则或产品发现过滤器不能排除回收站项目和表格记录权威。备份盘点必须拒绝或明确诊断链接、junction/reparse point、路径越界、不可读条目、活动事务状态不明确、无效的 Template 角色/伴随文件/配置关系、无效的表格伴随文件/记录/资源关系，以及无效的清单/载荷关系。

无写入预演可以把条目标识为忽略项、表格记录或完整回收站项目，但默认备份集不能静默遗漏其字节。用户要求的排除策略是一项独立、显式的备份选项，必须显示在预览和回执中；它不改变工作区分类。排除任何必需配置、伴随文件、记录或项目字节后，不得声称对应 Template Library、多维表格或回收站状态可以恢复。

当前托管内容边界没有备份命令。普通复制辅助功能不能称为能够识别内容边界的备份。正式备份必须通过干净恢复验收：恢复需要证明忽略文件、非受管字节、活动与已移入回收站的节点 UUID、精确 Template Library 根配置、每个 Template Root/Part 的文档/伴随文件/资源/批注、有效回收站清单与载荷、规则文件，以及与工作区分离的 Server 控制平面，均按照记录的策略得到处理。

启用 Template 界面前，恢复流程还必须重新盘点并验证相同的 Library/Root/Part 角色，不能根据路径猜测。恢复写入具有独立且经过审阅的边界；“忽略”“回收站”、`originStatus: unknown` 或伴随文件都不能被解释为覆盖既有目标或静默绑定 Template 配置的许可。

### 身份与会话控制平面

身份与会话控制平面是一个与托管工作区分离、由用户明确配置的目录。它包含本地 Owner 凭证摘要、会话与撤销状态、最少量安全事件，以及初始化前的一次性引导文件。它属于运行安全状态，不是可移植工作区内容，也不是文档、节点、资源、搜索、批注或修订的权威源。因此，只复制或同步工作区不会复制 Server 身份和活动会话。

当前身份与会话边界没有备份命令或恢复演练。运维人员必须把工作区和控制平面作为两个独立受保护的备份集，并在手动复制数据库前停止 Server；WAL 仍活动时只复制 SQLite 主文件，不构成受支持的快照。产品验收要求恢复流程在开放网络服务前，把可移植内容和控制平面状态恢复到彼此不相交的位置并完成完整性检查；根据已记录策略使会话失效或明确保留会话；保护控制平面文件权限；并证明可以在干净实例中恢复。一次性引导密钥被使用后不得进入备份，也绝不能导出到诊断包。

## 格式版本控制

每个持久的 Weftext 格式都有一个明确的版本。打开受支持的旧版本需要进行清单、兼容性检查、备份/恢复点、试运行、版本化事务和验证。中断的版本升级可以继续或回滚。对于不支持的格式，应用程序只读打开或安全拒绝打开；它永远不会猜测工作区语言，也不会静默删除字段。

旧版直接回收站布局 `.weftext-trash/<name>` 只通过明确的迁移计划接受。计划会盘点每个旧版条目并绑定摘要，生成新的临时回收站项目 ID，通过可恢复日志安装 `_weftext.trash-item.json` 和未修改载荷，并且只在验证后删除旧条目。旧路径或基础名称不能证明父节点/所有者 UUID。没有旧事务绑定的来源证据时，清单使用 `originStatus: unknown`，恢复必须由用户明确选择现有目标。迁移不能同时把旧版直接条目和 `_weftext.items` 作为两个权威源；发生冲突、内容格式错误、部分同步或字节不可读时会阻止迁移，并保留从外部快照恢复的可能。

## 诊断与安全模式

Desktop、WebUI、Server 和 CLI 根据各自能力提供安全模式、事务恢复、索引重建、工作区验证、日志和脱敏诊断包。诊断默认排除文档正文，且不得包含秘密、会话令牌、完整绝对路径或用户无权访问的节点元数据。用户可以在导出前检查诊断包清单。

Desktop 安全模式必须在原生且面向 Core 的事务边界执行，不能只依靠禁用界面控件。安全模式拒绝文档提交和工作区结构提交，同时允许读取、验证、诊断、恢复比较和设备本地草稿持久化。退出安全模式是一项明确的本地设置变更，本身不会提交草稿。

## 安全基线

- 节点 ID 是身份，而不是凭证。
- 服务器写入操作需要经过身份验证的会话和授权。
- 秘密保留在操作系统或 Server 密钥存储中，不得写入工作区文件、日志、URL 或诊断。
- 路径仅限于选定的工作区或本次请求专用的暂存区域。选定根路径只解析一次，并固定为已存在、规范且自身不是链接的目录，因此其祖先中的平台路径别名不会成为工作区权威；在单独规范明确支持前，选定根本身或其下任何位置出现符号链接或 reparse point 都必须安全拒绝。
- 批量、破坏性、跨工作区、权限变更和明文外发操作需要预览与确认。
- 依赖项、安装程序、更新、容器映像和发布工件需要来源证明、许可证声明、SBOM、漏洞审查和回滚说明。

本契约不覆盖已解锁设备上的管理员或内核级恶意软件、用户明确授权的数据外传、屏幕捕获，或全部有效加密凭据丢失。任何加密工作区功能都需要单独审查的设计和独立恢复路径。
