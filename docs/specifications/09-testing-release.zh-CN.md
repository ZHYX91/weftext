# 测试与发布证据

状态：当前架构契约。

## 证据层

质量声明分为：

- Core 源代码测试；
- 真实文件系统集成测试；
- CLI 测试；
- 打包的桌面测试；
- 支持的浏览器 WebUI 测试；
- 打包服务器/容器部署测试；
- 多客户端协作测试；
- 备份和灾难恢复演习；
- 手动日常使用和可访问性验收。

通过一层并不能替代另一层。构建或单元测试无法确定 GUI 可用性、浏览器兼容性、部署安全性、协作融合或可恢复性。

## Core和存储矩阵

目标格式测试涵盖所需标记、同名 AsciiDoc 根/子节点、唯一的顶层 `weftext` 映射、所有浅层元数据封装字段（包括仅根节点的 `template_library_root`）、无效/重复身份、按角色保留的命名、按规则分类的松散文件/目录/资源、非受管子树屏障、被忽略内容、缺失文档、重命名/移动后的身份保留、复制后的重新设键、父级派生、排序、资源（包括节点拥有的 `.md` 文件）、`weftext.annotations.json`、受角色约束的 `weftext.template.json`、封闭的 `.weftext-trash/_weftext.items` 类、封闭的任务节点头部规范配置、Chrono 路径和索引重建。内容规则测试保留有序匹配、glob/转义/大小写/路径安全、规范文档冲突、字节保留的节点拥有 Markdown 附件与明确分类的无主非受管 Markdown 之间的区别、对被忽略内容的非披露、保留回收站存储不可分类性，以及符号链接和 Windows junction/reparse 的安全拒绝行为。资源导入测试接受 `.md`，同时仍拒绝规范文档、保留的伴随文件/存储、不安全名称、过期修订和覆盖。直接子级回收站条目、尾随 `task:[...]` 出现和已废弃的 Query 语法仍是私有转换测试，而非受管运行时的正向夹具。

链接测试涵盖显式链接源顺序、规范名称、`weftext.aliases`、精确和规范化匹配、Unicode 文本、最长匹配优先排序、包含重叠、不明确的别名、重复提及、陈旧修订、排除的源区域、索引重建和预览/提交行为。对于同一出现的 `ABC` 和重叠的 `AB` 候选，`ABC` 是主要候选，链接它会从当前候选集中删除 `AB` 的出现。

随着平台变得受支持，路径和文件系统测试涵盖 Windows、macOS 和 Linux 规则：Unicode 规范化、仅区分大小写重命名、保留名称、长路径、文件锁、符号链接/重解析点、占位符、网络挂载和外部移动。

## 数据安全故障

故障注入涵盖临时文件创建、部分写入、刷新失败、原子替换、多文件准备/提交/清理、磁盘写满、进程终止、过期修订、外部修改、事务恢复、回收站恢复、冲突保留和备份恢复。设备本地草稿测试涵盖重启后的持久性、已验证替换、保留最后一个良好草稿的中断暂存、损坏记录的可见性、过期的外部修订、显式丢弃、提交后清理，以及安全模式下不修改工作区的草稿持久化。测试断言每个目标要么是完整旧修订，要么是完整新修订，并且会保留含糊证据，而不是静默清理。

回收站验收矩阵是每个声称支持的调用方的发布阻塞项。Core/真实文件系统案例涵盖：

- 精确和大小写折叠的同名节点/资源冲突，无需覆盖、重复删除/恢复/重放以及项目 ID 占用/冲突；
- 已删除子树的一项、未更改的后代名称/UUID/注释/资源以及共享一批 `operationId` 的单独资源项；
- 删除 B 时 A 仍位于 B 内、先删除 A 后删除 B、先恢复 B 后恢复 A，以及显式的原子父链恢复；
- 活动、已移入回收站、缺失和 `originStatus: unknown` 的父级/所有者；不得按名称捏造父级，并且目标/重命名要求必须明确；
- 外部清单/载荷修改、目录/清单 ID 不匹配、重复的永久 UUID、额外/缺失的载荷条目、非 UTF-8/链接/reparse 路径，以及精确/大小写折叠的同步冲突副本；
- 过时的修订、每次准备/应用/发布/验证崩溃边界、全有或全无的资源批次、幂等恢复以及模糊证据的保存；
- 拒绝删除非受管/被忽略的边界子树，以及原始非受管、被忽略、规范文档、伴随文件、事务或保留存储资源；
- 直接布局转换清点、来源未知的转换、冲突/阻塞行为、迁移恢复/回滚，以及拒绝保留两种运行时权威；
- 资源原始/备用所有者恢复、显式重命名、不覆盖、字节/摘要相等以及节点/资源项备份往返；和
- 独立的、更高权限的永久删除预览/确认/提交路径；该路径不能处理活动节点、畸形项目或未经审查的字节。

工作区修订测试分别改动一个清单字节、载荷字节、空载荷目录和项目路径名，并要求产生新修订。同步测试证明，部分/重复/冲突项目绝不会显示为有效活动节点或可恢复项目，也绝不会被隐藏为非受管/被忽略内容。完整备份和干净演练测试证明每一个项目存储字节和空目录均存在，并且恢复后其清单关系得到验证。

## 用户界面和可访问性

Desktop 和 WebUI 对节点操作、原生待办项切换、清单到任务节点提升、任务节点字段/链接、规范 Query、Template Library/Designer/实例化、AsciiDoc 编辑器视图、搜索、Chrono、注释、冲突解决、授权和恢复运行相同的行为案例。草稿、安全模式、精确 UTF-8 编辑、CJK/RTL/IME、大文档、导航和过期修订情形仍须跨界面覆盖。实时规范配置案例证明，浏览器接收规范 Core AsciiDoc 范围/计划时不拥有第二个解析器或 Template 编译器。源案例覆盖无效 `weftext` 元数据封装的打开失败行为、带显式切换的默认折叠、选择驱动的展开，以及保留无关行尾的精确拼接。Write/Read 隐藏操作性 YAML；Properties 将文档头属性与节点控件分开暴露；Source 显示精确字节。注释测试包括重叠标记、并发线程、参与者状态、孤立/重新锚定、建议、提升时的重新锚定/阻塞、Template 设计注释省略、Server 序列化/非披露以及崩溃安全的伴随文件事务。

Desktop、CLI、Server API 和 WebUI 使用同一个已签入的混合内容夹具，并断言相同的类别、相对/父级定位符、可选 UUID/所有者字段、没有规范文档重复、派生图标以及被忽略内容的非披露。结构和资源测试证明 Core 不能进入、覆盖或移动已分类边界。搜索和索引测试证明，非受管和被忽略的 Markdown 绝不会成为节点搜索或链接证据。即使产品清单排除被忽略字节，后续备份验收也必须恢复它们。共享导航案例针对 Desktop 和 Server WebUI 投影运行。它们验证 Explorer Hierarchy 仅包含受管节点；Contents 准确显示即时可见的 Core 子项；规范节点 AsciiDoc 不重复；被忽略/未授权内容不影响行、计数、面包屑、搜索、最近项、事件或可访问名称；非受管目录可浏览而不虚构选项卡；非受管文件/资源不暴露任何仅节点操作。现有的排序、焦点、键盘、屏幕阅读器、缩放、高对比度、RTL、长名称、窄宽度和 10,001 节点性能案例仍然是必需项。

节点操作语义矩阵是跨Core、桌面、本地/托管 WebUI、CLI 和服务器 DTO 的发布阻塞。它证明：

- 第二窗格获得焦点时，“在当前节点下创建”、重命名/移动/复制/移至回收站以及当前节点 Chrono 均捕获该窗格的 UUID，而非主窗格选择；
- 当预览或提交前窗格焦点、选择、导航、刷新、虚拟化或行顺序改变时，从明确的 Hierarchy、Contents、搜索、Chrono、回收站或资源行打开的上下文操作仍绑定到已捕获的 UUID/项目 ID；
- 重命名、移动、复制、分支移至回收站、项目恢复、将拥有的资源移至回收站和永久删除项目是独立的注册表项与对话框，只包含相关字段；重命名不是“带名称的移动”，Trash 没有目标位置控件，永久删除具有独立的样式、授权和二次确认；
- 每个预览均携带由 Core 派生、字节精确的 `scopeSummary` 值，涵盖根、后代、资源、注释伴随文件、字节、受影响/重写文档、身份策略、项目计数和操作 ID；每个调用方传输相同的封闭字段，不由前端重新计数；
- 重命名/移动/回收站/恢复保留永久 UUID，复制会为每个复制节点重新设键并暴露完整映射，且菜单项和确认对话框会在提交前说明该差异；
- 脏的源根、脏后代、脏资源所有者或已保留的回收站身份，以及受精确文档/链接重写影响的脏文档，都会在生成可执行预览前被草稿门控拦截；保存或显式丢弃后重新预览可成功，无关的脏节点仍不受阻；
- 预览后所需节点变脏时，提交会再次捕获且不写入；复制绝不会复制被脏源草稿遮蔽的旧磁盘版本；
- 一个具有多个后代的分支生成、计数并呈现一个 `trashItemId`；资源批次则以一个共享 `operationId` 为每个可独立恢复的文件呈现一项；
- 资源删除仅接受经 Core 证明的节点拥有常规文件，不能将非受管/被忽略内容、规范文档、注释伴随文件、保留存储字节、链接或 reparse 点重新解释为资源；以及
- 可访问名称和描述将节点分支定义为其同名文档、后代、拥有资源和注释伴随文件；目标排除须明确说明仍对完整分支执行操作，且渲染后的可访问 UI 中没有原始操作 ID。

该矩阵包括真实文件系统上的预览/提交竞争和过期修订案例、共享 bridge/API 序列化夹具、仅键盘和屏幕阅读器断言，以及打包的 Desktop/浏览器工作流。前端单元测试或帮助卡不能满足操作目标、草稿门控、范围证据或事务要求。

Explorer 验收要求覆盖 Core 投影、调用方一致性、React 交互、Server 薄客户端和 10,001 行窗口化测试。真实 Windows Desktop 与真实回环 Server WebUI 检查涵盖信息披露与打开、无需替换编辑器的非受管浏览、分屏跟随、键盘焦点移动、稳定的自然内容顺序、长文本/混合方向文本、窄 Explorer 布局和明确的高对比度主题。这些检查仅是交互证据：实体屏幕阅读器、完整 IME 组合会话、浏览器缩放矩阵和操作系统减少动态效果会话仍是手动验收工作，不得从自动化语义或 CSS 覆盖中推断。

打包 Desktop 验收要求自动化案例覆盖结构化 Write 的精确源/frontmatter 连续性、Core 提供的语义装饰、仅限 Core 表格范围的混合行尾表格编辑、每工作区仅 UUID 的选项卡/历史/书签/最近项/分屏恢复、避免重复选项卡、可移植图标修订验证，以及外部搜索索引的重建/增量/删除/回收站行为。后端故障注入必须证明，文档或结构提交后的派生索引刷新失败时，提交仍报告成功，并给出不会诱导重复写入的结构化警告。路径测试覆盖词法 `..`、相对路径、尚未创建的目标、符号链接，以及受支持时的 Windows junction/reparse 别名。Live Desktop 测试恢复活动选项卡 UUID，而非仅恢复演示用 localStorage；它拒绝自动显示中过期的第二窗格恢复草稿，并执行显式修订检查的第二窗格预览/提交/冲突路径。这些是工程门，而不是实体 IME、屏幕阅读器、键盘、显示模式或打包生命周期已获手动验收的证据。规范配置 UI 案例覆盖原生 H1–H6 输出、无无效元素的可访问 H7–H9 角色、真实大纲级别、紧凑 H1–H9 转换和精确 AsciiDoc 源连续性。引文案例覆盖精确深度 1–9 及大于 9、受保护标记、Core 文本/源范围、增加/减少操作，以及一致的嵌套 Write/Read/Source 呈现。

### 结构化编辑器验收

Desktop 和 WebUI 必须证明顶部工具栏、选择浮层、斜杠菜单、上下文菜单、快捷键和命令面板调用相同的语义注册表项及 Core `DocumentFormatPlan` 结果。案例覆盖独立的文档标题/副标题界面、紧凑 H1–H9 选择器、不可用操作原因、仅键盘操作、屏幕阅读器状态、窄工具栏溢出、IME 组合、CJK/RTL 选择、混合行尾、过期修订和受保护/畸形源。任何案例都不得经由渲染 HTML 往返，也不得重新序列化无关 AsciiDoc。

目标功能区矩阵还证明六个固定的 Home/Insert/Data/References/Review/View 选项卡、可访问的折叠/溢出行为、确定性的上下文 Table/Image/Dynamic View/Task/Template Design 选项卡，以及选择和 IME 组合期间的稳定焦点。它证明 Data（而非 Collection）是总括标签；多维表创建与规范 Query 动态视图插入仍然不同；Task 快捷操作和右侧 Inspector 详情共享一个操作/能力源；References 与 Review 保持分离，且不发明 Paper 节点或模式。每条功能区、Inspector、上下文菜单、斜杠、快捷键、浮层和命令面板路径都必须生成相同的强类型操作证据。

独立 Desktop 验收仅打开明确授予的 `.adoc` 和 `.asciidoc` 文件，并证明 Markdown、`.asc`、目录和从工作区非受管内容逃逸的尝试均被拒绝。夹具证明不会扫描父级/同级项，不会采用标记，不会创建 UUID、元数据封装或伴随文件，也不会建立工作区索引；通用 AsciiDoc 保持精确，而 Weftext 专有构造会被保留但不可用。六个功能区选项卡保持其位置，并暴露指定的启用/禁用组及原因；Data 被禁用，工作区上下文选项卡不会出现，也没有纯前端回退实现已禁用能力。保存案例覆盖精确摘要/文件身份、原子替换、权限保留、外部修改/替换/删除、链接/reparse 点、Compare/Save As、无同级文件的崩溃安全设备草稿/历史、释放授权，以及显式的全新 UUID Add to workspace 导入。格式刷案例证明单次使用、锁定重复、取消、重复上次操作和设备本地状态。描述符夹具涵盖兼容的行内、段落、列表、引文和标题应用，以及混合种类拒绝。负向夹具证明内容、链接目标/节点 UUID、锚点/ID、引文/注释正文、注释、任务语义、Query 表达式、Template 槽位和资源路径均不会被捕获或应用。计划所列精确范围以外的源保持字节不变。

表格案例覆盖零至多个连续前导列标题行、连续前导行标题列、二者交集、清除/重新应用标题区域，以及拒绝不连续或非前导区域。合并/拆分案例覆盖矩形选择、仅限一张表格、现有跨度边界、不支持的嵌套单元格、空内容和单一内容的直接合并、多个内容时按行优先精确组合的确认、确定性拆分为前导内容单元格和空单元格、精确 Undo 恢复、标题/锚点、无障碍表头关联、混合 Unicode 和通用处理器可读降级。无效操作在所有界面中均以相同的结构化 Core 原因禁用。

标题案例覆盖 `heading_only` 和 `preserve_subtree`、H1–H9 界限、后代级别同步调整、被拒绝的层级变更、转换为段落时的重新确定父级预览、大纲/路径更新、受保护源、显式锚点、链接、注释和应用后的源选择。文档标题始终在正文标题操作之外，且不会将前言/仅标题上下文伪造为 H1。

## 服务器和协作

## AI 智能体集成

### 规范 Query 与表达式验收

规范 Query 的发布证据是一套由 Core 共享的一致性矩阵，而不是各客户端分别维护的解析器快照。它覆盖：

- 在受保护范围之外精确识别 `[.weftext-query,version=1,view=...]`；带普通 AsciiDoc 角色的文字块会降级为普通文字块；运行时完全不包含私有迁移解析器；
- 强制 `from`、`scope`、`where`、`select`、`order by` 和 `limit` 的子句顺序，只有 `group by` 可选；接受任意合法的显式别名；拒绝别名遮蔽、`row.*` 和裸字段；
- 分离数据源、版本和视图：只有正文中的 `from` 选择 `nodes`、`tasks`、`headings` 或 `templates`，`view` 只改变呈现；不支持的版本会安全拒绝；模板角色清单尚不可用时，`from templates` 返回精确的 `domain_unavailable`，而不是空结果或回退结果行；
- 覆盖 `weftext.expr.v1` 的全部类型、比较/布尔/null/`in` 运算符和纯函数；小数严格限制为 34 位有效数字和 18 位小数，不接受指数或舍入；时长只接受 `P1D..P36500D`；null 比较按普通错误处理，同时固定可空成员判断；禁止访问文件系统、网络、环境变量、环境时钟、eval 或动态加载；
- 覆盖 `context.today + P14D` 和显式 `context.now/timezone/locale`，并证明主机或浏览器的时钟与区域设置不会改变已审阅的求值结果；
- 区分作者可空的 `document.title`、`document.subtitle` 与派生的 `document.display_title`；支持 Unicode `properties["名称"]`；并用精确诊断证明 `this.title` 和 `this.subtitle` 不存在；
- 文档只有标题或 Query 位于前言时，`this.heading` 为 null；覆盖嵌套 H1/H2 的章节归属、作为文档标题的 `= Title`、作为 H1–H9 的 `==` 到 `==========`、H1 的 `parent=null`，以及在 null 上调用 `section(this.heading)` 或访问标题成员时返回精确 `missing_heading_context`；
- `from headings as heading` 行包含标题、级别、锚点、父级、路径以及获准公开的所属节点/文档，并与词法上下文 `this.heading` 明确区分；
- 在焦点、选项卡、选择、导航、URL、虚拟化和请求默认值变化时，词法 `this.node/document/heading/query` 保持稳定；块标题可以为 null；Saved Query 在获得显式且不可变的嵌入上下文前返回 `missing_context`；
- 覆盖任务带标签联合的可空性、非 null `task.title`、稳定排序和确定性决胜规则、Unicode/CJK/RTL/CRLF 源、格式错误或受保护输入，以及精确的 16-KiB/2,048-token/256-node/32-depth/64-item-or-field/4-KiB-string/65,536-step/1,000-row/4-MiB 上限；超限不返回部分结果，所有已交付调用方获得相同结果和操作；以及
- 在解析强类型作用域、生成行或表达式诊断、分组、计数、排序、投影、限制、建议、导出或缓存之前先执行 ACL 与信息不披露；隐藏目标与缺失目标不可区分。

### 多维表格与动态视图验收

多维表格的发布证据是一套由 Core、Desktop、已公开的 CLI、Server 和 WebUI 共享的持久格式与事务矩阵。它覆盖封闭的 `weftext.table/v1` 伴随文件、分片的 `weftext.table-record/v1` 存储、每个非节点记录一个 JSON 文件、文件名/分片/解码 ID 绑定、全部字段/值/关系/资源类型、表内软删除、派生公式/视图/索引、ACL 信息不披露、部分同步协调、大表增量处理、完整物理备份与恢复，以及在没有数据库权威源时干净重建索引。

### 文档历史、比较与备份仓库验收

一个版本不能仅因写入副本就宣称具有 Version History 或正式备份。证据必须证明：`not_configured` 状态不创建隐式仓库；Recent History 如实标注 `This device only`；历史条目和对象采用精确封闭格式并有保留上限；历史捕获失败不会把已经成功的工作区提交改成失败；普通工作区同步不携带历史；草稿、回收站、事务日志、同步历史和派生索引都不会被冒充为备份。

比较证据覆盖当前版本、近期历史、备份、草稿、外部文件和其他节点之间的双向比较，以及带显式基准的三方合并。它验证 AsciiDoc 文档头、章节、列表、表格、受保护范围和扩展结构，精确的行/词回退，CJK/RTL 与不同换行符，系统身份差异折叠和 `weftext.id` 保护，资源/批注摘要，确定性限制，ACL 信息不披露，以及运行时和仓库对 Git 的零依赖。合并与历史恢复会绑定精确输入、变更块、拟生成源文本、当前修订和草稿；拒绝过期、重放、规范配置或受保护范围冲突；只通过恢复机制提交一次；创建新历史事件并保留当前身份。完整格式与矩阵以 [`22-document-history-comparison-and-backup-repositories.md`](22-document-history-comparison-and-backup-repositories.zh-CN.md) 为准。

### 模板库验收

仅加入夹具或 Designer 模型不能证明模板契约已经交付。完整验收要求：

- `weftext.template.json` 只在 Template Root 上有效；规范配置与版本组成固定配对；Root/Part 作用域只使用 UUID，并在重命名或移动后保持稳定；重复键、未知字段、schema、类型和边界错误会被拒绝；精确源文本得到保留；保留文件名出现在 Library、Part、普通节点或其他位置时返回诊断；
- 检查 `slot:name[]` 行内形式与 `slot::name[]` 块形式的种类、位置和受保护范围；同一个 `(scope UUID,name)` 声明用一个值替换全部出现位置；没有出现位置时报告未使用诊断；分别验证 text、attribute、validated-inline、validated-block 和 node-name；不执行 raw、if、for 或 Query；独立编写在普通 `.adoc` 中的 slot 语法，在 Weftext 和通用 AsciiDoc 下都保持无语义；
- 移入、移出模板角色位置以及在这些位置之间移动，均作为带预览的转换事务，具有精确的角色/所有者/伴随文件/源变更、退出时的安全实例化/删除、脏草稿门控、过期拒绝、恢复、带外修复诊断，以及不允许仅按路径降级；
- 每个生成节点使用一个新 UUID，每个 Root/Part 只有一个名称权威；绑定时禁止根调用方覆盖；完整重写由旧到新的内部 `node:` 链接；保留已授权的外部链接；使用可移植且无冲突的解析名称；精确复制资源；默认省略设计批注；拒绝任何残留的 slot、profile 或伴随文件；
- Template Designer 的 Design/Preview/Source 可以往返；提供 slot 标签、把选择内容转换为参数、通过斜杠菜单插入行内或块 slot、参数面板和事务化重命名；使用样例输入预览完整子树时零写入；保留精确源文本并清楚显示 Part 归属；
