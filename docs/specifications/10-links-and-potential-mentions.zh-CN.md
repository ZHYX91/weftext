# 链接与潜在提及

本规范定义候选项发现和确定性排序。规范的受管节点链接语法是 UUID `node:` 宏，定义见 [`15-weftext-asciidoc-profile.md`](15-weftext-asciidoc-profile.zh-CN.md)；只有在保持下述契约时，潜在提及匹配和批量链接动作才可用。

## 术语与权威

出链是节点文档中已存在的显式链接。潜在提及是尚未链接、可能通过另一节点的规范名称或用户写下的别名引用该节点的人工文本。

受管节点身份链接采用 `node:<uuid>[<authored label>]`。UUID 是解析权威，可选标签为作者写下的展示文本。由待办项提升为任务节点产生的链接也遵循同一规则；它不是任务状态镜像或第二个任务出现位置。

规范名称由节点目录基名派生。替代名称来自运行元数据封装中的 `weftext.aliases`。别名影响 Weftext 查找，但不是身份；改变别名绝不改变 `weftext.id`。

出链、反向链接、别名和潜在提及索引都是派生数据。它们可丢弃，并从规范 AsciiDoc 和节点身份重建。发现过程绝不自行插入或重写链接。

只有由 Core 分类的受管节点 AsciiDoc 参与。包括 Markdown 和松散 AsciiDoc 在内的可见非受管文件既不是节点链接来源也不是目标，结构事务中绝不重写；忽略内容既不检查也不披露。

## 出链顺序

显式出链出现位置按源文本顺序保留。UI 可对重复目标分组并显示计数，但保留出现位置，且以首次出现作为该组的默认位置。节点移动或重命名不得仅因路径改变而重新排序链接。

## 潜在提及排序

候选项按以下确定性元组排序：

1. 匹配文本长度，降序，按规范化 Unicode 标量序列而非 UTF-8 字节测量；
2. 匹配质量：精确规范名称、精确别名、规范化规范名称、再到规范化别名；
3. 源文本起始位置，升序；
4. 目标规范名称的自然顺序；
5. 目标节点 ID，作为稳定的最终排序依据。

长度优先于匹配种类。若同一源文本包含重叠的 `ABC` 和 `AB` 候选，`ABC` 必须先列出，即使 `ABC` 是别名且 `AB` 是另一节点的规范名称。

## 重叠与歧义

所有有效重叠候选均可检查，但最长候选为主候选。完全包含于主候选范围内的较短候选，会折叠在该次出现的其他候选之下。为主范围创建链接后，当前修订中该次出现的重叠候选被移除。

若一个匹配拼写解析到多个节点，UI 应展示一个含所有目标的歧义候选组。它不得按路径、最近使用或索引迭代顺序挑选目标。自动或批量链接会跳过歧义，除非用户在预览中解决它。

## 动作与修订

创建、移除或重写链接是具有基础修订、预览、精确源范围、选定目标 ID 和确定性补丁的 Core 文档动作。提交前，该动作针对当前文档和别名索引重新验证候选。候选过期、移动、删除、新增歧义或不再匹配时，应返回结构化冲突，而非编辑附近字符串。

批量创建链接绝不是隐式索引副作用。提交前必须展示纳入的出现位置、重叠、歧义、排除项、目标 ID 和精确 AsciiDoc 变更。

## 展示排除项

保留的 `weftext` 元数据封装不是人工文档内容，绝不参与字数、搜索摘要、别名或潜在提及。已有显式链接的展示文本不得就同一范围再次报告为未链接提及。

当 `node:` 目标带有有效任务节点配置时，Weftext 可以以当前状态、优先级或截止日期丰富解析后的链接展示。这些值读取自已授权目标投影，绝不作为缓存权威写回引用源文本。目标不可用、隐藏或无效时，应按普通不披露链接行为降级，而不暴露任务诊断或过期元数据。

启用批量创建前，初始语法决定必须分别定义匹配边界以及对代码围栏、行内代码、原始 HTML、标题、表格和极短名称的处理。上述尚未决定的选择不改变已接受的最长匹配优先规则。
