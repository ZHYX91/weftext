# 文档修订与编辑操作

本规范定义单文档操作边界；多文件操作使用 [`13-workspace-transactions.md`](13-workspace-transactions.zh-CN.md) 中的工作区事务边界。

## 精确源权威

文档修订是同名 `X/X.adoc` 规范节点文档中精确 UTF-8 字节的小写 SHA-256 摘要。行尾、字节序、YAML 拼写、注释、标量样式、空行和格式空白均参与计算。Weftext 在哈希或保存前不作规范化。必需的 `.weftext-format` 标记必须选择 `weftext.asciidoc.v1`；缺失/未知标记、缺失规范文档或存在竞争的同名候选项时，均安全拒绝。

Core 的读取结果在受信任进程内包含节点身份、节点目录、文档路径、精确源和修订。无效节点结构、非 UTF-8 源、链接/reparse 文档路径、无效 frontmatter、缺失身份、含糊元数据，或某个 `.weftext-rules` 祖先将目录或规范文档分类到受管边界之外时，读取均安全拒绝。传输和 CLI 响应只在需要时公开 UUID 及相对定位器，绝不公开这些主机绝对路径。

## 确定性编辑计划

首个编辑操作是在一个基础修订上、有序且互不重叠的 UTF-8 字节范围替换集合。范围必须落在字符边界上。Core 按起点、终点和替换文本规范化编辑，将其应用于精确源，并在不写入的情况下计算下一修订。

预览报告节点 ID、目标、基础和下一修订、规范化编辑、旧/新字节长度、内容是否变化以及精确提议源。编辑范围外的源保持逐字节一致。这既支持普通正文编辑，也支持未来狭窄的 YAML CST 补丁，而无需序列化整个 frontmatter。

结果源仍必须包含相同且唯一的顶层 `weftext` 映射及 `weftext.id`。移除、修改、重复身份元数据或使其含糊，都会拒绝计划。普通文本操作不能修复或重新生成身份。

原生待办项切换是针对一处经解析器确认的出现位置和精确标记范围的狭窄单文档操作；它绝不创建身份或字段。任务节点状态、优先级和日期编辑，是针对有效 `weftext-task` v1 规范配置的狭窄文字式文档头属性操作，且保留无关头部/正文字节。Core 在返回计划前重新解析并验证完整结果规范配置。依赖替换还需要已授权的工作区图，故使用工作区事务边界。将原生待办项提升为任务节点会同时创建节点并替换源，因此绝不拆分为单文档编辑及无关的创建调用；由 [`13-workspace-transactions.md`](13-workspace-transactions.zh-CN.md) 管辖。

非受管文件（包括 Markdown 或 `.adoc` 文件）不被节点文档操作边界接受，即使其字节含有看似有效的元数据封装。Core 不会将其解析、规范化、作为草稿处理、修补图标或作为节点提交。显式原始文件读取和导入是不同能力，不能隐式复用节点事务。

## 独立外部 AsciiDoc 边界

Desktop 可以对一个明确选定的外部 `.adoc` 或 `.asciidoc` 文件授予独立操作边界。该授予包含精确的规范化文件路径、平台提供时的文件对象身份，以及已打开字节的摘要。它不扫描父目录或同级项，不检查或采用工作区标记，不生成 UUID、元数据封装或伴随文件，也不允许节点或工作区操作。被分类为工作区非受管内容的 `.adoc` 文件仍处于其工作区内容边界中，不能通过该通道被静默重新打开。

独立计划使用共享的安全 AsciiDoc 解析器和语义格式化操作，但验证通用 AsciiDoc，而非 Weftext 受管节点元数据封装。Weftext 专用构造保持字节不变且不可用。保存时在获授目标旁暂存，保留适用权限、刷新、原子替换、重新打开并验证精确结果。摘要或文件身份改变、目标消失、变为链接/重解析点或权限改变时，提交被拒绝并提供比较或另存为；绝不自动重新计划和覆盖。草稿和最近历史是以保护隐私的文件身份为键的设备本地记录，绝不创建同级权威文件。

“添加到工作区”通过显式导入预览离开此边界；该预览创建具有全新 UUID 的新规范节点。它不收编外部目录、不把外部文件保留为节点权威，也不覆盖该源。独立功能区能力矩阵见 [`06-application-ui.md`](06-application-ui.zh-CN.md)。

## 感知规范配置的格式化计划

`DocumentFormatPlan` 是工具栏、选择浮层、斜杠菜单、上下文菜单、键盘、命令面板、CLI 和 Server 格式化操作的单文档强类型边界。请求绑定节点 UUID、基础修订、精确 UTF-8 选择、操作种类和强类型操作输入。Core 重新解析选定规范配置、解析受影响的语义块/单元格、返回选择能力和诊断，并构造狭窄替换。调用方不能把视觉 DOM 选择直接转换为 AsciiDoc 标点，或从 HTML 重建文档。

Core 可以从一处经解析器确认的选择提取 `FormatDescriptor`，并应用于另一处兼容选择。描述符只含可移植的语义格式：受支持的内联标记，以及兼容的段落、列表、引文或标题呈现。它绝不包含文本内容、链接目标或节点 UUID、显式锚点/ID、引文或脚注/尾注正文、注释、任务状态/日期/依赖、Query 表达式、Template 插槽、资源路径或任意源片段。捕获是只读的。应用返回普通的修订绑定 `DocumentFormatPlan`；不兼容、混合种类、受保护、格式错误或过期的目标均安全拒绝，而非部分应用描述符。

受控设备草稿的撤销/重做在保存前属于客户端本地编辑历史。保存结果仍须跨越此计划和提交边界，绝不豁免身份、精确源、配置文件或过期修订检查。“重复上次格式”只在设备本地编辑器状态保存最后一个 `FormatDescriptor`，并针对每个新目标重新验证它。

## 结构化表格与标题计划

表请求携带由 Core 解析的表范围，以及逻辑行、列或矩形单元格选择；前端 DOM 坐标不是事务证据。表头区域计划只接受前面连续的 `N` 行作为列标题，及前面连续的 `N` 列作为行标题。任一计数可为零，两个区域可并存，Core 只报告一次其交叉单元格。重复当前计数是无操作。原生配置文件拼写由 Core 配置文件写入器选择，隐藏表模型或伴随文件绝不成为存储权威。

合并计划接受一个有效表中连续的矩形选择。它拒绝切开既有跨度、表边界、受保护范围或不受支持的嵌套单元格结构的选择。零个或一个非空选中单元格可直接合并。多个非空单元格要求一项显式确认输入，并将其绑定到 Core 精确的行优先组合预览；计划按该顺序保留每个单元格正文，绝不静默用一个覆盖另一个。拆分计划恢复所表示的行/列网格，把合并内容保留在首个单元格，并创建其余空单元格。拆分是结构性操作，不是历史重建；只有草稿撤销能恢复精确的合并前分布。Core 返回结果尺寸、跨度/表头区域、内容处置、受影响字节范围和精确提议源。

标题级别计划识别经解析器确认的标题和请求的 H1-H9 级别。`heading_only` 只更改该标题并重新解析所得层级。`preserve_subtree` 以同一增量移动每个后代标题，同时保持相对结构。Core 拒绝 H0/正文标题混淆、超出 H1-H9 的结果、受保护/格式错误范围，或配置文件禁止的层级。转换为段落是独立操作，且接受前必须报告后代重新设定父级。标题文本、显式锚点、链接和注释目标均保持不变，除非另有独立显式操作；预览报告旧/新大纲路径和所有受影响标题。

所有表格与标题计划均在异步预览前捕获基础修订和已解析源范围。之后的光标、选择、窗格或文档变化都不能重新定向请求。完整的下一源必须重新解析为 `weftext.asciidoc.v1`；否则不返回可执行计划。

## 单文档提交

提交接受先前构建的计划。Core 会在暂存前重新读取节点，并拒绝身份变化或基础修订过期。它将精确下一源写入同一节点目录内、由请求拥有的临时文件，复制可移植文件权限，刷新并同步暂存文件，重新打开并验证其摘要，重验目标修订，经已审阅的跨平台临时文件实现原子替换文档，同步已提交文件，再重新打开并验证身份和修订。

无操作计划返回当前经验证修订而不重写文件。预览失败或过期修订提交不会改变目标。临时名称使用保留前缀 `.__weftext-transaction-`，并被工作区扫描忽略。

Core 的计划/提交只处理一份文档；工作区结构日志和启动回滚使用独立事务规范。自动合并、针对不合作外部编辑器的跨进程锁定及恢复 UI，均须在公开前具备各自的明确合约。

## 调用方与 Agent 边界

Desktop、CLI、Server 和获批准的 Agent 操作必须调用同一读取、计划和提交函数。只有 Core 返回经验证的已提交修订后，调用方才能把生成文本标为已提交。过期结果是冲突，而非自动重新计划并覆盖的许可。

只读 Agent 接口仅在启动工作区定界并通过有效重建清单进行 UUID 查找后，公开精确读取和修订。它不公开任何变更方法。Agent 变更保持禁用，直至操作请求将一个预览绑定到明确批准及同一 Core 提交路径。
