# 工作区事务与回收站

本规范定义工作区事务边界。结构性操作、回收站、查询、模板库、多维表、文档合并/历史恢复和备份仓库操作，只能通过下述与修订绑定、可恢复的契约公开。

## 工作区修订

结构性操作针对由 Core 分类的可移植权威派生的工作区修订进行计划。Core 对必需的 `.weftext-format`、存在时的 `.weftext-rules`、受管节点目录/AsciiDoc 文档、可见非受管目录/文件、资源、注释伴随文件、每个有效表伴随文件/分片/记录字节，以及 `.weftext-trash/_weftext.items` 内每个目录/清单/载荷字节计算哈希；路径为按路径和种类排序、以 `/` 分隔的 UTF-8 相对路径。已忽略条目不参与普通结构修订，因为事务不能读取或变更它们；专用完整备份清单仍包含它们。表记录和回收站项目权威始终参与工作区修订，即使产品发现不将两者作为普通文件公开，且内容规则不能在其存储内分类。更改规则或格式标记必然改变修订。派生索引及请求拥有的 `.__weftext-transaction-` 目录不参与。

无效清单、非 UTF-8 路径、符号链接或 reparse 点、不可读条目、重复身份或另一未完成事务，都会使计划安全拒绝。提交会在变更前立即重算同一修订。不匹配即为过期工作区冲突，绝不授权重新计划或覆盖。

若目标被分类为非受管/已忽略，受管文件操作会创建已分类路径，或移动/复制/回收站/恢复的源子树含有非受管或已忽略边界，计划也会失败。这刻意避免将隐藏的非节点字节作为节点操作的偶然副作用移动。选定受管分支内的有效表伴随文件/记录存储属于类型化分支权威而非偶然边界，必须完整计划；无效/不完整表关系会阻止结构性操作。非受管子树内的目标不能由节点 UUID 指定，因为 Core 从不在其中索引。资源导入、表资源引用和注释伴随文件创建均按同一规则集验证精确文件目标。

## 确定性计划

事务合约要求下列操作有修订绑定预览：

- 创建子节点；
- 在不改变父节点时重命名节点子树；
- 移动节点子树，不得把重命名隐藏在移动中；
- 复制子树，并为每个复制节点分配新的 UUIDv4；
- 将一棵完整受管子树移入新生成的工作区回收站项目；
- 将一个或多个独立、节点拥有的资源移入独立回收站项目并共享操作 ID；
- 将回收站项目恢复到已证实的原始位置、原子恢复精确父项目链，或恢复到显式选择的活动目标/名称；
- 以独立高权限确认永久删除选定回收站项目；
- 将直接子级回收站布局迁移为封闭的原始位置已知/未知项目；以及
- 重写已解析目标定位器改变的显式内部链接出现位置；
- 修补可移植相邻标题/正文呈现设置，而不重序列化 frontmatter；
- 将一个精确原生待办项出现位置提升为新生成的受管任务节点，同时以稳定 `node:` 链接替换源分支；以及
- 仅在验证提议的已授权完整图后替换任务节点的完整依赖集；以及
- 通过下述密封 `TaskMigration` 权威在内部执行一次完整本地尾随任务宏迁移；这不是调用方可见操作。

未来模板事务包必须新增独立修订绑定预览，用于配置/重新绑定/清除根精确模板库 UUID；将已审阅模板根实例化为完整、全新 UUID 的普通子树；以及借由显式源/伴随文件转换跨模板角色移动/恢复分支。这些目前并非公开 `Core` 操作，也不能由普通移动/复制/回收站 DTO 合成。

未来多维表事务包必须新增独立修订绑定预览，用于创建完整表节点；添加/编辑/批量编辑记录；软删除/恢复/永久删除表本地记录；添加/重命名/删除/转换字段和选项；添加/编辑/删除共享视图；导入或修复引用资源；更新类型化关系；复制/重新设键完整表；以及将精确原生 AsciiDoc 表范围升级为新表节点加规范块嵌入。这些不是普通文档/资源操作，前端无法依据原始路径或通用 JSON 写入合成。

调用方在计划前仅解析一次操作目标。当前节点/编辑器命令提供从聚焦窗格捕获的 UUID；行命令提供从该行捕获的显式 UUID 或回收站项目 ID。Core 只接受该不可变类型化身份并记录到计划。计划和提交都不读取客户端 `selectedNodeId`、跟随节点值、视觉行索引、聚焦窗格或原始显示路径。调用后的焦点/选择变化无效；不可用或过期身份会失败而不再解析。

计划记录操作、语义操作 ID、计划 ID、基础工作区修订、捕获目标身份和原始位置、执行节点 ID、旧/新工作区相对路径、生成副本 ID 和精确文档替换。UUID 仅在计划时生成一次，预览值即提交值。预览证据规范排序；可执行步骤保留确定性依赖顺序。

每个重命名、移动、复制、节点移入回收站和节点恢复计划都带有封闭、版本化、由 Core 编写的 `scopeSummary`：`rootNode: { nodeId, displayName }`；不含根的 `descendantNodeCount`；`resourceCount`；`annotationSidecarCount`；精确 `byteTotal`；规范排序 `affectedDocumentNodeIds` 与 `rewrittenDocumentNodeIds`；`identityPolicy`（`preserve` 或 `rekey`）；`trashItemCount`；以及可空 `operationId`。对于原子祖先链恢复，`rootNode` 是最外层恢复节点，捕获目标仍独立为用户选中项目。`affectedDocumentNodeIds` 包括绑定前、建议后状态间活动/载荷定位器或字节不同的每份文档：重命名/移动/回收站用保留源 ID，复制用生成目标 ID，恢复用恢复 ID，另加单独重写文档。`rewrittenDocumentNodeIds` 是接收精确源替换的子集。`byteTotal` 对当前字节被搬迁、复制、项目化、恢复或替换一次的每个唯一常规文件求和；目录为零，重叠绝不重复计数。计数/字节源于驱动日志的同一经验证物理清单和文档替换，而非客户端树或事后估计。非回收站计划报告零项目和空操作 ID；产生项目的回收站计划报告生成的操作 ID。重命名、移动、回收站、恢复使用 `preserve`；复制使用 `rekey`，携带完整旧到新 UUID 映射，且可见草稿脏时绝不从较旧磁盘字节复制源节点。一个被移入回收站的根分支无论后代数多少均报告一个项目。创建/导入及仅资源或异构多项目永久删除计划保留专用类型化证据；没有单一被操作节点分支时不虚构保留/重设键分支摘要。

原生待办项提升使用专用封闭 `promotionSummary` 证据，而非假定新节点原已作为被操作分支存在。它包括捕获源出现位置/范围和状态、生成任务节点身份/标题/父节点/名称、提升的后代/续接计数和字节、初始任务状态、受影响注释处置、替换链接标签/源、受影响文档 UUID 和精确字节总数。生成节点 UUID 仅作为新的持久身份出现一次；原生待办项没有旧 UUID 或重新设键映射。

计划还记录 Core 的规范 `draftSensitiveNodeIds`：节点源分支中每个永久节点 UUID；规范文档被替换或链接重写的每个节点；以及回收站项目或资源操作中的每个保留节点/所有者 UUID——其移除、恢复或永久删除可能使设备/会话草稿失效。资源删除证明精确文件由指定节点拥有，且它不是非受管、已忽略、规范文档、注释伴随文件、保留存储、链接/重解析或非常规内容。版本化的 Core、Desktop bridge、WebUI bridge、CLI 和 Server DTO 原样携带这些字段；调用方可删减显示名称，但不能省略授权或门控评估所需身份。

原生待办项提升还绑定精确所属文档修订和解析器确认的出现位置、完整附属分支、生成节点 UUID/路径/源、初始封闭 schema 的任务规范配置、精确原位置链接替换、注释处理和选定现有父节点。`[ ]` 映射到 `todo`；`[x]`/`[*]` 映射到 `completed`，不捏造关闭时间戳。默认父节点是源节点，但任意替代父节点/名称都显式且修订绑定。提升日志原子创建完整任务节点并替换原生待办项分支；绝不在仅一侧存在时报告成功，也不留下镜像复选框。

任务节点依赖计划将每个 UUID 唯一解析为携带有效 `weftext-task` v1 配置文件的已授权活动节点，并验证提议完整图。它拒绝自身/重复/循环边，且不披露隐藏与缺失目标。内联重复输入仅经显式转换处理；任务节点重复不属可接受 v1 目标。预览后任何无关可移植工作区字节变更均拒绝提交，而非对不同图静默重新计划。

旧版任务重新基线清单仍不属可执行计划集。其不透明完整本地工作区文件系统捕获及封闭 `weftext.task-rebaseline/v1` 预览绑定可移植工作区修订、精确源文档修订、生成身份/路径提案、注释清单和显式 `externalSnapshotBinding: not_provided`。其 `physicalInventoryBinding: workspace_revision_only` 不是完整物理前状态，`committable` 始终为 false，通用提交拒绝它。解码或重新验证此 DTO 绝不授予变更权威。

当前封闭的 Core 契约分别定义前向与回滚权威。前向应用仍专属 `workspace-transaction.v3`；任务提升仍是唯一 v2 操作，v1 日志拒绝提升和重新基线。私有前向规划器在精确物理 A、等同已审阅 v1 摘要和完整值的语义重建、外部快照验证以及物理 B = A 期间持有同一租约。外部快照须为工作区外完整且逐字节相等的物理树，且目录及常规文件对象身份不相交。v3 权威绑定根节点 UUID/文档修订/文件系统身份、修订、完整 A 和预期 C 条目/摘要、快照绑定/根身份及恢复定位符、完整映射、替换/新节点字节、批注证据、所有活动受管文档 UUID、完整原生草稿观测、本地 Owner 边界断言、限制和有序步骤。缺失、多余、重复、非规范、过期、链接/重新解析、别名或超限权威均安全拒绝。

内部前向提交路径需要新鲜本地 Owner 断言和新鲜完整草稿观测，然后在一个租约下重复物理 A、根、语义、快照和草稿检查才写日志。已提交 C 到 A 的精确回滚只能由不透明前向计划及精确进程本地提交结果导出。回滚计划观测完整物理和语义 C 加不变且不相交的精确 A 快照，要求当前 Owner 审阅断言和新的、含生成节点的完整全部活动文档草稿观测，仅导出提议到原始的源替换，之后把生成树移入暂存保留。合法的新 Owner 或授权纪元可审阅回滚；提交需针对该审阅主体和纪元再作另一独立断言。这些断言记录受信任原生调用边界；它们不是 ACL 能力且不导出。托管、受范围限制和非 Owner 调用方仍保持关闭。真实 Owner/ACL 权威与持久收据/审计集成实现前，产品执行也保持关闭。

规范 Query 目标只读且不创建工作区事务。其独立 Core 运行时包绑定精确 Query 源/范围、显式别名/域、类型化作用域、词法嵌入或 Saved Query 绑定、显式求值上下文、授权和资源限制。落地运行时不宣称完整产品调用方。没有普通目标专属修订绑定计划，Query 结果/操作证据绝不授权后续变更。

多维表记录/schema 操作不是规范 Query 变更。每个计划绑定表节点 UUID、记录 UUID、精确伴随文件/记录/资源指纹、提议的封闭 JSON 字节、schema/类型验证、关系目标、活动/已移入回收站状态、草稿敏感节点 ID、已授权操作者、字节/计数总数和每个日志步骤。schema 转换在提交前暂存并验证预期伴随文件和每条受影响记录。移动保留表/记录身份；复制生成完整新节点/记录映射并重写内部记录关系；整节点回收站/恢复保留精确存储。软删除记录留在精确表文件，而永久记录删除需要独立高权限摘要确认，且绝不猜测资源所有权。

文档比较和版本历史浏览只读且不创建工作区事务。应用选定比较处置或恢复一个历史文档源，须使用未来受规范 22 管辖的 `DocumentMergePlan` 或 `DocumentRestorePlan`。计划绑定当前目标节点/文档/工作区修订、每个不可变比较/历史/备份输入摘要、Core 编写的差异块处置、精确提议源、配置文件/系统/受保护范围验证、授权、草稿观测、到期和恢复步骤。同节点恢复保留当前 `weftext.id`；不同节点比较绝不授权身份复制。过期输入或目标权威被拒绝，而非在新字节重跑差异。

最近历史捕获是提交后的次要证据。成功工作区变更不会因设备本地历史条目无法发布而回滚或报告失败；提交响应改携带 `history_capture_failed`，调用方绝不重试工作区写入。正式备份仓库快照/保护/保留/垃圾回收操作使用独立仓库事务/租约，因目标与工作区不相交。仓库快照绑定一个精确工作区物理清单/修订，却仅写入不可变外部对象并最后写清单。恢复到活动工作区回到普通工作区预览/草稿/禁止覆盖/日志边界；仓库字节或原始快照路径绝不授予变更权威。

未来模板库配置计划必须绑定根修订、审阅的模板库节点 UUID、唯一活动解析、角色后果和全部诊断。它绝不从名称/路径推断目标，也不将直接伴随文件创建视为角色权威。

未来模板实例化必须使用专用封闭 `templateInstantiationSummary` 证据，而非假定复制普通节点分支。它冻结模板根与每个 Part UUID/文档/伴随文件修订、参数模式加类型化输入/上下文、每个求值绑定及已应用/默认处置、目标父节点、已解析单一权威目标名称、名称来源、新生成 UUID/路径映射、精确提议源、内部/外部链接处置、资源字节/摘要、省略设计注释计数/字节、源/目标 ACL、冲突诊断、草稿敏感 ID、字节/计数总数和每一步日志。Root `node_name` 绑定提供目标名称且调用方不可覆盖；没有它时调用方提供显式名称。Part 绑定提供名称，否则其原型基名提供。所有生成节点均普通；成功不含模板角色、`weftext.template.json` 或残留插槽/配置文件源。

未来模板角色边界移动必须冻结普通结构范围和 `templateRoleTransitionSummary`：旧/新 Library/Root/Part 角色及所属 Root、精确伴随文件创建/移除、激活、具体化或删除插槽所需每项源转换、残留/受保护诊断、链接/资源/注释、目标占用、ACL 和草稿。移入直接子级位置须有一份有效提议 Root 伴随文件；移入 Part 位置禁止嵌套伴随文件权威；移出须证明此前活动模板插槽/配置文件/伴随文件不存于普通输出。独立写入的普通类插槽源保持惰性，但仅路径计划或外部同步应用不得静默降级已验证原型；必须因需修复而阻止。

被复制文档唯一链接到复制子树中另一节点时，复制计划重定向该定位器至复制节点。外部链接仍指向原目标。含糊出现位置不得猜测。

工作区根不能移动、复制至自身内部、移入回收站或恢复。节点不能移入自身子树。现有目标、大小写折叠冲突、无效可移植名称、保留事务/规则/回收站项目路径、内容边界跨越和含糊链接目标均拒绝计划。原始路径绝不足以成为回收站恢复或永久删除权威。

### 精确设备草稿门控

共享原生/Server 变更边界向 Core 提供调用设备/会话的权威草稿注册表视图。`previewWorkspaceAction` 仅将注册表与 `draftSensitiveNodeIds` 相交，并返回范围化证据：需保持干净的 UUID、精确阻塞脏 UUID 和绑定这些 UUID 的不透明草稿存储观测。未来模板包落地时，实例化须包含每个模板 Root/Part 源节点，以免在设计草稿后使用较旧磁盘字节；角色转换须含角色/源/伴随文件或所有权改变的每个节点，及每份单独重写文档。交集非空时，Core 可返回说明范围却不签发可执行提交令牌。用户须修订保存或明确丢弃每个列出的草稿并请求新预览。不存在“仍使用磁盘版本”、全局“忽略草稿”或操作特定绕过。

日志应用前，`commitWorkspaceAction` 针对计划精确 `draftSensitiveNodeIds` 重复权威查找，任何新变脏成员均在不写入时被拒绝。两个入口点均实现门控；仅调用方警告不足。提交还执行普通工作区/文档修订检查，故预览后保存受影响草稿会使预览过期，必须重新计划。精确源/替换/重写/回收站身份集外的脏节点不阻止预览，也不只因变脏而使提交失效。UI 状态、缓存客户端布尔值和全局变化的无关草稿计数器都非门控权威。

## 可恢复日志

正在执行的计划拥有一个根级目录，名为 `.__weftext-transaction-workspace-<plan-id>`。它是临时恢复证据，不是可移植内容或索引权威，语义扫描器会忽略它。目录包含版本化 `journal.json`、经验证暂存内容及回滚所需的任何原件。v3 物理后状态/恢复扫描只能排除当前精确、已验证的日志目录对象和持有的租约锚点；不得忽略任意事务形状名称。

持久状态为：

1. `prepared`：基础修订已验证，所有替换/复制字节已暂存并计算摘要；未改变任何可移植目标；
2. `applying`：日志已持久化；经验证旧/新/暂存/保留摘要使恢复可推断最后完成步骤而无需猜测；
3. `committed`：预期最终清单和修订已重新打开并验证；可以安全地恢复清理。

对 v1/v2，启动恢复会移除完整 `prepared` 日志，按反向步骤回滚 `applying` 日志，并验证后移除 `committed` 日志。v3 则按绑定的前状态 A、后状态 C 和封闭逐步状态，对完整排除日志的工作区树分类：`prepared` 仅接受 A；`applying` 清理精确 A、将封闭混合状态回滚至精确 A，或在语义验证后完成精确 C；`committed` 仅接受经验证 C。独立的 `workspace-transaction.v4` 保留给 `TaskRebaseline` 精确回滚，并要求显式 `rollback_rebaseline` 方向。它将前状态 C、后状态 A 分类：`prepared` 仅接受 C；`applying` 清理精确 C，仅将封闭 ReplaceFile/RemovePath 混合状态逆转至精确 C，或语义验证后完成精确 A；`committed` 仅接受经验证 A。ReplaceFile 覆盖两次重命名两侧的目标、暂存和移出状态，RemovePath 只覆盖精确生成源与精确保留。即使物理前树或后树看似精确，v3/v4 也会先验证完整的预期暂存、移出与保留矩阵，并拒绝未知事务工件。每次分类还将外部快照重验为精确 A 并检查根文件系统身份。任何未触及、已忽略、非受管、注释、回收站或其他字节不同，恢复均不猜测。它保留日志/暂存/快照证据，标记需恢复，且不覆盖未知内容。恢复可安全关闭持久证据而不重验当前 ACL；新发起回滚仍需当前 Owner 权威。

日志工作区路径均为相对路径，且每次读取均验证。绝对路径、`..`、符号链接、未知 schema 版本、重复步骤及选定根外路径均安全拒绝。v3 和 v4 各自在私有恢复权威中携带一个规范 UTF-8 绝对外部快照定位器；它在暂存前受限，绑定入日志摘要，重验为不相交精确 A，并从公共 DTO 和 `Debug` 中删改。v3 无持久方向字段，永久保持 A 到 C 的前向；v4 有强制回滚方向，因此 schema/操作/方向混淆会安全拒绝而不变更既有 v3 字节。未来模板日志还须针对封闭摘要验证每个生成 UUID/路径/源、复制资源、重写链接、伴随文件处置和角色转换。日志清理不能使生成源、资源、身份、模板角色/伴随文件或回收站状态成为权威。

## 工作区回收站

工作区回收站是保留的隐藏根子节点 `.weftext-trash`，具有同名 `.weftext-trash.adoc` 规范文档和持久节点 UUID。可在首次使用时经同一事务日志创建。用户不得在保留回收站路径创建、重命名、移动、复制或资源编辑普通项目。已删除对象仅存放在 `.weftext-trash/_weftext.items/<trashItemId>`；`_weftext.items` 是特殊 Core 存储域，而非受管子节点、资源、非受管目录、已忽略目录、派生索引或事务日志。

### 回收站计划权威

通用节点移入回收站计划必须拒绝根 `template_library_root` 当前指定 UUID。未来模板事务包仅可在一个组合计划中移入该容器：该计划清除字段或将其重新绑定至另一个唯一有效活动节点，并预览每项由此产生角色变更。路径移动或回收站发布均不隐式编辑配置。

回收站计划记录完整基础工作区修订；生成的小写 UUIDv4 `operationId`；每个独立可恢复对象一个生成的、精确/大小写折叠均未占用的小写 UUIDv4 `trashItemId`；精确源身份/路径及物理清单；封闭清单字节和摘要；精确载荷清单、长度和摘要；首次使用所需目录；以及有序日志程序。项目目录与清单 ID 必须相符。UUID 只于计划时生成一次，提交绝不重新生成或静默添加后缀。

一个删除的节点根生成一个 `kind: node` 项目，内含完整未变的同名目录和全部后代。清单绑定永久节点 UUID、原始父 UUID/名称、可选祖先 UUID 提示和完整载荷树摘要；后代不成为项目。一个删除资源文件生成一个 `kind: resource` 项目，绑定原始所有者 UUID/名称、精确长度和 SHA-256。一批操作创建独立资源项目，分享一个 `operationId`，并全有或全无提交。带非受管/已忽略边界的受管子树，以及非受管、已忽略、保留、链接/重解析、非常规或非指定节点所有文件，均在计划存在前失败。

提交重验完整工作区修订、源证据、每项 ID 占用、清单/载荷形状和目标边界。它创建请求拥有的不覆盖暂存区，刷新并重新打开每一字节，持久进入 `applying`，将源移至暂存载荷，无替换发布每个完整项目目录，并验证预期修订。任一步故障注入都会恢复精确旧状态；报告成功时有每个项目且无源，报告回滚时有每个源且无项目。未知混合状态保留日志和全部证据。

当 B 被移入回收站时若 A 仍在 B 内，B 是一个项目。若 A 先被移入、B 后被移入，则为两个项目，A 的清单仅通过 B 的永久节点 UUID 与 B 关联。相同名称或历史路径不建立此关系。

### 恢复与永久删除

恢复计划基于完整经验证项目清单/载荷，而非路径。仅当记录父/所有者 UUID 活动，且精确及平台大小写折叠目标均空闲，才存在原始位置计划。缺失原始位置唯一解析到一个或多个完整节点项目时，Core 可构造显式审阅、原子的 `with-ancestors` 计划，在所选节点/资源前恢复最外层父链。它绝不将嵌套后代视作有独立清单来提取。

若原始位置真实缺失，或迁移清单为 `originStatus: unknown`，Core 将项目留在回收站直到用户选择已有活动父/所有者 UUID。名称冲突要求显式可移植重命名或不同目标。Core 绝不从存储名称/路径创建 B1，不覆盖精确或仅大小写冲突，也不将祖先提示视作权威。恢复保留永久节点 UUID、重验已安装字节、只消耗恢复项目目录，并可安全重放。含旧模板源的回收站载荷是封闭、非活动的精确字节证据，不是活动普通子树。在仍已配置 Library 下恢复至已证实 Root/Part 位置可保留精确字节。恢复至普通空间必须采用未来角色转换计划以具体化/删除活动插槽并移除配置文件/伴随文件，否则阻止。恢复绝不猜测或重新绑定 `template_library_root`；只有组合配置/回收站事务的精确回滚收据或单独审阅配置计划可这样做。

永久删除是一份独立计划，绑定选定项目 ID、精确清单、载荷摘要、字节总数、基础修订、更高权限及显式确认。它不能针对活动节点/原始路径，也不能清理格式错误/冲突项目。保留策略可提议此操作，却不能绕过同一日志和授权。回收站不是备份。

### 清单、同步冲突与迁移

Core 将回收站项目清点为封闭特殊类别。活动节点发现、链接、搜索、Chrono、任务和查询不进入载荷，但保留永久 UUID 必须在活动与已移入回收站权威之间唯一。缺失/额外清单或载荷条目、ID 不匹配、重复/大小写折叠项目 ID、活动/已移入回收站重复 UUID、变更聚合摘要、同步冲突副本、部分到达和同时恢复/删除证据都会产生类型化协调状态。普通变更不能穿过其中任何状态。

直接历史布局 `.weftext-trash/<name>` 仅是迁移输入。只读迁移计划清点并计算每个旧版条目摘要，生成项目/操作 ID，阻止冲突/不安全字节，并为每个独立可恢复条目创建封闭 v1 项目。若无密码学或事务绑定原始位置证据，清单使用 `originStatus: unknown`、空原始父/所有者 UUID，且要求显式目标恢复。迁移经外部快照、修订绑定、日志化、可恢复和回滚验证；Core 绝不保留直接条目和 `_weftext.items` 作为双运行时权威。

完整布局和封闭清单合约见 [`../architecture/17-workspace-trash-item-store.md`](../architecture/17-workspace-trash-item-store.zh-CN.md)。同步将项目字节作为可移植权威传输，但未完成事务日志仍是本地恢复证据，绝不作为协作协调。

## 调用方边界

Desktop、WebUI、Server、CLI 和获批准 Agent 的变更调用相同计划、提交及恢复函数。UI 代码不能直接移动文件、分配模板角色、求值插槽、生成 UUID、复制资源或重写链接。规范 Query 调用方消费同一只读 Core 计划/求值器，且没有新类型化操作计划时不能将结果行转成变更权威。DSH 保持只读，直到提案和批准记录能够把精确计划 ID 与基础工作区修订绑定到此提交路径。
