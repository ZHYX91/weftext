# Weftext 引文与参考文献

本规范定义引文出现、解析、编译和呈现边界。引用记录的创建和编辑需要使用此处描述的强类型 Citation Data 构造。

## 当前目标边界

规范 YAML frontmatter 仅包含 `weftext` 操作映射。结构化书目事实是作者文档数据，但对于通用字符串属性而言过于复杂。因此它们需要一个版本化的强类型 Weftext AsciiDoc 构造。本规范保留已接受的 `cite:`、`nocite::`、`bibliography::`、UUID 解析、编译和提供方中立 CSL 边界，但在没有解析器、编辑、通用降级、导入/导出和夹具证据的情况下，不会发明替代记录语法。

在该构造被接受之前，不存在规范的参考文献记录创作界面。没有可用强类型记录的引文出现仍会被诊断，而不会被猜测或丢弃。Markdown `@key` 形式、Pandoc 形式、原生 AsciiDoc 参考文献锚点和第三方 `citep`/`citet`/`citenp` 宏仍是显式导入器输入，而不是解析器别名。

`cite:[key]` 和 `bibliography::[]` 拼写是 `asciidoctor-bibtex` 与 `asciidoctor-bibliography` 扩展的既有交集。紧接的 `+[key]` 簇续写采用自 `asciidoctor-bibliography`。这种来源只是语法选择，而不是运行时依赖或兼容承诺：Weftext 两个 Ruby gem 都不加载，不把文档选择的 `.bib` 文件作为权威，也不接受任一扩展其余的别名、属性、数据库设置或渲染行为。Weftext 拥有下文的精确语法、普通节点数据权威、UUID 解析、事务、编译作用域和提供方中立 CSL 边界。

Core 拥有引用元数据验证、引文解析、源范围、键解析、重命名计划、诊断、引文簇、参考文献收集以及提供方中立 CSL 呈现请求。Desktop、CLI、Server、WebUI、导出器和智能体消费该模型，不得发明私有引文语法，也不得从未解析的源文本渲染。

## 引文源语法

规范行内宏是 `cite`。括号形式是默认簇形式：

```adoc
The result has been replicated cite:[wang2024].
```

`narrative` 目标为恰好一个项目选择叙述形式：

```adoc
cite:narrative[wang2024] reports the same result.
```

每个引文项目的第一个位置属性是其键。可选的具名属性为 `label`、`locator`、`prefix` 和 `suffix`：

```adoc
See cite:[wang2024,label=page,locator="59-61"].

See cite:[wang2024,prefix="compare ",suffix=", especially figure 2"].
```

紧接着链式相连的 `+[...]` 项目属于同一个括号引文簇，并拥有自己的属性。项目之间没有空白：

```adoc
Several studies agree cite:[wang2024,label=page,locator=59]+[smith2025,label=chapter,locator=2].
```

簇形式属于完整宏出现。叙述簇不能使用 `+[...]`；多个叙述引用被写成由作者散文连接的独立 `cite:narrative[...]` 出现。无法生成所请求单项目叙述形式的所选呈现器，会以精确诊断失败，而不是静默改变形式。

引文项目内容使用受限的文字属性语法。项目和具名属性在双引号外以逗号分隔；名称为小写 ASCII，且最多出现一次。未加引号的值是非空令牌，不包含空白、逗号、任一引号、方括号、反斜杠或花括号。需要空白或标点的值使用带 JSON 转义的 JSON 兼容双引号字符串。单引号字符串、AsciiDoc 属性引用、替换、行内标记、嵌套宏和可执行内容不会被求值或接受为替代值形式。JSON 解码后，前缀和后缀是纯 Unicode 字符串，而非嵌套 AsciiDoc。当未加引号令牌规则会拒绝某个值时，规范写入器会引用该值。

任意显示覆盖、原始渲染引文、样式名称、区域名称、引文编号和提供方特定标志都不是引文项目属性。没有显式 `label` 的定位符表示 `page`；没有 `locator` 的 `label` 无效。定位符标签使用 schema 和解析器定义的封闭、与 CSL 对齐的 v1 词汇表。

未知目标、属性、定位符标签、畸形链、空簇、无效键、无效文字值、叙述链和重复具名属性仍保留为精确源并会被诊断。受保护的 YAML、注释、文字/列出/源/直通块、行内直通内容和其他配置文件受保护范围绝不会产生引文出现。引文解析只发生在固定 AsciiDoc 基线启用宏替换的位置；转义或受保护的示例不是出现。

## 参考文献和未引用纳入

块宏标记作者编写的参考文献放置位置：

```adoc
bibliography::[]
```

默认纳入是在选定编译作用域内引用的每个唯一已解析引用，按节点 UUID 而非引文键去重。在普通的单节点 Read/Write 中，编译组件和默认作用域就是该节点。多节点导出计划在渲染前必须提供有序组件和显式、权限过滤的引用作用域；路径邻近、打开的选项卡、反向链接或参考文献宏的位置都不会推断成员资格。`include=all` 还会选择该显式作用域中的每个有效引用能力节点：

```adoc
bibliography::[include=all]
```

具体的未引用参考文献使用单独的非渲染块宏声明。一个 `nocite` 只贡献给包含它的组件：

```adoc
nocite::[wang2024,smith2025]
```

引文样式、参考文献样式、区域、排序、标题文本和级别以及编译作用域都属于已解析的导出配置文件。它们不是文档属性，也不会持久化在引用节点上。参考文献宏是视图放置位置，不是数据库声明或物化列表。Citation Data 可以从 BibTeX、CSL-JSON、RIS 或另一种经审查格式导入或导出，但没有外部数据库路径会成为规范文档语法。

Citation Data v1 在一个生成文档组件中最多允许一个参考文献放置位置。没有放置位置的组件仍会渲染行内引文，但不会在规范源中物化任何参考文献。章节参考文献、筛选参考文献、多个参考文献视图、注释样式引文放置和出版物范围的跨文档编号，需要后续显式配置文件版本，而不是含糊的 v1 行为。

## 呈现边界

Core 将已解析的簇和引用记录降级为提供方中立的呈现请求。已接受的呈现器使用固定 CSL 能力并返回结构化富文本及稳定源关联；客户端不抓取 HTML。对于相同的有序簇、引用事实、样式、区域和导出计划，渲染是确定性的。

呈现器不会读取工作区、解析键、获取 URL、加载任意处理器、执行 JavaScript 或 Ruby，也不会选择文件。缺失或重复键、无效引用元数据、不可用样式/区域、不支持定位符和畸形呈现器输出都会产生安全拒绝诊断。

Citation Presentation v1 将可用样式固定为 `apa`、`vancouver` 和 `chicago-notes`，区域固定为 `en-US`、`zh-CN` 和 `ar`。其能力响应识别呈现器和版本，并声明具有打包允许列表资产加载的离线、仅数据隔离模式。引用 UUID 而非作者键是提供方项目身份和返回 run/条目所有权。参考文献纳入由已解析编译显式提供；未引用条目的隐藏提供方请求排在已渲染簇之后，因此无法改变重复引文行为。

固定提供方无法安全表达 Citation Data v1 的文字或 `circa` 日期，并将其 `note` 输入视为处理器控制而非普通 CSL 事实，所以这些字段会在 Presentation v1 中以不支持引用数据诊断失败。包含 `<` 的文本也会安全拒绝，因为此提供方解释类似标记的输入；没有调用方或客户端会收到提供方标记。提供方链接只接受强类型 `http` 或 `https` run，并且提供方标记/透明元素、缺失或额外的参考文献条目、重复条目边界、无效 UUID 以及恐慌都会在没有部分输出的情况下失败。这些是明确的呈现限制，不是替代存储语法，也不是丢弃作者事实的许可。

原生 AsciiDoc `<<key>>` 引用和 `[[[key]]]` 参考文献锚点仅是可选的通用导出降级。该降级有损，绝不会成为存储权威或往返承诺。

## 编辑和事务

引文插入、引文簇编辑、`nocite` 和参考文献放置位置都是强类型 Core 计划。UI 表单和选择器提交强类型意图，绝不独立修补源字符串。在强类型 Citation Data 构造定义其源权威之前，引用创建、字段编辑和键重命名不能发布。

未来键重命名必须按 UUID 解析一个声明和每个受影响出现，验证完整源集合，预览精确编辑，以原子方式提交，并在失败时精确回滚。仅打开、索引、渲染、导入或查看引用绝不会规范化或重写其源。

## 验收边界

该功能仅在以下所有条件都满足时可用：

1. 强类型 Citation Data 构造具有机器可读 schema，以及跨平台的正向、负向、畸形、CJK、RTL 和精确源夹具。
2. Core 以精确 UTF-8 范围解析宏，并排除每一个受保护上下文。
3. 引用解析、重复/缺失诊断、键重命名和派生索引都经过无头测试。
4. CSL 呈现器经过依赖审查、具确定性、可离线使用、与工作区和网络访问隔离，并针对多种引文样式和区域进行测试。
5. 参考文献作用域、排序、`nocite`、空输出和呈现器失败均须通过安全拒绝测试。
6. Desktop 和 WebUI 引文选择器、引用表单、Source/Write/Read 投影、陈旧草稿行为和无障碍/IME 路径，在没有浏览器自有解析器的情况下消费同一个 Core 模型。
7. CLI 和 Server 在没有直接文件系统或客户端解析器权威的情况下，暴露同样的修订、诊断、授权和事务行为。
