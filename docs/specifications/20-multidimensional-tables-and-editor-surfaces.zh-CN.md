# 多维表和编辑器界面

本规范定义多维表契约。产品界面只能通过 Core 清单、封闭解码、事务、恢复、备份和本文档的验收要求创建 `weftext.table.json` 与 `weftext.records`。

## 术语和非目标

**多维表**是一个具有表配置文件和同表本地记录的普通受管节点。**记录**是该表所属的 JSON 值对象。**动态视图**是嵌入文档的规范 Query 投影。**原生表格**是普通 AsciiDoc 表格区块。

这些术语不可互换。特别是：

- 记录不是节点、文档、标题、任务、资源、注释或查询行域；
- 记录没有 `weftext.id`、规范 `.adoc`、子项、独立 ACL、节点属性或节点提升路径；
- 表配置文件不是工作区范围的数据库、节点注册表或通用节点元数据目录；
- 动态视图不会将查询的实体复制到表记录中；和
- 规范查询 v1 不会通过此规范获取隐藏的 `records` 域。

产品后续版本可将“创建关联节点”作为普通节点创建加节点关系事务提供。它不能把这一操作称为记录提升、将记录 UUID 保留为节点身份，或使两个对象拥有同一权威。

## 便携式布局和分类

表节点保留规范 `X/X.adoc` 文档，并可包含普通子节点和资源。其表格权威包含：

```text
X/
  X.adoc
  weftext.table.json
  weftext.records/
    <first-two-hex>/
      <lowercase-record-uuid>.json
```

文件名 `weftext.table.json` 和 `weftext.records` 是受管节点内保留的节点本地名称。伴随文件仅在节点规范文档旁有效；仅当相邻伴随文件有效时，记录存储才有效。非受管位置中的任一名称仍为非受管内容；受管节点中类型错误、链接/重新解析类型、配置文件无效或布局无效的名称均为类型化清单诊断，绝不回退为普通节点所属资源。

内容规则不能在 `weftext.records` 内分类，节点发现也绝不重新进入其中。它含有 256 个可选的小写分片目录 `00` 到 `ff`，每个只含普通 `.json` 记录文件；空分片目录有效。嵌套目录、冲突副本名称、临时文件、符号链接、连接点/重新解析点或无关资源都不是有效可移植权威。不带 `.json` 的记录文件名是小写 UUIDv4；其分片目录必须等于 UUID 的前两个十六进制字符，解码后的记录 `id` 必须等于文件名。记录身份是元组 `(owning table node UUID, record UUID)`；Core 生成的 UUID 虽为随机值，记录 UUID 仅在所属表内唯一。不存在工作区级记录注册表。

普通节点所属图像和文件作为资源留在保留记录存储之外。传统 `assets/` 目录可以使用，但没有特殊权威。表格伴随文件、每个分片目录、每个记录字节和每个引用资源均参与物理清单、工作区修订、同步、备份、冲突检测、事务计划和节点回收站/恢复。

## 表格伴随文件 v1

`weftext.table.json` 是 UTF-8 JSON，具有配置文件 `weftext.table/v1` 和整数版本 `1`。其高层成员正是：

```json
{
  "profile": "weftext.table/v1",
  "version": 1,
  "primaryFieldId": "7a4cd2c3-e4bf-4ff6-b1e4-786f20b51218",
  "fields": [],
  "views": []
}
```

重复键、未知成员、非 UTF-8 文本、非整数版本、不受支持的配置文件、非规范 UUID、Unicode NFC 下重复的 ID 或名称、默认大小写折叠冲突及超出配置限制均安全拒绝。JSON 成员顺序和空格不具语义。当 Core 创建或重写这一专用机器结构文件时，它输出确定性的双空格缩进 UTF-8 和 LF；绝不将重新序列化规范 AsciiDoc 文档作为副作用。

有 1 到 256 个有序字段定义。每个都有 `id`、`name`、`type`、`required` 和 `config`。 `id` 是稳定的小写 UUIDv4。 `name` 是 1 到 128 个 Unicode 标量值的可变、修剪显示文本，并且绝不是表达式或记录标识。 `required` 是布尔值。 `type` 是以下之一：

`text`、 `rich_text`、 `boolean`、 `decimal`、 `date`、 `instant`、 `single_select`、 `multi_select`、 `url`、 `email`、 `node_relation`、 `record_relation`、 `image`、 `file`、 `formula` 或 `rollup`。

`config` 按类型关闭：

- `text`、 `rich_text`、 `boolean`、 `date`、 `instant`、 `url` 和 `email` 使用 `{}`；
- `decimal` 使用 `{ "scale": N }`，其中 `N` 是 0 到 18；
- `single_select` 和 `multi_select` 使用 `{ "options": [...] }`；每个选项都具有完全稳定的 UUID `id`、可变的 `name` 以及来自 Weftext 拥有的可访问 `color` 目录的令牌；
- `node_relation` 使用 `{ "multiple": boolean }`；
- `record_relation` 使用 `{ "targetTableNodeId": UUID, "multiple": boolean }`，并且目标在评估或编辑时必须解析为一个授权的有效表节点；
- `image` 和 `file` 使用 `{ "multiple": boolean }`；
- `formula` 使用 `{ "resultType": scalar-type, "expression": string }`；和
- `rollup` 使用 `{ "relationFieldId": UUID, "targetFieldId": UUID, "function": aggregate }`。公式结果类型为 `text`、`boolean`、`decimal`、`date` 或 `instant`。汇总聚合为 `count`、`count_non_null`、`sum`、`average`、`minimum` 和 `maximum`；Core 会对引用的关系、目标和聚合进行类型检查。公式和汇总字段必须具有 `required: false`。循环、未解析的字段 ID、不兼容的类型、无效的目标表以及共享表达式范围之外的公式会使表规范配置无效，而不是生成猜测值。

主字段必须唯一解析为 `text` 字段，V1 中不得删除或转换。其 `required` 标志仍是显式模式选择。重命名只改变显示名称。该字段可选且值缺失时，UI 将其值用作记录显示文本，并回退到本地化的“无标题记录”展示，不写入默认值。

## 记录 v1

每个记录文件都是 UTF-8 JSON，具有配置文件 `weftext.table-record/v1` 和整数版本 `1`。其高层成员正是：

```json
{
  "profile": "weftext.table-record/v1",
  "version": 1,
  "id": "0a51d9d8-459d-4c32-9f68-0bf2b4e96f43",
  "state": "active",
  "trashedAt": null,
  "trashOperationId": null,
  "values": {}
}
```

`state` 为 `active` 或 `trashed`。活动记录要求 `trashedAt` 与 `trashOperationId` 为空。已移入回收站的记录要求规范 UTC RFC 3339 `trashedAt` 和小写 UUIDv4 `trashOperationId`；这些值在删除计划中只生成一次。恢复把这三个成员一并恢复为活动形式。产品表格视图排除已删除记录，除非用户打开专用“已删除记录”界面。

`values` 是一个对象，其键是现有的非计算字段 UUID。缺失意味着无效；显式 JSON null 不是规范的存储值。必填字段必须包含有效的非空值。禁止使用公式和汇总字段 ID。未知、重复或已删除的字段 ID 会使记录无效，直到显式架构修复事务解决它们为止。

值编码仅由字段定义决定：

- `text`、`url` 和 `email` 是 JSON 字符串； URL 和电子邮件接受封闭语法验证，但没有网络查找；
- `rich_text` 是一个被验证为有界 `weftext.asciidoc-inline.v1` 的 JSON 字符串，没有块、原始 HTML、包含、具有副作用的宏或编辑器私有 JSON；
- `boolean` 是一个 JSON 布尔值；
- `decimal` 是一个规范的以 10 为基数的字符串，没有指数，最多 34 个有效数字，并且小数位数不超过字段比例；
- `date` 是 `YYYY-MM-DD`；
- `instant` 是以 `Z` 结尾的规范 UTC RFC 3339 字符串；
- `single_select` 是一个配置选项 UUID，而 `multi_select` 是配置选项 UUID 的有序唯一数组；
- `node_relation` 是小写受管节点 UUID 的有序唯一数组，当 `multiple` 为 false 时最多有一项；
- `record_relation` 是精确包含 `tableNodeId` 和 `recordId` 的有序唯一对象数组，当 `multiple` 为 false 时最多包含一项；和
- `image` 和 `file` 是有序的唯一数组，当 `multiple` 为 false 时，最多包含一项。

图像项恰含 `path`、`alt` 和 `caption`；文件项恰含 `path` 和 `label`。展示字符串是可为空的有界文本。`path` 是规范化的、以 `/` 分隔的节点相关资源定位符。它不得为绝对路径，不得包含空组件/`.`/`..`，不得逃离所属表节点，也不得命名其规范文档、表格伴随文件、记录存储、批注伴随文件、事务证据或链接/重新解析点。资源字节永不嵌入 JSON。目标缺失或未经授权是类型化断开关系诊断，不授权重写或删除作者写下的值。

表格伴随文件限制为 1 MiB，单条记录为 1 MiB，存储字符串为 64 KiB，记录值为 256，选择选项为每字段 4,096 项，共享视图为 128 项，关系项和引用资源定位符均为每单元格 1,000 项。共享表达式的标记/深度/步数限制同样适用。超限即安全拒绝，不产生部分记录或部分结果。

## 表达式、公式和表视图

表过滤器和公式重用 `weftext.expr.v1` 的语法、类型、小数规则、纯函数和资源限制。表配置文件添加一个封闭的主机绑定：

- `record.id` 是表本地记录 UUID；
- `record.fields["<field UUID>"]` 是存储或计算字段的可为空类型化值；和
- `context` 与规范查询使用的显式评估上下文记录相同。

没有裸字段名称、可变名称查找、隐式当前行、环境时钟、文件系统、网络、环境、随机值、动态加载、`eval` 或客户端私有函数。可视化构建器显示字段名称，但序列化稳定的 ID。Core 在评估之前检测公式和汇总依赖周期。计算值随输入/架构修订一起返回，并且不能作为存储的单元格进行编辑。每个便携式共享视图均具有 `id`、`name`、`layout`、`filter`、`fields`、`sort`、`group`、`summaries` 和 `layoutConfig`。 ID 和名称遵循字段身份/名称规则。 `layout` 是 `grid`、 `board`、 `calendar`、 `timeline`、 `gallery` 或 `form`。 `filter` 为 null 或一个有界表达式字符串。 `fields` 是 `{ "fieldId": UUID, "visible": boolean }` 的有序数组，其中每个当前字段恰好包含一次。 `sort` 是 `{ "fieldId": UUID, "direction": "asc"|"desc", "nulls": "first"|"last" }` 的有序数组。 `group` 为 null 或一个等效的字段/方向/nulls 对象。 `summaries` 是 `{ "fieldId": UUID, "function": aggregate }` 的有序唯一数组，具有经过类型检查的聚合。

`layoutConfig` 按布局封闭：网格和表格使用 `{}`；看板只使用 `groupFieldId`；日历和时间线只使用 `startFieldId` 加可为空的 `endFieldId`；画廊使用可为空 `coverFieldId`。看板 V1 要求 `groupFieldId` 解析为 `single_select` 字段：选项 UUID/顺序提供明确泳道/值映射，缺失值为未分配。多选、关系、公式、汇总等字段不得通过视觉推断成为可写看板分组。字段宽度、行高、密度、打开面板、临时筛选、选择、滚动、泳道折叠和虚拟化窗口均为设备本地，绝不写入共享视图。Core 在分页前应用筛选、授权、稳定排序/分组及最终记录 ID 决胜。摘要以完整的已授权筛选总体计算，并与交付窗口分开标注；客户端不得把页面小计当作总计。完整看板投影/动作契约见 [`21-board-views.md`](21-board-views.zh-CN.md)。

私有视图以工作区 UUID 加表节点 UUID 为键存储在工作区外。“另存为共享视图”会预览精确伴随文件替换及过期表修订冲突。共享视图绝不包含复制的记录值或规范 Query 源文本，因为其总体正是所属表。

## 动态视图和规范查询

普通文档在光标处插入动态视图时，写入一个规范 `.weftext-query` 区块。构建器要求命名源（节点、任务、标题或模板），再以该源所用的同一 Core 解析器/类型检查器编辑范围、字段、筛选、分组、顺序、限制和初始布局。生成正文仍是唯一的可移植语义权威，在通用 AsciiDoc 中会降级成普通承载角色的文本区块。源域决定行类型，布局不能决定：选择任务列表不会把 `from nodes` 改为 `from tasks`，选择表格也不会创建多维表记录。“节点集合”“任务视图”“标题视图”“模板视图”只是显式查询域的 UI 名称，不是存储类型。

现有查询块 `view` 属性只是已接受的初始展示提示。临时筛选、宽度、密度、展开和滚动均为设备本地。查询看板使用规范标量 `group by` 作为泳道权威并遵循规范 21；不会复用表格 `groupFieldId`。若规范 Query v1 无法表达可移植列绑定、自定义泳道顺序/标签、日历字段、摘要或其他共享展示，UI 可私下预览，但必须禁用“保存到文档”并说明精确版本门。不得写入前端 JSON、批注、属性或第二个伴随文件绕过该门。Query 聚合及任何未来记录域都需要另行审查的 Query 版本。

仅当 Core 将选定的投影字段和键入的行标识映射到一个现有的窄操作时，可编辑的动态视图单元才可用。派生的显示标题、类似公式的投影、组标题、摘要、隐藏/未经授权的值以及不明确的表达式是只读的。批量更改、板拖动、日历重新安排和填充操作使用普通的确定性工作区事务，并且永远不会改变浏览器结果缓存。

## 功能区、上下文标签与检查器

桌面和 WebUI 编辑器使用一个紧凑的可折叠功能区，由共享语义操作注册表支持。其持久选项卡和最小所有权是：

| 产品标签 | 负责内容 |
| --- | --- |
| 主页 (`开始`) | 撤销/重做、段落/H1-H9、格式刷、清除格式、行内标记、列表/原生待办项、引文/提示、代码基础 |
| 插入 (`插入`) | 链接/节点链接/嵌入、图像、原生表格、多维表、动态视图、代码/数学/图表、批注、引文、交叉引用 |
| 数据 (`数据`) | 字段、筛选、排序、分组、摘要、布局、刷新、共享/私有视图状态、规范 Query 源入口 |
| 参考文献 (`引用`) | 引文/参考节点、脚注/尾注、参考书目、题注、交叉引用、索引、诊断 |
| 审阅 (`审阅`) | 评论、建议、拼写、变更导航、解决 |
| 查看 (`查看`) | Write/Source/Read、窗格、大纲/检查器可见性、缩放/密度、聚焦和无障碍展示 |

表格、图像、动态视图、任务和模板设计是上下文标签。仅显示适用标签，且每个标签都使用与上下文菜单、斜杠命令、快捷键、选择气泡和命令面板相同的 Core 能力结果和动作。窄窗口会将组折叠进无障碍的有标记溢出菜单；功能区不得抢占 IME 组合输入，也不得依赖悬停/右键。

选择原生表格会公开表格动作，如前导标题行/列、合并/拆分、插入/删除、题注和提升。选择多维表或动态视图会公开 Data 及其相应上下文标签，且对象名称和变更属于私有还是共享始终可见。选择原生待办项或任务节点会公开常用任务状态、优先级、截止日期和依赖命令；不得因此创建固定的第七标签。

右侧检查器保留持久的上下文面板：大纲、属性、批注、反向链接、任务详情、引文/参考详情和允许的 Server 访问详情。任务节点标题芯片可显示状态、优先级和截止日期，完整表单由检查器负责；原生待办项只提供已支持的简单控件和提升。References 是固定功能区标签，不是特殊“论文”标签或节点类型。选择引文会显示其出现位置和已解析参考；打开参考节点显示书目字段；文档范围显示引文及参考书目诊断。学术文档设置是模板，不是存储模式。

除非用户调用显式的可移植操作，否则功能区/检查器/设备状态永远不会进入规范源。聚焦选项卡、选定行、视觉索引、检查器状态和当前 URL 不是事务标识。

## Core 事务

每个表突变都是一个类型化的、修订版绑定的Core 计划，具有精确的目标身份、当前摘要、建议字节、范围/计数/字节证据、授权、草稿敏感性、无破坏路径、日志步骤和恢复收据。所需采取的行动包括：

- 在一次提交中创建一个表节点、规范文档、有效的 伴随文件 和空记录存储；
- 通过替换一条记录 JSON 文件来添加/编辑一条记录；
- 通过暂存每个精确记录替换并提交一次来批量添加/编辑；
- 通过精确的状态转换软删除/恢复记录，并为一批生成一个操作 ID；
- 在更高级别的确认下，仅永久删除选定的已删除记录；
- 通过仅 伴随文件 更改添加或重命名字段，其中值不需要重写；
- 仅在预览每个受影响的记录转换/阻止程序后删除或转换字段、删除选项或更改需求；
- 通过精确的 伴随文件 替换添加/编辑/删除共享视图；
- 自动导入资源和补丁引用记录；
- 仅在授权类型化目标解析后创建或修改关系；和
- 将精确的原生表格范围提升为完整新表节点，并以区块嵌入替换。

架构和记录写入无法报告部分成功。模式转换会暂存新的伴随文件和每条受影响的记录，重新验证完整的预期表，然后通过一个可恢复日志提交。伴随文件、记录、文档、关系目标、资源、工作区修订、ACL 或设备草稿中任一项过期，都会拒绝提交，而不会重新规划。

移动完整表节点会保留其节点和记录 ID。复制为目标生成新的节点 UUID、为每条记录生成新的记录 UUID，并使用完整映射重写目标表是复制源的记录关系。节点关系和外部表关系保持不变；复制分支以外的反向关系不重写。回收/恢复节点时，完整伴随文件、记录（包括表本地回收记录）、资源、子项和身份都会作为一个普通节点分支项目保留。

软删除记录不会把字节移入工作区回收站。永久删除只在精确摘要确认后删除选定的回收记录 JSON，绝不隐式删除资源。删除由活动或已回收记录引用的资源会阻断操作，或预览精确引用修复。每个注入日志步骤的恢复必须得到已验证的旧表或已验证的新表，不能留下混合模式/记录状态。

## 原生表格提升

只有该客户端提供规范 `node::UUID[]` 区块嵌入能力时，才可将 Core 解析出的原生 AsciiDoc 表格提升。预览包含源节点/范围/修订、标题解释、提议字段名称/类型/ID、记录 ID 与值、目标节点/父节点/名称、资源、精确替换源文本、不支持构造及完整事务范围。

第一个前导列标题区域提供显示名称；缺失/重复名称会获得明确审查提案，而非静默的最终标签。类型推断只是建议，未经确认绝不提交。行标题列是普通字段。跨越或合并的数据单元格、嵌套/不受支持区块、歧义标题、公式语义、不可访问资源、超限、冲突或无效目标区块均阻断转换，直至解决。Commit 创建新节点及全部权威，验证后在同一日志中以 `node::<new node UUID>[]` 替换精确原生表格范围。失败或回滚会逐字节恢复原始源文本并删除全部生成目标。前端不得让原生表格和单独创建的表节点作为两个已接受副本并存。

## 同步、索引、权限和备份

物理扫描器在返回活动表格投影前验证伴随文件和记录存储结构。伴随文件部分到达、记录分片缺失、文件名/ID/分片不匹配、重复、未知字段、无效值、冲突副本名称、链接/重新解析点或不兼容模式/记录到达均产生类型化协调问题。先前验证的设备本地投影可保留为只读且明确标为过期；它不能授权变更，也不能视为当前权威。

记录过滤、排序、分组、摘要、公式结果、反向关系和缩略图是工作区之外的一次性导出索引。它们通过表节点 UUID、记录 UUID 和权威指纹来键入条目。从相同的授权可移植字节和显式求值上下文进行重建必须产生相同的行、顺序、组、值和诊断。成功的权限提交后出现索引失败仍然是带有索引警告和重建要求的成功提交。

表 v1 仅具有表/节点级别的权限。服务器授权在浏览器交付之前过滤表存在、架构字段、记录、关系、摘要、选项、诊断、导出和选择器建议。隐藏和缺失的关系目标是无法区分的。行级 ACL、公共表单、每条记录注释、自动化和外部 API 令牌需要稍后的明确规范。

完整工作区备份包括规范表文档、伴随文件、每个分片目录和活动与已删除记录的字节、普通资源、批注、子节点、恢复所需的事务证据，以及包含表分支的任何完整工作区回收站项目。干净恢复会重新清点确切的表并重建索引，而无需数据库备份。忽略记录或表本地已删除行的备份不能声明该表是可恢复的。

## 接受矩阵

发布证据必须包括：

- 精确的有效/无效伴随文件和记录夹具；重复 JSON 键；未知成员；UUID/文件/分片绑定；NFC/大小写折叠碰撞；每个字段/值类型；小数/日期/instant 边界；受约束的 AsciiDoc 行内值；以及配置的大小/深度/数量上限；
- 字段/选项/视图重命名且身份不变；添加/删除/类型转换；必填字段拦截；公式/汇总输入和循环；稳定的排序、空值和同值排序行为；依赖上下文的时间；针对全部记录的汇总；以及确定性索引重建等价性；
- 节点与记录关系在重命名、移动、复制、移入回收站和恢复期间的行为，以及不可访问目标、部分同步、目标删除、记录软删除/恢复、批量操作 ID、永久删除确认、共享资源和资源引用修复；
- 单记录、批量、schema、资源、提升、复制、移动、节点移入回收站、恢复和永久删除事务，具有过期冲突、磁盘写满、锁定、进程终止、每个日志中断、启动恢复、精确回滚以及成功提交/索引失败行为；
- 原生表格提升，包括标题、Unicode/CJK/RTL、CRLF/LF、空/空值、提议类型、资源、冲突、合并/受保护阻断项、精确 `node::` 替换和逐字节相同回滚；
- 10,000、100,000 和 1,000,000 条记录大小证据，用于增量扫描、索引、过滤、排序、分组、摘要、虚拟化、有限内存和单记录编辑，无需进行不相关的重写；规范性预算仅在代表性硬件发布后才记录；
- 仅键盘网格导航和范围选择、屏幕阅读器行/列/标题语义、虚拟化下的焦点恢复、高对比度、缩放、减少动态效果、IME 安全单元格编辑、可访问的功能区溢出、上下文选项卡、检查器关系，以及所有输入方式之间一致的语义操作；
- 动态视图构建器与精确规范 Query 往返、数据源与布局分离、不存在隐藏的可移植 JSON、共享保存的版本门控、可编辑单元格操作证据、ACL 信息不披露，以及每个已交付调用方获得相同 Core 结果；以及
- 完整的物理备份加上干净的备用位置恢复，包含活动/已移入回收站的记录、资源、关系、节点回收站载荷，并且不需要数据库或索引工件。

在此矩阵通过之前，JSON 示例和 UI 原型仅是格式/设计夹具，不得通过发布版本写入用户工作区。
