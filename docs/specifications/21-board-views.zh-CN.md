# 看板视图

本规范绑定通用看板投影、Query/表格适配器、任务看板预设、变更规则和无障碍要求。仅当所引用的 Core 操作和事务能够重新验证并提交所定义的强类型意图时，看板操作才可用。

## 看板契约

看板是将强类型源行派生排列为泳道和卡片的视图。它没有规范的 Card 文件、Card ID 命名空间、卡片数据库或可移植前端状态。每个已交付看板投影绑定：

- `sourceKind`：规范 Query 或多维表格；
- 精确源身份和修订：Query 所有者/范围/源修订，或表格节点 UUID/共享视图 ID/伴随文件修订；
- 经权限过滤的泳道键和值标签；
- 强类型行/卡片身份和当前权威指纹；
- 投影的显示字段；
- 确定性卡片排序和结果/窗口界限；
- 每张卡片和每条泳道的能力及结构化不可用原因；以及
- 足以供 Core 重新验证的不透明操作证据，绝不是原始路径/DOM/视觉索引权威。

任务节点卡片键是其节点 UUID。节点卡片键是其节点 UUID。表格记录卡片键是 `(table node UUID, record UUID)`。原生待办项卡片键是所属节点 UUID、规范文档修订、经解析器确认的源文本范围和行种类的修订本地出现绑定；它不会持久化、链接或呈现为持久待办项身份。刷新后的源文本修订可以替换该键，并使较早操作失效。

通用看板 shell 可以消费此投影以渲染和路由操作。它不得从渲染文本中制造泳道、卡片字段、总计、身份、权限或变更。源适配器是所有已交付调用方共享的 Core/后端模块，而非独立的浏览器求值器。

## 规范 Query 看板

可移植 Query 看板是一个普通规范块，具有 `view=board` 和恰好一个标量 `group by`。当前 Query 语法仍具权威性：

```adoc
.Tasks
[.weftext-query,version=1,view=board]
....
from tasks as task
scope subtree(this.node)
where true
group by task.state as lane
select task.kind, task.id, task.title, task.state, task.priority, task.due, task.blocked, task.owner_node
order by task.due asc nulls last, task.title asc
limit 1000
....
```

`from`、`scope` 和 `where` 定义候选总体；`group by` 定义泳道键；`select` 定义卡片字段；`order by` 定义每条泳道内的顺序；`limit` 限定完整交付的行结果。看板绝不会把 `view=board` 解释为替换这些子句或保存第二个正文的许可。缺少 `group by`、非标量分组、不支持的源版本或不可用域，会产生构建器诊断，而不是无分组的可移植看板。

Core 在作用域、筛选、分组、投影、排序、限制、计数、诊断或建议之前求值授权。客户端仅接收已授权卡片和泳道值。V1 Query 没有聚合/总计结果契约，因此 Query 看板泳道可为已交付卡片显示“已加载 N”，但绝不可将该数字标为匹配总体总数。分页、总计、共享泳道标签/顺序、泳道内子泳道或其他语义，需要经审查的 Query/视图版本，而非仅 API 的浏览器增强。

任务看板预设以如下固定任务状态目录覆盖通用标量泳道呈现。其他 Query 看板通过 Core 的确定性标量升序排列泳道键，null 最后；本地化显示格式不能改变该顺序。`order by` 控制卡片，而非泳道身份。泳道折叠、聚焦卡片、滚动、密度和临时仅客户端隐藏均为设备本地状态。

## Query 看板写入能力

Query 看板默认只读。仅当 Core 证明分组表达式是一个直接可写源字段、目标泳道代表一个精确有效字段值、行种类具有一个狭窄的已接受操作，且调用方针对当前修订已获授权时，才启用跨泳道移动。

对于节点看板，v1 仅可为恰好一个直接文字文档属性的分组表达式启用移动，例如 `node.document.properties["status"]`。现有非 null 字符串值形成泳道，null 形成未分配。移至现有泳道会修补该精确属性字符串；移至未分配会通过普通属性操作移除它。计算表达式、显示标题、别名、路径、父级、多值值、处理器属性、公式和受保护/保留字段仍为只读。节点看板 v1 不能创建或重排泳道，因为任意字符串属性没有可移植选项目录。

标题和 Template Root 行在 v1 是只读看板卡片。未来直接操作可以启用特定字段，但视觉分组本身绝不授权标题重构或 Template 角色变更。通用 Query 看板 v1 没有行内新增卡片，因为 Query 作用域/分组不能识别安全的节点父级、文档插入位置或源构造器。

提交前，Core 会针对相同 Query 求值预期变更行。若它会因 `where`、作用域、授权、域有效性或限制/排序效果离开结果，操作预览会说明该处置。成功后重新加载权威结果；客户端不会将移动的卡片固定在它已不属于的泳道中。

## 多维表格看板

表格看板是表格视图，而非规范 Query。共享 `weftext.table.json` 视图使用 `layout: "board"`，且 `layoutConfig.groupFieldId` 必须解析为一个当前 `single_select` 字段。每个已配置选项 UUID 都是一个按作者选项顺序排列的泳道；选项标签/颜色属于呈现，而其 UUID 保持值权威。最终的未分配泳道代表缺失/null。多选、关系、公式、汇总、富文本、日期、布尔或计算分组对于看板 v1 都是只读/不支持的，而不会重复卡片或发明泳道变更语义。

一条记录恰好出现在一条泳道。移动至选项泳道会将该精确存储字段值替换为选项 UUID；移动至未分配会移除字段键。记录身份、其他字段、资源、关系和表格伴随文件保持不变。该操作使用表格记录事务，并在提交前重新验证记录、伴随文件/选项、视图、授权、当前表格/工作区修订和预期筛选。

由于所属表格和 schema 是显式的，新增卡片可用。它打开一个行内或检查器表单，其分组字段预设为目标选项，其他必填字段必须通过验证；提交经由表格事务创建一条全新的记录 JSON。它绝不会创建节点。表格看板可以单独显示 Core 计算的完整、已授权且已筛选的泳道总计，因为规范 20 独立定义了表格汇总。

私有表格看板视图状态保留在工作区之外。保存或更改共享视图会预览精确的伴随文件替换。卡片编辑仍是记录事务，绝不会仅因选定/聚焦泳道变化就重写视图伴随文件。

## 任务看板预设

任务看板是通过 `Insert -> Dynamic View -> Board -> Task Board` 选择所生成的专用 Query 看板。它要求 `from tasks` 和直接 `group by task.state`；通过源更改其中任一项时，刷新后会将其转为自定义 Query 看板，而不会保留隐藏任务看板语义。

Core 定义完整的泳道目录和顺序：

| 顺序 | 状态 | 产品标签 | 已关闭 |
| --- | --- | --- | --- |
| 1 | `todo` | 待办 | 否 |
| 2 | `in-progress` | 进行中 | 否 |
| 3 | `on-hold` | 暂缓 | 否 |
| 4 | `completed` | 已完成 | 是 |
| 5 | `cancelled` | 已取消 | 是 |

即使 Query 筛选当前未为某状态产生卡片，预设的全部五个泳道头仍作为工作流目标可用。已完成和已取消开始时折叠，为设备本地呈现；其标题仍可获得焦点，并在键盘、触摸或拖动移动期间临时展开。若预期转换不再满足作者 Query，预览会说明该卡片提交后将离开当前视图。

卡片呈现会识别种类：

- 清单：清单图形、非 null `task.title`、源节点显示、标记状态，以及仅真实清单操作；
- 任务节点：节点/任务图形、标题、选定的已授权优先级/截止日期/阻塞字段，以及强类型任务节点操作。

清单上的 null 任务节点专有字段会被省略，不显示为可编辑空白或默认值。源种类绝不只由颜色传达。打开清单会调用精确出现导航；打开任务节点首先在右侧检查器中提供任务详情，且可以打开普通节点编辑器。卡片标题、状态、优先级、截止日期或依赖变更绝不会直接变更缓存的看板行。

## 任务移动矩阵

| 源卡片 | 目标泳道 | 所需操作 |
| --- | --- | --- |
| 未勾选清单 | 已完成 | 精确清单标记关闭操作 |
| 已勾选清单 | 待办 | 精确清单标记重新打开操作 |
| 清单 | 其当前未完成/已完成泳道 | 无操作 |
| 清单 | 进行中、暂缓或已取消 | 显式原子提升并转换计划 |
| 任务节点 | 任意不同状态 | 狭窄任务节点状态计划 |

清单没有可表示的 `in-progress`、`on-hold` 或 `cancelled` 值。这些目标仍可见，但在悬停/聚焦/放置时显示“提升为任务节点”。放置会打开紧凑的、绑定修订的预览；绝不会仅在指针释放时改变状态。取消会把卡片返回其源泳道。

提升并转换计划不同于两个顺序变更。它绑定所有普通提升证据以及用户选择的最终状态，直接以该状态创建新任务节点，以经审查的稳定节点链接替换精确清单出现，处理完整附接分支/注释，并发布一次提交。不带看板目标的普通清单提升保留其现有默认状态映射。在调用方提供此组合操作之前，三个复杂清单目标可见但以需要提升原因为禁用。

任务节点移动可以使用轻量确认策略，因为它是一项狭窄、可逆字段操作；授权、过期修订、未保存草稿、依赖/规范配置无效或事务恢复仍会安全拒绝。多卡片移动需要一个经审查的原子计划，具有精确行/卡片身份和按种类处置；v1 可以省略它，而不是循环单次写入并报告部分成功。

## 排序和垂直拖动

v1 中泳道内的看板位置始终是派生的：

- Query 看板：规范 `order by` 加 Query 域的稳定最终排序依据；
- 表格看板：视图的强类型排序加记录 ID 作为最终排序依据。

不存在垂直拖动手柄。两张卡片之间的指针移动、键盘重排或触摸重排都不能创建可移植或私有手动顺序。如果客户端在水平拖动期间使用瞬时占位符，已提交卡片会返回其派生排序位置。手动排名设计必须在 UI 暴露前定义可移植权威、并发排名分配、压缩、混合清单/任务节点行为、具有不同排序的多个看板、复制/回收站/备份和精确事务。

## 创建和编辑

任务看板新增卡片始终创建任务节点。请求携带显式父节点 UUID、可移植名称/标题输入、初始泳道状态、当前工作区修订、授权以及生成身份/路径预览。嵌入的 `subtree(this.node)` 预设可以提议 `this.node` 作为父级；用户可见的不可变目标仍须在提交前捕获。工作区作用域、Saved Query、自定义 Query、当前焦点、选定卡片或视觉泳道都不提供隐式父级。

原生待办项只能在存在精确可编辑文档/列表插入位置处创建。看板可以深链接至“在文档中添加简单待办项”，但必须在提出插入前打开/捕获该目标；单独一列不足以构成权威。

表格看板新增卡片如上所述创建一条记录。节点/标题/Template/自定义 Query 看板在 v1 没有新增卡片。源特定标题编辑仅在现有 Core 操作可修补精确清单主体文本、任务/节点文档 Title、直接文档属性或记录主字段处可用。派生显示标题和计算/仅卡片投影为只读。

## UI 和无障碍

选择 Query 看板会暴露 Data 加 Dynamic View；选择表格看板会暴露 Data 加 Multidimensional Table。不会添加永久 Board 选项卡。最低限度控件为源/表格、适用时的作用域、筛选、分组字段/表达式、卡片字段、排序、共享/私有状态、刷新、Focus view，以及适用时的 Query Source。

宽布局使用水平可滚动泳道和独立虚拟化的卡片列表。每条泳道都有真实标题、标为已加载或总计的卡片数量标签、受支持时的新增能力、折叠状态和可访问操作。窄/移动布局使用泳道选择器和一个垂直卡片列表；拖动可选。Focus view 使用相同投影/源修订，绝不复制看板定义。

每个水平拖动操作都具有等价的卡片菜单 -> 移至、键盘移动命令和屏幕阅读器状态选择器。拖动开始会播报卡片/源/当前泳道；有效目标和操作种类无需悬停即可暴露；提升和离开视图后果会在确认前播报；成功后若卡片仍在则恢复对该卡片的焦点，若已离开则恢复对源泳道/状态消息的焦点。Escape 取消。指针、键盘和触摸路径提交相同的强类型操作。

IME 组合期间阻止卡片拖动和命令截获，直至组合结束。虚拟化在已加载窗口之间保留活动后代/卡片位置语义、选择、泳道标题和焦点。颜色绝不单独传达泳道、卡片种类、阻塞、无效或权限状态。缩放、高对比度、减少动态效果、RTL/混合方向、长 CJK 标题、窄泳道、离线/过期状态和检查器关系都是必需情形。

## 并发、非披露和失败

看板渲染和操作复用源授权；浏览器绝不会先接收隐藏卡片再将其隐藏。隐藏/缺失的节点、任务、关系、表格、字段、泳道选项和操作目标不可区分。计数、空泳道、建议、诊断、拖动目标、提升预览和新增默认值不得披露未授权权威。

操作在调用时捕获其强类型目标和修订。之后的焦点、选择、泳道重排动画、滚动或刷新都不能重新目标它。提交重新验证权威和预期结果。成功后索引/投影刷新失败会被报告为成功提交加刷新警告；不建议重试写入。失败会保持权威字节不变，或调用普通日志恢复后重新加载，而不是信任乐观 UI。

## 验收矩阵

发布证据覆盖：

- 每个已交付调用方中相同的 Core 看板投影、泳道/卡片顺序、身份、能力、不可用原因和源修订；
- 具有必需标量 `group by`、源/视图分离、精确卡片字段/顺序/限制、null 泳道、计算/只读分组、节点直接属性移动、预期离开视图行为、已加载数量标记和不存在隐藏可移植配置的规范 Query 往返；
- 表格 `single_select` 选项/未分配泳道、选项顺序/重命名/重排/删除、记录移动/新增/筛选、当前伴随文件/记录修订、精确共享/私有视图行为、完整已授权总计，以及拒绝多选/关系/计算分组；
- 全部五条任务泳道/顺序/标签、已折叠关闭泳道、清单/任务节点视觉和能力差异、精确完成/重新打开、任务节点状态变更、组合提升可用前需要提升的禁用状态，之后的原子提升并转换及取消/过期/草稿/注释/回滚/崩溃情形，且没有中间/重复卡片；
- 指针/键盘/触摸均无垂直手动排序，刷新后稳定派生顺序，以及重复/null/Unicode 值下精确的最终排序依据；
- 显式父级任务节点创建、没有含糊的清单/Query 创建、无节点的表格记录创建、仅直接标题/属性编辑，以及没有通用卡片权威；
- 卡片/泳道/计数/诊断/建议/操作之前的授权、隐藏/缺失不可区分、Server 参与者与会话绑定、拒绝重放，以及提交后刷新失败行为；
- 鼠标、触摸、纯键盘、屏幕阅读器、IME、缩放、高对比度、减少动态效果、RTL、CJK/长文本、已折叠目标、移动泳道选择器、Focus view、虚拟化、选择和检查器导航；以及
- 多达规范结果限制的代表性 Query 看板，加上 10,000、100,000 和 1,000,000 记录规模的表格看板，用于有界内存、增量投影、独立泳道虚拟化、取消和没有无关权威重写。

通过一个通用拖放组件测试或截图并不满足此契约。
