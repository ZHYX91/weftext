# 文档历史、比较和备份仓库

本规范定义文档历史、比较和正式备份仓库。任何客户端都不得将设备历史、回收站、同步文件夹或未经验证的副本标示为正式备份。

## 产品状态和术语

备份状态为 `not_configured`、`healthy`、`overdue`、`unavailable`、`verification_required` 或 `read_only` 之一。新的本地工作区以 `not_configured` 开始。Weftext 不会在工作区旁、应用数据内或同一磁盘其他位置创建隐式备份目标。可以启用 Recent History，但产品显示：

```text
Backup: Not configured
Recent History: This device only
Last formal backup: None
```

连接到 Server 仅在 Server 报告已授权的已配置目标和当前已验证状态时才会改变此情况。云同步工作区、同步提供方版本历史、工作区回收站、设备草稿存储、事务日志、本地 Recent History 或派生索引都不会将 `not_configured` 改为 `healthy`。

UI 术语 **Version History** 覆盖文档修订。**Chrono** 仍指日期节点创建，**Timeline** 仍指数据/视图布局。两者均不是备份或修订存储。

## Recent History 存储 v1

Desktop 将 Recent History 存储在所选工作区外、其 OS 应用数据根目录下，逻辑结构为：

```text
workspaces/<workspace-instance-scope>/history-v1/
  _weftext.history-store.json
  entries/<entry-id>.json
  objects/sha256/<first-two-hex>/<digest>
```

受信任的原生进程派生有界工作区实例作用域；它绝不是浏览器路径、凭据、可移植工作区 ID 或在公开 DTO 中披露的绝对路径。位于另一物理实例的复制工作区会获得独立的本地作用域，除非显式恢复/导入操作将选定历史作为只读证据附接。

`_weftext.history-store.json` 具有规范配置 `weftext.document-history-store/v1`、整数版本 `1`、小写 UUIDv4 `storeId`、不透明工作区实例绑定摘要、当前根节点 UUID、创建时间和保留配置。它不包含源正文、目标地址、凭据、搜索数据或可变的“当前文档”指针。未知/重复成员、无效标识符/时间/界限或工作区绑定不匹配均安全拒绝，并保留存储供诊断。

每个不可变条目均以小写 UUIDv4 命名，并具有封闭配置文件 `weftext.document-history-entry/v1`、版本 `1`、匹配的 `id`、节点 UUID、基础/结果文档修订字符串、基础/结果对象 SHA-256 摘要和长度、操作种类、显式偏移提交时间、可空且有界的操作者/设备显示证据，以及可选的用于呈现的前置条目 ID。操作种类为 `document_save`、`format`、`property_edit`、`merge`、`history_restore`、`external_resolution` 或另一种单独版本化的 Core 原生类型。前置项并非对象恢复所必需，也不能覆盖修订/摘要证据。

对象文件包含精确的原始规范源字节。其小写 64 位十六进制文件名及分片绑定 SHA-256 摘要；复用前会重新打开并验证现有对象。条目绝不嵌入源、路径、草稿、渲染 HTML、补丁或注释。完整条目 JSON 是无覆盖发布，且仅在两个对象均验证后进行。孤立对象或暂存字节不是版本，且仅通过有界存储维护清理。

对于成功的规范文档提交，Core/原生权威提供精确、已验证的前/结果源和修订。历史暂存可以在工作区变更前开始，但仅在工作区提交验证后发布条目。若条目发布失败，提交结果仍成功并添加结构化 `history_capture_failed` 警告；不会写入空的/捏造的条目。重试历史捕获是针对精确保留提交证据的独立幂等操作，绝不是重复文档提交。

Recent History 默认启用，具有可见、可配置的时间/空间保留策略。发布必须公开其有界默认值；禁用或清除时需确认，确认内容声明 `This device only` 并报告条目/字节数。保留会在策略内按最旧优先移除条目，随后只移除从剩余条目不可达的对象。受保护正式备份快照和其他设备/存储不属于该操作。损坏/不可读条目或对象仍是恢复/诊断问题，不会从当前源静默重新生成。

V1 Recent History 仅捕获规范文档源。它不声称在资源、注释、表格记录、Template 伴随文件、被忽略/非受管内容、回收站、子节点或 Server 状态发生变更时可以精确恢复节点/子树。历史 UI 会相应标示仅源恢复。完整恢复使用正式备份快照。

## 备份目标配置

备份配置是工作区外的设备或 Server 操作状态。它包括目标种类/地址、初始化后的仓库 ID、执行器模式/身份、计划、保留、认证引用、带宽/离线策略以及上次操作/验证摘要。凭据保留在 OS 或 Server 秘密存储中。诊断默认对秘密和完整远程/本地地址进行脱敏。

受支持的目标种类按能力显式版本化。V1 可独立交付本地目录、已挂载/网络目录、Server 受管文件系统和经审查的远程对象存储；不可用种类不会表示为通用 URL 回退。每个后端都要在产品支持前证明路径/根限制、无覆盖对象创建、原子或条件创建的清单、有界列出/读取/删除、写后读取验证、重试/幂等、中断恢复和错误映射。

执行器模式为 `this_device`、`server` 或 `read_only`：

- `this_device` 仅允许绑定的 Desktop 执行器创建快照、保护/取消保护、保留、验证和垃圾回收；
- `server` 仅允许已配置 Server 备份服务执行这些操作，而客户端请求已授权操作；以及
- `read_only` 允许清点、比较和恢复规划，但不允许仓库变更。

原始文件系统/网络/云同步仓库恰好有一个已配置写入者绑定。另一设备以只读方式附接，或初始化独立仓库。写入者转移是显式、经审查的接管：它验证仓库、证明不存在活动租约/请求、原子替换执行器绑定并记录回执；打开同一目录绝不会静默夺取它。受管后端可以在一个服务器端执行器后串行化多个请求者，但客户端仍不会发布清单或直接执行保留。

目标必须解析到所选工作区及任何请求拥有的工作区暂存区之外且不相交的位置。词法和解析后的包含关系、符号链接、Windows junction/reparse、硬链接别名和嵌套目标检查均安全拒绝。同磁盘目标会标为 `local recovery only`，除非用户明确确认它不能防范磁盘/设备丢失。位于工作区同步树内的目标不能是唯一正式备份。

## 备份仓库 v1

一个仓库目录绑定一个工作区备份谱系：

```text
<repository>/
  _weftext.backup-repository.json
  objects/sha256/<first-two-hex>/<digest>
  snapshots/<snapshot-id>.json
  protected/<snapshot-id>.json
  staging/<operation-id>/...
```

封闭仓库清单使用配置文件 `weftext.backup-repository/v1`、版本 `1`、仓库 UUIDv4、谱系 UUIDv4、根节点 UUID、创建时间、写入者模式/不透明写入者绑定以及对象/快照 schema 版本。它不包含目标地址、凭据、机器路径、工作区路径、用户秘密或可变的最新快照权威。仓库可以作为完整目标移动；重新连接时会验证其身份和显式工作区谱系绑定。

附接工作区要求精确的活动根节点 UUID 和显式谱系选择。具有相同根 UUID 的两个物理副本绝不会静默共享写入谱系：用户要么重新连接已知的持续实例，要么派生新的仓库谱系。派生不会复制或声明旧历史，除非显式导入/只读附接已获审查。

对象路径是小写 SHA-256，且包含精确的常规文件字节。对象创建是不可变、无覆盖的；复用前会验证既有字节/摘要/长度。若以后接受压缩或加密，必须保留单独版本化的明文内容摘要绑定和恢复契约；v1 不声称二者中的任一种。

每个 `snapshots/<snapshot-id>.json` 都是不可变、封闭的 `weftext.backup-snapshot/v1` 清单，并以匹配 UUIDv4 命名。它包含仓库/谱系 ID、根节点 UUID、显式偏移创建时间、原因（`scheduled`、`manual`、`pre_migration`、`pre_restore` 或单独版本化的种类）、可空的前置快照 ID、工作区格式标记/配置文件、完整物理清单摘要和按规范路径排序的完整条目列表。每个条目是一个封闭变体：

- 目录：规范化工作区相对 `/` 路径和 `kind: directory`；
- 常规文件：路径、`kind: file`、字节长度和 SHA-256 对象摘要。

根目录使用空相对路径；绝对路径、空的非根组件、`.`/`..`、分隔符别名、重复/精确大小写折叠冲突、非 UTF-8 路径、未知种类/成员、链接/reparse 点、硬链接别名歧义、缺失/额外对象或摘要/长度不匹配均使快照无效。因此空目录可往返。快照包含规范 08 要求的每一项物理权威，包括被忽略字节和回收站存储；分类可被记录为非权威显示证据，但不能遗漏字节。

快照发布取得一个精确、按安全拒绝规则处理的物理清单及工作区修订/租约，暂存/验证所有缺失对象，最后经由原子/无覆盖语义写入并重新打开完整清单，并返回一个回执，其中包含快照 ID、清单摘要、文件/目录/字节总计、复用/新对象总计、目标/仓库身份和验证结果。清单之后的工作区变更会拒绝或重启规划；绝不会产生混合时间的清单。没有已验证清单的暂存是不完整操作证据，而非快照。

`protected/<snapshot-id>.json` 是封闭的 `weftext.backup-protection/v1` 标记，带有匹配的仓库/谱系/快照 ID、显式偏移保护时间和有界标签。保护不会修改不可变快照。取消保护/删除是显式且经权限检查的；保留不能移除具有有效标记的清单。无效标记会阻止保留/垃圾回收，并保留所有可能被引用的对象。

初始已配置保留策略至少保留 24 个每小时、30 个每日和 12 个每月快照，以及每一个受保护快照。调度可以在完整物理摘要未变时跳过创建，同时记录成功检查，但不得静默削弱保留窗口。保留首先预览精确的未保护快照清单；提交仅通过可恢复仓库事务移除策略允许的清单/标记。对象垃圾回收是单独操作：它重新验证每个已保留/受保护清单，计算可达性，预览对象/字节删除，且绝不在清单不完整/损坏、活动暂存、另一租约或只读模式下删除。

没有 SQLite、派生目录、对象缓存或“latest”指针是仓库权威。实现可以在仓库外或明确派生的缓存目录内构建可丢弃索引，并从仓库/快照/保护清单重建它们。恢复和验证在这些缓存缺失时仍可工作。

## 无默认行为和健康

创建/打开工作区时，Weftext 提供非阻塞设置：选择本地/外部/网络目标、使用 Server 受管目标，或选择稍后。选择稍后会保持 `not_configured`，不创建仓库，也不阻止编辑。设置、Version History 和恢复中心会继续显示缺少正式备份，而不会反复模态中断。

选择目标后，会立即提供第一个完整快照。`healthy` 要求策略下当前成功的快照、完整仓库验证，以及在配置验证间隔内的干净恢复演练。没有重新打开/摘要验证的已完成复制不算成功。`overdue`、`unavailable` 或 `verification_required` 绝不会显示为安全。工作区提交独立于备份可用性而成功，但报告待备份/未备份状态；它们不会重试写入。

“立即备份此版本”会请求已配置执行器为完整工作区创建快照，而非仅复制一个 Recent History 源。只读客户端会在支持时转发一个已授权的 Server 请求，或解释其执行器不能写入。

## Server 和跨设备历史

Server 模式将当前工作区、控制平面和历史/备份仓库保持为不相交根目录。Server 是执行器，并使快照/保留/恢复操作与工作区变更串行化。一份一致的托管备份绑定一个工作区修订/物理清单、兼容的控制平面快照、仓库/历史状态和回执。活动控制平面 SQLite 通过其已接受的在线/静止过程备份；仅复制主数据库文件无效。

客户端可查看相同的已授权 Server Version History，无需直接仓库凭据或路径。Server 控制平面行可以索引/审计快照和历史 ID，但旧文档正文仍是仓库对象，而非仅 SQLite 的内容权威。可移植工作区同步/复制会省略 Server 历史；完整 Server 迁移包含单独清点的工作区、控制平面和仓库。

对于非 Server 云文件夹工作区，每台设备的 Recent History 仍是本地的。将多台设备连接至一个原始仓库不会授予多个写入者。设备可以共享对已挂载仓库的只读访问，或各自写入不同仓库。UI 可以按来源联合只读历史，但绝不会从未同步设备时钟发明一个总顺序；它按时间再按稳定源/条目 ID 排序，并标示来源。

## 比较输入和输出

Core 接受封闭、不可变的 `DocumentCompareInput` 引用：

- `current`：节点 UUID 加精确当前文档修订；
- `recent_history`：已授权存储/条目 ID 加绑定的节点/修订/摘要；
- `backup`：仓库/快照 ID 加节点 UUID 和精确快照文件摘要；
- `draft`：节点 UUID、配置文件、基础修订、来自调用设备/会话草稿边界的精确源摘要/源；
- `external`：来自冲突中心的精确捕获文件源/修订；或
- `other_node`：已授权节点 UUID 加精确当前修订。

双向比较接收 `left` 和 `right`。三向比较接收显式 `base`、`left` 和 `right`；全部三个配置文件必须兼容，否则转换是单独经审查的操作。授权和非披露先于历史查找、快照成员资格、源加载、解析诊断、计数或差异输出。隐藏和缺失版本/目标不可区分。

Core 使用规范配置文件解析每个精确源，并生成有界、确定性的 `DocumentComparison`：输入身份/摘要、同节点标志、系统元数据处置、有序强类型变更组、精确左右源范围、稳定显示片段、结构上下文、冲突分类，以及在单独清点时的资源/注释/记录/结构摘要。比较是只读、无副作用的；它不返回文件系统路径或写入能力。

引擎在稳定的行/词回退前匹配解析器所有的文档头、章节/标题、段落、列表、原生表格、受保护块和 Weftext 扩展块。它不执行包含/网络/宏，不渲染 HTML，不规范化行尾，不展开属性，也不重写任一源。仅当有确定性证明时，移动的唯一结构才可标为已移动；含糊之处仍是删除/添加或冲突，而非猜测的移动。

比较不同节点时，系统元数据封装范围会被折叠，且仅身份变更会从默认内容组排除。`weftext.id` 始终受保护，不得应用。用户可以检查完整 Source 差异，但节点身份、备份谱系、路径、派生反向链接/索引和文件系统时间戳绝不是可复制内容块。

限制涵盖每个源/对象大小、块、标题、表格单元格、差异令牌/块、递归、工作步骤、输出字节和总比较时间。越过限制会返回一个强类型的无部分结果诊断。CJK/RTL/字素边界以及 CRLF/LF/CR 源范围保持精确。

## 合并和历史恢复计划

查看/比较历史无需工作区事务。任何已接受内容块处置首先构建受控结果草稿。`DocumentMergePlan` 绑定目标节点/当前基础修订/源、每个比较输入摘要、比较 ID、选定内容块处置、精确提议源、目标配置文件解析/模型诊断、系统/受保护范围策略、授权、设备草稿观察和过期信息。它绝不应用视觉行号、过期片段、原始路径或客户端生成补丁。

只有当 Core 能生成确定且精确的替换时，才提供 `Use left`、`Use right` 和 `Keep both`。需要人工编辑的冲突会创建明确的可编辑结果范围。提交前会重新解析最终结果，并以精确源文本和语义变更形式预览。提交通过普通可恢复事务写入一个目标文档，并记录新的 Recent History 或 Server 历史事件；如果提交后的历史记录失败，文档提交仍然成功，但会显示警告。

`DocumentRestorePlan` 是从一个精确 Recent History 或备份版本进行全源替换的特化计划。它显示当前与所选版本的比较、目标节点、所选源的来源/时间/摘要、被排除资源/伴随文件、系统元数据封装处理、结果文档以及草稿/过期/权限后果。同一节点恢复会保留当前 `weftext.id`；较旧元数据封装不能替换身份。“恢复为新节点”则是结构创建计划，具有新的 UUID/名称/父级，以及单独经审查的链接/资源行为。

完整节点/子树/工作区恢复仅来自正式备份快照。其演练会验证仓库/快照/对象完整性、目标位置、当前物理清单、身份、冲突、权限、当前草稿、禁止覆盖策略和回滚/替代位置策略。恢复到替代位置是默认的低风险演练。干净恢复会重新打开目标，并比较完整预期清单/身份/摘要，之后仓库健康才可以提升。

## UI 契约

Review 包含 Compare 和 Version History。Compare 提供上一版本、Version History、另一文档、备份快照以及解决草稿/外部冲突。右侧检查器中的 Version History 合并可用条目，同时显示 `This device`、`Backup`、`Server` 或 `Protected restore point` 之一，以及精确可用性和是否可以完整恢复。

比较界面支持行内和并排模式、变更导航、结构上下文、安全时的源文本/渲染切换、系统元数据折叠、资源/批注摘要以及逐项变更处置。用户选择创建结果草稿之前，比较结果不可编辑。没有当前版本与所选版本的预览时，恢复绝不能成为主操作；把旧源文本复制到剪贴板与应用该版本是两种不同动作。

备份设置以脱敏形式显示目标类型/地址、执行器、策略、上次尝试、上次成功快照、上次验证、上次干净恢复演练、待备份/未备份变更、仓库健康和只读状态。首次运行的稍后仍可用。没有已配置目标意味着没有绿色盾牌/勾选标记或“受保护”措辞。

所有控件均有键盘和屏幕阅读器语义；变更、插入、删除和冲突内容绝不只用颜色传达。IME 组合输入与变更快捷键隔离。大型比较或历史列表可以虚拟化，但不得丢失焦点、源位置、来源或所选内容块状态。Desktop、托管/本地 WebUI、CLI、Server API 和获准智能体接口，对其公开的每项能力都使用相同的 Core 比较与计划证据。

## 验收矩阵

发布证据包括：

- 具有 `not_configured` 的干净工作区；Recent History 默认值/来源；非阻塞设置；没有隐式文件夹；如实的同磁盘/只读/过期/不可用/验证状态；以及不因同步/回收站/草稿/日志重新分类；
- 精确 Recent History 存储/条目/对象解码、重复键/ID/路径/摘要/绑定失败、前/结果捕获、提交成功/历史失败分离、孤立清理、有界保留/清除/禁用、损坏保留以及没有工作区或跨设备同步；
- 本地、外部、网络、Server、只读及每个声称的远程后端，具备路径不相交、写入者绑定/接管、租约、无覆盖、重试/幂等、部分暂存、凭据脱敏、离线恢复和多请求串行化；
- 封闭仓库/快照/保护 schema、包括空/被忽略/非受管/回收站/表格/template 字节的完整物理清单、不可变去重对象、最后发布清单、未变快照检查、24/30/12 保留、受保护点、可恢复清单删除/垃圾回收、派生索引删除/重建和拒绝损坏；
- 计划/手动/迁移前/恢复前快照、完整回执、工作区变更竞争、同根复制工作区谱系派生/重新连接、本地专用警告、配对的 Server 工作区/控制平面/历史一致性以及干净的替代位置恢复演练；
- 每组双向比较输入和三方合并基准、相同或不同节点、系统身份保护、文档标题/文档头/正文标题/列表/表格/受保护范围/扩展结构、移动或含糊变更块、行/词回退、资源/批注摘要、CRLF/LF/CR、CJK/RTL/字素簇、畸形源文本、限制与取消、确定性输出，以及对 Git 运行时或仓库的零依赖；
- 合并/恢复内容块处置、冲突编辑、精确提议源、解析/配置文件失败、过期目标/历史/仓库、未保存草稿、ACL/非披露、重放/过期、崩溃恢复、成功提交加历史捕获失败、新历史事件、身份保留以及恢复为新节点的新身份；以及
- 已交付的 Desktop/WebUI/Server/CLI 一致性、仅键盘和屏幕阅读器比较/历史/恢复、IME、缩放、高对比度、减少动态效果、虚拟化、脱敏诊断，以及经权限过滤的历史/计数/时间/操作者/快照非披露。

Recent History 列表、Git 包装器、差异库截图、同步副本，或没有干净恢复的备份清单，都不满足此契约。
